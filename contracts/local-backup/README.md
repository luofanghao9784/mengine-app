# 本地备份与恢复契约

这是本地独立试用实例的离线工具，不是线上灾备服务，也不提供企业管理员下载整库的接口。真实模型、外部通知与付费服务不参与验证。

## 操作与状态

运行入口为 `python3 scripts/local/backup.py`。所有路径必须是当前用户所有的私有目录；密钥必须在备份集合之外。工具只启动自己持锁的 PostgreSQL 18，使用临时 Unix socket，拒绝接管仍在运行的原实例。

| 命令 | 参数 | 实际效果 |
|---|---|---|
| `create` | `--directory 原实例 --output 新备份 --key-file 独立密钥` | 真正转储数据库与尚未物理清除的原件；逐表和逐文件摘要，排除登录会话 |
| `verify` | `--bundle 备份 --key-file 独立密钥` | 校验签名、完整文件清单、摘要、大小及到期时间 |
| `repack` | `--bundle 备份 --output 新副本 --key-file 独立密钥` | 复制已校验备份，保持原快照 ID、生成时间和到期时间 |
| `restore` | `--bundle 备份 --output 新恢复目录 --key-file 独立密钥` | 实际还原数据库及原件；核对逐表摘要后转为 `QUARANTINED` |
| `reconcile` | `--directory 恢复目录 --current-directory 原权威实例 --key-file 独立密钥` | 重新读取独立当前状态，处理删除及派生内容，记录签名证据；保持 `CURRENT_STATE_CHECKED_QUARANTINED` |
| `activate` | 同 `reconcile` | 再次即时核对当前状态，在当前有效身份、空间和授权的交集内显式开放；生成全新本地密码；状态为 `ACTIVATED` |
| `rotate` | `--directory 备份集合 --key-file 独立密钥` | 删除集合内签名有效且已过期的备份和未开放恢复实例；不删除未知、被篡改、正在运行或已开放的实例 |

`reconcile` 不是开放授权。`activate` 是本地操作者明确选择将恢复实例投入使用的动作。它不启动服务；成功后才能通过既有 `trial:start` 启动。操作者须将旧实例保持停用，避免两个独立业务副本同时投入使用；此工具没有远程集群切换或跨实例持续同步机制。

## 备份时间和真实性

v2 签名清单包含 `snapshotId`、`sourceInstanceId`、实际数据库快照开始的 `createdAt`、严格等于其后 30 日的 `expiresAt`、PostgreSQL 主版本、迁移脚本名与 SHA256、原数据库事务序号、逐表行数及摘要、原件/转储的大小与 SHA256、代码版本。文件时间、读取、复制和 `repack` 都不能重置期限。过期备份不能恢复，过期待开放副本不能激活；轮转不是仅按目录名或 mtime 删除。

已显式开放的恢复实例是新的实际业务实例。它可以建立自己的独立来源登记，进行新的真实数据库快照；这不会改变旧备份或副本的 ID 和到期时间。未开放副本不能通过 `create` 续期。已开放实例之后可按正常 Flyway 路径升级：既有迁移必须精确保留，新增迁移须已进入显式恢复覆盖清单；不会要求再次用旧权威实例开放，也不会借升级重放旧执行。旧 v1 备份没有足够的来源与期限证据，不进入本契约的自动恢复流程；旧 v1 格式的独立签名密钥仍可使用。

Flyway 版本从迁移文件动态取得，允许编号空缺，不再写死 V1–V15。实际迁移必须与工作树完全相同。恢复适配器另有显式 `coverage.json`：迁移文件 hash、全部数据表、schema 目录指纹及需要离线映射的 `DepartureResidualCleanup.java` 实现摘要；新增模块、未知表、改列/约束/视图/函数都拒绝恢复核验或开放，不能只更新一个“最高版本”跳过语义适配。PostgreSQL 18 对部分 CHECK/index 表达式在转储还原后会重写为等价形式，清单记录了干净迁移及真实 dump/restore 的两个已验证指纹。

## 当前状态证据

首次备份将原目录、原 PostgreSQL cluster ID 与来源 UUID 签名登记在原实例以及密钥旁的独立登记文件。`reconcile`/`activate` 只接受同一已登记、当前停用的权威原数据库，整个读取与应用期间持有两边实例锁。旧备份、待开放恢复副本、异源目录、缺失登记或早于原快照的数据库事务状态不能替代当前证据。

证据文件仅记录控制对象摘要、必要 ID/状态、适配器版本及处理结果，不复制账号密码 hash、业务正文或模型上下文。缺证据、签名错误、schema 不匹配或应用失败时保持隔离，不自动开放。完全丢失当前权威实例且无独立当前状态来源的场景，本轮只能完成隔离还原；不把旧快照自身当作“当前有效”。本机已获文件/密钥控制的操作者属于工具信任边界，签名不等同于抵御本机管理员篡改。

## 恢复边界

- 先确认真实还原逐表一致，再撤销旧会话和待接受邀请、停用旧账号/密码/旧授权。`trial:start` 先核对 API jar 中全部迁移与当前工作树精确一致，旧构建不能打开较新权限结构；还需要绑定恢复目录、PostgreSQL cluster、schema 和证据的签名开放凭证，不能只改一个布尔开关。
- `activate` 不复用旧密码。账号只在相同 ID、邮箱仍有效时恢复；企业、成员、空间、维护能力与治理负责人都按当前权威状态重建可用交集。缺失或改变归属的私人空间不会继续向旧 owner 开放，必要时保守停用该旧账号。无可用平台身份时仅生成本地平台运维身份，不授予企业成员或内容权限。
- 保留政策与离职/退出准备清单同步当前实际版本，`ASSESSED` 不被当作完成离职或退出；不据此修改身份权限，不重新计算既有资料截止。当前控制记录引用了快照中缺失的身份或空间时保守隔离该企业。
- 正式离职/企业退出执行、范围隔离、删除证据与原截止按当前权威记录重建。`CANCELLED` 才解除对应正式守卫，准备清单、到期或恢复本身不会解除。离职目标成员保持停用；退出窗口只保留当前仍有效的明确共享导出授权，私人会话、草稿与新业务仍不可用，旧退出导出包实际 chunk 被删除且清单/分包失效。
- 已核对的退出企业可能在原实例保持 `ACTIVE`，用于治理和限时导出。工具只在双方停止、恢复 API 未启动且当前证据核验完成后，在一个离线事务内暂禁 `departure_tenant_activation` 与 `departure_member_activation` 两个确切触发器，复制当前已有身份交集，并在同一事务中启回；前后检查均启用，任何异常回滚。不会使用 `session_replication_role` 或禁用全部触发器。此必要恢复路径不能用于普通在线重新激活，正式退出事实及业务读取限制始终保留。
- 当前正式退出已到原截止且停止已完成时，离线重做同范围残余正文清理，覆盖档案值/来源、个人空间档案、计划及历史/幂等回执、来源说明/版本/补交备注、会话标题/公网查询、诊断警告和呈现偏好；成员离职保留共享企业资产，企业退出覆盖企业范围。它在配置核对后执行，不能由旧配置重新带回正文。
- 独立对象清理使用正式 `scrub_lifecycle_object` 实际擦除旧快照正文，保留必要身份和独立发布成果。已清除操作通知按当前完成回执再次移除；事件序号继续超过当前已处理编号，不复用旧序号。任务/尝试计量、幂等与权限/删除记录保留。策略版本及原锚点、原截止保持当前值，不因恢复延期。
- 旧运行任务记为 `RESULT_UNKNOWN`，保留结果核对要求；旧待执行任务与计划暂停，旧租约失效，旧模型使用账不冒充成功。旧解析及资料清理租约也失效。开放不会自动重跑旧任务与持续计划；当前权威状态中已经生效的删除、退出窗口到期和保留政策仍由正常维护执行器推进，不因备份恢复取消其效力。
- 已授权计划的一次后续检查不会因恢复重新执行：仍待处理的检查取消，当前已派发事实保留；若派发产生的任务不在快照内，保留“已派发、任务不在本次恢复数据中”，不伪造任务或重发。来源/任务或退出期限要求清理时，同步擦除检查理由。会话偏好保存回执仅保留独立枚举及来源位置摘要，不据回执重新保存偏好或覆盖后来修改；实际偏好继续按当前档案版本核对。
- 私人画报调整消息沿其真实任务生命周期保存，当前已擦除的卡片快照与原说明不会从旧备份恢复；来源和实际历史依赖必须仍对应当前记录与权限。后来修改或撤回评价不自动取消另行明确提交的调整任务。旧调整任务不自动继续，不重发评价或任务；独立发布副本不依赖作者私人任务。
- 站内转发仅保留确切副本的原接受与当前打开事实，不重新发送、不补造收件人、不凭转发记录授予阅读权。当前已擦除的附言同步清除，身份/接收人关系无法对应时隐藏该旧转发；独立副本按其本身当前权限读取。
- 关注布局采用当前权威位置，保持完整小数精度；布局修订高于两边已有修订，旧移动回执只保留原事实，不再次移动卡片。排序位置不授予来源、成果或会话内容读取权。
- 当前已删除、待清理或身份无法对应的资料，恢复副本清除原件和源绑定的回复、尝试快照、附件、私文稿、经验使用说明、反馈与上下文评审；物理删除完成才记录清理完成。明确发布的独立资料副本不跟随源文件级联删除，按目的空间当前权限读取。
- 共享独立副本的评价属于读者本人，仅以该副本的确切资料版本为来源，不因作者原任务删除一并失效。副本当前删除会清理反馈及来源绑定的纠正/候选，读者当前撤权会阻止重新读取；独立明确偏好按其自身当前状态核对。若当前权威反馈已改评、撤回或目标/来源身份不再对应，隔离旧备份中的意见版本，不把旧 ACTIVE 评价重新作为当前意见，也不复制新反馈原文。
- 档案、明确偏好和方法以确切版本恢复。当前不可逆 `scrubbed` 标记即使尚未同步为生命周期 PURGED，也要重新擦除旧快照中的该版本正文；较新版本不受牵连。旧快照的方法头、发布与采用记录不能充当当前依赖：当前版本不在备份内时保持无有效头/采用，不重建新正文或重新采用旧方法。真实仍在用的版本继续按当前证据保留，普通日常删除的依赖规则不因恢复开放而放宽。
- 当前有效配置证据会参与核对；档案版本、经验发布、来源配置仅与当前生效的保留版本精确相同时才重新有效。不能对应当前配置的内容保持停用，恢复已经生效的方法采用依据当前权威采用状态与精确保留的版本/发布记录；评测标准后来升版不自动撤销已生效采用，方法版本或发布身份缺失/不匹配才保持停用，评估正文按自身生命周期处理。新的采用/回退继续由方法服务核对当前评测条件；旧导出包清除实际 chunk，推荐配置使用当前值，呈现记录本身不授予内容权限。旧持续计划始终需新的显式恢复动作。本地恢复后的管理配置采用与完整生产灾备属于各自验收范围。

## 本地技术日志

监督器只管理自身 0700 目录下的 `logs/`，服务和 PostgreSQL 输出经所属管道写入分段；没有在运行中复制、截断仍被子进程写入的文件。分段名记录其最初生成的 UTC 时间，达到 4 MiB 或跨日产生新段；启动、写入和运行期间至少每分钟清理超过 30 日的段。总存储同时上限 128 MiB / 128 段，容量不足可提前移除最旧诊断段。这是本机平台技术日志固定上限，不将某企业政策套到共享日志。

复制、touch 或重启不重置段的日期。旧 `service.log` / `postgres.log` 仅在停止状态迁移，原文件可证明的出生时间作为保守上界；无法证明原始时间的旧诊断内容不重新续期。未知文件、符号链接、硬链接和非私有权限会拒绝日志操作；不删除其他类型文件。日志不包含业务数据库备份，不参加恢复开放判定。

## 验证

无需数据库的边界测试：

```sh
python3 -m unittest discover -s tests/local -p '*test.py' -q
```

真正的 PostgreSQL 18 合成数据库测试，每例使用新的私有临时目录，不读取既有试用数据：

```sh
RUN_BACKUP_DB_TESTS=1 python3 -m unittest discover -s tests/local -p backup_integration_test.py -v
```

实际 Spring HTTP 登录/原件读取验证还需要本工作树已编译的 API 类与 `TaskContextIntegrationTest` 的 Maven 依赖报告；不启动模型，也不连外部系统：

```sh
RUN_BACKUP_DB_TESTS=1 RUN_BACKUP_HTTP_TESTS=1 python3 -m unittest discover -s tests/local -p backup_integration_test.py -v
```

HTTP 测试的数据库由当前迁移建立，因此仅在该合成进程关闭 Flyway 再执行，避免用测试自建历史表模拟 Flyway checksum；生产与 `trial:start` 不关闭迁移校验。完整浏览器演练使用新的 `restore → reconcile → activate` 流程，验证未开放实例不能启动、旧密码与旧会话拒绝、新凭据登录、当前删除和撤权保留，以及恢复后可继续编辑。它只建立可销毁的合成试用实例。

```sh
npm run trial:build
npm run test:backup
```

维护者在逐一审查并实现新迁移的恢复语义后，可运行以下命令从全新合成数据库重新记录目录指纹。该命令不会读取任何已有企业数据库；不能将它用作跳过新模块适配的通用“修复版本不匹配”开关。

```sh
python3 scripts/local/backup_coverage.py --reviewed-through 42
```
