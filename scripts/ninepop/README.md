# 9POP 全业务只读接入

范围与批次见 [实施记录](../../docs/交接/9POP全业务接入实施-2026-10-15.md)。`approved-scope-20261015.json` 是已获准的源字段投影，不包含源数据；原三表保持原连接和字段定义。`governance_codebook.py` 保存首轮解释及依据性质，推断/未知不自动升级为业务确认。

`full_collector.py --config /私有目录/来源配置.json` 仅接受部署安装的固定列投影，输出 v2 完整快照。配置与投影文件须属于运行账号，权限 0600；凭据只置于私有配置，不能放入此目录。配置字段以脚本 `collect` 校验为准，源库只接受本机 9pop_v2；远程部署通过受控 SSH 安装，在同机环回连接使用列级 SELECT 账号。

采集输出包含受限业务记录，保存时使用私有部署目录；不要输出到聊天、公共日志或提交 Git。生产注册由 `DATABASE_DEPLOYED_SOURCES` 指向私有 registry，命令和目标企业固定，模型与浏览器不能传入 SQL。既有注册项须保留。

部署顺序：扫描结构 → 全量拉取并保持 deployment 模式 → 导出部署上下文 → 编写完整字段解释、UNKNOWN 排除和非可加约束 → preview 全量检查 → 带统计依据初始化知识 → apply → 补齐跨批次外键 → 启用既有服务的周期同步。使用 [签名部署客户端](../data-foundation/deploy-governance.py)，不直接写业务 SQLite 表伪造完成状态。

新结构/投影须重新部署治理；完整性校验失败保留旧快照。每组来源有独立事务时点，不把多组数据声明为同一时点。当前 200 万单元格/64MiB/每表 10 万行是拒绝边界，达到上限需继续扩展实现，不能改为截断。

验证：`python3 -m unittest discover -s tests/ninepop`。Wiki 的 `source-snapshot.test.ts` 验证超过一万行、失败回滚、只读来源和权限隔离；部署治理测试验证未知字段与禁止求和、字典基线和模型接续。生产回执与真实业务记录仅保留在私有发布证据目录。

源 SQL NOT NULL 与文本非空分开处理。仅经源码核实的 `course_products.payment_methods` 声明 `allowEmptyColumns`；保留空字符串，不替换业务值，真实 NULL 仍按必填校验拒绝。投影元数据修改后重新同步整组来源并重做受影响治理绑定。


## 本地首次接入准备

`local_connection.py --config <私有配置> --check`只检查禁用安装；`ssh_reader.py`显式拒绝enabled=false，当前本地实例不注册可运行真实provider。原三表通过full_collector.collect_config复用v2完整分页。history_scope的候选/孤儿/歧义默认隔离，不代替平台权限。详见[本地准备验证](../../docs/协作/企业首次接入/04接入准备本地实现与合成验证-2026-10-19.md)。

## 本地正式服务链合成联调（2026-10-19）

`scoped_scene_export.py`将受信部署规则和授权投影为现有scene-export 1.1，不读网络、不输出未审核原表。输入必须有显式快照版本；规则、内容、来源版本及账号名单共同进入变更指纹。无证据行隔离，不能将旧禁用reference草案自动启用。

`tests/ninepop/scene_fixture.py`仅生成合成数据，供Java正式登记/权限读取集成测试使用，不能用作真实provider。运行命令、验证和未完成边界见[服务链联调](../../docs/协作/企业首次接入/04.03正式登记与权限链路合成联调-2026-10-19.md)。


## 员工消费投影（2026-10-21）

`consumer_history.py`解析有来源的课程/会员时间线、工资承担月份和等级使用期间；`consumer_projection.py`仅接受受信部署配置，生成用途列白名单和既有岗位读者计划，不接收模型传入的规则或SQL。部署入口仍使用签名来源/治理及现有权限接口。真实快照、姓名账号映射和发布回执仅存私有目录；不能直接以合成测试数据发布到正式实例。

最新本地338路由、68项脚本测试、实际账号验收与保留隔离见[员工画报消费链路](../../docs/交接/员工画报数据消费链路-实施与验证-2026-10-21.md)。
