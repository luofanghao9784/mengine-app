# 9POP 全业务只读接入

范围与批次见 [实施记录](../../docs/交接/9POP全业务接入实施-2026-10-15.md)。`approved-scope-20261015.json` 是已获准的源字段投影，不包含源数据；原三表保持原连接和字段定义。`governance_codebook.py` 保存首轮解释及依据性质，推断/未知不自动升级为业务确认。

`full_collector.py --config /私有目录/来源配置.json` 仅接受部署安装的固定列投影，输出 v2 完整快照。配置与投影文件须属于运行账号，权限 0600；凭据只置于私有配置，不能放入此目录。配置字段以脚本 `collect` 校验为准，源库只接受本机 9pop_v2；远程部署通过受控 SSH 安装，在同机环回连接使用列级 SELECT 账号。

采集输出包含受限业务记录，保存时使用私有部署目录；不要输出到聊天、公共日志或提交 Git。生产注册由 `DATABASE_DEPLOYED_SOURCES` 指向私有 registry，命令和目标企业固定，模型与浏览器不能传入 SQL。既有注册项须保留。

部署顺序：扫描结构 → 全量拉取并保持 deployment 模式 → 导出部署上下文 → 编写完整字段解释、UNKNOWN 排除和非可加约束 → preview 全量检查 → 带统计依据初始化知识 → apply → 补齐跨批次外键 → 启用既有服务的周期同步。使用 [签名部署客户端](../data-foundation/deploy-governance.py)，不直接写业务 SQLite 表伪造完成状态。

新结构/投影须重新部署治理；完整性校验失败保留旧快照。每组来源有独立事务时点，不把多组数据声明为同一时点。当前 200 万单元格/64MiB/每表 10 万行是拒绝边界，达到上限需继续扩展实现，不能改为截断。

验证：`python3 -m unittest discover -s tests/ninepop`。Wiki 的 `source-snapshot.test.ts` 验证超过一万行、失败回滚、只读来源和权限隔离；部署治理测试验证未知字段与禁止求和、字典基线和模型接续。生产回执与真实业务记录仅保留在私有发布证据目录。
