## 文件

- `inventory.py`：只读统计现有本地实例；凭据仅传入本机 psql 环境，不输出业务正文。
- `rehearse-linux-database.py`：已在目标服务器验证，以指定镜像 ID 创建无网、无端口的全新 PG18 演练副本；逐表核对并停止容器，保留私有证据。不是最终迁移或业务上线脚本。
- `compose.rehearsal.json`：独立 Compose 项目与私有网络；仅网页发布 `127.0.0.1:18480`，不占用现有数据库或业务端口。所有服务须显式选择 `rehearsal` profile。默认不自动重启、不联网、不调用模型、不启用会话/采集/画报执行及解析器。它会允许应用在**演练副本**上正常迁移和维护，不能把它称作只读数据库。
- `nginx-internal.conf`：容器内部静态网页与 `/api/` 代理，不转发内部执行与健康接口。
- `nginx-ai.conf.example`：未来主机独立 HTTPS 业务代理；证书已签发，但后端未部署，不能直接替换当前维护站点。无须更改其他站点。
- `.env.example`：仅非敏感配置。镜像须核实来源、版本与 linux/amd64 摘要；Node 24.20.0、Java 21、PostgreSQL 18.6；网页用非特权 Nginx 镜像（UID 101）。

## 演练目录契约

将 `DREAMCORE_ROOT` 指向全新独立目录，禁止指向 9POP、其他项目或本机原实例。目标需要：

```text
release/api.jar
release/web/                 # 本次前端 dist 内容
release/engine/              # 本次 engine dist、package.json、Linux npm ci --omit=dev 依赖
release/nginx-internal.conf
postgres/                   # 全新 PG18 数据目录，绝不复制 macOS 的物理 PG 目录
objects/                    # 校验过的文件副本，API UID 10001 可读写
secrets/database-password   # PostgreSQL 初始化密码，无换行歧义
secrets/api.env             # DATABASE_PASSWORD、TASK_ENGINE_TOKEN
secrets/engine.env          # 相同 TASK_ENGINE_TOKEN；演练不放模型 Key
```

原账号和密码散列来自逻辑数据库迁移，不运行新管理员 bootstrap。上述数据库角色是隔离实例的库所有者，不是复用 9POP 账号；实际运行是否拆分迁移/应用角色在正式部署验收中处理。secret 文件归最小读取主体、权限 0600；不把其内容提交、打印到日志或打入网页包。Compose 内环境变量仍可被宿主管理员查看。

JAR/前端可使用本机已构建产物；Node 依赖在匹配版本 Linux 环境重装，不复制 macOS 虚拟环境或原生依赖。固定源码 SHA、迁移清单、产物摘要与依赖锁。模板配置校验不检查镜像存在、挂载权限或服务行为。

## 资源预算（待演练修正）

API 1280MiB / 0.75 核，引擎 640MiB / 0.5 核，数据库 512MiB / 0.4 核，网页 64MiB / 0.1 核，总内存上限约 2.44GiB，总 CPU 配额 1.75 核。容器不增加 swap，日志每容器最多约 30MiB；只读根目录与限额 tmpfs。磁盘尚无硬配额，不把日志限制当作资料或数据库限制。解析器正式启用后必须重新预算。

现有业务执行槽位硬编码 20，容器 CPU 限额不等于业务并发限制；正式启用前需实现并验证部署级小并发，保留账号业务额度语义。当前不启用任务，不能宣称已经具备低并发云端运行能力。

## 检查与切换顺序

1. 完成 Linux 文件解析/表格计算隔离适配、V98 全数据迁移校验、后台任务与采集配置的迁移审查；不得关闭安全校验来跑通。
2. 选择固定镜像摘要，准备全新演练目录和合成凭据后，使用 `docker compose --env-file <私有配置> -f scripts/deploy/compose.rehearsal.json --profile rehearsal config --quiet` 检查；不能把输出展开的凭据存入日志。
3. 在新实例演练逻辑导出/还原、文件摘要校验、账号权限和历史资料读取；限制出口并保持模型和自动任务关闭。独立 PostgreSQL 18.6，不升级或连接宿主 PG14。
4. 完成中文排序/搜索、三端登录、跨租户/撤权、原件下载、文稿导出、文件解析、模型回调/停止/重试、实际内存峰值及 9POP 健康验证。合成验证先行，再按授权验证现有数据。
5. 确定切换时间，停止旧实例用户写入及自动执行，核对所有在途任务；保持原 PG 可读用于最终 `pg_dump`。在冻结期间复制原件、导出固定数据库快照及配置，计算摘要。不用在线复制 PG 数据目录。
6. 目标还原后核对表/对象数量、主外键、权限、资料版本、画报来源及任务终态，保持原账号；使旧会话失效并重新登录。不得把恢复重置密码机制不加区分地用于保留账号迁移。
7. DNS/TLS 就绪、nginx 配置检查通过后才接流量。正式配置需单独审查开放出口、真实模型凭据、解析器、定时任务与同机 9POP 只读采集适配；不能直接启用本演练配置。
8. 仅一套实例启用采集与定时画报。切换初期观察业务高峰。未放量前保留源冻结副本；云端产生新写入后回退须先保全增量，不能直接重启旧副本造成分叉或数据丢失。

不会执行 `docker system prune`、修改现有容器/数据库、重启 9POP 或替换系统 Node。域名迁移时更换入口、证书和相应回调配置；持久数据继续独立迁移。
