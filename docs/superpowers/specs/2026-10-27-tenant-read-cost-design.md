# 多企业 Scene 与版本读取重构

用户授权：按审查优先级实现跨企业锁隔离与减少重复全量读取，保障多企业权限、任务生产消费，仅本地及 PR。延续 Issue #204 / PR #205，不操作生产。

方案：Scene 读写锁按企业隔离，引用计数覆盖持锁及等待者，最后一个调用结束后回收。保留同企业读写互斥及外部调用后的权限复核，避免删锁导致撤权回归。此阶段不把外部权限语义改为乐观事务；它保留同企业慢请求的等待，也不增加多实例锁保证。

资料详情把目标 ID 下推到现有授权列表 SQL，避免映射无关目录；汇总仍读取当前全部获权资产。简报确定性指纹复用现有版本证据收据，按企业/数据集/快照/当前元数据区分，保留原有指纹值，不触发历史去重重置。权限每次使用时检查，清理快照同时清理收据；简报指纹在 READ_COMMITTED 缓存未命中时用收据键事务锁抑制重复计算；REPEATABLE_READ 冷缺失按自身快照计算且不插入收据，避免等待后仍不可见的 40001 冲突。已有 CHECKS/PREFLIGHT/INSIGHT_FACTS 的并发行为不在本次改动范围。

不采用全局缓存权限，不给共享锁加超时绕过，不新建通用缓存框架。此阶段不改页面轮询、新旧会话迁移或任务消费者。

验收：慢企业写操作不阻塞其他企业读写；同企业撤权与写入仍互斥，异常后锁释放；详情不调用全目录读取，输出及权限与原逻辑一致；同版本指纹值保持兼容，重复读取不访问原始行，元数据/版本变更失效，跨企业不可借用，清理后不可复用；保留两个企业并发派发与消费补位回归。
