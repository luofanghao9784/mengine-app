# 工作导航蓝点提示

2026-10-05 用户确认：会话有未读回复或需要补充信息／核对结果时提示；智能画报有尚未打开的新卡片时提示。实际阅读处理后清除，进入页面本身不清除。

## 实现范围

沿 AI-01、AI-12—AI-13、CUI-05 的站内交付与阅读行为，在客户端左侧会话、智能画报图标右上角增加无数字蓝点。

- 会话：本人、当前获权空间、未删除的业务会话，存在未读回复，或有可读且来源仍有效的 USER 任务处于 WAITING_INPUT、PARTIAL、RESULT_UNKNOWN。执行中、排队、等待部署能力及自动画报任务不误标为待处理。
- 画报：复用生成画报的候选来源、当前空间权限、隐藏偏好、静默计划和版本已读证据；只计算 TASK 生成卡片，不把普通资料副本加入。未读条件在候选池截断之前执行，不因最近卡片均已读而漏掉较早的未读卡片。
- GET `/api/v1/tenants/{tenant}/workspace/notifications` 仅返回本人当前企业的两个布尔值，使用 private, no-store，不返回正文或其他员工记录；管理员角色不会扩大私人内容范围。契约见 `contracts/public-api/workspace-notifications.openapi.json`。
- 可见时每 5 秒核验，恢复焦点及页面切换时核验；会话阅读与画报已读回执成功后立即重读摘要。在途读请求合并，账户／企业切换和卸载取消旧请求；401、403、404 清除旧提示。其他暂时错误保留最近有效提示，不把接口失败伪装为无待处理。

## 2026-10-06 部分完成回复已读后清除

用户反馈无待处理会话仍显示蓝点。真实原因是个人会话“查询当前掌握的企业信息范围”状态 PARTIAL，但 reply_revision 与 read_reply_revision 都为 1，既无 required_input，也不要求结果核对。导航摘要把 PARTIAL 无条件作为待处理，导致已读后仍亮点，与会话界面没有补充入口的行为不一致。

修正仅针对导航摘要：PARTIAL 不再触发持续待处理提示，未读回复仍按版本提示；WAITING_INPUT 和 RESULT_UNKNOWN 保留持续提示。未修改会话状态、已读回执或资料权限，也未触发模型。独立 PostgreSQL 的 ConversationNotificationReadIntegrationTest 共 8 项通过（含继承的权限回归）。当前运行安装只替换 ConversationService 的一条 SQL 字符串常量，其余 JAR 条目逐一核对相同；备份与安装清单位于 `.local/conversation-dot-20261006`。运行源码历史快照缺少该摘要方法，未覆盖其源文件；当前 main 源码已同步条件。真实页面核验蓝点已清除，截图 `.local/conversation-dot-20261006/蓝点已清除.png`。
