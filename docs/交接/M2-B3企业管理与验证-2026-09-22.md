# M2-B3 企业管理与验证

日期：2026-09-22。授权：用户在 M2-B2 后要求“继续下一步”。范围按[任务书第 4.1 节](../技术/开发任务书-V0.1.md)，延续 WS-01—WS-16、POS-03；实施决定见 DEC-051。本批核心功能完成本地实现和验证，待审查与用户体验；两项业务权限未确认，保持未开放。

## 已实现

`/tenant-admin/` 使用真实身份与企业数据，提供五个入口：

- 企业成员：姓名/邮箱搜索、启用/停用过滤、分页、角色与账号状态、停用/恢复。
- 成员邀请：生成本企业普通成员邀请、查看等待/已加入/过期/撤销状态、撤销邀请，最新优先、有界分页。已有邀请接受与过期规则继续有效。
- 共享空间：搜索分页、创建、改名、查看授权名单、添加有效成员或撤销授权。授权名单中的停用成员显示访问暂停。
- 管理记录：成员、邀请、共享空间授权、企业名称变更的操作者、对象与时间，不显示私人工作内容。
- 企业设置：修改名称；企业选择器与概况同步刷新。用量和复杂配置不提前放模拟数据。

主题、按钮、弹窗、分页、加载/失败、稳定请求键重试等复用三端实现。前端在 `src/tenant/`，总台与企业管理共用 `src/shared/admin.tsx`；业务接口在 `TenantAdminController/Service`，复用既有身份与邀请能力。无第三方管理界面嵌入，无引擎或供应商类型进入业务 DTO。

## 权限及实施边界

1. 服务端按实时账号、企业和企业成员授权。仅有效的本企业管理员可使用管理 API；普通成员、其他企业管理员和只有平台角色的账号被拒绝。
2. 管理端只列共享空间元信息，不接受个人空间 ID。共享空间创建者不自动获得客户端访问权；客户端仅列个人自有空间和显式授权的共享空间。
3. 成员停用不删除账号、个人空间或旧授权；本企业新请求立即被拒绝，其他企业身份不受影响。恢复成员后原授权继续有效。该保留/恢复机制是本批可逆实现选择，未擅自写为用户已确认的离职政策。
4. 新增空间授权要求目标为本企业有效成员且账号有效；停用成员可撤销旧授权，不能新增。最后一名有效管理员不能停用；管理员数量按账号、成员均启用计算。
5. 两项问题已向用户提出但尚未确认：管理员能否显式把自己加入共享空间、能否任命其他管理员。当前自授权新增返回 `SELF_GRANT_NOT_ENABLED`，角色调整无接口；已有自身授权可撤销。不把这两项临时关闭状态当成用户选择永久禁止。企业负责人转交、离职资料交接继续另定。
6. 审计只保存管理事件元信息及相关对象 ID；显示名称读取对象当前名称，不是历史名称快照。总台仍只看自己的操作白名单，不因新增企业管理而看到员工或内容数据。
7. 当前无真实文件、检索或运行中 Agent 任务。本轮撤权证明覆盖企业上下文、管理接口与共享空间可见性；M2-C1/D1 与后续模块仍须验证文件、下载、检索、缓存及任务撤权。

## 事务、重试与升级

- 企业设置、成员状态、空间分别有版本。状态、改名和授权请求携带 expectedVersion；旧版本明确 409，页面要求刷新后重新确认。
- 新写入按请求键锁→企业行锁→子记录顺序处理，并在获得锁后复查权限；同账号的同键异内容/异操作拒绝。成功重试返回当前状态，不重放旧授权或停用动作。
- 读取和邀请持有企业共享锁；锁与成员授权查询分为独立 SQL，防止等待锁期间成员已被停用，却继续使用此前联表查询快照。专门并发测试让读取和邀请先等待，再提交停用，二者均返回 403。
- 只追加 Flyway V4：成员/空间管理版本、企业设置版本、授权对象审计列、企业记录索引；保留 V1—V3。升级前已存在的共享空间创建者原有隐含访问权转成显式成员授权，个人空间不回填；新空间无自动授权。已填充 V2→V4 升级与版本非负约束有实际验证。
- 共享空间不删除、不自动转移归属；本轮没有实现复杂空间角色或将访问权等同于发布/编辑权。后续实际资源动作继续独立校验。
- 邀请仍仅本地受控文件投递，失败回滚沿用既有服务；API、页面、审计和日志没有明文令牌。真实邮件供应商尚未接入，未外发邀请。
