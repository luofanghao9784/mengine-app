## 真实版本切换

旧版从 `65443b35719be33b1a4e3d19214d0768a6b0daa5` 的 engine 目录导出，按原依赖锁安装并编译；新版使用本批 0.9.1。源码没有用环境变量改写版本。各自加载实际 dist/catalog 资源，模型只由测试入口注入本机合成传输，生产入口不导入该夹具。

演练建立两个合成企业，原引擎先完成真实授权检索、工具执行和产物保存，创建个人文稿/PDF 与会话画报。候选旁路预检没有模型请求；兼容后切换测试路由，平台/数据库未重启，原登录会话仍有效。新 Agent 和 SOURCE_LOOKUP 结果记录 0.9.1。

不兼容候选预检失败；故意将测试路由指向该候选后，平台任务明确 FAILED/`TASK_RUNTIME_INCOMPATIBLE`，候选收到 **0 次 POST**。随后让真实 Agent 的合成模型响应停在途中，停止该引擎：任务失败，无回复/产物冒充成功。切回实际 0.9.0 后显式重试，同任务 attempt 从 1 到 2，结果记录 0.9.0；重复同请求只有一个任务，不再次执行模型。

整个流程多次比对旧会话及引用、原件版本/元数据、附件与 PDF 字节、画报卡片和文稿内容均不变；总台不能下载私人产物，跨企业访问拒绝，企业停用后旧产物和缓存导出也拒绝。回退后的会话截图已目视检查，位于 `.local/m7-engine/rollback-history.png`；结果与构建摘要在 `result.json`，不提交临时日志或合成运行输出。

构建摘要覆盖 package.json/package-lock.json、dist 和 catalog（不包含已安装 node_modules；依赖由锁文件及 npm ci/许可检查验证）。当前演练输出：

- 0.9.0：`9e9544e2afafc0fdf033ce226e316bdb79ea5baed7112c0bafd95c1d4268bb38`
- 0.9.1：`0da427b6a274b6fb3e9984c23f93e44c763f1bf5238dfec71c345d5abc9b39a2`

首次独立构建因 macOS 临时路径 `/var` 与实际 `/private/var` 别名导致 npm 将包当作额外链接项，`npm ci` 报锁文件不一致。对测试导出根目录使用 realpath 后原锁文件原样安装成功，没有改旧版本源码/依赖；夹具同时隔离继承的 npm 配置变量。既有 Agent 回归首次在旧版固定值 `0.9.0` 的断言失败，改为使用统一编译版本后整套通过，没有放宽版本验证。
