# 资讯卡片配图

用户要求资讯类卡片配图。列表和详情均增加图片区域：可用时使用获权原文的正文图片，详情提供来源链接；否则使用本地统一主题插画，详情明确“非新闻现场图片”。插画为项目自绘 SVG，不是事件现场照片，也不调用图片生成模型。

原图读取沿用公开 HTTPS、公共 DNS 地址校验、地址固定及每次跳转重新校验。只接受 128 KiB 内 JPEG/PNG，服务端检查真实格式与像素数不超过 800 万，拒绝 SVG/HTML 伪装。图片嵌入保存的来源快照，浏览器不直接请求第三方图片；整个任务只携带一张原图，保持既有 256 KiB 引擎回执边界。图片二进制不会进入模型提示；模型仍只见原文和来源句柄。普通会话的网页读取不新增图片请求。

提取正文 article／明确媒体容器中的图片，排除头像、标识、广告容器、推广文字、文件名式或通用“图片”说明，不采用未经确认的站点分享封面。这是有限结构筛选，不是图像语义审核；来源无明确图片、超限或读取失败时回退插画，不能据此声称每篇都有真实现场照片。

现有 15:15 资讯的两份原文都仅找到媒体推广图；实测后排除，改为主题插画，正文与生成结果不变，变更记录在本地审计中。没有新模型调用，没有消耗生成额度。

验证：29 项真实服务端组件／独立 PostgreSQL 回归、25 项引擎回归、前端构建通过。涵盖内网图片地址拒绝、普通网页无图片请求、原图编码限制、格式校验、资讯文档封面归属与广告／头像排除。真实客户端已展示主题插画。图片来源可用路径以合成图片验证，不将媒体推广图的读取成功当作合适配图验收。

本地安装仅覆盖本切片 API 类与引擎文件。完整前端构建曾显露运行实例既有展示补丁差异，已恢复安装前前端并只注入资讯图片组件／样式，保留既有图表口径与版式。源码保留正式组件实现。运行 API jar 与启动记录哈希一致，截图在忽略目录 news-cover-detail.png。并未发布生产。
