# 画报生成卡片分步交互

用户于 2026-10-05 确认：生成入口全部在卡片内部完成，依次选择数量、确认类型，再提交生成；类型采用可多选标签，默认由系统决定，界面仅保留必要元素。

- 点击「生成」进入数量选择，范围 1–6。显示服务端返回的今日可用次数，超出剩余额度的数量不可选择。
- 「下一步」进入类型确认，提供默认、洞察、数据、建议、资讯、成果。默认与明确类型互斥；明确类型最多选择本次数量种。「上一步」返回修改数量，数量缩小时截去超出的类型。
- 数量为本次总数，多选不叠加次数。按选择顺序轮流分配类型，例如 3 张、洞察和建议对应 2 次洞察、1 次建议。每次执行最多交付一张有证据支持的新画报，不承诺一定生成足额卡片。
- `/briefing/generation/selection` 在同一事务内确认请求、校验剩余额度并创建有序队列。账号与企业范围由服务端校验；重复请求重放原结果，改变同一请求的参数会冲突。V92 支持同一次选择下排队的同类任务，旧触发的合并约束保留。
- 沿用既有每日运行额度（默认 6 次）和日界线、管理员额度重置记录，自动与手动任务共用原有运行预算。已开始的执行计入使用次数；未开始的排队任务预留次数；取消未开始任务释放预留。新接口不将超额请求排到次日；旧接口的等待与恢复行为保留。
- 取消任意本次队列任务，由服务端一次事务取消同次尚未完成的任务。已完成的卡片保留。队列编号在浏览器会话中保留，以便刷新后继续跟踪超过历史列表上限的任务。

验证：隔离 PostgreSQL 的 3 项新集成检查，覆盖总量预留、重复请求、并发超额、取消释放与权限边界；原生成服务 41 项回归检查；4 项浏览器合成检查，覆盖数量、多选、默认、返回、剩余额度、重试和取消。前端类型检查与构建通过。本次不触发真实模型调用；真实生成的内容和足额交付仍取决于资料、能力及模型执行结果。
