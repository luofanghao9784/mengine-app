# 画报引擎对齐新卡面：实施与验证

日期：2026-10-11。范围沿 [任务书](../技术/画报引擎对齐新卡面-开发任务书-V0.1.md) 的原需求编号。在本目录 main 顺序开发，未使用开发 worktree、并行代理或向其他会话发消息。未部署、未调用真实模型、未重新生成旧卡。

## 实施范围

- E1：两列默认 GROUPED_BAR；当前尝试成功的汇总与构成回执默认 CURRENT_BAR。模型明确指定 TABLE 保留。平台汇总路径也执行原版式校验，不再无条件覆盖模型选择。
- E2/E4：选图说明按期间、类别、组数、增减、排名、精确核数区分；保留 DUMBBELL 协议兼容。两条实际行动用 STEPS、两个实际方案用 COMPARISON；单值结论用 KEY_METRIC 并指定重点字段。没有放宽段落索引或事实约束。
- E3：表达规范 1.0.3；数据标题独立表达结论，28 字仅建议。保守识别以“分析/分布/情况”结尾且无明确方向词的标题，交付前返回 BRIEFING_TITLE_TOPIC_ONLY 供模型修正；不声称穷尽语义判断。合成模型已验证一次纠错后交付；超长结论不因 28 字建议被拒绝，原 80 字上限保留。
- E5：用户授权助手核对名称和维护层。平台 `BriefingDisplayLabels` 维护原值→中文的源适配字典，按 dataset_key 和实际列名限定。读取已获权文档时给出独立 chartLabels，前端只投影到图形、表格图形及重点数字的标签；依据区保留原值。未知字段/取值不翻译，不改变核验、哈希、指纹或重点分组匹配。
- E6：用户选择先做构成。新增 COMPOSITION，固定快照全量 SUM/COUNT、单类别、可选同范围日期筛选；总量和份额均由平台提供。负值拒绝，零总量无份额；份额半入至六位小数，类别金额精确和等于总量。平台与引擎复核回执，普通分组汇总/两期对比仍禁止占比结论。契约与计算素材配方白名单已扩展。多期序列、比例带不在本轮。
- E7：逐组核验全部零/缺失才跳过，不把正负相抵误判为空；返回 NO_NEW_CONTENT / NO_USEFUL_CONTENT，不创建卡或预留指纹，重试同样跳过。原计算证据和用量不抹除。

## 字典核对依据

只读取 9POP 源码，没有修改 9POP 项目或真实数据：

- `apps/admin-end-ui/src/app/services/m3MemberApi.ts` 的 `statusLabel`：待开课、开课中、体验中、尾款限制、请假中、停卡中、已结束、保底续期、已退款、未购课。
- `backend/src/main/java/com/ninepop/backend/order/service/AdminOrderQueryService.java` 的订单/收款状态转换，以及 `order/statemachine/OrderStateMachine.java` 的原值：订单待首款、待补凭证、待尾款、已完成、已取消、已退款；收款待确认收款、已确认待补凭证、待财务审核、财务退回、财务已确认、已取消。
- `backend/src/main/java/com/ninepop/backend/session/SessionRules.java` 与 `member/MemberSelfSessionService.java`：课时 effective 为有效，voided 为已作废。
- 本项目 `scripts/ninepop/detail_collector.py`：上述四类 dataset_key 及精确中文列名。收款类型沿全款/定金/尾款。

字典不对所有叫 active 的值做全局替换。未核对的扩展数据源、复合分组显示名和其他状态保留原值。后续扩展字典仍须核对实际业务列，不能按英语猜测。

## 协议和评审边界

新增能力 `datasetCompositionVersion=1.0`；旧平台没有此声明时引擎不提供 COMPOSITION。请求/回执见 `contracts/engine-api/dataset-composition.schema.json`；原交付契约新增可选 chartLabels 和 chart.composition。原 SUMMARY 的空 sharePercent 不序列化，普通图表空 composition 不序列化，避免无关旧回执与图表指纹变化。

平台侧核对来源固定、当前权限、回执审计、精确计算、幂等和交付；引擎侧核对能力协商、原字段保留、schema 子集、份额/总量校验和结束回执。当前是一名维护者在同一主线的两侧核对，不冒充独立双方审批；正式契约评审、真实模型选图质量及用户阅读验收仍待完成。
