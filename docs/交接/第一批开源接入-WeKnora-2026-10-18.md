# 第一批开源接入 · 2026-10-18

用户已选择 WeKnora 承担索引、语义与混合召回、重排。pgvector 不再作为本轮并列方案；WeKnora 内部采用何种存储由其部署配置决定。Wiki 编译只保留为知识草稿生成器候选，没有接管现有 Wiki 的确认、发布和撤回。

本轮代码在当前工作区 `main` 开发，三项开关默认关闭。没有切换原运行实例、迁移真实业务数据或部署 WeKnora/Langfuse。当前没有 Docker 和可用实例地址、密钥，不能把 HTTP 契约测试称为真实语义检索验收。

## 实际接入

| 部位 | 接入方式 | 平台保留 |
| --- | --- | --- |
| PDF 解析 | Docling 2.140.0，CPU、离线模型、原沙箱内独立配方 | 原件、版本、解析任务、页码引用、权限复核；其他格式沿用原解析器 |
| 检索 | WeKnora v0.8.3，平台片段逐个建立手工文档索引；指定文档 ID 做混合召回和重排 | 企业/空间/文件权限、版本选择、原文、引用、任务来源回执 |
| 调用观测 | Langfuse OTEL/tracing SDK 6.0.0，AgentTasks 下的模型调用和平台工具回调 | 任务状态、计量/收费回执和业务审计 |

WeKnora 契约核对到提交 `3e22822c1d2397be730c458c7539d0eb8c113a24`：创建手工知识、查询解析状态、指定知识范围混合检索及删除。未使用其前端、问答生成器、外部采集或 Wiki 编译。

检索前以现有授权 SQL 选择当前版本/任务固定版本的片段，转换为非空 `knowledge_ids`；空范围不向服务发请求。使用 `/api/v1/knowledge-bases/{id}/hybrid-search`，向量与关键词均启用，要求重排，关闭上下文扩展。结果必须属于请求范围，随后再次查询平台权限和版本，仅返回本地原文与原有引用身份，不使用远端返回的正文或 URL。

当前单次范围最多 1000 个片段，最多请求前 100 个结果；超限明确要求缩小范围。任何范围内片段未就绪都返回索引未就绪，未做静默关键词回退。完整召回质量、复杂中文表格效果、容量和分页稳定性仍需真实语料对照；配置了向量/关键词开关并不证明部署端已正确配置两类索引。

V150 新增企业到 KB 的唯一绑定及持久化索引队列。状态覆盖排队、上传、索引中、就绪、失败、创建结果不明、待删和已删。过期上传不自动重复创建。软删除立即通过平台权限阻止读取，后台删除远端副本；恢复后可重新建立映射。永久清理只有所有远端索引确认删除后才能显示完成，即使关闭检索开关，也不会把未删副本伪报为清理完成。

## 部署配置与操作

先在隔离环境部署固定版本 WeKnora，配置文档类型 KB、向量模型、关键词索引和重排模型。每家企业使用独立 KB，关闭面向用户的 WeKnora 直连入口和不需要的共享能力。服务凭据只放平台环境，不能给三端浏览器。部署端必须处理查询日志：核对版本的处理器会在 info 级别记录查询词，需限制日志级别、访问与保留期限。

平台环境（值由部署环境提供，不写入仓库）：

```sh
WEKNORA_ENABLED=true
WEKNORA_URL=https://your-private-weknora-origin
WEKNORA_API_KEY=<service-key>
WEKNORA_RERANK_MODEL_ID=<configured-model-id>
```

URL 仅接受 HTTPS 源站，回环地址允许 HTTP；不跟随重定向。不设置模型 ID 时使用 WeKnora 自身默认重排模型。非空结果没有 `meta.rerank.applied=true` 时返回重排不可用。

V150 迁移后，由部署维护者把实际企业 UUID 和独立 KB ID 写入 `knowledge_index_targets(tenant_id, knowledge_base_id, enabled)`。默认禁用，确认隔离与模型配置后才启用。不要通过复制示例随机 UUID 建立真实企业绑定。后台在已解析资料上回填，文件原件不直接交给 WeKnora。

维护查询（不含正文/密钥）：

```sql
SELECT tenant_id, state, count(*) FROM knowledge_remote_index GROUP BY tenant_id,state;
SELECT id, tenant_id, material_id, version_id, knowledge_base_id, remote_id, state, error_code
FROM knowledge_remote_index WHERE state IN ('UNKNOWN','FAILED','DELETE_PENDING','DELETING');
```

`UNKNOWN` 需在 WeKnora 查找标题 `mengine-<knowledge_remote_index.id>`，核对 KB 与原文映射后补记真实远端 ID 并进入 `INDEXING` 或 `DELETE_PENDING`；发现多份先清理重复副本。只有确认请求确实未创建文档后，才可将该条重新排队。不能直接把不明结果标为已删或无条件重试。`FAILED` 应先排除模型/权限问题；保留既有远端 ID 时进入 `INDEXING` 重查，没有远端副作用证据前不重新创建。

停用时先把目标绑定 `enabled=false`，保持 worker 运行直至副本删除并核对所有 UNKNOWN；随后关闭 `WEKNORA_ENABLED`。直接关闭总开关会恢复原关键词检索，但不会自动删除远端副本。备份、WeKnora 自身日志与存储回收不包含在平台在线删除回执中，部署需单独定义保留策略。

Docling 安装（可信部署步骤可以联网下载公共依赖/模型；解析任务不能联网）：

```sh
. .local/runtime-env.sh
npm run setup:parser -- --with-tests
workers/parser/.venv/bin/python -m pip install -r workers/parser/requirements-docling.txt
workers/parser/.venv/bin/python workers/parser/prepare_docling.py
```

仍需安装既有 Poppler/Tesseract 工具。准备脚本下载布局/表格模型、校验固定 OSD 文件，并建立 TSV 配置和模型 SHA-256 清单；模型不纳入 Git。将该清单与安装环境依赖锁定记录一起保存用于部署复现；Docling 主版本固定不等于全部传递依赖与模型修订已冻结。

配置 `DOCLING_ENABLED=true` 后仅 PDF 路由到 Docling；不自动重解析历史版本。最多 20 MiB、30 页、500 片段/40 万字，页码来自模型输出的来源定位；表格保留文本，未当作精确计算依据。输出标记 `PARTIAL` 和需核对。缺包/模型、超限或失败不自动冒充成功。现有 75 秒沙箱/85 秒 Java 外层限额保留；Linux 专用 Docling 配方上限为 2 GiB/64 进程/1 CPU，普通配方仍为 512 MiB/32 进程/0.5 CPU。Linux 的新配方尚未在真实 Linux 主机验收。

Langfuse 引擎环境：

```sh
AGENT_LANGFUSE_ENABLED=true
LANGFUSE_BASE_URL=https://your-private-langfuse-origin
LANGFUSE_PUBLIC_KEY=<public-key>
LANGFUSE_SECRET_KEY=<secret-key>
```

必须显式指定源站，不自动使用官方云。隔离的 OTEL provider 只导出本适配器的 span；内容仅任务/尝试 UUID、固定动作名、模型名、状态和数值用量，不含提示词、资料、工具输入输出或原始异常。失败不改变执行结果，业务计量回执仍独立必需。公司分析等其他执行入口尚未加追踪，不把本轮称为全系统观测。
