# 治理指标统一执行第三批（2026-10-16）

用户确认第三批目标：会话和画报统一消费治理成果，由后端执行指标，AI 解读回执。继续单 main 顺序开发、兼容云端既有产物的局部发布，不替换未知来源的整个云端应用。

## 行为与边界

企业指标目录每五分钟检查已同步且获权的数据集，按治理元信息规则生成 COUNT 记录数、带源单位的 SUM 候选，每个企业最多 100 项。候选按来源及规则去重；不会覆盖人工定义，不调用收费模型，不自动发布。可暂停自动生成或手动触发一次。生成任务计入处理记录。

管理员编辑草稿，核对业务粒度、单位、重复记录和范围，并明确确认固定计算计划后才能发布。支持固定快照 COUNT/SUM、0–3 个分组字段、固定日期边界和时区；排除项必须为“无”。需要状态过滤、去重、退款剔除、跨表规则的指标尚不能直接执行，应先治理数据来源，不能用全表合计代替。COUNT 只表示记录数，不能自动解释为人数或订单数。

已有 RAG 词面检索返回已发布版本及 executionRequest。治理数据的 compare_dataset 必须携带读取过的 metricId/version，精确匹配后端生成的计划；没有适用已发布计划则拒绝计算，要求补充确认口径。继续验证企业、来源权限、固定快照、租约及任务版本，撤回或变更后旧任务不可继续使用。普通非治理文件计算保持原有行为。

计算回执登记指标版本、快照、任务尝试和计划指纹。DATA 画报必须引用同次任务的计算回执；企业端和总台读取同一指标目录及计算次数。服务端校验确定性计算与 DATA 卡片，不声称能机械证明 AI 任意自然语言数字陈述；纯文本、上传文件及其他工具的语义审查仍属后续范围。当前没有已发布业务指标时，受治理的数值输出会等待人工核实发布，不替用户发布推断口径。
