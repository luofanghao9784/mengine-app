## 证据与结论的边界

本次重新逐值核对：梦擎当前快照与独立采集端的获准全量包一致，共 11,684 条、30 列，8 个分区数量合计一致。采集配置选用的候选键在此快照中缺失 0、重复 0。全量对比在本机执行，未把原始记录或个人数据发给模型。

来源证据来自当前导出表头、字段映射及采集端 `collector/formats.py`、`collector/pipeline.py`。它们能说明文本/精确十进制/日期的保存方式、是否换算单位、采集去重规则，不能证实币种、到账、源数据库主键或业务记录粒度。

这些字段依据标为 `definitionScope: TECHNICAL_ONLY`。治理提示与服务端输出校验均要求其保持 `UNKNOWN`，不能因模型返回 `REVISE` 就升级为业务定义已确认。新草稿保留具体保存规则及缺失依据，避免重复一个空泛的“待确认”。业务含义需要另有来源字段说明、接口定义或业务确认，不能由字段名猜测。

## 配置与处理

实例私有 `.local/trial/governance-evidence.json` 包含 `tenantId`、`entries`、`schema`。启动器检查本人归属、0600 普通文件和基本结构，显式传入 `GOVERNANCE_SOURCE_EVIDENCE`；恢复模式不自动启用，环境继承不选择其他文件。该文件不入库。

`entries` 沿既有证据协议按企业和 `datasetId` 绑定。`schema` 新增可选的导出回执项：

```json
{
  "kind": "export-validation",
  "datasetId": "<部署数据集 UUID>",
  "snapshotId": "<实际接收快照 UUID>",
  "columns": ["<列名>"],
  "rowCount": 1,
  "rowsSha256": "<UTF-8 紧凑 JSON 行数组的 SHA-256>",
  "candidateKeyColumns": ["<采集候选键列>"]
}
```

服务端对当前完整行数组重算摘要、数量、列顺序和候选键空值/重复，不直接采信回执写着成功。不同快照为 `STALE`，值/列/数量不一致为 `MISMATCH`，键异常为 `VIOLATIONS`，无回执为 `NOT_PROVIDED`。`CHECKED` 只针对该次导出接收核验。数据更新后需重新核对再安装新回执，不把一次核验当作后续每小时更新均已通过。

来源没有声明数据库约束时，顶层仍为 `NO_SOURCE_CONSTRAINTS`。页面显示已完成的导出核验数量，同时保留“源系统业务约束未声明”的提示；不填造合格行数、质量分或审计链完整性。未修改基础 `fieldDefinitions`、数据集标识、源端业务数据或访问权限。

首轮模型将技术说明全部选为 `REVISE`，本次未发布该草稿；随后补充服务端技术证据范围限制并重新执行。历史任务保留，不能用变更状态掩盖已发生的调用。
