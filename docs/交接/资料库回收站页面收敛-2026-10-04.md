# 资料库回收站页面收敛

日期：2026-10-04。用户已确认方案并授权实施；实现完成不等于客户验收。沿用资料维护、空间查看／维护分权和既有生命周期要求，产品决定见 [DEC-129](../技术/开发决策记录.md#dec-129资料回收站复用资料库页面与操作样式)。

## 交互结果

- 资料库工具栏“回收站”进入同一页面的 `recycle=trash`，保留企业、空间和原目录。返回时保留正常列表的搜索、显示方式和滚动位置，修正 Firefox／WebKit 因较短回收页面截断滚动位置的问题。
- 默认列表；仍可切换卡片。列表字段为名称、原位置、删除时间、保留截止和操作。搜索只检索当前获权空间的回收项名称，筛选先于分页；空列表不显示分页。
- 文件与文件夹卡片／列表的 `⋯` 提供“删除”，读取最新修订后使用小确认窗。文件夹确认展示受影响的资料数量。取消、Escape 和关闭不写入。
- 恢复直接操作；原文件夹尚不可用时显示“请先恢复原文件夹”。恢复原位置，不恢复已撤销的权限、不恢复单独删除的子项、不自动重启任务。
- `recycle=records` 为次级“删除记录”，展示过期、正在清理及在线清理完成项；失败清理在详情内显示真实错误与重试。已完成在线清理不代表备份清理完成。
- 有现有彻底清理资格的回收项才显示“彻底删除”，单独确认不可恢复的影响。未新增保留期限、权限或永久删除资格。
- 网络结果不确定时保留原请求的幂等键与修订，禁止通过搜索、切换显示方式或返回页丢失该请求。界面直接刷新反映成功结果，无新的成功说明栏。

## 实现边界

服务端继续使用 MaterialLifecycleService 的访问、截止、父目录、修订和幂等检查；list 增加 TRASH／RECORDS 筛选、名称搜索、原目录路径与父目录可用性。删除正文不进入回收站搜索，没有数据库迁移。共享空间需要维护权，企业管理员身份不自动覆盖私人空间或共享资料；额外彻底清理资格仍由现有能力检查执行。

生成文稿是独立的 object lifecycle DOCUMENT，恢复到停用状态，与文件原件恢复语义不同。本轮未将其 ID 当作 MATERIAL，也未自动改变文稿启用规则。文稿版本维护仍沿用既有入口。会话回收站仍位于个人设置；企业管理端现有清理回执保持可用。

主要实现：`src/lifecycle/MaterialRecycle.tsx`、`MaterialActions.tsx`、`recycle.css`，以及资料库、公共契约和 MaterialLifecycleService。旧 MaterialMaintenance 的多层维护弹窗已移除，仅保留企业管理端使用的 MaterialCleanupStatus。
