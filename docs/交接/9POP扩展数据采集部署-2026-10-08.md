## 新增来源

| 主题 | 数据集 |
| --- | --- |
| 财务基础及资金 | 核算主体、支付账户目录、资金流水、备用金流水、往来款项、往来变动 |
| 资金保障 | 工资资金预留、租金周期与付款计划 |
| 对账 | 对账批次、账户余额、主体差异、历史对账参考 |
| 工资 | 工资条与分项应付、工资调整项目 |
| 分红 | 参与主体、期间、期间比例、权益事件、支付批次、支付分配明细 |
| 课程与课债 | 会员课程权益、最新日正式课债、最新日旧课参考、旧课参考计算批次 |
| 经营关联 | 退款事实、订单分期、课时成本与跨店承担、体验课开课激活、正式成交转化、会员转店、转店双边结算 |
| 类型与主数据 | 审批状态事实、审批业务类型、门店、教练岗位归属、课程产品 |

源字段及固定 SQL 位于 `scripts/ninepop/business_catalog.py`。每个新增来源附带业务解释，例如工资确认与付款分开、内部划转不能重复计收入、备用金与业务流水不叠加、现金与非现金分列、分红权益不等于现金、旧课参考不等于新系统负债。模型可通过已有 dataset 元数据工具读取说明。

**本轮范围边界：** 课债新增投影只含源库最新日及其批次字段，不包含全历史每日课债或月收入汇总，也不宣称最新日必然是完整业务批次；旧课另带批次计数用于核对。现有课时明细和新增课时成本是同一事实的不同字段，不可重复累计。线上支付关闭且无交易的模块、合同附件、私人 AI 会话、健康与生物识别数据未加入此次自动采集。后续更多来源按原调查目录接续，不能把本轮 40 个投影称为全库复制。

## 采集器及启动修复

`detail_collector.py` 复用原固定协议，增加 36 个经源库字段验证的投影，并拒绝重复数据集 ID。查询继续使用 REPEATABLE READ / READ ONLY 一致性快照，固定列、固定主机、查询超时和 ROLLBACK；不接受客户端或模型 SQL。金额保留整数分，数据库 NULL 保留为空，状态和冲销关联不丢弃。未读取密码、令牌、电话号码、地址、原始附件或审批 JSON 正文作为业务数据。

实际预采集输出约 4.5 MB、250,839 个单元格；请求约 19.4 KB，低于现有请求 64 KiB、响应 20 MiB、总单元格 1,000,000 和单表 100,000 行限额。越界时失败且保留上一成功快照，不静默截断。

原实例重启丢失外部采集器配置，本轮在 `scripts/local/trial.py` 增加实例级 `collection-runtime.json`：显式安装后，普通重启重新验证私有配置和可执行文件并保留采集能力。恢复实例含 `restore.json` 时不自动重启外部采集，仍需显式配置。无配置实例不自动启用采集。

本轮实际以原启动命令重启，**未额外传 `--collection-config`**，成功读取已安装配置并触发真实定时采集，验证普通重启路径。仅同步本次启动脚本与部署私有采集器；原 API JAR、前端、引擎、账号配置、模型配置保持原样。关键配置/JAR SHA-256 前后相同，保留 `manualModelAcceptance=true`，未因取数恢复而开启付费自动画报。

回退材料在同目录 `before/`，含部署前 `database.dump` 与 SHA-256、旧启动脚本及旧四项 manifest/source。优先关闭自动调度，通过原主机 CLI 重新部署完整旧四项 manifest，使新增来源撤回并触发既有来源围栏，再将实例采集器配置改回 `.local/ninepop-details/collector`；需要时恢复旧启动脚本并受控重启。保留新增历史快照及来源撤回审计，不用整库还原覆盖部署后用户活动。整库备份只作为灾难恢复依据。

负责人专属权限是本次成员授权状态；后续新增人员、负责人交接或改动空间权限时，必须继续核对敏感来源和历史成果的实际读取范围。
