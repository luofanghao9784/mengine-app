# 企业数据基座与总台接口对接

2026-10-13 实现；本地联调版本，尚未推送。用户要求以数据基座场景替代企业管理入口，按企业对接总台数据库与资料库，并复用标签、口径。细分权限产品设计后续处理，现有登录、企业成员和管理员校验继续生效。

## 已实现链路

- `/tenant-admin/` 使用总台账号身份进入企业数据基座场景。保留现有页面、治理操作、知识库与星图；正式入口默认打开数据基座。原型独立地址仍可用于原有演示联调。
- 浏览器请求 `/api/tenant-admin/v1/tenants/{tenant}/scene/dispatch`；总台核对当前账号所属企业，调用签名服务接口。总台操作使用对应 `/api/platform-admin/v1/tenants/{tenant}/scene/*` 路径。
- Mengine `/api/internal/platform-scene` 使用 HMAC SHA-256、60 秒时间窗和一次性 nonce；只开放场景读取、治理和知识处理接口。源企业/服务身份必须由运维显式绑定，未绑定返回 404，绝不回退到演示企业。
- `SceneService` 把治理准入的数据表部署为原生 `data_connections/business_datasets`，由原生采集任务产生 `dataset_snapshots`；资料和知识通过 `MaterialService` 进入企业共享空间资料库并解析。总台引擎页新增“企业数据基座接入”，可按企业同步输入、处理知识和查看标签口径。
- 总台后台每 60 秒检查绑定企业的输入变更，按内容指纹去重；有待处理知识时调度现有 Mengine 模型能力，再收纳结果。模型与凭据仍由现有 Mengine 配置管理，不复制到浏览器。总台原生通用会话模型仍需独立配置；此次验证不等于其模型已启用。

## 标签与口径复用

`scene_asset_links` 保存当前来源映射及标签、表含义、字段解释、单位、业务字典；`scene_asset_revisions` 留存版本元数据。数据集的原生字段定义包含解释和单位；模型通过 `DatasetTaskContext.sourceSemantics` 获取同一份来源标签与字典。

表语义发生变化时生成新数据集身份、撤下旧身份，避免历史任务套用新口径。同一来源重复同步保持资料 ID 与版本不变；资料更新走原生资料版本。撤回或不再符合准入条件的来源会撤下对应当前数据集/资料库条目，历史版本保留。仅接收已治理的可用行，敏感字段不导出，文本经过既有脱敏。

这是定时增量判定与全量快照采集，并非数据库 CDC 或实时强一致。数据基座上游数据库同步仍由既有同步任务负责；源库 → 数据基座 → 总台之间存在任务间隔。失败可在处理记录/采集任务中查看并重试。

## 配置与启动

两侧服务环境设置相同的 `MENGINE_PLATFORM_BRIDGE_KEY`（至少 32 字符随机密钥）；总台可设置 `MENGINE_PLATFORM_BRIDGE_URL`，默认 `http://127.0.0.1:4400/api/internal/platform-scene`。非本机连接必须使用 HTTPS。密钥只保存在忽略的本地环境文件或部署密钥管理中。

运维绑定：

1. 在总台创建企业、企业管理员和共享空间；写入 `scene_bindings(tenant_id, workspace_id, connection_id, maintainer_id)`，管理员必须属于该企业。连接 ID 使用新 UUID。
2. 在 Mengine 写入 `platform_tenant_bindings(platform_tenant, source_tenant, user_id)`，源服务账号必须属于源企业并具备 admin/steward 身份。源企业只能绑定一个总台企业，防止重复分发。
3. 应用 V122/V123 迁移后启动 API，启动 Mengine API，再从总台引擎页同步。禁止通过浏览器请求自行选择源企业身份。

本地 `sh .local/start-three.sh` 启动 PostgreSQL/API/预览；Vite 使用 5173，代理 API 55623 和 Mengine 4400。运行前先配置本地工具路径与环境；`.local` 文件不提交。构建 Java 前先停止已有试运行，不能覆盖运行中的 JAR。
