# 企业 AI 工作空间 Demo：解压后从这里开始

这是空谷无界场景的纯前端演示包，包含已构建网页、前端源码、合成经营数据和公开新闻摘要。40张智能画报、6个工作空间、45份资料与3段示例会话可体验。新闻照片从原站加载，需联网；未附带下载的第三方照片。AI回复、权限与业务执行均为前端模拟，不需要账号、API Key、数据库或后端。

## 最快的打开方式

1. **先完整解压 ZIP**，不要在压缩包预览窗口中运行文件。
2. 用 Codex 打开解压后的 `enterprise-ai-workspace-demo` 文件夹（其中应直接看到 `package.json`、`dist` 和 `scripts`）。
3. 把下面的提示词发给 Codex。

```text
请在当前目录启动这个企业 AI 工作空间前端 Demo，让我在本机浏览器体验。

先阅读 README.md，确认当前目录含 package.json、dist/index.html 和 scripts/serve-demo.mjs。
本次只启动现成演示，不改界面、业务或数据，也不接入真实 AI、后端或部署服务。

1. 检查可用的 Node.js，项目要求 22.12.0 或更高版本。如果命令不在 PATH，先检查当前开发环境是否已有可用的 Node 运行时；确实没有时再说明需要安装的环境。
2. 优先执行 node scripts/serve-demo.mjs。它只依赖 Node 内置模块，不需要 npm ci、重新构建或安装浏览器测试工具。
3. 默认地址是 http://127.0.0.1:4173/。端口被其他程序占用时，不要结束其他程序，改用 node scripts/serve-demo.mjs --port 4174（或其他空闲端口），并告诉我实际地址。
4. 保持服务进程运行，检查首页与静态资源能正常加载。如果有浏览器工具，再确认智能画报、会话和资料库可以打开；没有浏览器工具时明确只完成了 HTTP 检查。
5. 打开或给出可点击的本地地址，说明如何停止和下次启动。不要只把命令交给我而不执行，也不要在验证后关掉我要体验的服务。

若 dist 确实缺失，先说明演示包不完整；已有完整源码时可执行 npm ci、npm run build，再启动上述服务。不要升级依赖或修改锁文件。
```

## 手动启动

电脑需有 Node.js 22.12.0 或更高版本。在解压文件夹内打开终端执行：

```bash
node scripts/serve-demo.mjs
```

然后在浏览器打开 `http://127.0.0.1:4173/`。也可执行 `npm run demo`，两者相同。预览已构建网页无需安装项目依赖，Node 已就绪时页面和内部资料可离线运行，新闻原图与原文需要联网。不要双击 `dist/index.html`，网页需要通过这个本地 HTTP 服务加载。

服务仅绑定当前电脑 `127.0.0.1`，无需配置公网服务器。保持终端运行；在启动服务的终端按 `Ctrl+C` 停止。下次执行同一命令即可。端口冲突时使用 `node scripts/serve-demo.mjs --port 4174`，并打开对应地址。

脚本不依赖 shell 特有命令，可用于 Windows、macOS 和 Linux；实际验证平台以包内 `验证记录.txt` 为准。

## 数据如何保存

- 内置经营、客户及研发记录为合成演示数据，资讯摘要来自真实公开报道，首次打开自动加载。
- 空谷场景使用独立存储；重置仅清除当前浏览器的空谷修改，不删除旧版通用Demo存储。
- 操作记录保存在自己的浏览器 localStorage，不与发送方或其他同事同步。发送方浏览器里的导入文件、个人修改、对话和卡片偏好不会随 ZIP 带过去。
- 用同一浏览器和同一地址继续体验；更换浏览器、端口或把 `127.0.0.1` 改为 `localhost` 会使用不同的本地数据区。
- 可在“个人设置 → 重置”恢复初始演示；重置会清除当前演示操作。
- 当前包是制作时的页面版本，不会自动接收后续更新。

## 包内文件与可选源码运行

| 文件 | 用途 |
| --- | --- |
| `dist/` | 已构建网页，直接预览使用 |
| `scripts/serve-demo.mjs` | 仅使用 Node 内置模块的启动服务 |
| `src/`、`public/`、`index.html` | 前端源码、合成数据与素材 |
| `package.json`、`package-lock.json`、配置文件 | 后续源码运行与构建 |
| `tests/` | 原项目的状态与浏览器测试 |
| `验证记录.txt`、`文件校验清单.json` | 打包时的验证范围与文件完整性记录 |

转发包不包含 `node_modules`、环境凭据、本机日志、浏览器个人数据及完整内部产品／商业文档。跨电脑重新开发时依赖由锁文件安装，避免直接复制原电脑的依赖。

仅在需要修改源码时执行（首次安装需要联网）：

```bash
npm ci
npm run dev
```

开发模式默认地址 `http://127.0.0.1:5173/`。需要更新转发包里的静态页面时执行 `npm run build`，再用 `node scripts/serve-demo.mjs` 预览。单纯看 Demo 不必运行测试或重新安装依赖。继续产品开发需回到完整项目，补齐原有需求、协作规则及决策记录。
