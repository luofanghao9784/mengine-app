# M2-B2 总台管理与验证

日期：2026-09-22。授权：用户要求“继续下一步 M2-B2”。范围依据[任务书第 4.1 节](../技术/开发任务书-V0.1.md)，原需求 WS-01—WS-16、POS-03 的管理基础部分；状态与邀请实施选择见 DEC-050。本记录区分本地开发、真实接口验证、部署与用户验收。

## 本批可用能力

在平台账号登录的 `/platform-admin/` 中：

- 企业列表、名称搜索、状态过滤、分页；开通企业并指定初始管理员邮箱。
- 企业详情展示状态、开通时间、有效成员/空间数量、初始管理员邮箱与邀请状态。
- 尚未加入的初始管理员可更换邮箱并重新生成邀请；原邀请失效。已加入后拒绝此操作，不能借此更换既有管理员或改密码。
- 停用/恢复企业；使用版本校验防止覆盖其他管理员的更新，使用稳定请求键处理重试。
- 企业总量/使用中/停用数量、当次平台和数据库连接状态、邀请投递模式。
- 仅总台开通、停用、恢复、初始邀请更换的管理记录，含操作者、时间和成功结果。

复用三端主题、控件、弹窗和顶栏操作布局；桌面左侧圆形导航与窄屏底部导航沿当前客户端风格。详情关闭后保留列表状态。数据来自真实服务，没有模拟企业统计、模型用量或运行记录。

平台角色仍不产生客户成员身份；总台 API 无客户正文、会话、代入或内容导出入口，不展示员工工作/登录事件。初始邀请响应只有元信息，令牌只在本地受控投递文件中。

## 状态与数据规则

- ACTIVE → SUSPENDED → ACTIVE：停用阻止该企业新的上下文访问、管理写入和邀请接受；账号在其他企业的授权不受影响。保留成员关系，恢复不自动启用单独停用的成员。
- 每次变更提交 `expectedVersion`；旧版本返回 `STALE_TENANT_VERSION`，页面要求刷新后重新确认。重复请求返回当前详情、不重做旧动作。例如已经恢复后重试旧停用请求，企业保持使用中。
- 新邀请与撤销旧邀请同事务，投递失败回滚；企业锁先于邀请锁。与接受邀请并发时只能完成一个有效结果，不同时建立两套初始管理员。
- Flyway V3 新增 `management_version` 与初始邀请映射；对已有 V2 数据回填最早 TENANT_ADMIN 邀请。企业和邀请通过组合外键约束归属。
- 前端写请求未确认时保留原内容与请求键供重试，期间不丢弃操作弹窗；切回浏览器时静默复核有效身份，保留填写中的表单，失效或连接未确认时撤下旧身份。

本阶段尚无真实文件下载、检索与运行中 Agent 任务，因此上述停用验证只覆盖已实现的身份/管理边界；全链路撤权仍在 M2-C1/D1 及资料/引擎模块完成。

## 运行与检查

手动开发按[README](../../README.md#总台管理m2-b2)和[平台说明](../../apps/api/README.md)准备本项目专用 PostgreSQL、local profile、私有邀请投递目录，并使用受控 CLI 初始化平台账号。无预置账号，无公网注册入口。身份和总台功能不需要运行引擎。

本轮环境：macOS、Node 24.20.0、OpenJDK 21.0.11、PostgreSQL 18.6、Chromium。命令在独立工作目录执行：

```bash
npm ci
npm ci --prefix engine
npm run test:api
npm run build
npm test
npm run test:contracts
npm run test:platform-admin
npm run test:access
npm run test:identity:restart
```

`test:api` 打包真实后端；浏览器脚本使用构建产物。后三个集成命令及后端测试各自创建独占临时 PostgreSQL、端口、私有凭据和合成账号，结束后清理所属服务与测试库；不能指向客户或日常开发数据库。首次需要 `npx playwright install chromium`；PostgreSQL 工具可用 `POSTGRES_BIN` 指定。

总台浏览器验证特意让首次开通在服务端提交后丢失响应，再通过页面原请求重试；最终只有一个企业和一份初始邀请。另用真实并发请求改变企业状态，验证旧确认页面收到版本冲突；停用后旧管理员会话访问被拒绝，恢复后重新读取有效身份。搜索空状态、分页、网络失败隐藏旧数据、详情重试、有效身份切回窗口保留表单均有实际操作。
