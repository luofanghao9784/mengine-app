# 官网与云端登录入口约定

用户确认访问顺序为“先进入官网，再进入登录页面”。官网由 Claude 开发，本轮不修改其源码或独立仓库；以下供后续集成使用，不代表官网已交付或公网应用已经开放。

## 临时域名下的入口

| 地址 | 用途 |
| --- | --- |
| `https://ai.9pop.top/` | 官网首页；官网产物就绪后接入，当前仍是维护页 |
| `https://ai.9pop.top/workspace/` | 官网“登录 / 进入工作空间”按钮目标；未登录显示现有登录页，已登录进入工作空间 |
| `/tenant-admin/` | 企业管理入口，仍由服务端权限控制 |
| `/platform-admin/` | 平台管理独立身份入口，不作为官网普通用户登录链接 |

官网与应用在同域分路径运行作为可逆部署选择。普通登录链接使用 `/workspace/` 即可；若官网之后部署在另一域名，按钮使用完整应用 URL。后续正式域名更换只需调整目标地址及站点证书/配置。

## 官网构建与代理衔接

- 应用保留 `/workspace/`、`/tenant-admin/`、`/platform-admin/`、`/api/`、`/assets/`；不要由官网 SPA fallback 接管这些路径。
- 现有应用构建资源使用 `/assets/`。建议官网资源放到独立的 `/website-assets/` 等命名空间，或在集成时给其中一套构建配置独立 base，避免两套发布覆盖同名目录。本轮不替 Claude 改构建配置。
- 官网首页只包含公开内容与普通登录链接，不携带账号、密码、会话或私有资料；使用现有应用的登录流程和安全 Cookie。
- `/internal/`、`/actuator/` 不从公开站点透传；私有对象目录不配置静态服务。
- 官网构建交付后，先在私有 HTTPS 演练入口验证：首页 → 登录 → 工作空间、刷新/返回、资源地址与退出登录。通过后再替换公网维护入口。官网设计就绪不代表业务数据已完成最终迁移。

## 当前依据与边界

现有 `src/identity/AccessApp.tsx` 根据会话状态显示登录或已登录界面，`src/identity/session.tsx` 负责会话刷新，无需为了官网另建一套认证。三端 Vite 构建入口见 `vite.config.ts`。本轮记录接口约定，没有向其他会话发送消息，也没有部署尚未交付的官网。
