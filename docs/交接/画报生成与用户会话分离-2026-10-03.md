# 画报生成与用户会话分离（2026-10-03）

用户从实际会话列表指出系统画报触发记录挤占用户会话，并授权按讨论方案实施。沿用 AI-01、AI-11—AI-13、CUI-05、DASH-01—DASH-04；决定见 [DEC-126](../技术/开发决策记录.md#dec-126-画报后台生成与用户会话分离2026-10-03)。

## 交付行为

- 首次、事件、周期和“生成更多”沿既有生成批次执行，在画报页显示状态和交付内容。服务端记录 `BRIEFING_GENERATION` 会话用途与 `SYSTEM_BRIEFING` 任务来源，普通会话列表及消息历史只呈现用户任务；审计与原始执行记录继续保留。
- 阅读卡片或打开“发起会话”只读取已有内容与讨论关联，不创建会话、不调用模型。未发送时展示确切卡片上下文；第一次有效发送在同一事务内建立讨论并提交用户任务。附件所需的空草稿可以预先存在，但不进入普通会话列表。
- 讨论按本人、来源任务、版本及尝试唯一关联。重复打开复用已建立讨论；丢响应重试沿同一请求键返回同一会话和任务。卡片上下文由服务端验证，不依赖标题或前端拼接提示词。
- 来源空间、企业、账号及撤权检查继续生效，非法首条发送整体回滚。系统生成任务不能通过普通会话动作接口重试或续问，生成状态与恢复沿原生成批次接口。

## 存量迁移

V52 按 `briefing_generation_batches.task_id` 及企业、发起者、空间匹配识别系统任务，不按标题关键词判断。纯系统会话改为生成记录；含真实用户追问的混合会话仍可见，标题与排序取用户活动，历史消息不再显示系统提示词。

迁移不删除任务、回复、文件、卡片或偏好，不改变卡片 ID、任务版本和尝试号。画报列表、推荐候选和旧偏好接口同时支持后台生成用途；精确任务/卡片读取继续可用。主动生成策略、频率、额度、模型配置均沿原值。

## 验证

- 前端构建完成；284 项单元检查、82 项公共契约检查、17 项画报浏览器检查通过。
- API 回归覆盖连续 10 次生成、列表隔离、卡片/推荐保留、首次发送事务与重试、附件空草稿、企业/账号/空间撤权，以及从 V51 迁移纯系统/混合/同名用户会话、原回复/附件/偏好保留与重复迁移。
- API 最终相关回归共 105 项通过，覆盖普通会话、任务上下文、推荐与反馈调整。自动测试使用隔离 PostgreSQL、合成数据及模拟模型，不作为真实模型内容质量或用户人工验收。回填并行输入框调整后，两项首次讨论/丢响应检查再次通过；卡片标记文案由“来自会话”改为“AI 生成”，避免把内部任务存储当作用户会话来源。

## 原实例核对结果

原实例现运行数据库 V52。迁移前后均为 31 条内部会话记录、40 条任务；13 条纯系统记录改为后台生成用途，普通列表保留 16 条有用户发送的会话，2 条历史空讨论草稿继续保留但不占列表。任务原事实、会话身份、全部产物、资料和版本、卡片及旧偏好的摘要逐项一致。

浏览器实测普通列表无系统触发提示词，原“你好”会话消息仍在；原系统生成画报可阅读、打开讨论可呈现确切内容，复用历史空讨论期间会话/任务数量均未增加。三端入口返回 200，浏览器无 error。未在原实例发送测试提问或额外模型请求；首次有效发送及权限/重试行为由上述合成测试证明，真实模型回答仍需自然使用验收。
