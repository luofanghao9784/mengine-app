# 企业管理端“场景外壳”原型交接（2026-10-13）

本文交接的是企业管理端重新梳理后的**前端原型**和**数据基座的后端需求**，供后续开发接手。原型只在开发环境可见，使用合成数据，没有替换现有企业管理端页面，也没有接任何后端接口。

- 分支：`claude/ADM-001-scene-shell-prototype`（基于 `main` 的 `cc6000f`）
- 本地入口：`npm run dev` 后打开 `http://localhost:5173/tenant-admin/prototype/`
- 状态：界面原型，用户已在本地逐轮确认 3D 画面、导航和数据基座卡片；其余板块的卡片**尚未确认**。

## 一、用户已确认的功能框架

| 板块 | 定位 | 已确认的要点 |
|---|---|---|
| 引擎（首页） | 企业范围的引擎仪表盘 | 沿用总台引擎仪表盘的 3D 舞台；下方是待办卡和数据卡，不要简报 |
| 数据基座 | 数据接入、治理、目录 | 资料也算数据，和业务数据在同一套治理里处理；口径和取数频率由部署方确定，管理端只读 |
| 知识库 | 企业知识网络 | 数据和资料里的知识由输入模块的模型生成；会话知识由主模型生成候选、输入模块核验（第二期） |
| 经验库 | 独立板块 | 企业经验 + 通用经验 |
| 输出 | 画报、会话回复、成果文件 | — |
| 成员与权限 | 成员、共享空间、邀请、职责与交接 | 权限跟着共享空间走 |
| 用量与运行 | 用量图表 | — |
| 企业信息 | 企业背景、AI 内容偏好、资讯来源、企业设置、操作审计、保留与退出 | 外网资讯来源在这里增删 |

明确的规则：

- 管理员可以看到全企业对象的**名称、状态、口径**，看不到正文和数据预览（仍需空间授权）。管理员身份不自动获得内容读取权。
- 资料的标签和摘要由输入模型自动生成并直接生效，不做人工提案。
- 敏感信息命中后给“暂不提供给 AI”开关。
- 资料库的上传、整理、删除在客户端，不在管理端。
- 已去掉：数据基座的“撤下与清理”。
- 用户明确排除过：人工建表、连接配置、内置 AI 字段解释、岗位密级、权限双人审批。

## 二、界面形态（已确认）

- **3D 铺满整个窗口做背景**，复用线上引擎舞台 `src/operations/engine-stage/`，不另画一套。
- **下方是浅色多卡片**，直接浮在 3D 上，没有整块底板。
- **导航是一条独立的深色长条**，挂在卡片组上方，随卡片上下滑动；每项是图标加名称，不显示数字快捷键和 logo。logo 在左上角标题前，标题栏没有副标题。
- **三档位置**：收起（卡片升到顶，3D 只剩顶部）、半屏（3D 占 60%）、全屏（只剩导航）。只靠自然上下滚动切换，没有拖动拉手，右上角没有按钮。
- **切换板块不改变 3D 视图大小**。只有去没有 3D 的页面（成员与权限、用量与运行、企业信息）才收起，回来时恢复到之前那一档。
- 收起时要一屏排完所有卡片，放不下就在卡片内滚动；半屏时可以只露出一部分。
- 数字用干净的无衬线等宽数字，不用艺术字体。

### 数据基座和知识库的 3D 画面

两者和引擎是**同一个模型**，切换板块只是同一台相机换位置。

- **数据基座**：画的是治理过程，不是一条条数据。
  - 左侧三片光尘是三个来源：外部数据集、内部资料库、外网数据集。
  - 向右依次穿过三道由大到小、反向自转的处理星门：解析、口径标注、检查。进入第一道门即“接入”，进入梦核即“AI 可用”，这两步不设门。
  - 星尘逐门减少、变亮，并沿途并入三条始终可见的星链；星链随门的大小自然收拢，过最后一道门后就是引擎自己的三条输入光流。
  - 最后一道门立在引擎输入光流的起点上，引擎首页也能看到它。
  - 不单独摆出卡住的记录；选中一条卡住的记录时，它卡在的那道门亮起来。
- **知识库**：梦核内部的星链。镜头推进核心，引擎其余一切隐去；节点是知识，连线**只画真实存在的知识关联**；节点默认带小标题，大小按被关联次数，鼠标靠近轻微放大并高亮关联。

## 四、数据基座：后端需求

这是唯一一个功能、3D、卡片都已确认的板块，建议先做。

### 1. 输入按三个来源描述

现有遥测通道是 `COLLECTION / KNOWLEDGE / RETRIEVAL`（外部取数 / 资料解析 / 资料检索，见 `contracts/public-api/engine-telemetry.ts`）。用户要求输入按三个来源讲：**外部数据集、内部资料库、外网数据集**。

原型里只是通过 `channelNames` 换了显示名，数字仍来自旧通道。真正的调整属于契约变更，需要定：三个来源各自的运行中、排队、完成数怎么统计，旧通道如何对应或保留。

### 2. 治理五步的状态模型

每一项数据或资料都有一个统一的治理状态：

| 步 | 名称 | 说明 |
|---|---|---|
| 1 | 接入 | 进入系统 |
| 2 | 解析 | 结构化数据读出行列；资料提取文字 |
| 3 | 口径标注 | 字段含义、单位、依据；资料的属性和关联 |
| 4 | 检查 | 敏感信息、时效、完整性 |
| 5 | AI 可用 | 可以被引擎调用 |

需要能回答：每一步通过了多少项；每一项停在哪一步、为什么停、每一步的摘要（如“10 / 12 个字段”“3,204 行”）。业务数据、资料、外网数据走同一套状态。

### 3. 管理员的四种操作

其余一律只读。

| 操作 | 触发场景 | 效果 |
|---|---|---|
| 暂不提供给 AI | 敏感信息命中；也可对任何已可用的数据使用 | 引擎不再调用该项，可撤销 |
| 确认可以提供 | 敏感信息命中，管理员判断可以提供 | 放行，继续后续步骤 |
| 重试解析 | 解析失败 | 重新排队 |
| 立即取数 | 来源超期或取数失败 | 立即触发一次取数 |

- 口径不明确：只读。显示哪几个字段不明确，由部署方确定后自动继续。
- 取数频率：只读，显示部署设定值。
- 不做批量操作（用户确认暂时不用）。
- 操作应进操作审计。

### 4. 三栏需要的数据

- **治理**：未达到“AI 可用”的项（卡住的、处理中的），带所属空间、类型（业务数据 / 资料）、卡在哪一步、原因。
- **接入**：每个接入的名称、所属空间、包含的数据集、取数频率、最近若干次取数的时间和成败、下次尝试时间、失败原因；按三类来源汇总健康状态。成员上传的资料和外网资讯各作为一条接入。
- **目录**：已可用的项，带字段口径（字段、含义、依据）、版本、行数、所属空间、近 7 天被调用次数。

### 5. 可见范围

上述接口只返回名称、状态、口径和统计，不返回正文和数据预览；需在服务端执行，不能靠前端隐藏。

## 五、还没定的事

- 知识库、经验库、输出、成员与权限、用量与运行、企业信息六个板块的卡片：原型里是通用的“清单 + 详情 + 侧栏”，用户还没逐个确认功能和布局。建议每个板块先和用户确认功能与卡片，再做后端和接入。
- 知识库后端（知识生成、关联、企业知识网络、会话知识候选）尚未写需求，等知识库卡片确认后一并写。
- 经验库和输出两个板块的 3D 仍用引擎舞台自带的聚焦面板。
- 引擎首页上，最后一道星门套在左侧三个来源的数字标签外面，略有重叠；三条输入光流的起点为配合更小的星门向中间收拢了约三成。用户已看过，未提出异议，也未明确确认。
- 数据基座合成数据的数字互相对不上（如标签写“治理 14”，清单里只有 8 条有名字的记录），接真实数据后自然一致。
- 没有实测帧率。用户反馈过星尘多时性能不够，已把星尘从约 2600 减到约 700；星门的装饰线条也占一部分开销，仍卡的话可以简化刻度和连接肋。
