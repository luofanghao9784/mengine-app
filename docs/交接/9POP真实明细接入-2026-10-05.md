## 采集与权限

- `scripts/ninepop/detail_collector.py` 固定四类 SQL；同一 MySQL REPEATABLE READ / READ ONLY 一致性快照中查询，最后 ROLLBACK。按请求绑定的企业、连接、数据集 ID 与列定义校验，不接收页面 SQL 或任意目标地址。
- 只读事务约束本次数据库会话，**不宣称源运维账户本身仅有只读权限**。密码留在源服务器环境中，SSH 校验已知主机；错误输出使用固定失败码，原始数据库错误不进入产品日志。
- 部署复用已有 `--provision-collection`、采集进程协议、后台任务、不可变版本及空间服务端授权。配置管理权不自动授予内容阅读权；总台支持访问继续绑定现任企业负责人的实际权限并留痕。
- 当前两空间均由现有企业管理员“9POP曹鸿健”负责，只授权该成员。尚无已加入的财务成员，不擅自将其他邀请或账号认定为财务。财务人员加入后需由负责人明确授权对应空间。
- 自动取数保持关闭，等待用户选择更新频率；可使用“立即更新”。数据更新不触发自动模型分析、画报生成或持续计划，本实例仍维持手动真实模型验收策略。
- 未改变旧“9POP 独立验收”企业的数据或 90 日收款汇总定义；本次采集器仅接受新连接的四类档案请求。

## 本地维护与复现

私有部署目录为项目 `.local/ninepop-details/`，0700。`source.json` 绑定作用域，`manifest.json` 是部署定义，`runtime.json` 仅含可执行路径，均为 0600，不纳入 Git。`collector` 为 0700 包装程序，调用目录内经过验证的采集器副本，避免后续源码编辑改变已部署执行内容。`before-deployment.dump` 是变更前完整本地数据库备份，含业务数据，必须按私有备份保管，不在共享日志中展示。

当前服务仍使用原固定 API 产物；无新迁移或 API 合约。重新启动已有验收目录时，保留原 live/manual 配置并显式附加：

```sh
--collection-config '/Users/dim/AI Coding/企业AI工作空间/.local/ninepop-details/runtime.json'
```

不附加该参数的常规启动不会自动恢复外部采集能力。重新部署元数据时调用现有 host CLI，设置 `COLLECTION_MANIFEST_FILE` 指向私有 manifest；数据目的空间和字段变更必须创建新数据集身份，不能给历史快照换归属。

故障时先停自动调度并排查源连接，保留上一成功版本；不要修改 9POP 业务数据来满足采集。源字段、权限或业务统计口径变化应先重新核对，再部署固定字段。禁用采集可在所属实例的启动配置中移除采集器并重启，既有快照保留且仍执行空间权限。
