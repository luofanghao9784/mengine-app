# 资讯候选筛选与去重修复 · 2026-10-06

用户确认按诊断建议调整。前一轮“无新内容”只证明有限候选没有产生未报道原文，并不能代表当天不存在相关新闻。

## 原因与变化

旧链路：Bing RSS 每主题最多返回 3 个候选；整个任务最多读 4 篇原文；读取后按 URL 与正文哈希去重。四个空间都选择健身/健康两组固定公开主题，前 4 篇恰好是已报道文章，耗尽额度后健康主题后面的天天基金文章未读取。

新链路：

- Bing RSS 最多保留 20 条合格候选，任务候选池仍有上限；保留 HTTPS、公开地址、日期与 RSS 安全校验。
- 优先读取未报道 URL，在这一组内优先发布时间较新的候选。已报道文章只作一次独立更新复查；若正文哈希变化仍可进入来源。新原文读取预算 4 次，旧文章复查预算 1 次，任务内同 URL 不重复读取。没有把去重简化为永久屏蔽旧 URL。
- 补充站点按“未报道候选不足”触发，不再被前几条旧文章阻止。
- 最多尝试 3 个获准且相关的公开主题。主题须先由服务端登记，重复请求幂等；第 4 个主题拒绝。仍不把企业私有名称、人员、营收、资料原文作为网络搜索词。
- 分别记录已有报道、原文读取失败、过期、正文不足、明显推广与预算未覆盖的候选。全部主题尝试后只有读取失败或候选核验达到上限时保留错误码，不能伪装成“没有新闻”。已报道或候选不足的状态明确限定为本轮结果。
- 针对真实复测中发现的“体育官方app下载最新版”推广标题，增加明确推广词过滤；候选标题及读取后的网页标题都检查。该过滤只是限定模式，不声称能证明所有网站内容真实或无推广。
- 部分结束的 INFO 批次仅在 2–3 个登记主题、相同数量成功搜索回执、无网页来源、成功 task_control、没有失败或其他工具回执的条件下结束为无新内容；其他失败继续保留。

## 验证

- 35 项引擎检索/发现/权限测试通过，涵盖旧新闻不占新原文额度、第二主题新候选能够读取、20 条候选边界、原文更新、失败原因、明显推广过滤及发布时间优先。
- 59 项 API 集成检查通过。另执行空搜索结束定向回归，覆盖 1、2、3 个主题的状态与零扣次数，通过。
- 前端构建通过；本地安装只更新两个目标 API 类族、三个引擎模块，以及当前客户端的三条原因文案。未覆盖其他未提交前端改动。
- 在最终安装的运行版本中，使用原有两个真实公开关键词及相同账号历史去重记录复测。成功读取 3 篇此前未报道的原文：新浪体育场馆假日开放、腾讯健身器材行业报道、天天基金智能穿戴医疗设备报道。此前被额度挡住的第三篇已经进入 PAGE 来源，明显推广候选未进入来源。
- 最终检索统计：9 个候选，3 篇可用原文，1 篇正文不足，1 篇推广候选，读取失败 0；读取预算未耗尽。旧文独立复查 1 次，新候选读取 4 次。

真实检索是来源链路验证，未调用主模型，未创建新的画报卡片、未扣生成次数。资讯内容的业务相关性仍须由后续选题与原文核验完成；30 天新鲜度窗口保留，未把“此前未报道”表述为“今天发布”。单任务主模型仍为 8 轮，自动额度 8、手动额度 6 不变，全局自动执行保持关闭。

安装时重复前端补丁检查曾导致本地服务短暂停止，已修正并恢复；数据库数据保留，最终网页响应 200，运行目标类与本次构建一致，资讯引擎模块一致；共享 agent-task 模块只安装本次资讯变更，未混入同时出现的数据分析草稿依赖，最终模块导入检查通过。
