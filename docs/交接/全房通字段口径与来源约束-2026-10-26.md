## 可执行约束

在既有企业和数据集绑定的私有 `schema` 中新增 `kind: value-rule`，由服务端对完整当前快照检查，模型不能返回自称通过的结果。每项必须携带依据，未知列、无依据或不支持的规则拒绝执行。

| 规则 | 实际检查 |
| --- | --- |
| 唯一键及必填 | 账单编号非空且不重复；完整历史导出范围由企业确认 |
| DECIMAL | 12 个金额字段使用精确十进制，保留正负号和 NULL |
| DATE | 3 个日期字段为有效 ISO 日期，NULL 保留 |
| ENUM | 业务类型限集中、整租、合租、其他、普租；收付标记限收、付 |
| PREFIX_DECIMAL | 收付状态为已收、已付，或待平账：加合法有符号金额；+0 不自动结清 |
| ORDINAL | 缴费次数为缴纳押金或正整数第 N 次，允许 NULL |
| TEXT | 其余文本列保留源值，非 NULL 值不得为全空白 |

示例（合成列，不含业务记录）：

```json
{"kind":"value-rule","datasetId":"<数据集 UUID>","id":"amount-type","column":"金额","type":"DECIMAL","nullable":true,"evidence":"<来源规则定位及确认记录>"}
```

结果输出各规则的检查数、异常数和依据，不输出违规记录的个人字段。异常保留为需处理；仅已声明规则全通过且字段均有依据时，移除本次已解决的 UNKNOWN 和未声明约束提示。没有声明的银行到账、抵扣勾稽、税务、跨表外键不冒充检查通过。

## 验证与回退

隔离 PostgreSQL 定向测试 19 项通过，包含有符号精确金额、NULL、无效日期、值域/状态/期次、来源依据拒绝、当前快照绑定和发布后有异常/无异常两种状态。构建成功。

私有证据更新前已留存备份，治理历史保留。回退通过选择先前治理版本及恢复对应证据文件进行，不直接修改历史任务或覆盖后续业务数据。后续新快照仍需重新核对导出接收回执，规则则在每次治理时重新执行。

## 本地发布结果

真实 SYSTEM_MODEL 草稿返回 30 项 REVISE，逐列证据原文通过服务端校验，12 个金额字段的单位与确认字典一致。已发布到当前第 2 版完整快照：字段 UNKNOWN 数为 0，数据资产 available=true、needsAttention=false、checksPassed=true；30 项字段值规则异常 0，声明主键重复 0，必填缺失 0。真实浏览器核对口径标注页和发布检查摘要通过，无页面 JavaScript 错误。运行后端产物摘要与测试构建一致。

前几次调用失败保留原有任务：压缩源码使输出成为无效 JSON；随后一次返回来源 URL 而非证据原文，被服务端拒绝。部署输入改用经核对的字段定义及可定位代码摘要，并明确提示引用 definition 原文、不能用 URL/哈希替代；重新生成后通过。没有修补模型返回值或把失败任务直接改成成功。原始行没有发给治理模型。
