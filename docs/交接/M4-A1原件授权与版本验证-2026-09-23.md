重点行为：

1. 二进制版本 v1 被选择后再上传 v2，读取仍得到 v1 的确切字节和摘要。取消阻止旧 token 读取/发布；重试固定原选择、使用新 token，排队显示尚未读取。更换版本复用旧幂等键返回冲突。
2. 同名文件不构成授权；未选版本、伪造 material/version 关系、不同空间和企业均拒绝。共享只读成员可处理其有查看权限的资料；超过数量/单份/合计大小时事务回滚，不残留任务或选择。
3. 选定历史版本的检索只返回该版本片段，即使当前新版和其他资料均命中关键词。无原件选择的原有最新版本检索继续有效。
4. 内部 HTTP 需要准确尝试凭证，拒绝自报路径等未知字段；响应 no-store。停用企业、撤销空间权限后拒绝读取/下载；其他成员及管理员不能下载私人产物。
5. 平台拒绝伪造/遗漏原件读取回执，不写入成功结果。引擎校验 base64、大小、摘要、清单稳定性和显式句柄；读取后的撤权会中断正在等待的沙箱调用。该用例在沙箱 run 入口建立同步屏障，不将其描述为新的 Linux 容器 READY 后撤权实测。
6. 浏览器选定 v1、刷新恢复草稿，再上传 v2，任务处理 v1 全部 **4000 行**，下载 `original-summary.json` 的行数及合计均为 4000；来源包含固定原件而非截取片段。刷新后版本和读取状态仍在，桌面及 390px 手机视图可用，总台下载被拒绝。

模型夹具额外断言该场景的原始标记不出现在模型请求中，证明 read_original 不直接返回文件正文；不推广为任何脚本输出都不会泄露正文。格式支持与模型语义正确性仍需分别验收。

本工作树忽略目录 `.local/m4-agent/` 保存 `result.json`、`original-desktop.png`、`original-mobile.png` 和其他既有截图。新原件链路在 macOS 执行器验证；Linux 实际 7 项来自[上一切片](M4-A1-Linux隔离执行与回收验证-2026-09-23.md)，本批未重建 Linux VM 或重跑真实容器全套，不把 Docker 控制夹具写成此次 Linux 原件验收。
