# 数据期间汇总与 Harness 计算规则

用户授权按系统能力修复，不针对某条测试会话写规则，也不自动重试或修改其状态。本次沿 AI-11—AI-13 的真实执行、固定资料版本与计算依据要求推进。

## 能力

既有 `compare_dataset` 增加 `operation=SUMMARY`，按 1—3 个实际列名分组，使用 SUM 或 COUNT 对固定快照全部记录计算期间累计。默认 COMPARE 保留两期／两类别的确定性比较及数据画报交付链路。两种模式都支持独立的 `dateColumn`、`dateFrom`、`dateTo`：起止业务日期均含当日，可省略一端，日期按显式 IANA 时区（默认 Asia/Shanghai）处理；SQL 时间、ISO 本地／带偏移时间及日期沿既有日期解析能力执行。

例如累计统计使用 SUMMARY、groupColumns=[门店,收款状态]、valueColumn=实收金额、dateColumn=确认时间、dateFrom=2026-08-01。没有要求第二个比较月份，也不将确认时间替换成创建时间。单位沿原始列保留；COUNT 是记录数，不是去重人数。

缺失日期默认报错；明确指定 missingDates=EXCLUDE 时排除并返回 missingDateRows。非法非空日期仍报错，范围外记录保留 ignoredRows；空范围报 DATASET_NO_MATCHING_DATA，不伪造零。原快照行数、匹配／排除记录、请求参数、哈希与计算结果写入不可变计算附件。COMPARE 筛选后的图表范围改为“日期筛选”，不再误标全部快照。SUMMARY 不冒充两期数据图表；系统画报的比较工具只开放 COMPARE，仍可在日期范围筛选后比较两种业务状态。

## Harness

后端授权检查增加可选 datasetAnalysisVersion=1.0；只有版本获确认时才开放 SUMMARY 和日期筛选字段，旧后端仍使用两期计算，避免新参数被旧服务忽略而返回全历史总额。普通会话每次模型调用附加通用数据分析规则：区分累计与对比，优先确定所需列和固定快照后调用计算，只补读缺失列和必要类别样本，不逐行读取来做总数，不重复错误参数，不要求累计请求再提供第二月份，披露日期缺失和统计范围。未扩展访问权限或提高执行上限。

## 验证与运行

- 独立临时 PostgreSQL：DatasetSummaryIntegrationTest 6 项、DatasetCalculationIntegrationTest 10 项、TaskDatasetIntegrationTest 8 项，共 24 项通过。覆盖金额精度、时区和含末日边界、缺失日期、空结果、非法日期、固定快照、撤权、幂等附件及日期筛选数据图表。
- Engine 相关 63 项通过，包括真实 Harness 编排（合成模型／平台）：搜索后一次 SUMMARY 计算完成、旧能力不暴露日期范围参数、画报不误用 SUMMARY、回执验证与既有交付流程。
- 本地 54803 实例已安装窄范围 API 计算／能力检查类和 engine 模块；所有其他 JAR 条目保留，Harness 运行文件按片段替换。备份及清单在 `.local/dataset-summary-20261006`；无数据迁移、额度变更、测试会话修改或真实模型重试。
- 这是开发验证与本地安装，尚未宣称真实模型能完成用户全部业务问题。后续测试使用相同通用规则，不对特定企业或会话添加特例。
