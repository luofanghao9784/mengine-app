# M7-A1 断网与草稿恢复验证

2026-09-24，M7-A1 第六切片、DEC-074；沿用 POS-06、AI-01/AI-02/AI-04 及个人文稿编辑范围。云端工作为主，只处理本标签页草稿和明确重试，不建立完整离线编辑或自动同步。

## 修复与行为

会话和文稿此前均会静默忽略 sessionStorage 写入错误，会话仍固定显示“草稿在本标签页恢复”，且旧草稿可能遗留。现由共用草稿存储函数返回实际读写结果；写入失败时提示先复制保留，停止宣称最新草稿可恢复，并尽量移除**当前键**的过期副本，不清空其他存储。存储再次可写并发生编辑或明确提交后，成功写入会清除写入失败提示。读取受限或 JSON 损坏单独提示，不阻止继续编辑。

浏览器无法持久化不等于服务端拒绝工作；保留当前组件内输入和待确认请求，重试继续使用原编号。请求状态不确定且存储失败时，提示离开页面后先核对服务端记录，避免重新提交。正常存储下，断网或响应丢失后的待确认请求仍可刷新恢复；联网不会自动发送。

没有更改企业/空间权限、共享规则、身份失效清理、服务端版本冲突处理或幂等契约。后台权限检查失败仍收起内容，不以保留草稿为理由绕过身份和资料访问复核。

先将写入故障加入浏览器验收，在旧产品代码上复现失败：页面找不到故障提示，见本地 `.local-draft-red.log`。随后修复并回归：

- `npm run build`；`npm test`：109 项前端测试通过（新增 3 项存储故障测试）。
- 脚本严格 TypeScript 检查：会话/文稿旅程及两个实际服务入口。
- 三种浏览器的三端/资料/会话旅程：断网时服务端尚无新会话，恢复联网后仍为 0；明确重试接受后丢弃响应，再刷新重试，只有一个会话和一个任务。另验存储拒绝时原输入仍可编辑、旧副本被移除、后续存储恢复，以及无法存储时同页重试的请求 ID 不变且会话数不增加。
- 三种浏览器的 Agent/文稿旅程：文稿存储失败明确提示且旧草稿移除，恢复后刷新取得最新草稿；断网保存不新增版本，联网后明确重试接受但丢响应，刷新再次重试最终仅到 v2。继续原有版本冲突、Word/PDF 导出、共享/企业动态和撤权清理流程。

```bash

npm test
npm run test:browsers -- --journey=three-surfaces
npm run test:browsers -- --journey=agent
```

本批仅前端与验收代码变化，不将打包当作再次运行后端全量单元测试。本地故障用浏览器离线开关、指定草稿键的写入异常和实际响应丢失注入；不等于目标手机操作系统的磁盘耗尽或所有隐私模式验收。

## 限制与接续

当存储完全被禁止，连删除旧副本也可能失败；不能保证离开页面、组件重建或刷新后的恢复，页面因此要求先复制。会话和文稿没有云草稿、跨设备同步或自动重放；存储故障本身不会更改账号权限。历史版本只读，不写草稿。

本批待非作者审查与用户体验，未合入 main、未部署或使用客户资料。下一优先验收是实际模型的回答与工具调用质量：已向用户确认是否使用 DeepSeek、是否已有账号和本轮费用上限；确认前不调用付费服务、不发送项目或客户资料。WeKnora、实际搜索、目标真机、云运行与规模限制继续保留原任务，不因本地验收完成而标为交付。
