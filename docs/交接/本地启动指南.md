# 本地启动指南

> 目标：从零克隆到三端可访问，全部命令可直接复制执行。
> 验证环境：macOS（Apple Silicon）+ JDK 21 + Node 24.20 + Python 3.9+ + PostgreSQL 18；Linux（Ubuntu/Debian）下同样可按本指南启动，见下方「Linux 环境说明」。

---

## 一、需要先准备好的东西

| 依赖 | 版本 | 用途 |
|---|---|---|
| JDK | 21 | 编译并运行后端 |
| Node.js | 以 `.node-version` 为准（当前 24.20.0） | 前端、引擎、构建脚本 |
| Python | 3.9+ | 启动脚本、解析器虚拟环境 |
| PostgreSQL | 18 | 本地数据库（需要 `initdb` / `pg_ctl` / `psql`） |

JDK / Node / PostgreSQL 不需要装进系统 PATH，只要在启动前把路径加进去即可（见第六节「启动」）。

### Linux 环境说明

- **JDK 21**：如 `sudo apt-get install openjdk-21-jdk-headless`，或解压 Temurin 21 并设置 `JAVA_HOME`。
- **PostgreSQL 18 服务端**：启动器会自己用 `initdb` 建库、用 `pg_ctl` 启停，因此只装客户端（`psql`）不够，必须装服务端二进制。例如按 PostgreSQL 官方 apt 源安装 `postgresql-18`，二进制位于 `/usr/lib/postgresql/18/bin`，然后 `export POSTGRES_BIN=/usr/lib/postgresql/18/bin`。无需启动系统自带的 postgresql 服务。
- **Node.js**：版本以仓库根目录 `.node-version` 为准（可用 nvm / fnm / 官方二进制包）。
- **Python**：系统 `python3`（3.9 及以上）即可，需带 `venv` 模块（Debian/Ubuntu 上为 `python3-venv`）。

## 二、克隆与安装

```bash
git clone https://github.com/luofanghao9784/dreamcore-workspace.git
cd dreamcore-workspace

# 启用本地 git 钩子（拦截直接推 main）
npm run setup:git

# 安装前端与引擎依赖
npm ci
npm --prefix engine ci
```

---

## 三、构建

一条命令完成三项构建（需先完成第二节的 `npm ci` 与 `npm --prefix engine ci`，并设置好 `JAVA_HOME`，否则引擎会报 TS2307 找不到模块、后端无法编译）：

```bash
npm run trial:build
```

它依次执行下面三步，也可单独运行：

```bash
# 前端产物 + 类型检查
npm run build

# 引擎
npm run build:engine

# 后端 jar
JAVA_HOME=/path/to/jdk-21 ./apps/api/mvnw -B -f apps/api/pom.xml -DskipTests package
```

完整首次顺序：`npm ci` → `npm --prefix engine ci` → `npm run trial:build` → `npm run trial:start`。未构建直接 `trial:start` 会报「缺少构建产物；先运行 npm run trial:build。」

构建完成后应存在：

```
dist/                                  前端产物（trial 用 vite preview 提供）
engine/dist/                           引擎产物
apps/api/target/workspace-api-*.jar    后端 jar
```

## 四、资料解析（可选）

不做资料上传解析可以跳过；跳过时知识库开关为关闭状态。

```bash
python3 scripts/knowledge/setup.py               # 等价于 npm run setup:parser；Python 3.9+

# 需要运行解析器测试（npm run test:parser）时，改为安装测试依赖：
python3 scripts/knowledge/setup.py --with-tests
```

这会在 `workers/parser/.venv` 建虚拟环境并安装解析依赖（Word / Excel / 纯文本 / Markdown）。
需要 PDF 时另装 Poppler、Tesseract 与 docling，见 `workers/parser/README.md`。

## 五、模型配置（可选）

不接模型也能启动，只是 AI 对话不可用，界面、资料、权限功能照常验证。

接真实模型需要把凭据写入私有文件（目录不入 Git）：

```bash
mkdir -p .local/model-private
chmod 700 .local/model-private
```

`.local/model-private/deepseek.json`（权限必须是 600）：

```json
{
  "format": "dreamcore-local-model-v1",
  "workspace": "/绝对路径/dreamcore-workspace",
  "provider": "deepseek",
  "model": "deepseek-flash",
  "workspaceId": "",
  "apiKey": "你自己的密钥",
  "routineModel": "deepseek-flash"
}
```

> `workspace` 必须写成当前克隆的绝对路径，否则校验不通过。
> 每人用自己的密钥，不要共用。

## 六、启动

```bash
export JAVA_HOME=/path/to/jdk-21
export PATH="$JAVA_HOME/bin:/path/to/node-24/bin:$PATH"
export POSTGRES_BIN=/path/to/postgresql-18/bin
```

**接真实模型：**

```bash
npm run trial:start -- --live --model-config .local/model-private/deepseek.json --phone-local --enable-live
```

**不接模型：**

```bash
npm run trial:start
```

首次启动会自动：建本地数据库集群、跑数据库迁移、创建随机总台账号、启动 API / 引擎 / 前端。

启动成功会打印入口地址与账号文件路径。**保持该终端窗口打开。**

首次启动时端口随机分配并写入 `.local/trial/config.json`，下文的 `54029` 仅为示例，请以启动输出或 `npm run trial:status` 打印的地址为准。

## 九、停止与重启

在运行终端按 `Ctrl+C`。**数据保留**——账号、企业、资料、会话都还在，下次启动直接可用。

```bash
# 另开终端查看状态
npm run trial:status
```

端口在首次启动后固定写入 `.local/trial/config.json`，重启不变。

**重置为空环境：** 启动器不提供重置命令，实例数据都在 `.local/trial/`。确认不再需要其中的账号与数据后，先 `npm run trial:stop`，再删除（或改名备份）`.local/trial/` 目录，下次 `npm run trial:start` 会重新初始化数据库并生成新的随机账号。需要保留数据时先用 `npm run trial:backup`。

需要完整启用当前已实现能力时，见[本地全功能配置与验证](本地全功能启用-2026-10-25.md)。PPT 需要同时开启引擎渲染与平台下载能力；隐藏入口开关是构建时配置，修改后须重新构建前端。

## 十、常见问题

| 现象 | 原因与处理 |
|---|---|
| `缺少 initdb；需要 Node、Java 21、PostgreSQL 18（可设置 POSTGRES_BIN）。` | 没设 `POSTGRES_BIN`，或该目录下没有 PostgreSQL 18 的可执行文件 |
| `JAVA_HOME is not set` | 忘记 export，或路径指向 JRE 而不是 JDK |
| 启动报模型配置错误 | `.local/model-private/*.json` 里的 `workspace` 不是当前克隆的绝对路径 |
| `缺少构建产物；先运行 npm run trial:build。` | 未构建；按第三节先跑 `npm run trial:build` |
| 端口被占用 | 上次没停干净；`npm run trial:stop` 后再启动 |
| 页面 200 但登录失败 | 首次启动生成的账号在 `.local/trial/accounts.json`，不要用旧实例的密码 |
| 上传后解析不动 | 没有装解析依赖（第四节），或知识库开关为关 |

## 十一、和「工作区」的关系

本仓库可能放在一个更大的工作区目录里，工作区还有：

- `run-trial.sh`：把第六节的环境变量和启动命令包成一行，等价物
- `tools/`：便携版 JDK / Node / Python / PostgreSQL

**这些不在仓库里**，克隆仓库拿不到。没有工作区时，按本指南第二到六节自己准备即可；
有工作区时，直接跑 `../run-trial.sh --live --model-config .local/model-private/deepseek.json --phone-local --enable-live`。

## 原生集成测试前置构建

运行 Native*IntegrationTest 或 NativeSdkBrowserIT 前，在仓库根目录运行 `npm --prefix engine ci`（首次/依赖变更时）和 `npm run build:engine`。缺少 engine/dist 必需文件会直接报 `NATIVE_TEST_ENGINE_NOT_BUILT`，不要当成权限或派发业务故障。已有产物存在不代表与当前源码一致，切换版本后重新构建。
