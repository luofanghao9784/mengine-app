## 实现与验证记录

1. 初次 API 基线的 12 项失败来自新 worktree 没有解析器环境。运行既有 `scripts/knowledge/setup.py --with-tests` 后，原 165 项通过。未接外部模型。
2. 新上传回执把 `acceptedVersion` 与 `currentVersion` 分开；原请求重放返回它实际保存的历史版本。无法可靠追溯的旧请求明确返回 `HISTORICAL_UNKNOWN`。撤权先于回执读取。相应旧撤权测试从“返回当前版本”改为明确核对原 v1/当前 v2。
3. 目录上传真实浏览器暴露两个问题：异步挂载的目录 input 属性未设置，以及 FormData 未显式指定文件名导致相对目录进入 multipart 文件名。均修复并完成真实旅程。测试注入也改为原生请求发出后模拟丢回执，避免 Playwright 重放磁盘文件时缺失正文。
4. 人工来源的覆盖为人工声明；与解析状态和业务完整性分开。补交绑定确切历史版本；历史无关周期补交不解除当前逾期。配置历史独立保存；资料回收后依据不再参与覆盖，并显示不可用版本数量，不保留可下载名称旁路。
5. 管理职责不能隐含客户正文权；存量管理员不自动变成主要授权负责人。紧急停用切断本企业资格并保留负责人归属；涉及负责人/最后管理员时普通恢复不能绕过待核验记录。治理测试单独清理本地登录桶，生产限流未放宽。
6. 生命周期只有明确删除动作给对象设置 30 天开发默认回收期，不自动给全部旧资产追溯清理。在线原件、派生正文及最小删除身份分阶段处理；物理失败记录 FAILED，可明确重试；在线完成不宣称备份完成。恢复不会继续已经取消的解析。
7. 生命周期页面手机溢出已修复，真实三端旅程再次通过并人工查看桌面/390px截图。清理采用真实后台 worker，浏览器只轮询实际进度，未直接改数据库伪造完成。复审发现的父目录阻塞其他企业到期队列已修复并回归；快速回收恢复的旧任务执行隔离与任务控制切片统一接入。
8. 所有本轮浏览器运行都使用监督脚本拥有的临时数据库、端口、账号和合成资料。一次测试回调未捕获异常留下的专属 PostgreSQL 已核验绝对路径后停止；未按通用端口或名称关闭用户其他程序。


9. 任务控制已接入真实资料回收：回收后旧任务令牌失效，立即恢复资料也不能让迟到结果写入；尝试历史按当时来源权限读取。RESULT_UNKNOWN 与 INTERRUPTED 分别计数，等待/暂停/部分完成也纳入三端运行观测；已物理清理的原件不继续计作在线存储。全套 API 中发现一项新增统计测试夹具缺 workspace_id，修正后对应41项联合通过；测试 Spring 缓存限制为6个上下文，避免增加功能后占满临时 PostgreSQL 连接，生产连接配置未调整。
