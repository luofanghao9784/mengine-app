# 画报出卡失败修复（2026-10-04）

更新：2026-10-04 10:07（上海时间）。范围为 DEC-120 / BG 系统画报生成链路。修复已叠加到原本地 live 实例；原账号真实生成并阅读一张 DATA 卡。后续批次暴露的交付参数恢复和无新增内容边界已修正并通过回归；最终版本的下一次原账号真实调用等待额度恢复，不能把此前成功的一批记作所有后续修改的真实验收。

## 失败原因与修正

1. 检索循环耗尽八次模型调用：只有服务端确认的画报生成任务采用一次空查询概览、最多两次定向检索。到达三次后移除检索工具；模型仍要求第四次时，返回明确的检索已关闭回执，不执行新查询、不伪造搜索结果。普通会话保持原检索预算。
2. 最后一次调用无法交付：Harness 原先预留纯文本收尾，画报最后一轮现在保留 `deliver_briefing`。有效平台交付回执可直接结束该生成任务，无需额外文字收尾。
3. 所选资料缺少经营底表：AUTO / DATA 在未消费资料中没有 XLSX 时，可复用同一授权空间的至多一份当前 XLSX，配合最多两份未消费资料。仍限三个版本；显式其他类型保持原选择规则。复用不代表数据更新，期间、权限和去重规则保留。
4. 长文档占满授权片段：空查询按所选文件轮流返回片段。画报概览最多六个片段，留四个名额给定向检索；其他查询保持原规则和十个授权片段上限。
5. 反复计算挤占交付预算：一次成功的 `compare_table` 后，只保留并指定交付工具。再次计算被拒绝，不能将计算失败掩盖成完整任务。
6. 指定工具时的真实模型响应被误拒绝：实际 Qwen 返回非空 `tool_calls` 并使用 `finish_reason=stop`。适配器只在平台已指定唯一交付函数时接受该组合；仍校验函数名、数量和参数，无工具调用的普通 `stop` 不冒充交付。缺失路由字段的兼容有合成测试；本次真实日志并未观察到字段缺失。指定工具格式依据[百炼 Function Calling 文档](https://help.aliyun.com/en/model-studio/qwen-function-calling)。
7. 纠正参数后仍被早先失败阻断：本地 schema 拒绝现在也写入平台工具台账，实际业务动作不执行。只允许系统生成任务在最后一次真实交付成功、具有当前尝试的产物或无新增审计证明时，恢复此前失败的交付尝试。台账仍保留 failed，来源检索、计算等其他失败和普通会话仍不得转成 COMPLETE。平台同时核对最后一条实际台账，不能只信引擎报告的顺序。
8. “暂无新内容”被保存成卡片：明确的无新增标题在系统生成任务中返回经授权、具有资料依据的 `NO_NEW_CONTENT / NO_USEFUL_CONTENT`，记录审计、不保存产物；普通会话拒绝此类状态卡。AUTO 不得擅自交付 INFO。历史误生成的状态卡通过现有偏好服务设置隐藏，记录和产物保留，可恢复。

这些属于可逆实现修正，未新增业务类型或将待确认的业务判断升级为用户确认。个人六批 / UTC 日、企业四十八批 / UTC 日、个人并发一批、企业并发两批、单批一张卡及最多三个资料版本均未调整；失败执行仍计额度。
