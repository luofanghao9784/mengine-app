## 主流程人工验收

目标：围绕一个自己熟悉的真实业务主题，完成“企业开通 → 成员和空间 → 资料上传/解析 → AI 分析 → 个人成果 → 企业共享 → 反馈与运行观测”。已有企业、成员或空间就复用；每一步先记录是否通过，再进入下一步。本清单的按钮和行为已与当前正式客户端源码核对，不把预期结果写成已通过的真实业务验收。

准备一个小主题，例如“本周某项目进展”，先选2–3份内容较短、自己熟悉的资料：项目说明、最新进展/会议纪要、相关规则。先用 TXT、Markdown、DOCX 或可复制文字的短 PDF。自己先记下3个可核对的事实和1个资料没写的信息。当前单文件20 MiB上限；首轮不需要扫描件、复杂表格或大批量导入。

准备平台管理员、企业管理员、普通成员三个身份；企业管理员和成员使用不同邮箱标识即可。当前邀请不发邮件，姓名和密码在接受邀请时设置，密码15–128字符。三个端在同一浏览器共享登录，三个标签不是三套独立身份；可以顺序退出/切换账号，或使用不同浏览器用户配置分别登录。

### 1. 总台开通企业

进入 `/platform-admin/`，用 `.local/selfuse-live/accounts.json` 中的平台账号登录，邮箱为 `platform@trial.example.test`。点击“开通企业”，填写“企业名称”“初始管理员邮箱”。由本次管理员负责企业授权时，勾选“明确指定此初始管理员为企业授权负责人候选人”，点击“确认开通”。

预期：企业列表能看到该企业；详情中有发给该邮箱的初始管理员邀请，状态为等待接受。开通企业不等于管理员已激活。

### 2. 接受邀请，激活企业管理员

当前是本地投递。在本轮工作树终端执行：

```bash
cd '/Users/dim/.codex/worktrees/base-release-offline/企业AI工作空间'
npm run trial:invitations -- --directory .local/selfuse-live
npm run trial:invitation -- <对应邮箱的邀请ID> --directory .local/selfuse-live
```

第二条按邮箱找ID，第三条输出对应私有JSON路径；在本机打开该文件，只复制 `token` 字段的值（不含引号）。进入 `/tenant-admin/`；若仍登录平台账号，先从头像菜单退出。点击“我有邀请码”，粘贴 token，填写“你的姓名”“设置密码”“确认密码”，点击“创建账号并加入”，随后用受邀邮箱登录。

若本来已有该邮箱账号，选择“已有账号，先登录”，再接受邀请，不另建账号。若开通时已指定授权负责人候选人，在“职责与授权”中勾选知悉职责，再点击“接受企业授权负责人职责”。

预期：能够进入自己的企业管理；企业名称正确。管理员资格、负责人职责与内容读取权限分别生效。

### 3. 邀请一个成员，建立共享空间

企业管理端进入“企业配置”，点击“邀请成员”，填写另一个邮箱并“生成邀请”。按第2步获取该成员 token，在独立浏览器会话或退出管理员后，进入 `/workspace/` 通过“我有邀请码”激活成员。再切回管理员。

在“企业配置 → 共享空间”点击“创建空间”，例如“真实验收—项目进展”。在空间中“添加成员”，按邮箱搜索、选择并“确认添加”；给执行上传和发布的成员点击“允许维护”，再“确认允许维护”。同时把将用于查看共享成果的管理员账号加入该空间，作为第二位有权读者。

预期：成员客户端能看到共享空间，进入后显示“可上传与维护”。新加成员默认只读；管理员创建空间也不会自动拥有其内容权限。自己的个人空间仍独立存在。

### 4. 上传资料并确认已经可检索

成员登录客户端，进入“资料库”，选择刚才的共享空间，可先“新建文件夹”，再“上传资料”。打开每份文件的“资料与历史版本”，点击“查看 v1 解析”。

预期：有原件、版本记录和解析内容。文本通常显示“已提取文字”；若显示“部分解析 · 请核对”，要核对本次关心的文字是否已提取。点击“搜索内容”，在“内容关键词”输入一个独特的项目名称或原文关键词，再点“检索”，确认返回对应片段和来源版本。旁边的“搜索资料名称”只查文件名，不能用来验证正文是否可检索。上传成功不等于解析成功；“解析未完成”“暂不支持此格式”不能作为已可供AI读取的依据。

### 5. 发起真实AI任务，检查事实与连续处理

进入“会话”，新建会话，检查“资料范围”为上一步共享空间。当前默认 AI 工作任务，不再选择“任务方式”；纯关键词搜索在资料库进行。第一轮“工作要求”可使用：

> 请检索当前空间中关于【项目名称】的资料，整理项目目标、最新进展、尚未解决的问题。每一项给出资料依据；区分资料中的事实与你的判断。没有找到的信息请明确写“资料未提供”。先控制在500字以内。

点击“开始任务”。预期：任务有实际处理状态，完成后出现“本次处理完成”和回复。用准备的3个事实核对内容，打开来源引用核对文件、版本和对应片段，检查资料没写的信息是否被编造。

同一会话再发：

> 在上面的结论基础上，整理一份给负责人的简短工作简报，分为“当前情况、主要问题、下一步建议”。人员和日期只有资料明确给出时才写；建议标为建议，不要表述成已经完成的工作。

预期：能够承接当前问题并组织可用的内容；不能只重复上一轮回答。连续上下文使用和资料事实准确性分别记录。失败/等待/超时应按真实状态记录，不以出现一段文字就判定任务成功，也不连续重复点击重发。

### 6. 检查画报，沉淀个人文稿

进入“智能画报”，默认显示“推荐”。展开“更多视图”，将“画报视图”设为“最新会话成果”，必要时点击右上角刷新图标。预期：本人的成功AI会话成果自动汇入，不需要先保存文稿；每个会话展示最新一条符合条件的成功成果，并非每次回复一张卡。点击卡片先打开阅读详情，再点“继续会话”，保留确切成果卡片并进入原会话追问；失败、等待和纯资料查找不应被展示成这种成功成果。已读卡片仅变淡，刷新后不因已读而移到末尾。

回到成功回复，点击“保存为个人文稿”。在编辑页修改“文稿标题”或一小段“文稿正文”，点击“保存新版本”，查看版本号和“上一版本”。预期：修改得到新版本，旧版本仍可查；以后从“资料库 → 个人文稿”能重新进入。文稿此时仍仅本人可见。

保存后点“导出 Word”或“导出 PDF”，打开实际下载文件核对标题和正文。未保存修改应先保存；首轮按普通文字及标题验收，不要求完整Office排版。

### 7. 发布给团队，验证另一身份能看到成果

在已保存文稿中点击“发布到企业资料库”，选择刚才的目标共享空间，“发布方式”选“新建企业资料”，格式选 Word 或 PDF，选择目标文件夹。确认内容适合该空间成员独立阅读，勾选发布确认，点击“确认发布”。

预期：出现企业资料版本及“查看目标文件夹”。切换到第3步已加入空间的管理员账号，从客户端资料库打开共享空间，查看/下载该文件；也可在“智能画报 → 推荐”查找企业发布副本，打开卡片详情后下载。该身份能读发布文件，但不能因此读作者的私人会话和个人文稿。

个人文稿后续修改不会自动改写共享文件。要测试一次更新，明确再次发布，选择“更新已有企业资料”，预期企业资料产生新版本。

### 8. 提交反馈，核对运行记录与持久性

作者回到会话任务下“评价 / 建议”，选择“已达到”“部分达到”或“未达到”，填写具体原因，点击“保存评价与建议”。打开画报卡片详情，点击侧边“评价 / 建议”，分别试用“有用”，或“没用”后选具体原因并保存；画报有用与任务达成是两种评价。

预期：能看到评价已保存，刷新后仍在；评价不会自动改写原回复或立刻进入经验库。企业管理员打开“运行概览”，查看“各次尝试的模型用量 → 正式模型调用”，应出现本轮业务任务的调用记录；一项任务可能多次请求，不能要求数字等于发送消息数。缺失用量要明确显示未知，不能当成零。

最后退出、重新登录并刷新，确认资料、会话、文稿、企业发布副本和反馈仍存在。服务重启验收放在没有任务执行、没有未保存编辑时：执行 `npm run trial:stop:live`，再执行 `npm run trial:start:live`，按输出地址重新进入。已启用计划或排队任务会按正常规则续作；页面刷新与服务重启是不同的验收项。

记录模板：步骤／通过或失败／实际现象／预期结果／页面地址／任务或资料标识／截图。遇到卡点，停在该步给出这些信息；不需要先把所有管理模块点完。

这轮主流程不包含企业外部系统连接、批量扫描、任意脚本执行、持续主动计划或AI自进化效果。后续按主流程反馈再逐项增加验收范围。

## 本机配置及连接检查

在本机交互终端执行：

```bash
npm run model:configure
```

依次输入空间 ID、模型快照和 API Key。模型回车默认 `qwen3.7-plus-2026-05-26`；Key 隐藏输入，不进入命令历史、会话或网页。配置保存在本工作树 `.local/model-private/bailian.json`，目录 0700、文件 0600，已由 `.local` Git 排除规则覆盖。配置器不发云端请求；修改 Key 或模型后重复此命令，再重启服务。

```bash
npm run model:check:local
npm run model:smoke
```

`check:local` 只检查本地配置，输出 `liveVerified:false`。`smoke` 明确执行一次不含业务数据的短请求，最多 64 输出 token，不自动重试；`liveVerified:true` 才表示这一次真实请求成功，报告只包含状态、模型、耗时、用量和请求数，不含回复正文或 Key。缺少配置会直接失败，不启用模拟回答。需要验证工具回放时可显式执行 `npm run model:smoke -- --tools`，最多两次模型请求。

smoke 是独立连接诊断，不写入业务任务计量表；供应商费用仍实际发生，应以百炼账单为准。正式任务沿既有平台请求登记和用量回执执行；缺失用量保持未知。目前的次数/token/时限约束不是人民币累计预算封顶。

## 启动与保留数据

当前机器本轮已构建。新检出或后续代码变动时，先按[三端指南](本地三端试用指南.md)安装依赖/解析器，再执行 `npm run trial:build`。然后：

```bash
npm run trial:start:live
```

保留该终端，访问它输出的本机地址。另一个终端：

```bash
npm run trial:status:live
npm run trial:stop:live
```

独立实例目录为 `.local/selfuse-live`。正常停止、重启保留账号、企业、资料、会话与任务记录；账号位置为该目录 `accounts.json`，首次只生成平台管理员。没有默认企业或演示业务数据。邀请仍只写入本机文件，不发邮件。旧普通试用继续用 `trial:start`，默认模型关闭。

启动前校验私有文件归属、模型配置、引擎身份/版本/协议及实际 `agent-live` 模式；Key 只注入引擎及短时连接检查进程，API/Web 不获得 Key。配置和引擎启动预检不发送模型探测请求；API 启动后，既有已授权排队任务与启用计划按正常规则继续执行，可能在 ready 前调用模型。`ready` 不证明供应商鉴权成功。旧 off 目录不能直接用 live 启动，以免已有合成计划转为付费任务。新 live 环境中，后续由用户启用的持续计划按其正常调度规则运行。

## 备份与恢复

备份、核验、隔离恢复和显式开放仍使用[三端指南的当前恢复流程](本地三端试用指南.md#m7-a1-本地备份与新目录还原)，原实例参数换为 `.local/selfuse-live`。模型私有配置在实例外，不收进实例备份。

恢复不会自动重启模型或旧任务/计划。完成 `reconcile`、`activate` 且保持原实例停止后，要让恢复目录重新接模型，显式执行一次：

```bash
python3 scripts/local/trial.py start --live --reconnect-live --directory .local/restored/<恢复实例>
```

此入口再次核验已签名的开放凭证，不能跳过隔离恢复；不修改旧任务或计划状态。接入成功后，该目录记录 live 模式，后续用同一 `--directory` 和 `--live` 启动即可，不再需要 `--reconnect-live`。不要手动编辑实例配置绕过检查。
