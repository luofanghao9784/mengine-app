## 恢复证据

- 对比 **31 张非会话表**的行数和完整内容摘要；外部 **7 个原件**的大小/SHA-256 一致；bytea 产物和 Word/PDF 导出缓存也包含在逐表验证中。
- 对比 **17 组 API 快照**，覆盖企业/空间上下文、会话及固定引用、私人文稿/历史版本、共享发布、资料解析与共享动态；**10 次下载**逐字节一致，包括历史原件、独立共享副本、私有产物、Word 和 PDF。
- 原实例包含两个企业、同一账号跨企业成员及明确空间权限；恢复后平台管理员不能读客户文稿，企业管理员不能读成员私人文稿，跨企业替换 ID 被拒绝。原账号以原密码重新登录，成员关系/维护权限保留。
- 用原有效会话 Cookie（连 Cookie 名也改成恢复实例实际使用的名称）访问新环境，得到 401；确认没有复制会话数据。1 份待接受邀请变为 REVOKED，原 token 返回 409 `INVITATION_UNAVAILABLE`；已接受成员不受影响。
- 恢复后文稿 v2 正确显示，保存 v3 成功，同请求重复提交仍是 v3；管理员可生成新邀请。这同时覆盖恢复后自增序列、审计和写入幂等继续工作。
- 工具在运行中的实例上拒绝备份，原接口继续可用；拒绝还原到已存在的源目录，源配置不覆盖；使用后原备份仍可校验。新数据库密码不同于原密码，恢复账号说明没有原明文密码。

文稿与产物的 AGENT 上游是明确标记 `verification` 的合成 SQL 夹具，只在新建的一次性试用根目录、回环地址和固定测试数据库身份下写入；真实文稿保存/导出/共享走公开业务 API。没有调用模型，也不把该夹具作为模型工作成果的验证。M3 本地解析、SOURCE_LOOKUP 会话则是真实执行。

边界单测覆盖：清单/文件篡改、错误密钥、缺失/额外文件、符号链接、非法路径/大小/权限、现存或嵌套目标、迁移不匹配、运行锁、排队任务、其他工作树来源、复制期间变化、还原失败无可启动配置、停止失败保留可能运行的数据库。测试不会删除原试用或其他项目目录。

截图和合成结果位于工作树 `.local/m7-a1/restored-document.png`、`backup-result.json` 与 `result.json`，不提交运行输出。还原后的中文文稿页面已目视检查；既有三端桌面/390px 视口流程随演练通过，不等于手机真机验收。

首轮演练发现验证夹具把 `displayName` 随登录请求发送，被既有严格字段校验拒绝；第二轮将失效邀请错误期望为 400，实际现有契约为 409。修正夹具字段和契约断言后通过，没有放宽业务 API。单独 TS 检查按本仓库 TypeScript 7 使用 `--ignoreConfig --types node`，没有更换类型系统或运行依赖。
