## 调查与实现决定

同事版的学习文章直接按来源读权限展示，并按维护资格校订/下架。当前产品区分读取资料、执行任务和发布共享成果。本批保留其“单份资料生成文章、保留原文依据、来源变更失效”的做法，先接当前私人任务草稿，不自动扩大共享范围。此为本次已授权合并内的分批实现决定，不把未实现的共享文章标记完成。

- 从 Wiki 资料阅读点击“生成学习草稿”，创建现有个人空间中的 AGENT 会话任务；正常任务队列、停止/重试、企业用量、模型配置与执行记录继续沿现有系统。当前客户端会话中也能找到该任务，尚未另建后台学习任务分类。
- 只允许本人当前可读的共享资料；可独立授权单文件，不要求读取其父空间。不使用管理员兜底读权限。执行资格继续由既有任务系统检查。
- 固定版本 ID、解析 generation 与 run ID，仅输入按序前 10 个解析片段，合计最多 6,000 个 Java/JS 字符；不足全文件时页面和提示均明确覆盖限制。PARTIAL 解析不假装完整。
- 在现有 AgentTasks 中新增受限学习分支，复用实际 Harness、已部署 ModelPort 和模型用量记录；一轮模型调用，没有工具、网页、历史会话、个人偏好或经验上下文。正常会话分支保持原协议。
- 服务端 task check 返回 Wiki 来源时不返回偏好/通用上下文；执行登记只接受空工具集。旧引擎不能用普通工具执行该学习任务，需 API 与引擎一并升级，失败时不产生有效草稿。
- 结果严格校验 title≤80、intro≤250、content≤1500、1—4 条 quote；每条依据 6—200 字，必须逐字出现在对应已输入片段。引擎和服务端双重校验，不将结构有效等同于事实正确。
- 发起前、执行检查、完成、阅读均重新校验来源。上传新版本或重新解析后 Wiki 草稿标记来源变化并隐藏旧文章；撤权/清理按现有任务及文件机制阻断。旧私人任务保留的历史回执仍遵守现有任务规则，不伪装被新版本覆盖。
- 请求键幂等；同一人同一资料已有等待/运行/暂停/结果待核对任务时，不再创建第二个任务。页面不自动重试模型请求，明确重试仍用原请求键。
- V116 只存来源/任务引用，无来源正文或文章副本。文章内容仍在既有 conversation_tasks/attempts 管理，沿既有保留、回收和清理；当前列表和详情只允许发起人读取，管理员和其他来源读者不会获得他人草稿。

## 接口与代码

新增 `/api/v1/tenants/{tenant}/wiki-learning`：

| 方法/路径 | 行为 |
| --- | --- |
| GET 根路径，offset | 本人获权任务草稿列表，20 条分页 |
| GET /{id} | 本人草稿及经过校验的文章；来源变化时 article=null |
| POST /sources/{material} | requestId、versionId、generation；固定来源创建任务或返回幂等结果 |

读取响应 private/no-store、nosniff；写入沿现有登录和 CSRF。内部 check 可返回 wikiLearning，执行 open 的空工具集仅 Wiki 任务允许，普通任务不能借此绕过原登记规则。HTTP/引擎不增加凭据或第二套调度。
