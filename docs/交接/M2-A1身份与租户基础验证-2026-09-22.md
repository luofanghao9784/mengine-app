# M2-A1 身份与租户基础验证

日期：2026-09-22。依据：[任务书](../技术/开发任务书-V0.1.md)、[三端权限](../技术/三端架构与管理权限-V0.1.md)、[DEC-048](../技术/开发决策记录.md#dec-048m2-a1-身份与租户基础实现2026-09-22)。状态：已实现、本地合成验证通过，待审查；未部署、未用户验收。

## 本批结果

- Spring Boot 平台接入 PostgreSQL 与 Flyway：账号、企业、企业成员、平台角色、空间归属、邀请、会话、请求幂等与审计持久化。
- 受控 CLI 建立首位平台管理员；邮箱密码登录、当前身份、企业上下文、退出；默认安全 Cookie 与 CSRF，登录后轮换会话。
- 平台开通企业并生成初始管理员邀请，企业管理员邀请普通成员；接受、过期、撤销、同键重试、并发接受都有真实数据库验证。
- 平台和企业权限分别检查，不通过管理角色读取客户内容或其他员工个人空间。已有账号加入另一企业须登录本人，邀请不能重置原密码。
- 邀请仅写本机私有目录用于合成验证，不发送邮件、响应不包含令牌。原件/资料库、会话/画报页面和真实 AI 未接入。

## 实际验证

环境：macOS、Java 21.0.11、Node 24.20.0、PostgreSQL 18.6；专用临时数据库自动创建/清理，未连接其他项目数据库。

身份测试使用两个合成企业及平台管理员、企业管理员、普通成员，具体覆盖：

- 未登录、缺少/旧 CSRF、错密码拒绝；登录会话 ID 轮换，退出、超时和全局账号停用后拒绝旧会话。
- 平台身份不能读取企业上下文；A 管理员不能调用 B 管理接口；普通成员不能管理邀请；总台没有内容接口。
- 管理员与成员只看到各自个人空间；跨企业空间组合外键拒绝；不能通过请求额外 role 字段提权。
- 同 requestId 重试不重复建企业/邀请，改变内容拒绝；并发接受仅一个成功、只建一个账号和个人空间。
- 邀请过期、撤销、跨企业撤销、已有账号本人校验；投递失败时企业及邀请回滚。
- 企业成员/企业状态和平台角色变更对已有会话的新请求立即生效。状态变更使用测试 SQL，**不代表停用管理 API/页面已交付**。
- 登录尝试限流持久化，密码以摘要存储；基础审计无邮箱正文、密码或令牌。

## 接续与限制

1. M2-B1 接入[身份契约](../../contracts/public-api/identity.openapi.json)，建立共用登录态、两管理端入口及基础布局，继续沿当前客户端样式。客户端 Demo 目前仍可单独运行。
2. M2-B2/B3 补齐停用操作、成员/共享空间管理、实际管理页面及相应审计；M2-B4 才是供用户体验的三端邀请登录全流程。本批只验证 HTTP 服务流程。
3. 真实邮件、密码恢复、平台账号运维、MFA、生产代理/会话策略及部署没有在本批验收；生产邀请默认关闭，不将本地文件投递当成可靠邮件服务。
4. 当前查询在服务层按企业与空间过滤，数据库组合外键保证归属；无 RLS。平台不持有客户内容接口不等于基础设施运维无法访问数据库，部署仍需单独管理运维权限。
5. 本批基于 M1-A1 的待审查 Draft PR #1（基线 `58e12ee`），独立分支 `codex/platform/M2-A1-identity`。没有把前项标作已合并；远端 CI 未启用，结果均为本地执行。两项都需按现有 Git 规则审查后集成。
