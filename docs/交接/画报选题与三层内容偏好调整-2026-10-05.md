# 画报选题与三层内容偏好调整

用户于 2026-10-05 授权执行统一入口方案。沿用现有文字规则、权限和版本记录，不恢复下拉配置，不改写旧画报。

## 已实现

- 总台引擎管理、企业信息、个人档案三个入口统一为内容表达、画报选题、规则记录。表达仍区分通用与画报，选题使用独立 `TOPICS` 目标；记录保留历史修订与撤回。
- 页面读取本层可编辑规则和获权继承规则，展示来源、目标、版本。企业页不带个人规则；个人页按当前企业隔离；支持会话不得冒用私人规则。空规则继承其他层，空白状态不插入演示偏好。
- V91 扩展总台规则目标并新增 `briefing_topic_selections`。规则沿已有任务快照冻结；旧 ALL/BRIEFING 与旧任务快照继续可读。选题提案随任务删除，保存任务内一至三个候选、所选索引和策略版本，重复保存同一内容幂等，改换内容冲突。
- 独立运行模块 `briefing-topic-strategy.ts` 提供默认策略、阶段控制和 `select_briefing_topic` 工具。候选明确问题、证据需求、计算需求、新增价值和预期类型；先记录选择再计算或交付。提案不等于事实、计算成功或权限授权。重试读取已记录提案。
- 第三次数据查找后停止继续读取，但仍可计算。需计算的已选主题进入受控计算；计算成功后仅交付；失败不强制重复计算，保留报告证据缺口的路径。不以类型配额凑卡。
- 来源、资料授权、计量、计算回执和私有交付验证仍由原服务执行。文字偏好不能改变业务数值、发布资格、协议或权限。明确临时要求不自动保存为长期偏好。

## 实现决定

这是首版内部选题策略，候选由真实模型在获权上下文内提出，平台校验协议并保存提案；不是已验证的自动业务价值评分器。近期卡片沿既有任务上下文参与选题；原有重复交付校验继续执行，不能声称已经建立可靠的语义去重算法。业务约束继续由既有业务服务执行，不把企业自由文本偏好升级为硬性业务规则。

默认策略不依赖新增偏好：未录入 TOPICS 时也能执行。资讯仍依赖实际资讯来源，成果仍依赖真实完成成果，选题偏好不能制造这些能力。

- 54803 实例更新至 V91，API 健康和工作空间访问均为 200；实际企业支持页面已显示选题标签与录入入口。真实截图及恢复快照保存在 `.local/topic-strategy-20261005/`，数据库备份仅本地私有保存。
- 首次真实验证：选题记录成功，模型随后反复请求已关闭的读取工具，达到 TASK_LIMIT。据此增加选题结果驱动的下一步工具约束，避免仅靠提示说明控制阶段。后续真实验收结果见下方补充。

运行更新只替换本切片 API 类、迁移和引擎模块；运行源码的 Harness 与旧 task-context 存在异常类型差异，保留表达纠错提示并作兼容处理。安装不等于用户人工验收。

## 最终真实验收补充

第三次真实验收成功，批次状态 SUCCEEDED，执行回执依次为三次 task_context、select_briefing_topic、compare_dataset、deliver_briefing，全部成功。实际页面新增一张“数据”类型卡片；选题提案、全量计算与交付分别有真实记录。两次前序失败保留：第一次未形成有效计算，第二次计算请求被拒绝并达到执行上限；随后将计算接口错误反馈限制为允许的静态错误代码，避免错误正文或业务数据进入提示与诊断。229 项引擎测试包含该反馈的隐私边界验证。
