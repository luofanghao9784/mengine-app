## 启动与停止

在主目录 `/Users/dim/AI Coding/企业AI工作空间` 的最新 `main` 执行，目录归属见[统一版本记录](开发目录整合与统一版本-2026-09-24.md)。需要 Node.js 24.20.0、JDK 21、Python 3、PostgreSQL 18 命令行工具，已在 macOS 验证。可通过 `POSTGRES_BIN` 指定 PostgreSQL 二进制目录。

```bash
npm ci
npm ci --prefix engine
npm run setup:parser  # 本地解析另需 Poppler 与 Tesseract
npm run trial:build
npm run trial:start
```

启动后保留该终端，按输出的本机地址访问。端口首次随机分配，后续沿用；不要把旧 Demo 的 5173 当作此试用地址。另一个终端可运行：

```bash
npm run trial:status
npm run trial:stop
```

停止保留账号、企业、邀请、共享空间授权、资料目录/原件/版本和服务端会话；登录会话仍遵守 30 分钟不活动过期，私人对话记录不会因此删除。再次运行 `trial:start` 即可继续。代码更新后先停止，重新执行 `trial:build`，再启动；运行中的服务不会自动采用源码变动。

本机服务只监听 `127.0.0.1`，不用于手机通过局域网访问或公网分享。启动器不支持 Windows 主机；网页窄屏已验证，多系统/手机真机验收另行进行。无需手动启动梦核引擎，启动器会管理本任务的独立本地引擎进程。

## 从空环境体验完整流程

1. 用 `platform` 账号进入总台，开通一个合成企业，填写初始管理员的测试邮箱，例如 `admin@trial.example.test`。
2. 邀请仅投递到本机私有文件。运行 `npm run trial:invitations` 按邮箱找邀请 ID，再运行 `npm run trial:invitation -- <邀请ID>` 定位文件，用编辑器打开并复制其中 `token`。记录列表不代表邀请仍有效，以管理页面和服务端接受结果为准。
3. 用独立浏览器会话进入企业管理端，选择“我有邀请码”，粘贴令牌，设置姓名和密码完成激活，再用受邀邮箱登录。
4. 在企业管理端邀请普通成员；按相同方式获取邀请，在另一独立浏览器会话的客户端激活并登录。若受邀邮箱已有账号，先登录该账号，再接受邀请；不会重置已有密码。
5. 管理员创建共享空间并添加该成员，新增和既有成员默认只读。管理员在授权名单中选择“允许维护”，成员才可在该共享空间新建文件夹、上传资料或更新版本。“设为只读”保留下载；撤销访问后切回客户端或刷新，共享空间消失，旧下载地址也失效。企业管理员的管理身份不自动带来自己的共享空间读取权。
6. 再开通另一企业，邀请同一成员加入。成员可切换企业，但不能跨企业调用管理接口。停用某企业或其中一个成员身份不会删除其在另一企业的身份。
7. 停止并重新启动服务，检查企业、成员、授权和管理记录保留。退出再登录仍以数据库实际状态为准。

服务端支持的密码长度为 15–128 字符。当前不提供管理员任命、自授权、密码重置或真实邮件投递；这不是完整上线环境。

## 资料库操作

- 个人资料由本人维护；企业资料页汇总本人有权查看的共享空间，排除全部个人空间。企业汇总中上传时需选择具体共享空间。
- 进入目录可新建子文件夹、上传原件；搜索按名称查找当前空间内的资料，并展示所在路径。当前不提供目录/文件移动、删除或重命名。
- 点击资料查看版本，选择“上传新版本”保留同一资料 ID 和全部历史版本。直接在列表上传同名文件会新建独立资料。并发版本过期会明确报错，不覆盖他人的更新。
- 上传结果因网络中断无法确认时，保持弹窗并选择重试；系统复用同一次请求，避免重复创建。
- 默认单文件上限 20 MiB；已配置本地解析器时可处理当前默认支持格式、扫描件 OCR、表格和关键词检索，失败或不支持时明确显示状态。WeKnora 实机和真实模型理解仍未启用。下载始终按当前权限校验，没有可公开分享的原件链接。

## 权限变化体验

使用管理员身份将成员“设为只读”，再切回成员页面：页面重新聚焦后会复核权限，已经打开的上传/新建目录/新版本窗口会退出编辑状态，只读成员仍可下载。撤销访问、停用成员或企业后，旧下载地址会被服务端拒绝。收到拒绝后详情不再保留旧文件名/版本列表；已确认不可用的页面不会继续保存迟到的下载响应。

页面没有后台推送撤权通知，持续停留时不承诺自动即时清空；每次后端请求仍重新授权。已经下载的文件不能从设备端撤回。恢复企业不改变成员自身的停用状态，恢复成员不恢复已撤销的空间授权。重新添加空间成员仍默认只读。

## 数据与常见问题

- `.local/trial`：仅本机可访问的配置、账号、数据库、私有原件、邀请和日志；已从 Git 排除，不放入 Demo 转发包。保留该工作树才能继续使用；未安排跨版本数据库回退或用户数据迁移。
- 端口冲突：启动会拒绝，不会关闭占用程序。先停止自己的占用程序，或用 `npm run trial:start -- --directory <新的空目录>` 创建另一个环境；其后 `status`、`stop`、`invitations` 也需携带同一目录参数。
- 重复启动：先查看 `trial:status`，原终端或 `trial:stop` 可正常停止。不要按端口批量杀进程。
- 启动失败：检查构建产物、依赖和 `.local/trial/service.log` / `postgres.log`；不要把私有配置或整份日志随意粘贴外发。正常停止已验证；强制杀死监督进程造成的遗留服务需要开发者定位，启动器不会接管未知进程。
- 页面连接失败：确认 `trial:status` 为 ready；点击重试。状态未确认时不会使用旧身份或回退到 Demo 数据。

实现与验证范围见[M2-D1 撤权记录](M2-D1撤权与停用验证-2026-09-23.md)、[M2-C1 资料记录](M2-C1资料真实接入与验证-2026-09-22.md)和[M2-B4 联调记录](M2-B4三端联调与验证-2026-09-22.md)，后续任务见[开发任务书](../技术/开发任务书-V0.1.md)。

## M7-A1 本地备份与新目录还原

在包含 M7-A1 的工作树运行。先完成/取消排队及运行任务，正常停止试用；命令不会停止运行中的其他服务。路径应选当前工作树外部或 `.local` 下独立私有子目录；以下名称只用一次，再备份/还原换新名字，不覆盖既有目录。

```bash
npm run trial:stop
npm run trial:backup -- --output .local/backups/selfuse-20260924
npm run trial:backup:verify -- --bundle .local/backups/selfuse-20260924
npm run trial:restore -- --bundle .local/backups/selfuse-20260924 --output .local/restored/selfuse-20260924
npm run trial:start -- --directory .local/restored/selfuse-20260924
```

默认原实例为 `.local/trial`；其他实例给备份命令增加 `--directory 原实例路径`。父目录不存在时自动建立为 0700；父目录已存在但权限开放时拒绝，不擅自修改权限。默认密钥位于 `.local/backup-private/signing.json`，不会随备份复制；三条备份/校验/还原命令均支持 `--key-file 私有密钥路径`。需要保存并分开保护备份包和此密钥，丢失密钥不能恢复；密钥校验不等于文件加密。不要将两者提交 Git 或当作普通附件分享。

恢复只写新目录、生成新数据库密码和端口，原环境保持原位。原账号用备份时密码重新登录，旧会话失效，未接受邀请作废，可由管理员重新生成；已接受成员和空间授权保留。新目录 `accounts.json` 只有提示，不包含原密码；恢复结果记录在 `restore.json`。没有复制邀请投递文件、浏览器未保存草稿、日志、第三方配置或密钥。

切换代码/机器时需先准备对应迁移版本、依赖及构建产物；首批只支持 PostgreSQL 18、当前 V14 的本地实例，迁移摘要不匹配会拒绝。不要把目标指定到原目录，即使目录为空也不会覆盖。启动失败可检查该新目录的 `service.log`；若报告临时数据库停止失败，应先排障，不能删除 PID 文件或数据库目录强行重试。

独立演练命令：`npm run test:trial-safety`、`npm run test:backup`（先安装 Chromium、运行 `npm run setup:parser` 和 `npm run trial:build`）。演练创建并清理自己的两企业数据，不接触既有 `.local/trial`。范围与证据见[技术边界](../技术/M7-A1本地备份与还原边界.md)和[还原验证](M7-A1本地备份与还原验证-2026-09-24.md)。
