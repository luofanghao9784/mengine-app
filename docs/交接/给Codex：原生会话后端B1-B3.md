# 给 Codex：DH 原生会话后端 B1–B3（#120）

> 用户转交。先读本文件提到的文档，按仓库协作规范执行（`docs/协作/协同规范.md`）。

## 背景

#120 的前端整合由 Claude 负责，后端与引擎由你负责。前端第一批（会话页内的对话流、工具过程、审批 / 提问卡、成果文件、状态栏、输入框）已在 PR #139 完成，但只能用合成事件预览，真实会话还要跳到官方 DH 窗口。你的任务是提供让这套界面接通真实数据的后端能力。

必读：
- `docs/技术/DH原生会话前端对齐清单.md`：第一节已确认的决定、第二节 B1–B8、附录 A（事件约定）、附录 B（前端已按此实现的调用约定）
- `docs/技术/DH-0.2.1-原生会话迁移.md`：末节“可复用接口核实”
- 前端解析与调用：`src/native-conversation/chat/`（`events.ts`、`transcript.ts`、`useNativeFeed.ts`、`NativeChat.tsx`）

## 本次范围：B1、B2、B3

1. **B1 会话事件转发**：员工在梦擎页面打开原生会话时，平台把该会话的 DH `SessionEvent` 原样（`{type, seq, time, data}`）推给前端；支持带最后收到的 `seq` 断线续传和历史冷读取；只转发该员工本人、当前授权仍有效的会话。平台只做鉴权、按会话过滤与去除内部字段，不改写语义。如何从运行时取得事件（官方 Web 运行时的会话接口，或改用 SDK 协议 `dsh-sdk-protocol` 驱动），由你评估决定，并在迁移文档中写明理由。
2. **B2 上行操作**：发送消息（可带员工有权读取的资料版本）、停止当前轮、回答 AI 提问（`ask_user_question` 的答案）、审批同意 / 拒绝、回复评价。全部经平台按员工身份与会话授权核对后转给运行时；写操作带 `requestId` 重试去重。
3. **B3 运行状态与预算**：运行 / 空闲，以及本任务已用费用、软阈值、硬上限、已用时长；数据来自桥接容器的预算台账（平台可读的汇报通道），不能用计时器或模型自述。

接口形状请以附录 B 为起点；需要调整就直接改清单附录 B 与契约，并在 PR 里写明，前端随之修改。

## 必须守住

- 引擎与运行时不直连数据库；企业身份、权限、预算、发布始终由平台决定，每次请求重新核对（现有 `check` 机制）。
- 不破坏现有能力：官方 DH 独立窗口、`/native-conversations` 独立入口、停止 / 继续、私人成果与员工确认发布、旧会话接续都要继续可用。
- 默认关闭：部署未配置原生运行环境时，行为与现在一致。
- 不改 `src/native-conversation/` 的界面（Claude 负责）；只在 `contracts/public-api/native-conversations.ts` 与 OpenAPI 中补契约。
- 需要数据库迁移时，先在 #120 登记版本号（当前 main 已到 V175）。
- 不操作生产、不部署。

1. 等 PR #139 合并后，从最新 main 开分支 `feat/dh-native-relay`；沿用 #120，在 #120 下留言登记本次范围与分支。
