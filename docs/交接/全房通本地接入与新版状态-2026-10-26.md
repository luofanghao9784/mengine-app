# 全房通本地接入与新版状态 · 2026-10-26

用户明确要求将独立采集端的数据接入本地梦擎“美租集团”，并以其截图中的新版数据基座为准。维护者 luofanghao9784，Codex 执行；显示修复认领 [Issue #103](https://github.com/dimmm1125-coder/dreamcore-workspace/issues/103)。未操作生产环境。

## 实际接入

- 连接器独立于本仓库，位于桌面 `meizu-data-collector`，代码和源端调度均在该项目维护。梦擎只读已校验快照。
- 核实本地已激活的美租企业及现有负责人，创建仅负责人可读的“全房通”共享空间；部署来源连接“全房通”和业务表“财务-流水账”。真实 ID、凭据、备份、私有配置与接收回执不入 Git。
- 首次梦擎采集任务成功，11,684 条/30 列通过现有负责人 API 分页全行读回，与采集端逐值一致。同一身份跨企业访问拒绝，目标空间成员表核实仅负责人一人。
- 源端采集和梦擎快照读取均设为每小时，时区 Asia/Shanghai。连续周期、故障恢复与撤权仍待单独验收；不存在已验证的实时或全菜单接入承诺。
- 新版入口为 `/tenant-admin/#tenant=<实际企业UUID>&place=data`。此前 `admin=database` 是旧版表格入口；两处读取同一原生采集快照。

## 本次显示修复

原生接口此前把所有表的 `source` 固定写成“企业业务数据”，新版页面无法按登记的连接名称分组。现在仅在获权数据集集合中，以同企业连接 ID 查询来源名称并按连接缓存，供新版来源分组显示。表名称保持自身定义，未增加任何成员权限或更改源数据。

原生接口的 `auditValid` 明确为 null，表示尚未提供审计链完整性校验。前端此前把 null 当作 false，错误显示“审计异常”；现在契约允许 null：true 对应正常，false 保留异常提示，null 显示“审计未核验”。没有把未执行检查的状态写为 true。原生操作审计记录与来源行数、主键、分区及接收核对仍按各自依据保存。

首次接入时仅接入与解析完成，页面显示“已采集 · 待治理检查与发布”。旧版表格中的 v1“已完成”对应采集任务完成。用户随后反馈停滞，后续修复及当前状态如下。

## 治理链路接续

排查确认三处断点：企业背景为空，原生治理执行接口返回 `GOVERNANCE_BACKGROUND_REQUIRED`；引擎未实现后端调用的 `/internal/v1/governance-model`；新版原生数据基座只读展示，没有任务操作。不是源端重采失败，也不是模型凭据仍然失效。

- 用户明确授权生成企业背景后，通过企业信息 API 保存四项：美租集团名称、全房通数据接入与租赁业务数据管理、全房通数据来源说明、财务账单汇总的使用边界。未虚构经营规模、地域、币种或核算规则，未改变身份或读取范围。
- 增加仅结构化表、`SYSTEM_MODEL` 的受认证引擎路由。校验冻结输入指纹，仅把字段、数量、空值统计、来源证据和现有背景交给模型，不传原始业务行；单次有界调用，无数据操作工具、无发布权限。
- 同任务同尝试重放共享模型结果；显式重试使用新尝试。传输中断、超时或过期执行租约可能已经产生调用，标记失败并要求显式重试，不自动再次付费执行。
- 原生页面根据真实任务分别显示缺少背景、未开始、处理中、失败、草稿待发布及来源过期。可生成草稿、查看完整字段依据与限制、重试，并由有权限者显式发布；权限及当前来源校验仍由服务端执行。
- 修正结构化发布仍携带已退役知识正文的兼容错误：结构化发布仅保存字段治理包；草稿摘要与限制保留在原任务，不能伪装成知识文章。

本地真实 DeepSeek 最小连接检查成功；随后“财务-流水账”真实模型任务成功返回 `DRAFT_READY`，覆盖 30 个字段。因没有字段级来源定义，30 项均保留 `UNKNOWN`，没有将金额或结算状态猜成事实。随后本地发布回执已确认生效，页面为“治理结果已生效 · 保留待核实项与解析限制”。真实 AI 使用获权工具 `compare_dataset` 汇总出源值“收”4,633 条、“付”7,051 条，合计 11,684 条，与 PostgreSQL 快照独立分组一致；live 执行、工具成功及 4 次模型返回均有回执。背景、快照或权限变化后需重新核对。

本次没有扩展文档/Codex 的原生引擎执行。通用字段证据绑定已接续实现，但全房通导出端已有的分区计数、主键与逐值接收校验尚未作为治理来源约束导入；因此模型不会把这些尚未传入的结果当成已执行的治理检查。

## 多来源结构化数据接续

用户要求流程兼容数据库和其他平台。补充按 datasetId 绑定字段证据，旧表名证据仅在企业内名称唯一时使用；导出字段说明、数据库元数据和 API 定义共用引用校验。三类合成标准表验证不同列名、长整数、高精度小数、时间戳、JSON、布尔和空值的保存与同一治理任务链路。

新增证据范围与通用口径测试后，定向后端共 16 项通过；浏览器另增加 1 项，确认未核验质量显示未知，AI 可用详情明确“合格记录数未核验”。首次真实 AI 回答曾额外推断一行代表一张账单，已补通用记录粒度约束；第二次实际查询复算一致，并更正该无依据推断。协议、限制与后续适配器范围见[结构化数据统一接入与 AI 验收](../技术/结构化数据统一接入与AI验收.md)。
