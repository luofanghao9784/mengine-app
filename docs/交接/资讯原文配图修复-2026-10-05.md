# 资讯原文配图修复

用户反馈新生成资讯仍无配图。本轮沿用现有资讯正文，不再调用模型、不重新生成卡片、不消耗生成额度。

## 根因与修复

- 腾讯原文正文图片使用通用 alt="图片"，旧识别规则错误排除；保留头像、二维码、推广、文件名占位图等过滤，正文内通用描述不再一概排除。
- 每篇最多三张正文候选图，共用五秒图片读取预算。先尝试可用原文图片，跳过宽高比超过 2.2 的机构宣传横幅；保持公开地址/跳转限制、PNG/JPEG、128 KiB 和服务端真实栅格格式/像素校验。
- 当前运行客户端未包含源码已有的 NewsCover 组件。本轮只为当前入口补齐组件及样式，保留会话、导航、生成卡片等其他修改；没有恢复旧版页面。

## 真实验证

目标任务 831f81cc-7c47-4889-be9e-2c73ba91d5d6。原文 https://news.qq.com/rain/a/20260923A09EFH00。

通过产品 PublicReader 的公开 DNS 与代理校验重新读取原文，选中活动现场照片；JPEG 76041 字节，960×639。旧的机构横幅 960×396 被跳过。对本地目标任务的相同原文 URL、企业、成功状态与原来源 JSON 做精确保护后补入 image 字段，并记录 NEWS_COVER_BACKFILLED。旧来源备份保留在本机 .local 中。未修改正文、卡片内容哈希、任务状态或额度。

浏览器验证列表和详情都出现“资讯原文配图”，真实图片加载成功，自然尺寸 960×639；详情注明原文来源。截图保留 .local/news-body-cover-detail.png。

引擎原文采集、候选图片、安全边界与搜索回归 30 项通过。修复后引擎模块同步至既有本地验收实例。未部署生产。

边界：找不到符合条件的原文图片时展示明确的主题插画，不假称现场照片；原图过大、格式不支持或网络失败仍可回退。图片与文字采集独立，图片失败不伪造正文生成失败。
