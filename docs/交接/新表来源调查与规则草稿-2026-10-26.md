# 新表来源调查与规则草稿

本轮实现已登记来源范围内的新表自动调查、生成草稿与逐批核验。梦擎 Issue #131，采集端 Issue #21；分别接续来源定义交付 PR #129/#20。只在本地启用，没有生产操作。

采集端在导入通过结构/数量/范围检查后自动执行调查；梦擎拉取适配器开启 `sourceResearchEnabled` 后也自动补齐草稿。资料来自部署批准的公开静态代码或结构化字典，公开 HTTPS 获取固定地址并校验正文摘要。新表可复用同来源资料目录，无须逐表添加调查任务。仍须先登记允许采集的范围，不自动登录/接入新的系统。

结构化字典必须匹配表名，明确描述才能作为有据解释；支持字符串枚举、必填和精确数值上下界。官方界面代码中的 title/label 与 stateMapper 只作为字段和枚举候选，未证明导出映射的枚举不参与业务合格判定。空值、去重计数属于本批观察，不升级为业务主键或全历史规则。未知业务含义、复杂条件和冲突继续保留缺证原因。

草稿版本与本批核验分开，重放不创建重复草稿；数据改变会重检规则，来源变化会产生新草稿或缺证提示。失败使当前成功指针失效，历史版本仍可追溯。草稿不替换已批准 sourceContract，也不自动发布到梦擎。当前采用确定性解析与检查，无新增模型调用。

## 本地实际验证

六张表均产生独立草稿并通过梦擎部署绑定核验：财务流水账 11,638 条、整租房间 206 条、整租房东 206 条、合租房间 919 条、合租房东 456 条、维修 16,229 条。这是本轮读取到的快照，不承诺数据持续不变。

固定的全房通公开代码中识别到 43 个表内字段映射线索（不同表分别计数）、1 个维修字段的枚举候选；未获取到能完整证明五张新表业务口径的字典。故独立调查草稿为 NEEDS_EVIDENCE，不宣称已经补齐所有业务规则。财务原先已批准的口径、逐批规则和自动分析就绪状态保留，新增草稿中的 UNKNOWN 不会覆盖原已发布解释。

2026-10-26 18:25（北京时间），实际梦擎拉取任务成功，六表交付且批准契约原样保留；财务详情仍为 11,638 条可查询、检查通过、自动分析就绪。其余新表缺证仍可阻止相应自动分析，本轮没有将 WAITING_DATA 改成伪成功。

本地安装使用独立的私有版本目录，未覆盖另一采集会话的开发源码和浏览器导出脚本。后续现有梦擎拉取会重复执行调查，未另设定时器；采集管理页新增入口需要运行新采集端代码，本轮没有重启另一会话运行的采集服务。

## 检查与接续

梦擎只读核验命令重新计算包摘要，检查当前快照、字段、范围、草稿正文和规则回执对应关系，拒绝错配、陈旧快照及草稿自称批准：

```sh
source .local/env.sh
python3 scripts/data-foundation/verify-source-rule-drafts.py --binding /绝对路径/私有绑定.json
python3 scripts/data-foundation/test_source_rule_drafts.py
```

命令核验的是身份和快照对应关系，不替代完整业务批准。新增字典和来源版本按部署策略登记后，后续采集自动重建草稿、逐批复核；确证后仍走现有来源定义批准/发布边界。原财务规则不需要重新确认。

回退：将本轮私有备份中的 `binding.json.before` 和 `collect.before` 恢复到原绑定与包装脚本（包装脚本权限 700）；保留草稿目录作追溯，恢复原拉取适配器即可。本轮没有数据库迁移。不要删除原批准契约或治理证据。

本轮验证记录：采集端 54 项 Python 测试通过（其中 13 项直接覆盖来源调查，另有适配器和 HTTP 接口测试），梦擎只读绑定核验 4 项测试通过；合成浏览器验证了缺证提示、认证下载和草稿未批准状态；`npm run build` 通过。真实公开来源文档的 HTTPS 获取与摘要比对、已安装适配器六表输出和现有契约不变检查通过。未重新跑无关后端测试，没有宣称真实模型、完整业务批准或生产验收。
