## 本轮修正

1. 首轮六页稿把月度客户数 40、45、52 相加称为客户总数 137，资料并无跨月去重依据。补充统计口径规则：客户等去重指标不能直接跨期相加；演练标识、事实、推导和建议分开。
2. 八页稿的渲染/上传工具成功，但通用预算收尾将成果任务标为 PARTIAL。确认后的 render_presentation 改为空参数调用，直接使用服务端冻结稿；两份真实上传回执验证后结束本轮并给出系统交付确认，不再依赖模型额外总结。减少重复内容输出，不扩大模型预算。
3. 后续复验发现无依据年份和客单价解释。补充不得猜测年份、客户单位、去重状态和指标定义；演练用例在确认前拦截本资料未提供的年份、137 客户合计和丢失演练标识。此检查仅针对固定验收资料，不能宣称产品已具备通用事实审查器。
4. 新增显式验收入口、单案例重跑、脱敏错误码、模型调用量与 token 回执。保留失败样本；链路通过与内容/排版验收分开记录。

## 复现

```bash
npm run test:ppt:rehearsal
npm run build:engine
python3 scripts/local/ppt_acceptance.py check --config .local/model-private/ppt-cloud.json
python3 scripts/local/ppt_acceptance.py live --config .local/model-private/ppt-cloud.json
# 只重跑指定案例
python3 scripts/local/ppt_acceptance.py live --config .local/model-private/ppt-cloud.json --case data-analysis-8
```

`test:ppt:check`、`test:ppt:live` 默认读取项目原有默认配置路径。当前为这次验收单独保存的配置，应传上面的 `--config`，不代表默认配置已经设置。输出在 `.local/ppt-acceptance/<run-id>/`；原始 report.json 的 qualityAccepted 始终为 false，防止自动测试代替人工质量判断。
