# 数据基座与治理可靠性加固（2026-10-14）

本轮依据：用户要求上线前重点打磨数据基座、数据治理，前端不新增功能，保留现有企业数据和基本业务流程。修改限于 Wiki 后端及对应测试；运行副本与主项目 `integrations/mengine-wiki` 已同步。

## 已实现的规则

| 环节 | 改动及实际作用 |
| --- | --- |
| 源库读取 | PostgreSQL 显式使用 REPEATABLE READ READ ONLY；MySQL 显式使用 REPEATABLE READ 与一致性快照，只接受 InnoDB 接入库。SQLite 保持只读事务。保证单次读取的数据视图，不承诺不同任务、不同表在同一时间发布。 |
| 日期保真 | PostgreSQL DATE 使用连接级文本解析，避免转换成带时区时间戳后日期偏移或被误隔离；不改全局驱动解析器。 |
| 扫描期间撤权/停用 | 外部读取完成后重新校验连接授权与配置版本，拒绝覆盖已改变的配置；扫描结果和审计同事务提交。 |
| 数据时效准入 | 沿用已有“两个同步周期”的治理阈值，接到模型数据查询、数据发现、业务知识生成/读取、对话依赖校验及总台导出。超过阈值、同步停用、连接停用、结构不匹配时，拒绝新使用；历史原始记录不删除。 |
| 无变化同步 | 沿用成功检查更新 lastSuccess、内容不变不增加数据版本的机制。时效校验读取同步回执，不把每次检查时间混入字典指纹，避免无效重学。 |
| 历史导入 | 无同步任务的数据作为历史输入兼容保留；模型查询增加 sourceFreshness，区分 historical/scheduled/stale/blocked。historical 不等于“已经证明最新”。 |
| 人工校验 | 记录服务端检查依据，覆盖源数据、关联表、实际业务字典；同步类问题还覆盖同步任务状态。审批时依据变化返回 409，已批准依据变化后重新打开；人工批准不改变行质量、不伪造同步成功。 |
| 资料检查 | 处理失败或未完成不能因为没有检查结果就自动“复检通过”；旧人工确认在资料状态变化后失效；未处理完成的资料不能提交人工确认。 |
| 处理留痕 | 结构化问题“开始处理”与审计同事务提交，按企业定位更新。 |

时效规则是容许最多两个同步周期的有界滞后，不是实时一致。一次同步失败但上次成功仍在时效范围内时仍可使用；超过时效后阻断。配置范围沿用 5–1440 分钟。业务需要更短延迟时必须另行提供更短周期或 CDC 能力，不能仅通过提示词承诺。

总台导出撤下不可用输入后，由既有总台接入工作循环传播；已输出文件或总台缓存不是通过本轮代码瞬间撤回。端到端任务发布仍需总台侧统一版本与时效校验，不能把本轮源侧保护当作跨系统强一致发布。

## 当前交付边界和上线必办项

1. 本地 15 张表均没有持续同步任务：12 张为历史导入，3 张为数据库手动拉取。需要按企业核实真实来源、同步频率与允许滞后，再接通持续同步；当前不能声称这些表随业务库实时更新。
2. 当前全量拉取上限仍为每表 1 万行、30 个字段、20 MB；超限明确失败并保留旧数据，不截断冒充完整。生产数据超限须实现分页/增量与完整性验收，不能仅调大 UI 显示数量。
3. 本轮保障单次源端读取、单库发布事务和使用入口校验；跨表统一发布批次、CDC/删除事件、跨系统缓存撤回及总台任务发布前的统一版本闸门仍未实现。
4. 第二轮已加入共享 SQLite 文件内的持久执行租约与失效写入阻断；跨机高可用、灾备恢复演练、真实源库故障与容量压测尚需独立验收，不应按已支持集群高可用交付。
5. 人工校验接口沿用现有 expectedVersion，不新增前端字段。服务端检测依据的变化会拦截提交，但不同浏览器同时查看不同关联版本的严格审批快照绑定，仍需接口/客户端携带检查令牌后才能完整保证。
6. 全量回归存在已确认的历史失败；清理或重新对齐这些契约并获得完整回归结果后，才能给出正式生产交付结论。


## 第二轮：同步执行保护与核心回归恢复

用户继续优化后，增加 `source_leases` 持久表，按企业及连接/任务分别占用。租约有效期为 120 秒，长于当前取数超时上限；使用原子条件写入竞争所有权。租约到期后可由后续任务接管，旧执行者在读取返回、事务发布和任务回执保存时校验自身凭据。释放只删除自己的 owner，不删除后继任务；失去凭据的任务不再向接替任务写失败事件。此机制用于共享同一 SQLite 文件的执行者，尚未声称支持跨机集群。

配置调整检查持久占用；完成回执保留数据库中的最新启停、周期与执行账号配置，避免旧内存对象覆盖新配置。后台调度跳过其他执行者占用的任务/连接。异常退出遗留的 running 任务在占用到期后进入恢复，不再受未来 nextAt 阻挡；正常任务仍沿用既有同步周期。恢复是重试，并非承诺外部取数只执行一次；发布由版本、事务与租约共同约束。

测试恢复没有重新开放手工建表、记录编辑和人工口径提交接口：增加仅用于隔离测试的合成数据准备函数，使业务口径 11 项、结构化治理 4 项真正执行核心断言。撤权断言验证服务端 404，治理测试显式配置职责范围。原来无限等待模型被调用的并发测试改用获准的管理员，并在请求提前结束时立即失败、始终释放测试闸门；该并发限流测试独立通过。
