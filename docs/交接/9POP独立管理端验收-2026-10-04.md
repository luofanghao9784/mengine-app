# 9POP 独立管理端验收

## 授权与边界

用户调整交付顺序：先准备 9POP 真实流程独立验收环境，原五批目标不变。原 `55167` 不修改；独立端口、数据库、对象目录和固定代码产物。客户双端共享客户身份，总台使用独立身份。后台开发不能热更新验收页面。

外部系统仅读取，不回写、不删除、不通知、不调整生产配置或权限。企业正文、数据明细和会话不因验收向总台开放。真实模型调用等待本次费用范围确认，不把离线检索视为真实生成。

## 只读核查

- 历史 9POP Demo 和经营资料导入为固定快照，不是持续采集器。已检查的本机脚本、服务器部署目录和定时任务目录未发现可直接复用的自动采集程序。
- 现有 SSH 与服务器内部 MySQL 连接可用，只读事务探测成功。凭据仍留在服务器原配置中，未复制或输出。
- 现有数据库账号有较大权限，并非只读账号。验收适配器使用固定白名单 SQL、只读事务、查询超时，不接受页面或模型传入 SQL。此限制不等于数据库账号权限隔离；长期专用只读账号需另行部署授权。
- 首轮范围：近 90 个自然日（含当日截至取数时刻）、按日和门店聚合的已确认收款及其中待财务复核子集。复用原核验 SQL 的收款状态、订单过滤口径；不包括会员、联系方式、凭证和会话。空白日期不人为补零，金额单位为分，待复核不是未收款。
- 原百炼私有配置存在，历史曾获准真实验收；未发现本次独立环境的费用上限，已向用户询问。未调用模型。

## 实现

- `scripts/acceptance/ninepop_collector.py`：部署固定数据身份和列定义，校验企业、连接、数据集、运行 ID 后才连接原服务器。远端凭据不离开服务器；输出仅进入私有进程协议和获权数据集。失败退出，不返回旧快照或预填数据。
- `scripts/local/trial.py --collection-config`：仅接收本人所有的 0600 文件和不可被其他用户改写的绝对可执行文件，继续拒绝继承生产环境设置。
- 验收代码与构建产物将独立复制并记录来源版本及哈希，运行 Vite preview，不使用开发热更新。实例数据与固定代码分开。

3. 实际页面开启每小时取数并保存，服务端存在 nextDue；随后关闭，保留频率供用户自行启用。没有创建或调整画报计划。此轮未等待一个完整小时，不将保存频率宣称为定时触发已自然验收。
4. 独立总台会话读取业务数据集与客户身份均返回 401；总台遥测仅返回固定运行状态字段，通过字段白名单检查。浏览器未发现跨端切换入口或页面脚本错误。
5. 两端截图已在本机私有部署目录核对。原 55167 与新两端均返回 HTTP 200；原实例未停止、迁移或替换。

## 用户验收步骤

1. 本机打开账号文件，用客户账号进入企业端。数据库 → 数据接入 → 9POP 经营数据，核对取数途径、范围与权限。
2. 调整自动取数，选择所需频率并保存。该设置不决定画报生成频率；可按需要保持关闭并手动取数。
3. 点击立即更新，等待任务完成；查看更新记录，首笔失败为真实查询兼容问题的历史记录，已修复。
4. 数据库 → 数据管理，打开近 90 天门店每日收款，核对覆盖时间、版本、单位和统计说明。
5. 新标签页打开客户端，使用同一客户账号；可同时保留企业端。
6. 另开总台，用独立总台账号查看概览、系统运行和企业状态；不应看到收款正文、会员数据或原始会话。
7. 获权会话和画报使用真实数据的模型验证**尚未完成**。待用户确认本次模型调用费用范围，再受控启用已有百炼配置、验证生成与来源依赖。当前不以离线检索冒充真实 AI 生成。
