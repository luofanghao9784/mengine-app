## 审查与修复

原 PR 确认仅新增 `site/` 37 个文件。已阅读 PR 描述、`site/README.md` 与 `site/src/engine/README.md`。原版本构建成功、页面无 JS 错误，但实际合成画报是 5 张，且有两处缺失应答（governance、conversation attachment draft）。更重要的是，同域演示直接启动真实客户端会清理父页面的真实会话草稿；使用合成哨兵复现草稿丢失后，在 demo boot 前隔离浏览器内存存储和通知，并补齐两个 mock。复测父页面草稿保留、4 个首页 iframe 无缺失 mock、无真实 API 或外部请求。

登录只改 `site/src/login/auth.ts` 内的适配和辅助逻辑，`Login.tsx` 保持原样。员工/企业管理员用 `/api/v1/auth/login`，平台使用独立 `/api/platform-admin/v1/auth/login` 和相应 CSRF。响应按现有身份契约校验，固定跳转 `/workspace/`、`/tenant-admin/`、`/platform-admin/`；普通成员无法经前端变成管理员，后端仍执行权限检查。验证码 challenge 仅保留内存、绑定手机号和有效期；邀请只接受本站有效链接/43 位 token，服务器保存 hash 后交给 `/workspace/#invite`，不把 token 放进跳转地址。

当前后端只支持禁用/本地短信测试投递，没有真实短信供应商。界面不假报短信发送，不暴露本地验证码。真正的短信找回密码仍待供应商接入，不属于本轮新增能力。

新增 `tsconfig.integration.json` 并用于 build，将原先排除的 Login/demo 也纳入检查。资源目录改为 `website-assets/`，避开产品 `/assets/`；字体继续自托管。与现有产品同源，不新增 CORS，不扩大 Cookie Domain。
