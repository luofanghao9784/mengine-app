### 演练中发现并修正

1. 私有目录的 umask 把预期 0750 收窄成 0700，API 无法进入工作目录；显式设置仅 root/dreamcore 可访问的目录权限后修复。
2. Docker internal 网络下的端口发布未实际生效，改为宿主直连专用数据库私网地址，并只放行这一地址。未开放整个外网或复用现有数据库。
3. 原配置不识别代理后的 HTTPS，使平台登录 Cookie 缺少 Secure；使用 Tomcat native 转发解析，内部代理匹配限定 `127.0.0.1` / `::1`，Nginx 固定传入 HTTPS 标记。复测成功，不采用信任任意代理或关闭 Cookie 安全设置的做法。
4. 导出/离职归档 worker 配置名按实现改为 `worker-enabled` / `archive-worker-enabled`；应用验证副本允许正常维护，但不影响原库。早期登录检查曾在应用未就绪时失败，只有后续完整成功结果记为通过。
5. 主动停止 Java 时完成 graceful shutdown、退出码 143，systemd 曾将其标为失败；已为本服务补 `SuccessExitStatus=143`，确认 MainPID=0 后清除该已解释的停止状态。不是运行中崩溃。

验证后停止 API 和数据库容器，未启用开机自启，保留发布包、数据和私有 Nginx 配置供接续；临时本机 SSH 隧道已关闭。API 运行时一次采样约 271MiB、数据库约 40.6MiB，仅是空闲验证采样，不是生产峰值。最终复核本机 54803 为 200，9POP health UP、coach/boss HTTPS 200 且 TLS 成功，公网 ai 503，服务器剩余约 22GiB。
