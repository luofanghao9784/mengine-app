# 共用权限查询性能修复与本地验证（2026-10-21）

范围：用户授权修复客户端和企业管理端共用瓶颈，保持权限规则，更新原本地实例。沿 WS-02、WS-03、WS-08、AI-02、AI-11—AI-13、DASH-01—DASH-04；不新增业务规则。

## 原因与更新关系

- 旧 `scene_asset_readable` 把目标匹配和历史版本连续性判断放在同一 OR 中，复杂 JSON 范围函数参与大量无关来源比较。685 个来源的整批检查在有效授权条件下超过 8 秒被取消；关闭 JIT 仍超时。
- 管理端 `BackgroundKnowledgeService` 对 16 条企业背景逐条查询关联方法，反复扫描来源和校验权限；读事务持有既有企业共享锁，拖延需要企业排他锁的同步等操作。采样见管理查询超过 20 秒、另一个请求等待超过 22 秒、8 个连接全部忙碌。
- 关注画报的 3 秒语句上限先触发，前端呈现统一的“请求未完成”。同步积压还使 5 分钟权限租约过期，按原规则临时隐藏相应来源；不能把空列表当作性能恢复证据。
- 背景关联能力可追溯至 `1957e3f3`（10月18日），路由权限函数进入整合提交 `fe8d576d`（10月20日）。`2a5680f3`（10月21日）将实际消费扩展到338条路由，扩大了查询规模。属于更新后暴露/放大的性能回归。尚未逐版本重放，不能断言仅某一提交引入全部问题；原有功能/权限验收未覆盖此次真实元数据规模下的跨端并发性能。

## 实现

1. V159：先按目标 ID 或历史数据集的企业、连接、空间、来源键定位候选，物化候选后再比对 JSON 范围和来源/路由读者。增加活跃链接目标索引、历史来源目标索引。保留非场景资源分支、治理有效期、成员/账号状态、总部代理映射、来源 ACL、路由交集，以及历史版本的未清理、状态、字段/口径一致条件。
2. 背景知识：一次查询所有当前可读背景的显式依赖；每个关联来源校验一次；按背景独立排序并保留21条上限。授权锁、事务和方法版本有效性检查保持原样。无权限缓存、不增加数据库连接、不延长关注接口超时。
3. 本轮未改动此前工作树中推荐接口、前端、模型启动脚本等既有未提交修改。后端打包沿当前工作树，保留那些已存在的后端改动；没有重建前端或启用真实模型。

- 隔离副本：685来源权限查询由超过8000毫秒超时降至38.486毫秒。副本的5分钟租约过期后，仅在隔离库延长租约以复现捕获时的有效授权条件；运行实例未人工改租约，由原同步工作器正常刷新。
- 84项不同后端测试通过（后续受影响类按最终代码重跑）：路由/来源ACL/撤权/历史连续性/跨空间、画报、推荐、背景和迁移。新增V154结果等价比较、201来源2秒查询预算、多个背景独立21条上限与共享依赖撤权测试。
- 实例真实读取：8个账号、2504次资料请求，与部署前权限预期完全一致；1154允许、1350拒绝、0差异，4路并发下单次最大62毫秒。覆盖既有保存的消费来源权限矩阵，非所有未来资源组合。
- 两端共用接口并发：8路、128次读取，0失败。上下文最大8毫秒，关注最大103毫秒，推荐最大252毫秒，背景最大374毫秒。为本机该轮样本，不是吞吐承诺。
- 浏览器：推荐15张已有卡正常呈现；关注显示真实的“还没有关注的卡片”；会话列表、个人资料库（含本人企业上传引用）正常；企业管理的数据基座407项、知识星链360条（含企业背景分组）、企业背景16项、成员列表正常。
- 正常后台同步从故障期间一次约8分钟恢复至约3.15秒，权限租约有效；收尾无超过3秒的活动查询。新服务/数据库日志均0 ERROR、0 statement timeout。
