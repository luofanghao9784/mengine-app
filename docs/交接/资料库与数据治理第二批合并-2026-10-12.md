# 资料库与数据治理第二批合并

日期：2026-10-12。状态：本地实现与合成验证通过，未提交、未部署、未客户验收。

本批承接[知识工作台首批](知识工作台首批合并-2026-10-12.md)和[合并调查](同事企业管理端合并调查-2026-10-12.md)，按用户“继续下一批次”的授权，将同事版的数据治理组织方式接入当前资料库、版本和权限体系。不是整套管理端合并完成。

## 已接入的功能

企业管理端资料库提供“数据治理、解析处理、文件与目录”三个栏目，默认进入数据治理；原文件目录、上传、版本、回收与解析重试继续保留。旧解析页可通过 `admin=materials&section=processing` 进入，文件页继续使用 `section=files`。

治理页面采用同事版的风险指标、优先行动清单、规则筛选、排序分页、评分解释和资料诊断结构，接入真实平台接口：

- 获权资料、需要关注、敏感信息提醒、尚未完整检查四张可下钻指标卡。
- 手机号、身份证号、邮箱、标签、复核日期、内容信息量六项规则检查。
- 标签与复核日期维护、保存并检查、脱敏前确认、真实版本与问题回执。
- 当前规则平均分；没有正文或只有部分解析时不计分，不用零分或满分代替未知。
- 名称搜索、问题类型过滤、风险优先/低分优先/最近检查排序及服务端分页。

“文件与目录”继续复用当前已落地的独立授权、下载控制、版本与移动/删除规则。本批没有为了复刻同事页面丢弃现有文件夹或回收功能，也没有引入同事的独立账号库。

## 权限与业务规则

全部列表、统计和诊断使用当前 `library_mask`；读取要求文件阅读权限，保存检查和脱敏要求当前文件编辑权限及有效业务资格。管理员没有默认正文访问权。个人资料不进入企业治理页；独立文件授权只显示“共享资料”，不泄露无权父空间名称。

原 MaterialProcessingService 仍按空间成员列资料，本批改为逐文件权限过滤，并对父空间名称和维护资格分别判定。防止在新增文件拒绝规则后，旧解析页仍显示被拒绝的文件。

同事版的下列规则没有直接迁入：管理员 read-all、自动隔离、密级提升、自动补“待分类”、处理后自动延长复核日期 90 天。它们涉及权限或业务事实，不能由界面迁移自动引入。本批检查只产生诊断与审计，不修改授权、公开范围或密级；设置复核日期不等于完成业务复核。

沿同事版评分公式：100 分起，每项问题扣 16，最低 20；仅基于本次可检查文本。缺少复核日期也给出提醒，日期按北京时间的日历日判定，读取时重新识别新到期提醒。该公式是可替换的规则评分，不代表业务正确性、身份证校验、专业 DLP 或完整二进制原件安全结论。

## 检查与脱敏依据

TXT、MD、Markdown：对最多 2,000,000 字节的有效 UTF-8 原件检查，明确标注“完整文本原件”。其他类型：使用固定解析运行的文本块，最多 2,000,000 字符；完整解析和部分解析分别标记，不把图片或未提取内容视为已检查。

没有可用正文时只保留标签/日期提醒，不计算内容分数。文件版本、解析运行或对应解析状态变化后，旧报告不作为当前结果。报告保存固定版本和解析依据；同一资料的检查修订号递增。

自动脱敏仅支持上述 UTF-8 文本原件：替换手机号、身份证号和邮箱格式为占位符，通过现有 MaterialService 创建同一文件的新版本，权限和位置保持。原版本仍保留敏感信息，确认界面明确说明，不宣称彻底删除。PDF/DOCX 等原件不能由解析文本替换，须人工修订原件并上传新版本。

请求包含文件版本、检查修订号和 requestId。服务端在权限检查和版本锁内执行，保存真实报告与审计；同一请求重试返回原回执，不重复写文件版本。客户端在提交结果不确定时保留表单和请求编号，阻止关闭/导航，直到重试核对。

## 接口与存储

新增 `V110__material_governance.sql`，保存版本绑定的 `material_governance_reports`。业务接口不提供报告改写或删除，处理记录按修订号追加；报告只保存规则标识、标签、日期与依据，不保存匹配到的敏感正文。

接口位于 `/api/v1/tenants/{tenant}/material-governance`：

| 方法与路径 | 行为 |
| --- | --- |
| GET 根路径 | 当前获权列表、统计、过滤、分页 |
| GET `/{material}` | 重新鉴权并读取当前诊断 |
| POST `/{material}/check` | 按版本维护标签日期并检查，保存回执 |
| POST `/{material}/redact` | 原件文本脱敏为新版本，保存检查与审计 |

服务端：`MaterialGovernanceService`、`MaterialGovernanceController`；契约：`contracts/public-api/material-governance.ts`；前端：`MaterialGovernance.tsx`、`governance-client.ts`、`material-governance.css`。接入 `TenantMaterials.tsx`，修正 `MaterialProcessingService.java` 的权限投影。错误代码使用 `MATERIAL_GOVERNANCE_` 前缀，避免与既有企业职责治理混淆。

最终验证时工作区还出现其他工作新增的 `V111__library_moves_and_audit.sql` 与资料权限/技能中心文件；最终数据库检查运行到 V111，通过结果包含当时工作区状态。这些新增内容不归入本批改动。

当前资料权限的企业级启用开关继续由原模块控制，本批不为真实企业启用。V110 依赖 V109 权限函数；上线和恢复前需一并核验迁移、报告表备份/恢复及现有恢复放行规则。没有将旧数据库重建成同事版 SQLite。
