# 上传表格结构化接入（2026-10-14）

## 对用户的实际变化

前端组件和布局未修改。通过原有资料上传接口上传表格后，后台执行：

原件与版本保存 → 隔离解析 → 独立完整表格校验 → 合格共享表进入结构化数据集 → 引擎按原件权限读取和计算。

原有资料解析和原件下载保留。已结构化的文件在自动画报的数据选择中优先作为数据集，避免同一文件的文本片段与表格重复充当来源。模型数据工具附带文件版本、摘要、上传时间、校验时间和“只代表文件内容”的时效说明。

## 支持与回退规则

| 输入 | 自动处理 |
| --- | --- |
| UTF-8 CSV（含 BOM、引号、多行单元格）、TSV | 首个非空行作表头，完整读取和校验后入表 |
| 单工作表 XLSX | 无公式、错误值、隐藏内容、合并单元格及复杂报表布局时可入表 |
| 多工作表、公式、汇总行、筛选/复杂格式、无法确认精度的 Excel | 保留为资料，记录具体原因 |
| XLS | 保留原资料解析路径，不把缓存值自动作为确定业务数据；建议转换为简单 XLSX/CSV |
| 表头重复或为空、行列不齐、空表、超过限制 | 不发布部分表，保留原件和解析结果 |
| 个人空间、未进入资料库的会话附件 | 不自动转为企业共享数据集 |

单表最多 10,000 条记录、30 列、单元格 2,000 字符、累计单元格 UTF-8 内容 1 MB；结构输出还受 1.5 MB 协议预算约束。超限整体回退，不静默截断。文档片段本身达到既有 500 块限制，不影响独立完整表格结果的校验。

空白整行忽略，其他空值与重复行保留。未获得主键/必填声明时不能把重复行或空值武断判错。类型只在全列一致时识别数值、日期和布尔，其余保留文本。编号、前导零、金额小数原文不转换为浮点数。

## 一致性和权限

1. 同一资料的新版本一旦保存，旧版数据表立即从当前数据读取中排除，不等新表解析成功才停用。
2. 后到的旧解析结果不能重新发布旧版。重解析期间停止旧结果；成功后相同文件版本复用快照，不重复建表。
3. 同一不可变原件若重解析得到不同内容，回退并记录 `FILE_TABLE_REPARSE_CHANGED`，不静默覆盖历史快照。
4. 数据表不仅检查企业与空间权限，还检查原件的资料级权限。已有管理能力不自动授予文件内容读取权。
5. 当前版本、解析批次、资料是否入库、归档/回收状态都参与读取门禁。模型已固定使用的表，在原件变化后也会被来源有效性检查阻断。
6. 导出额外遵守原件下载权限。正式清理原件时，结构化副本及已有数据派生任务进入同一清理链路。
7. 文件没有持续源库同步。上传新文件应使用原资料“上传新版本”；另建资料表示另一份独立来源，不以同名覆盖，也不跨文件猜测主键合并。

## 存储和接口

- `file_table_sources`：原件版本、解析批次、结构化数据集、状态及原因。
- 复用 `business_datasets`、`dataset_snapshots`、`collection_runs`；合格原件形成已完成的文件采集记录。
- 复用原有 `/scene-foundation` 和详情契约合并企业资料来源，文件条目使用 `file-` 前缀防止与 Wiki 资产标识混淆。
- 原件始终在 Java 资料库，不跨授权域复制到 Wiki SQLite。现有 Wiki 数据库数据集继续按原桥接方式工作。
- 没有新增浏览器 API、前端按钮、手工行编辑接口或任意库表写入入口。文件“立即取数”和定时数据库同步不开放，因为文件更新来自上传新版本。
- 此改造没有为文件表自动生成 Wiki 业务字典；详情明确显示原文件结构及未确认业务语义。既有模型资料学习保留，不冒充已经完成业务口径确认。
