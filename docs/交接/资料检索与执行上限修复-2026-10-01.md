# 资料检索与执行上限修复

2026-10-01，沿用 AI-01—AI-04、WS-08—WS-11。用户以已导入的经营底表验收时收到 `TASK_LIMIT`。

## 原因与处理

失败记录显示约 15 秒内执行了 8 次模型请求（7 次资料搜索、1 次能力目录查询），全部模型请求正常返回，但没有最终回答。工作簿原解析逐行拆分，标题、字段和数值相互脱离；搜索仅返回少量片段，模型重复检索后触及调用上限。

- 解析器 `local-3` 将 XLSX 连续非空行组合成不超过 2000 字符的片段，空行分隔表块，保留坐标和原始数值。长表续段附有明确标注的原始前文，不推断表头，不改变统计口径。旧版本、旧解析及旧引用保留，重新解析只影响后续任务选择。
- 引擎 `0.12.1` 明确搜索为字面关键词 AND 匹配，提示使用短关键词。1.5 任务在既有 8 次模型调用内预留最后一轮回复；同时按剩余时间收尾，55 秒任务在剩余不超过 40 秒时的下一轮禁止继续工具调用。最后一轮输出有依据的阶段结果并保留未完成事项，平台记录为 PARTIAL。未放宽调用次数、模型输出 token、权限和执行能力。模型忽略收尾要求仍失败，不能执行额外工具。运行中的请求仍受总时限约束，不保证所有任务均可完成。
- 平台解析适配器新增 `local-3` 白名单，兼容旧版本。没有数据迁移或检索权限变化。

- 17 项解析测试通过，覆盖相邻数值与字段完整性、长表续段、错误维度、资源上限及真实 OS 沙箱。
- 108 项引擎测试通过；新增耗尽检索预算后保留阶段结果、最后一轮禁用工具、保持 8 次计量上限、慢检索后提前预留回复时间的验证。
- 40 项真实 PostgreSQL 集成测试通过（KnowledgeIntegrationTest、AgentIntegrationTest、AgentUsageIntegrationTest），包括权限隔离、历史引用、撤权与用量记录。
- 对用户工作簿的本地解析得到 43 个片段，768 个非空单元格均保持原值；月度收款表的标题、字段和 10 行记录在同一可检索片段内。私有资料和查询记录不进入 Git。

## 本机更新与边界

已更新本机原 `55167` 实例，保留原数据库及模型配置。为避免带入另一项手机号功能，本机 API 构建以原实例基线 `5c4fe41` 加本次解析白名单与任务等待时间补丁，41 个迁移文件逐字节保持一致；最终 API 包相对原包仅有三个 Java 类变化。完整产物摘要及回退副本保留在运行目录 `.local/runtime-releases/retrieval-limit-fix-20261001/`；API 为 `f15d3a2` 补丁，引擎最终来源 `1174807`。没有改写业务数据库、账号或模型配置。

此修复使资料片段适合模型检索，不代表 live 已开放完整工作簿脚本处理、原生经营图表或任意代码执行。真实模型质量和用户验收分别记录。

第二次真实回归已取到完整收款底表，随后第二轮生成在 12 秒处被模型 HTTP 超时中断。协调调整为单次模型 45 秒、引擎任务 55 秒、平台 HTTP 60 秒（外层等待 62 秒）、任务租约 90 秒；取消与撤权仍实时生效，调用次数及 token 上限保持不变。该配置用于有限等待正常生成，不自动重试请求。
