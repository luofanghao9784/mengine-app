# 首期治理四项补齐

用户授权依次处理内部资料Codex导入、资料版本/权限绑定、采集后的成果有效性，以及页面误报。本次只实现、测试和部署技术能力，没有治理真实内容、调用产品模型、生成画报或发布真实知识。

## 1. 内部资料成果导入

新增NativeMaterialGovernance与V161独立不可变成果表。沿现有主机`--native-governance`命令增加`material-context`、`material-preview`、`material-apply`，不开放HTTP写入口。输入/输出继续要求私有绝对路径，命令运行禁用定时处理器。

包包含contractVersion=1.0、id、tenantId、recipientId、backgroundVersion、producer=CODEX_OPERATOR及items。每项带source（materialId/versionId/runId/token）、title、content及evidence（chunkId/text）。最多20份/包，引用必须真实存在于对应解析片段。预览不写成果；正式应用校验当前治理负责人、版本和权限，并记录审计，同ID同内容幂等。拒绝伪造引用，不建立假的conversation_task或模型成功记录，不编造模型费用。成果仅向授权接收人展示，来源全员可读不扩大混合成果读取权限。

## 2. 资料引用绑定

资料token绑定企业、原件版本、解析批次、空间、原件哈希和完整解析片段。每次读取复核当前背景、当前解析和读取资格；重新解析、原件替换、撤回、背景变化或撤权后隐藏正文。

数据治理包增加materials引用数组；引用资料的首期包使用contractVersion=1.1并必须带非空引用。原1.0数据包保留兼容，只用于不引用内部资料的成果。资料引用校验与数据包提交处于同一事务；读取与发布时都校验，不只在生成时校验。运营者必须将所有实际引用资料列入包，不能用自由文本evidence代替结构化资料引用。

## 3. 每日采集与版本有效性

数据token由单纯快照UUID改为内容依据：数据行内容SHA256、覆盖时间、列结构、字段定义、空间、企业背景与身份范围。快照UUID仍保留在context用于追溯。

- 新快照内容、顺序、覆盖时间及其他依据完全一致时，可沿用当前已验证成果。
- 任一依据改变，成果隐藏并列入待复核；不自动把旧结论套到新数据，不自动调用模型。
- 重排也保守判为变化；覆盖时间改变也需复核。包中一个来源变化会使整包失效，建议按业务关联小批发布。
- 不停止或修改每日03:00采集。此改动不代表自动增量语义治理已实现，变化内容仍需另行治理与发布授权。

## 4. 页面真实状态

110张表仅有采集快照时，接入/结构化就绪，口径/治理检查/治理后AI可用等待；不显示合格行数或虚构质量分。已解析内部资料的原文可检索与治理后可用分开，需真实检查通过及已发布知识才能计入后者。新导入资料成果不伪造material_governance_reports，治理检查仍需真实执行。

未核验审计状态返回null，页面展示未核验，不再把未核验投影为审计异常。原始数据和原文读取权限不变。治理解释成果不覆盖原始表的field_definitions；知识展示与原始数据质量检查是独立结果。
