# 本地三类模型接入 · 2026-10-21

用户授权将业务模型统一接入 DeepSeek Flash，知识检索采用百炼 text-embedding-v4 和 qwen3-rerank。本轮在 main 顺序修改，运行目标为本机 `.local/ninepop-colleague`，不是云端生产部署。

## 配置与运行

- 主引擎及常规任务使用同一份 `.local/model-private/deepseek.json`，model、routineModel 均为 deepseek-flash。密钥仅保存在本机私有配置及服务进程环境中。
- 新版数据服务随 supervisor 的显式 live 配置启用，沿用企业绑定、签名桥接、资料及账号权限。无模型启动仍保持关闭；已有 off 实例仍须明确 `--enable-live`，恢复实例仍沿恢复激活检查。
- 数据服务的普通生成、知识分析与工具回放支持 DeepSeek 非思考参数，状态展示正确标识服务商；原百炼适配保留。
- WeKnora 使用独立的 9POP KB 和仅该 KB 的 ingest/retrieve 凭据，未复用宠物店 KB。模型为 text-embedding-v4（1024 维）和 qwen3-rerank。平台的企业绑定写入 knowledge_index_targets，凭据位于实例 weknora-runtime.json。
- 启动仅接通模型能力，不恢复旧采集连接、旧计划和自动任务。现有自动任务暂停状态保留；手动会话已验证。模型接通不等于全部业务功能完成验收。

本机启动（已具备构建及私有配置）：

```sh
. .local/runtime-env.sh
export POSTGRES_BIN="$PWD/.local/postgres-tools/bin"
python3 scripts/local/weknora_service.py start
python3 scripts/local/trial.py start --directory .local/ninepop-colleague --live --enable-live --phone-local --model-config .local/model-private/deepseek.json
```

本机原有启动文件已更新。三端仍共用 `http://127.0.0.1:58021`。

## 只读来源索引修正

同步资料的权限掩码为只读/可下载，旧索引 worker 错误要求原解析发起人具有编辑权限，导致 ACCESS_CHANGED。部署显式启用企业 KB 后，索引只读取已解析的固定来源，不修改源资料，因此改为复核当前读取权限。企业成员资格、有效资料/版本、企业 KB 绑定及检索前后权限检查继续生效，未修改业务授权表或提升用户权限。

仅对本轮失败且 remote_id 为空、错误为 ACCESS_CHANGED 的记录重新排队；不重试 UNKNOWN 或可能已产生远端副作用的创建请求。历史索引在后台逐条建立，全部就绪前相关范围可能返回索引未就绪，不冒充完整检索验收。

## 实际验证

- DeepSeek 官方适配真实工具往返：2 次请求成功，记录输入 405 / 输出 48 Token。
- 数据服务真实 DeepSeek 普通生成成功，输入 11 / 输出 3 Token。
- 员工账号通过应用 API 新建连接验证会话，任务 SUCCEEDED，modelName=deepseek-flash，回复“模型连接正常。”
- WeKnora 合成短文真实向量化、限定文档混合搜索、Rerank applied=true 及删除请求通过。
- 新建 9POP KB 的限定已索引文档真实检索成功，返回 1 条且 Rerank applied=true；没有返回范围外文档。这是单文档链路验证，不代表全量索引完成。
- 本地配置边界 20 项、启动边界 13 项、场景模型配置 2 项、数据服务模型协议 3 项、签名桥接隔离 1 项通过。
- WeKnora 数据库集成 13 项通过，新增只读可索引且不提升编辑权限、撤权后不发送原文。此组使用合成 HTTP 上游，不等于真实语义质量验证。
- 数据服务及 API 构建通过。私有运行证据和切换前数据库备份位于 `.local/model-rollout/`。

未做云端生产部署、全量历史资料召回质量评估或客户业务验收。费用按真实模型用量计费，不用连接成功代替财务分析准确性验收。
