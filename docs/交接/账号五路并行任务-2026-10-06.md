# 账号五路并行任务 · 2026-10-06

用户确认：单账号允许同时生成 5 张画报，会话也允许 5 路并行。

## 规则

- 同企业、同账号的画报任务最多 5 个同时执行；普通会话任务另有 5 个执行槽。超过上限继续 QUEUED，不能直接报失败。
- 普通会话指不同会话中的独立任务；同一个会话内原有单活动任务与消息顺序约束保留。
- 单实例执行器/引擎总容量 20；数据库调度跨 API 实例同时限制全局 RUNNING 为 20，同企业最多 20。画报登记任务同企业原上限 2 提高到 20，使账号的 5 路可真正运行。该总容量为本阶段资源控制，不是无限并发或模型供应商容量承诺。
- 每日手动 6、自动 8 的成功卡额度不变。派发时把本分类已启动的排队/运行任务作为额度预留，避免并行后重复越过剩余额度。失败、取消、无新内容不扣成功卡次数。

## 实现

ConversationWorker 的调度回调只领取任务并立即交给有界虚拟线程执行器，20 个信号量槽位在 finally 中归还。单任务异常独立记录，不中断同批其他任务；关停时中断执行，保留租约/状态恢复链路。多实例/多线程领取通过数据库短事务级派发锁保护计数与领取；模型执行不持有此锁。领取 SQL 跳过账号分类槽位已满的任务，其他账号可以继续。

BriefingGenerationService 每个策略先结算所有已派发任务，再选取未派发任务，不再因首个运行中的批次阻止后续批次；结算后若没有待派发批次，本次不立即追加自动任务，保留原自动触发节奏。Worker 每轮为同策略最多派发 5 个批次。权限、来源、取消、结果证据与幂等校验保持。

引擎独立任务容量从 2 提升为 20，仍按 task/attempt 去重，仍保持单任务 8 轮调用上限。

## 验证

- 73 项 API 测试通过：5 个并发竞争领取得到 5 个不同任务，第 6 个等待，另一账号可领取，完成后释放槽位；同策略六张画报派发前五张，第六张等待且在完成后继续；额度、权限、幂等、历史回执与恢复回归通过。
- 独立 Worker 测试让 5 个真实 Java 执行调用同时阻塞在同一屏障，任一调用返回前全部已进入；释放后 4 个成功、1 个失败，互不阻塞。
- 独立 Worker 关停定向回归（2 项）通过，中断不伪造失败/成功；等待线程退出后检查结果，避免异步假通过。
- 引擎容量测试：20 个不同任务同时进入授权请求，第 21 个 ENGINE_BUSY，结束后槽位可再次使用；没有调用主模型。
- 引擎资讯与交付回归测试通过，构建通过。
- 本地安装仅覆盖目标调度/任务服务类族，以及现有引擎任务容量条件；前端、其他引擎功能保留。共享 ConversationService 仅编译本次派发变更，未混入未提交的导航通知方法。安装前无运行/排队任务。

已安装本地验收实例，自动执行开关保持关闭。本次为并发行为、容量与安装验证，未执行 5 路付费云模型调用、未重置或扣减用户画报额度，不声称已验证供应商在 20 路下的吞吐或限流。
