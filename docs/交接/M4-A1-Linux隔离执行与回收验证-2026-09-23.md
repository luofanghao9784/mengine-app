真实 Linux 场景：

1. 授权数据计算输出 2000；同一端口完成候选 INI 合成试验、READY 后复用并标记 Linux 隔离。
2. 宿主路径、socket、改写输入/根目录和子进程调用被拒绝；环境中的合成秘密不继承；外网连接返回网络不可达。
3. Buffer 大量分配由 cgroup OOM 终止；临时盘/产物盘分别在 8 MiB / 4 MiB 发生真实 ENOSPC，文件清理后可返回容量证明。CPU/PID 的实际有效值由监督程序检查，未进行耗尽或吞吐压测。
4. 死循环由时限终止；确认任务已写入 READY 后取消，实际执行容器及输入卷删除。
5. 两个并发任务使用同名文件、不同字节，返回各自结果；第三任务收到 EXECUTOR_BUSY。
6. 目录/链接产物、超量 stdout、写出文件后抛错都不能交付成功半成品。对只读输入创建链接先被 Node 权限拒绝，另外使用目录产物验证收集器拒绝，未放宽限制迎合测试。
7. 确认子任务实际开始后 SIGKILL 引擎调用进程，容器监督程序自行终止任务；独立回收进程等到真实 60 秒到期后删除容器和输入卷，最终均为零。没有用修改系统时间或提前到期替代该崩溃验收。

浏览器复用现有页面，覆盖桌面/390px 手机视图、结果下载与内容核对、私人候选报告、刷新恢复、取消、总台下载 403。测试模型、搜索和候选归档传输为合成夹具；不把它写成模型自主选包或实际公开搜索验收。

本工作树忽略目录保存 `.local/m4-linux/result.json`、`.local/m4-agent/result.json` 及合成数据截图。最终 Linux 全套耗时约 65 秒。早期一次并发用例在 25 秒调用方期限触发取消，未定位到稳定原因；加请求阶段计时后连续 5 轮专项复验通过，随后无调试插桩的完整 7 项及网页链路通过。没有宣称修复了未知根因，也不据此承诺生产并发稳定性；云节点验证需继续保留请求耗时与资源监测。
