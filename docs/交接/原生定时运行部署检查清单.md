# 原生定时运行部署检查清单

关联 #120 / #184 审阅项 2。此文仅为部署交接；部署由 luofanghao9784 单独执行，代理不操作生产。

- API 主机（不仅是 DH 容器）安装 engine/package.json 指定的 Node：>=24.20.0 <25，服务进程 PATH 可找到 node。
- 将同一发布版本的 engine/scripts/native-schedule-rules.mjs、engine/package.json、engine/package-lock.json 一起交付。在对应 engine 目录按锁文件安装依赖（npm --prefix engine ci），须包含 @deepseek-ai/dsh-schedule 及传递依赖。不能只交付 JAR 或 engine/dist。
- 非仓库布局通过 dreamcore.native.schedule-rules 指定脚本绝对路径；脚本相邻 engine/node_modules 必须可解析。
- 开启原生运行环境且 schedules-enabled=true 时，API 启动前执行一个固定合成规则检查，不启动 Harness、不访问模型。缺少 Node、脚本或模块则启动失败，提示 NATIVE_SCHEDULE_RULES_UNAVAILABLE 及修复命令；不把依赖缺失报告为员工规则错误。
- 未配置 web-url，或明确 schedules-enabled=false 时不做此预检，旧模式不因缺少 Node 改变行为。
- 部署负责人在正式启用前检查启动结果及定时日志。权限、预算、发布每次仍由平台核对；不能以健康检查成功替代真实验收。

本地验证：NativeSchedulePreflightTest 覆盖启用时缺脚本、缺包、未配置/禁用兼容及官方规则正常评估。未部署、无客户验收。
