## 已实现

- `compare_dataset` 的比较和汇总计算保存服务端计算回执。只有具有该回执、所属任务成功完成、当前仍可读取的结果可以入库；历史未登记回执的结果不自动升级为已核验素材。模型生成同名 JSON 不能替代回执。
- 素材稳定身份、递增的不可变版本、精确原始 artifact/snapshot 引用、计算方法和业务请求指纹。相同 artifact 重试不重复入库，也不能延长有效期；变更业务查询需新建素材身份。
- 每个新版本使用实际计算回执时间作为生成时间，另存入库时间；来源覆盖截止、最近复核时间与有效期分别记录。
- 当前只支持确定性计算素材。事实、分析判断和建议尚未接入，不将计算成功等同于经营判断正确。
- 正文继续保存在既有成果生命周期存储，素材池不复制私人正文。原件清理后的派生成果擦除仍生效。
- 每次读取重新检查企业、账号、任务所有者、任务及来源的当前权限与生命周期。不因用户同属一个空间就开放原私人任务素材；不以管理员身份替代私人任务所有者。
- 当前快照按规范行序计算指纹，保留重复行的数量意义。新采集内容不变只记录复核观察；新增、删除、修改记录会令相应素材需要重算。首批使用整个数据集依赖，可能多算，但不会漏掉后续新增行。
- 历史读取返回 `CURRENT / STALE / EXPIRED / SUPERSEDED` 及原证据，不替换旧内容。`CURRENT` 只代表与最新可用快照内容一致，不代表数据实时。
- 内部 `forUse` 要求调用方提供业务覆盖截止标准，覆盖时间未知或不足时拒绝使用；消费事务和最终提交都需要调用。画报消费端尚未接入，不能将此方法存在视为完整交付围栏已经完成。
- 读取事务持有来源及证据锁，阻止撤回/擦除与同一消费事务交错。已有独立发布链路未改造，仍按其自身权限工作。

## 代码与契约

- [V96 迁移](../../apps/api/src/main/resources/db/migration/V96__analysis_calculation_materials.sql)：计算回执、素材、版本和观察；复合企业关系、证据校验、不可变记录与版本转换约束。
- [素材服务](../../apps/api/src/main/java/com/dreamcore/workspace/analysis/CalculationMaterialService.java)：入库、按版本读取、内容观察和按业务截止使用。
- [验收接口](../../apps/api/src/main/java/com/dreamcore/workspace/analysis/CalculationMaterialController.java)与 [OpenAPI](../../contracts/public-api/analysis-materials.openapi.json)：默认关闭，仅支持本人计算素材的明确入库和历史读取。
- [计算服务](../../apps/api/src/main/java/com/dreamcore/workspace/conversation/DatasetCalculationService.java)：成功计算登记真实回执，不增加模型调用。

接口通过 `ANALYSIS_MATERIAL_API_ENABLED=true` 显式开启；默认 `false`。此开关不创建后台任务，不配置企业分析身份，不增加任何受众，不授权发布。

首批有效期由受控调用明确传入，必须在未来且不晚于原计算后 31 天。这是技术上限，不是已确认的业务时效策略；业务覆盖时间必须另行检查。后续模型工具不得自行决定这个参数。

## 验证

独立、临时 PostgreSQL 中运行，未连接 9POP 业务库或正在使用的验收实例：

```sh
python3 scripts/with-test-postgres.py ./apps/api/mvnw -q -f apps/api/pom.xml \
  -Dtest=CalculationMaterialHttpIntegrationTest,DatasetCalculationIntegrationTest,DatasetSummaryIntegrationTest,DocumentPublicationIntegrationTest test
```

结果：39 项通过，0 失败、0 错误、0 跳过。

- 新素材服务及真实 HTTP 检查 17 项（HTTP 测试继承 16 项服务用例，不重复计数）：并发幂等、版本纠正、查询范围保护、未知/过旧覆盖、过期、权限撤销、来源撤回与清理、事务并发、CSRF、其他成员拒绝访问、私有响应禁止缓存。
- 既有数据比较 10 项、汇总计算 6 项、明确文稿发布 6 项回归通过。
- V96 在测试库迁移成功，`git diff --check` 通过。

以上证明持久化及权限行为，不是模型自主发现主题、经营结论质量或真实多岗位交付验收。未做正式数据迁移或用户验收。

## 接续顺序与剩余范围

1. 完成阶段 A：受控企业分析身份、其明确来源范围，以及四类素材的统一校验与发布依据；不能直接把当前私人素材改为全企业可见。
2. 接入模型自主主题生命周期、事件合并及范围依赖，补齐真正的选择性重算；当前没有硬编码业务主题。
3. 在手动及主动生成链路接入素材选取、实际复用与最终交付复核。现有画报仍使用原链路，本切片尚不能宣称已降低实际运行的重复计算成本。
4. 合成多受众验证后，再进行 9POP 负责人范围的真实调用。非负责人财务受众继续等待后续授权；新自动运行的预算和策略须在上线记录中明确。

回退：关闭验收 API 后继续使用原画报流程；迁移是新增表，旧成果和旧读取路径不变。不删除证据表回滚业务，不整库恢复覆盖新记录。部署前还需检查备份/恢复对新对象的处理和运行配置。
