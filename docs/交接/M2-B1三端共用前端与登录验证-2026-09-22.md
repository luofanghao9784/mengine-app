# M2-B1 三端共用前端与登录验证

日期：2026-09-22。对应[任务书](../技术/开发任务书-V0.1.md) M2-B1、[三端设计](../技术/三端架构与管理权限-V0.1.md)第 4 节，实施选择见 DEC-049。用户授权“开始 M2-B1”，本批实现共享前端与真实身份流程；本地通过不代表代码已合入或用户已验收。

## 实现范围

- `src/shared/`：主题色、基础样式、按钮/字段/弹窗/状态标记/空状态、圆形导航和标题操作布局。原客户端同步复用，旧 `src/components/ui.tsx` 兼容导出；管理端不依赖 DemoProvider、种子数据或浏览器模拟业务状态。
- Vite 多页面入口：`/workspace/` 客户端身份与可访问空间元信息；`/tenant-admin/` 企业身份与管理布局；`/platform-admin/` 平台身份与总台布局。原 `/` 独立 Demo 保留。
- 邀请制邮箱密码登录、新账号激活、已有账号接受另一企业邀请、刷新恢复、退出与会话失效反馈。邀请接受后新账号显式登录；已有账号不借邀请改密码。
- 真正可用的角色导航、直接入口拒绝、企业切换及请求取消。前端只展示服务端返回的身份，业务接口仍由 Spring Security 和平台权限校验；平台身份不自动获得客户空间。
- 连接失败/状态不确定明确提示，不挂载 Demo 或沿用旧身份。跨页面用 BroadcastChannel 和不含身份信息的 storage 标记触发重新查询；不持久化密码、令牌或账号信息。
- 三端沿用浅蓝画布、白卡、圆形导航、顶栏集中操作；窄屏改为底部导航。管理页面显示真实入口状态，没有模拟企业统计。

邀请可在登录页点击“我有邀请码”，或由本地受控方式打开 `#invite=<令牌>`。页面读取后立即移除地址中的令牌，仅内存暂存，刷新需重新提供。首期仍无真实邮件发送。

企业列表、开通/停用与初始管理员页面属于 M2-B2；成员/空间维护属于 M2-B3；完整管理操作贯通属于 M2-B4。本次没有提前声称这些操作已交付。客户端会话、画报、资料真实业务接入继续按后续任务执行。

## 运行与验证入口

依赖：Node 24.20.0、JDK 21、Python 3、PostgreSQL 18 工具及 Playwright Chromium。本轮使用 macOS、Chromium；目标 iOS/Android/HarmonyOS/macOS/Windows 真机浏览器尚未验收。

```bash
npm ci
npx playwright install chromium
npm run build
npm test
./apps/api/mvnw -B -f apps/api/pom.xml -DskipTests package
npm run test:access
```

真实人工开发环境按[平台说明](../../apps/api/README.md)配置本项目专用数据库、local profile 并受控初始化平台账号，随后启动平台和 `npm run dev`。三个入口共用同源 Cookie；开发/预览 `/api` 默认代理到本机 18181，可通过 `DREAMCORE_DEV_API_URL` 指定。身份流程无需引擎启动。不能用其他项目/客户数据库运行合成验证。

`test:access` 自动创建并清理专用临时 PostgreSQL，使用平台 CLI、真实管理 API 和私有邀请文件建立两个合成企业及多角色。随后启动真实 API 与构建产物预览，操作 Chromium；结束清理所属进程、数据库和凭据。测试不留下可日常登录的账号。

真实三端浏览器脚本覆盖：

1. 匿名登录、错误密码、新账号邀请激活、同页打开邀请链接及地址令牌移除、登录/刷新。
2. 管理员与普通成员导航、直接进入无权端拒绝、真实跨企业及跨角色 API 403；平台身份访问客户上下文被拒绝。
3. 本人接受第二企业邀请、切换企业与刷新恢复；延迟真实企业 A 响应返回后，企业 B 页面不被覆盖。
4. 网络故障时旧身份隐藏、明确错误与恢复；跨页面退出、Cookie 丢失后返回登录。此处会话失效用移除 Cookie 验证，不宣称实等 30 分钟过期。
5. 桌面和 390px 窄屏布局、移动账号弹窗、三个端无横向溢出；密码、邀请令牌不写入浏览器存储或捕获的服务日志。

## 旧测试差异

曾选跑 13 项旧会话/资料/导航测试，出现 5 项失败后停止，不能将其记录为全量通过。失败涉及旧色值和旧通用 Demo 样例/存储键。选取两类代表用例，在未含本次修改的 M2-A1 基线 `cfc0541` 重跑，均同样失败：

- `conversation-presentation` 的“导航进入淡蓝色”仍期望 `rgb(245,249,255)`，而基线当前实际画布是 `rgb(248,251,255)`。
- `library-reader` 的“卡片与列表共用资料”读取旧存储键 `enterprise-ai-demo-v1`，在空谷当前默认场景得到 null。

本批保留客户端已有色值及数据，不为旧断言改回历史产品状态；使用当前空谷流程和受影响导航完成回归。其余旧脚本未全量重新验收，后续维护历史场景测试时另行整理。
