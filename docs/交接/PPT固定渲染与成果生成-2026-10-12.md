# PPT 固定渲染与成果生成

2026-10-12。本批已完成固定 PPT 渲染程序与任务成果交付链路，实际生成并下载了六页中文 PPTX。模型内容使用明确的合成测试适配器；本项目真实模型配置尚未就绪，未声称完成真实模型质量验收。没有部署、重启运行实例、提交或推送。

## 当前可用范围

- 新建 1–8 页、16:9 的可编辑 PPTX。建议常规请求为 4–6 页，以适配既有单次模型输出预算。
- 两套固定配色，封面、正文要点、原生表格、原生柱状图四种版式。
- 表格最多 6 行数据、5 列；图表最多 8 个非负数据点并要求单位，嵌入原生工作簿。不是整页截图。
- 每次尝试生成一份 `presentation.pptx` 和一份 `presentation-source.json`；后者保存大纲、图表/表格数据、来源引用与配方版本。
- 检索到的空间资料由本次任务授权校验，引用保留在幻灯片备注和源 JSON。伪造 sourceId 在进入渲染器前失败。
- 会话进展中新增“生成 PPT”“读取技能说明”的中文工具标签，交付复用原有附件下载入口。本批没有新增技能中心页面或选择器。

暂不支持：任意 PPT 模板导入、用户图片/URL、宏、动画、已有附件逐页编辑、在线预览与 PDF 自动交付。源 JSON 为后续修订保留基础，不表示这些能力已提供。开发过程中导出的 PDF 仅用于人工检查。

## 渲染环境与执行边界

沿用项目 Node 24.20.x。本版使用固定可信 Node worker 执行渲染；模型只能提供 JSON，不能提交代码、XML、路径、URL 或样式对象。不是面向任意代码的隔离执行环境，不扩大 `run_javascript` 等通用工具的 live 权限。

worker 不继承环境变量或启动参数，单次超时 8 秒，最多并发 2 个，V8 old/young heap 上限分别为 192/32 MiB，栈 4 MiB。该数值是 worker 的 V8 资源限制，不是整个进程的操作系统内存上限。取消会终止 worker。

最大 8 MiB PPTX，产物检查 ZIP CRC、必要 OOXML 文件、页数、条目数量、非法文件路径、宏和外部关系；再通过 S1 的分块通道上传。最终仍由任务 finish 同事务发布并校验成功工具回执、技能激活回执、两份成果引用、当前权限与租约。

普通任务的 55 秒 Harness / 8 次模型调用 / 单次 2048 输出 token / 90 秒租约没有全局放大。仅注册工具列表容量从 16 增到 20，实际工具执行次数仍沿用每任务预算。8 秒渲染预算位于既有任务期限内；更长报告和高级预览需要后续单独预算设计。

PPT 字体声明为 Noto Sans CJK SC，未嵌入字体。本机 LibreOffice 检查使用系统中文字体回退；不同客户设备的字体排版仍需验收。尚未构建或部署新的 Linux 镜像，跨系统字体一致性和服务端预览是后续项。

## 开关与运行方法

默认关闭。平台开关为：

```text
dreamcore.tasks.artifact-transfer-enabled=true
dreamcore.tasks.ppt-renderer-enabled=true
```

引擎显式开启 `AGENT_PPT_RENDERER_ENABLED=true` 时先执行真实小文稿渲染就绪检查，再创建 Agent。需要同时配置项目既有模型网关；设置 PPT 开关不会自动获得模型凭据。平台返回的 `presentationRendererVersion=1.0`、成果通道 1.0、本地渲染器同时存在时，技能才可发现并激活。

运行包准备：

```bash
npm --prefix engine ci --ignore-scripts
npm --prefix engine run build
npm --prefix engine run licenses:check
```

不在任务执行过程中联网安装依赖。本批未修改任何运行实例的开关。真实模型检查命令 `python3 scripts/local/live_model.py check` 返回“尚未配置本项目模型”；后续在本机终端通过既有 `npm run model:configure` 流程配置，不将密钥写入对话或仓库。
