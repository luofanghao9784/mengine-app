## 已完成

### 受控文件成果

新增内部 `artifact-transfer:1.0` 协议，路径前缀为 `/internal/v1/agent-access/{task}/artifacts`：

| 接口 | 输入/行为 |
|---|---|
| POST `/prepare` | clientKey、filename、mediaType、bytes、sha256；返回 uploadId |
| POST `/{uploadId}/chunk` | offset、contentBase64；每块最多 256 KiB，顺序提交，精确重传幂等 |
| POST `/{uploadId}/complete` | 校验完整长度和 SHA256；变为 READY，仍不可下载 |
| 既有任务 finish | 结果 1.5 使用 name、sha256、uploadId 引用；同事务生成成果、清空暂存内容、更新任务 |

身份仅来自任务尝试的 Bearer 租约，服务端推导企业、空间和操作者。准备、分块、完成、发布复用既有任务/来源授权校验，并检查租约、停止标记和已注册执行工具。其他用户、其他企业、其他任务、过期租约不能使用暂存成果。完成上传不能冒充完成任务：仍要求成功工具回执与合法最终结果。

单文件及单次尝试成果总量上限 20 MiB，最多 8 个成果。允许扩展名与声明 MIME 的配对为 PPTX、XLSX、HTML、JSON、PNG、JPG、Markdown、TXT、CSV、ZIP；这里是传输类型白名单，不代表已实现相应渲染器或文件格式深度验证。后续渲染器还须校验格式结构。

旧协议和未协商新通道时仍使用原小文件回传限制。引擎在普通工具结果进入 Harness 前完成上传，只将有界元数据交给模型，不提高 Harness 的 64 KiB 工具结果上限，不向模型传递 uploadId。工具失败后的未发布字节由清理任务回收，不会成为可下载成果。

迁移 `V112__task_artifact_transfers.sql` 增加尝试级暂存表，并为既有 conversation_artifacts 标记 transferred。第一版复用既有私有 BYTEA 成果存储；没有引入新的对象存储或对外链接。暂存到期 1 小时，清理默认每 60 秒执行，也清除已失去有效运行租约的暂存。正式成果继续使用既有下载与生命周期权限。

下载仍强制 attachment/application/octet-stream，并校验字节数和摘要。HTML 不在当前站点执行。客户端元数据和下载读取上限调整到 20 MiB。

### 可信多文件包

TrustedCatalog 保留 1.0 内置技能兼容，增加 2.0 发行包：

- 固定 GitHub 仓库、40 位 commit、技能版本及许可；允许 MIT、MIT-0、Apache-2.0。
- 总摘要绑定身份、来源、依赖能力、工具需求与逐文件清单；激活时验证整个包的长度和 SHA256。
- 包最多 128 个文件、单文件 1 MiB、总计 2 MiB；入口及可读文本资源另限 64 KiB。
- 必須含 SKILL.md 与 LICENSE 或 LICENSE.txt；拒绝越界路径、重复路径与符号链接。
- `read_skill_resource` 只读已激活技能中列入清单的 Markdown/TXT/JSON，不执行脚本、不安装依赖、不访问运行时 URL。
- 只有指定工具和 renderer 等依赖全部具备，包才进入 available 列表。可用能力集合由可信运行端注入，不接受模型自行声明。

上游准备目录及实际运行目录仍分开。本批没有把 PPT/Web 上游原包加入正式 runtime manifest；五个来源、两个准备包、14 个文件的固定摘要仍有效。
