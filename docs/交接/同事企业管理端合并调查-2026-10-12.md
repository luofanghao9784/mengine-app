## 结论与合并原则

两个版本可以整合，但不是同一工程的分支合并。建议按用户要求，以同事版的重合功能与页面交互为优先，接入当前仓库统一账号、企业与空间权限、数据版本、任务及审计底座；当前独有的管理能力继续保留。这个技术落地方式属于建议，尚未实施。

同事版实际上同时包含员工知识工作台、Agent 和企业治理，不只是企业管理后台。不能将整个应用直接替换当前 `/tenant-admin/`，否则会形成第二套登录、会话、文件存储、模型任务和权限系统。

重合功能优先同事版，不应默认为允许管理员读取全部资料、用部门替代空间、删除当前负责人交接和离职流程。发现业务冲突时应单独列出，不把技术迁移当成访问范围的确认。

## 必须处理的语义冲突

### 管理员正文访问范围

同事 `apps/api/src/domain.ts` 的 `canRead` 同时在密级和范围条件中放行 `role === 'admin'`。`apps/api/test/security.test.ts` 约第 95—112 行也明确断言管理员可以读取目标资料、获得摘要和 HTTP 200，因此不是仅界面误显示。

本次直接执行该纯函数，以同企业、最低密级、非所有者、其他部门、私有、无 grants、ready 资料为合成场景，结果为：

| 场景 | 结果 |
| --- | --- |
| 企业管理员读取他人私有资料 | true |
| 普通成员读取同一资料 | false |
| 其他企业管理员读取同一资料 | false |
| 管理员无编辑授权直接编辑 | false |

同事 README 与交接文档“管理权限不等于正文阅读权限”的描述与实际 read-all 规则不一致。当前 `MaterialAccess.java` 则按个人所有权或共享空间成员关系检查；[资料库权限需求](../产品/资料库权限、操作留痕与版本历史-需求说明-V0.1.md) LIB-05 再次明确企业管理权不自动产生正文阅读权。建议迁移时保留此边界，重写同事权限相关测试预期。

### 组织和账号不能直接替换

同事 `User` 只有一个 `tenantId`、一个 `department` 和一个 `role`；`users.email` 全局唯一。当前账号可以加入多个企业，企业负责人、企业管理员、空间负责人各有独立职责。部门不等于共享空间；同事 `admin/steward/manager/member/auditor` 也不能逐项直接替换当前身份。

若新增治理负责人、审计员、密级和双人权限审批会改变用户可操作范围，应作为独立业务差异收口；不阻止先完成页面和只读数据适配。

### 资料和知识对象不能混用

同事 `Doc` 同时携带正文、版本、权限版本、解析和治理状态；数据集也与文档身份关联。当前原件、解析知识、固定数据快照、经验和私人会话成果分别管理。应建立对象映射和稳定引用，不能按名称将 Wiki 条目当作企业经验，也不能把同事归档直接解释成当前已清理。

新资料权限需求还包含文件夹继承、独立下载、编辑与移动删除分离；同事 `Grant` 只有 read/edit，不构成这些规则的完整实现。

### 引擎和数据库同步不能重复启动

同事 Harness 在 API 内执行，服务重启会把未完成任务记为失败；当前独立引擎和计量需要统一接入。照搬运行入口会产生另一组并发、取消、重试、模型费用和用量记录。

同事 `database-connections.ts` 已有同步任务、手动触发与 5 秒调度扫描，数据库中有 `database_sync_jobs/history`。包内早期文档“只有手动快照”已过时；是否具备远程源库可靠同步，需要独立运行验证，不能从代码存在直接推定生产能力。当前已有采集任务也不能因此被静默替换。

## 建议实施顺序

1. **固定两边基线。** 保留 ZIP 哈希，登记可迁入源码及许可；重新核对当前未提交资料权限改动。继续在本目录 `main` 顺序开发，不创建新开发 worktree。
2. **首个闭环选择知识工作台。** 迁入同事布局、指标下钻和资料列表呈现，以当前统一登录、企业选择和真实获权资料 API 驱动。验证切换企业、普通成员/管理员差异、空数据、错误和无权限，不先启用新模型任务。
3. **完成资料库与治理。** 对齐最新文件夹/文件权限需求，接入同事治理筛选、诊断与处理流程，统一原件、版本、回收和审计。
4. **完成数据基座与业务字典。** 保留既有连接/采集来源与固定快照，迁入口径候选、审批和受控业务查询；通过合成记录证明版本约束、跨表粒度和撤权生效。
5. **接入 Wiki、治理助手与审批审计。** Wiki 保留来源依赖；模型工具接当前任务引擎；审批与审计统一到现有身份和事件机制。
6. **收口管理能力和验收。** 将当前成员邀请、负责人交接、离职、企业信息、用量、企业退出、总台支持访问放入最终页面结构，完成三端回归后再安排部署。

首批不建议直接替换总台或员工客户端，也不在此调查中承诺完整合并工期。主要成本在业务对象和授权契约，不在 React 页面搬迁。
