# 2026-10-25 · 统一切换到新版协作规则

**改动级别**：L1 本地改动（仅文档与仓库配置，未部署）

## 改了什么

### 1. 把新版协作规则同步到 `main`

来源分支 `docs/fix-collab-claim-flow`（提交 `07493f6`），涉及：

- `docs/协作/协同规范.md`、`任务看板.md`、`VIBE-CODING-工作流程.md`
- `AGENTS.md`、`CLAUDE.md`、`.github/CODEOWNERS`

核心变化：认领改为在 GitHub 开 Issue（不再往 `main` 推看板）；`CODEOWNERS` 登记双方账号，审查按「一名非作者批准」；免费私有仓库没有分支保护，改用本地 `pre-push` 钩子 + 流程自觉。

### 2. 调整认领与开工检查的顺序

原来是「① 开认领 Issue → ② 检查重叠」，等于先占位置再看有没有撞车。

现改为**先查重、再认领**：

- 铁律二标题：`先认领，再动手` → `先查重，再认领，再动手`
- 流程九步：`① 查重 → ② 开认领 Issue → ③ 开分支 …`
- 补了理由：Issue 在共用仓库即时可见，搜一下就知道有没有人在做；先认领再查重，冲突已经发生

### 3. 收窄生产写操作的表述

原表述（`不碰线上` / `任何代理不得连接服务器`）范围过宽，连只读排查也一并禁掉。现统一改为**只禁止写操作**：

> 生产服务器、生产数据库、生产配置上的写操作（部署、改配置、改数据、重启服务）只由部署负责人执行；只读核验（查看日志、状态、目录清单）经部署负责人授权后可执行，且不得输出凭据内容。

同步修改四处：`AGENTS.md`、`CLAUDE.md`（硬规则 + 两人协作）、`协同规范.md` §九、`VIBE-CODING-工作流程.md`。

### 4. 新增可执行的本地启动指南

新增 `docs/交接/本地启动指南.md`：从克隆到三端可访问，十一节，命令可直接复制执行（工具链要求、构建、解析依赖、模型配置、启动、验证、停止、常见问题）。

原规则里引用的 `续接说明.md` 在仓库之外，克隆后拿不到；现在改为链接仓库内的指南。链接位置：`AGENTS.md`「开始工作」、`CLAUDE.md`「常用命令」、`协同规范.md` §三。

### 5. 修正一处文字不一致

`协同规范.md` 原写「`CODEOWNERS` 目前只登记 `@dimmm1125-coder`」，但同一次提交里 `CODEOWNERS` 已登记双方账号。按实际状态改正。

## 为什么改

用户认可新版协作方式，要求统一到同一版本后共同执行。三处调整分别是：消除"先占位再查重"的逻辑倒置；把过宽的禁令收窄到真正危险的写操作，避免只读排查也无法进行；补上仓库内可执行的启动路径，新成员不必依赖仓库外的文件。

## 影响范围

- 仅文档与仓库配置，**不涉及代码、数据库迁移或运行时行为**
- 不改变产品功能
