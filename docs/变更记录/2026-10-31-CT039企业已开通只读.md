# CT-039 企业已开通功能只读

基准 `75ab17a`（含空态壳 `7e21bc0`）。新增 `GET /api/tenant-admin/v1/opened-capabilities` / `listOpenedCapabilities` 及独立 OpenAPI 契约；前端、第四端控制器、目录 GET 和 grants GET 均未改动。成功响应为 `{"items":[{"enterpriseFunction":"quality-check","displayName":"质量检查"}]}`，生产 adapter 当前返回 `{"items":[]}`。

客户会话的唯一 ACTIVE 成员身份决定企业；无法确定或唯一企业服务非 ACTIVE → 404「暂时不能查看已开通功能」，标【待补-会话】。未登录、仅第四端/总台会话 → 401「请求未获授权。」；未开通 → 200 空列表；请求自报企业（query/body/附加路径）→ 400「有无法识别的字段，请检查后再提交」。跨企业响应不含他企名称、功能、材料或内部授权字段。

使用测试专用 Primary 端口实现的内存种子，企业甲开通 quality-check，企业乙有独有 table-compare；删除甲种子覆盖未开通。没有登记写、授权写或投影迁移。`qualityops` 禁止依赖 agentregistry/agentadmin 的源码断言位于默认运行的 `OpenedCapabilitiesIntegrationTest`。

验证命令使用 PATH 中已安装的 Java 21.0.12.1 与 PostgreSQL 18.6（本机 `/usr/libexec/java_home -v 21` 未发现 JDK、无 brew）：

```sh
export JAVA_HOME="$(dirname "$(dirname "$(command -v java)")")"
export POSTGRES_BIN="$(dirname "$(command -v pg_ctl)")"
python3 scripts/with-test-postgres.py ./apps/api/mvnw -B -f apps/api/pom.xml test -Dtest=OpenedCapabilitiesIntegrationTest
```

指定集成测试 9 项通过，0 失败、0 错误、0 跳过；包含源码包边界与契约钉值断言。仅本地合成验证，未部署。共享 error.schema.json 的既有错误码枚举缺口及 adapter 替换边界见[开发决策记录](../技术/开发决策记录.md#2026-10-31ct-039-企业已开通功能只读端口)。
