## 2026-10-28 · 后台轮询 CPU 优化

**改动级别**：L2 部署（PR #211；生产 WeKnora Langfuse 已关）

### 改了什么
经验接入复核改为按需、成批、单次可用性判断；企业信息分析在空闲时跳过发现视图；会话、知识、索引、采集、画报与场景输入等 worker 空闲时用内存门禁拉长间隔，有活再恢复快轮询。生产侧将 WeKnora 的 Langfuse 关闭，避免缺密钥反复重启。

### 为什么改
打开功能开关后，生产 Java 进程持续高 CPU。根因是后台空转轮询（尤其经验可用性逐行调用与企业分析发现），不是 4 核 8G 容量不足。

### 影响范围
- 涉及哪个端：平台 API 后台
- 涉及哪些功能：经验接入、企业信息分析、任务/知识/索引/采集/画报/场景输入调度
- 是否涉及数据库迁移：否

### 怎么验证的
- [x] `IdleGateTest`、`ExperienceIntakeIntegrationTest`、`CompanyAnalysisDiscoveryTest` 共 13 项通过
- [x] 生产：`LANGFUSE_ENABLED=false`，备份 `/etc/mengine/langfuse-off-backup-20261028-022939`
- [x] API class-patch 发版到 `/opt/mengine/releases/d88e6e002a61112ba3d3f87e8a7f84a2ffc0e9f9`（保留现网迁移集，不引入 V171/V178–V184）；四个服务 active；jar 含 `IdleGate`
- [ ] 发版后持续观察空闲 CPU 是否下降

### 怎么回滚
切换 `/opt/mengine/current` 到 `/opt/mengine/releases/865ccdc0f108e4fe7c3d834492ec5993d71dbe44-pr211-rollback` 并重启 `mengine-api`；备份在 `/data/mengine/backups/pr211-20261028-d88e6e00`。WeKnora 从 Langfuse 备份恢复 `weknora.env`（需先配齐密钥）。

### 备注
因生产 jar 故意不含原生会话迁移 V171/V178–V184，本次用 class-patch 只替换 10 个 worker 相关 class，未整包替换 main 构建的 fat jar。
会话 worker 的回执恢复放在 IdleGate 之前：空闲只跳过领任务，避免 `RESULT_UNKNOWN` 被空闲窗口拖住。
