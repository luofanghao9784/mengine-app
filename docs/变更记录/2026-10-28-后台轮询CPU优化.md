## 2026-10-28 · 后台轮询 CPU 优化

**改动级别**：L1 本地改动（生产 WeKnora Langfuse 开关另见备注）

### 改了什么
经验接入复核改为按需、成批、单次可用性判断；企业信息分析在空闲时跳过发现视图；会话、知识、索引、采集、画报与场景输入等 worker 空闲时用内存门禁拉长间隔，有活再恢复快轮询。生产侧将 WeKnora 的 Langfuse 关闭，避免缺密钥反复重启。

### 为什么改
打开功能开关后，生产 Java 进程持续高 CPU。根因是后台空转轮询（尤其经验可用性逐行调用与企业分析发现），不是 4 核 8G 容量不足。

### 影响范围
- 涉及哪个端：平台 API 后台
- 涉及哪些功能：经验接入、企业信息分析、任务/知识/索引/采集/画报/场景输入调度
- 是否涉及数据库迁移：否

### 怎么验证的
- [x] `IdleGateTest`、`ExperienceIntakeIntegrationTest`、`CompanyAnalysisDiscoveryTest` 共 13 项通过
- [ ] 关键路径实测（需发版后）
- [x] 生产：`LANGFUSE_ENABLED=false`，备份 `/etc/mengine/langfuse-off-backup-20261028-022939`，`mengine-weknora` active/running（MainPID 非 0）
- [ ] API 优化 jar 尚未发到生产

### 怎么回滚
代码回退本次改动；WeKnora 从上述备份恢复 `weknora.env` 并重启（需先配齐 Langfuse 密钥）。

### 备注
代码在本地工作区，尚未提交。空闲 CPU 下降依赖后续认领 Issue、开 PR、合并后再发 API。Langfuse 关闭只消 WeKnora 崩溃循环。
