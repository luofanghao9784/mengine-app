# 2026-10-27 · 多企业简报空闲调度优化

**改动级别**：L1 本地改动；关联认领 #204。

## 改了什么

自动简报没有新工作时结束本轮，空闲检查按策略逐步退避 5、10、20、40、60 秒。已有批次绕过退避，最多连续推进五轮，只有批次状态或任务绑定发生变化才进入下一轮。候选按企业交错，企业内最久未检查优先，防止一家企业的多条策略占满一轮。

执行中的任务已完成状态对账、且没有待派发批次时，不再重复计算全量来源指纹。任务消费者、执行租约、配额、权限检查和模型调用不变；没有跨请求缓存来源权限。

## 为什么改

生产只读采样发现无活动任务时仍有 PostgreSQL CPU 负载；代码中每条候选固定五次 tick，部分无变化策略仍反复计算数据指纹和历史资格。用户确认空闲退避最长 60 秒，同时要求多个企业接入时保留生产与消费效率。

## 影响范围

后端 BriefingGenerationService / BriefingGenerationWorker；新增公共迁移 V188，策略增加调度时间与退避字段，活跃批次增加查询索引。基于 main 9b36b1e5 开发，与当前生产非 DH 发布基线不同。本 PR 不部署，也不是可直接替换线上包的声明。

## 限制与回滚

60 秒是空闲退避间隔上限，不保证过载时 60 秒内完成检查或生成；每轮仍最多 20 条候选，五轮是每条策略推进上限。固定延迟会叠加整轮实际耗时，多企业增长后的容量要另行按生产负载评估。

此次仅减少重复进入昂贵路径的次数，不实现全局事件通知或历史 SQL 重构，不宣称生产 CPU 已降低。主线与生产迁移存在历史差异，上线前须另行准备回补和迁移演练。旧代码忽略新增字段，回退代码可恢复旧调度；生产迁移不在本次操作范围。
