# 2026-10-25 · 画报上下文注入治理字段口径（方案 A：只做提示）

**改动级别**：L1 本地改动（未部署）

## 改了什么

让画报任务在读取数据集时，能看到人工发布过的字段口径（列含义、单位、是否已确认）。

| 文件 | 变化 |
|---|---|
| `context/GovernedFieldContext.java` | 新增。只读查询该数据集最新一条已发布治理版本，产出 `{authority:false, source, releasedAt, usage, fields[]}` |
| `context/DatasetTaskContext.java` | 画报任务构建数据集上下文时，追加 `governedFields` 字段；非画报任务不加 |
| `test/.../GovernedFieldContextTest.java` | 新增 5 个测试 |

注入内容示例：

```json
"governedFields": {
  "authority": false,
  "source": "NATIVE_GOVERNANCE_RELEASE",
  "releasedAt": "2026-10-25T…",
  "usage": "人工发布后确认的字段口径，仅用于解读，不改变计算规则。status=SOURCE_DOCUMENTED 表示已核对；UNKNOWN 表示口径未确认，不得据列名推断金额、单位或业务状态，也不得因此拒绝计算。",
  "fields": [
    {"column":"收款金额","meaning":"门店收款合计，单位为分","unit":"分","status":"SOURCE_DOCUMENTED"}
  ]
}
```

治理缺失时注入 `{"authority":false,"source":"NONE","usage":"该数据集尚未发布治理口径；…"}`，不报错。

## 为什么改

画报此前只使用部署时的字段定义和场景分析规则；模型产出、人工发布的原生治理口径（`native_governance_releases`）只供人查看，不进任何计算或画报链路。

用户选择方案 A：先让模型"知道口径"，但不改变计算规则、不禁止任何列。理由是治理覆盖尚不完整，B/C 会让大部分画报直接算不出来；等治理版本积累到一定覆盖后再评估是否升级。

## 影响范围

- 仅影响**画报任务**的数据集上下文；普通会话的载荷逐字节不变
- **不改变任何计算规则**：`DatasetCalculationService`、`CalculationConditions` 未触碰
- 未知/未确认列照常参与计算
- 只读 `native_governance_releases`；治理发布侧无改动
- 按当前用户权限过滤（`headquarters_permission_actor`），看不到别人收到的版本
