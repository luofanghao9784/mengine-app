# 2026-10-29 · Linux CI 跳过本机沙箱用例

**改动级别**：L1 本地改动

### 改了什么

引擎里三条依赖 macOS 本机沙箱的用例，在非 darwin 上与 gateway、candidates 一样跳过。Linux 的 Contracts·Engine 门禁不再被 `SANDBOX_UNAVAILABLE` 挡住。macOS 上这三条仍跑真实 `LocalNodeSandbox`。非 darwin 上「沙箱不可用」的否定断言保持原样。

### 为什么改

`LocalNodeSandbox` 在非 macOS 上故意抛 `SANDBOX_UNAVAILABLE`。GitHub Actions 的 ubuntu 跑「actual sandbox」时，文件配方两条和原件整包一条必然失败。生产沙箱逻辑没有改。

### 影响范围

- 涉及哪个端：无运行时改动。只动引擎测试、一份 Linux 许可检查用的 darwin-arm64 LICENSE 副本，和本记录。
- 涉及哪些功能：无。
- 是否涉及数据库迁移：否

### 怎么验证的

- [x] Linux、Node 24.20.0：`npm --prefix engine test` 里 465 项为 451 通过、14 跳过、0 失败。三条目标用例为 skip。`sandbox.test.mjs` 的「invalid grants, pre-cancelled work and absent sandbox fail closed」通过，其中非 darwin 仍断言 `SANDBOX_UNAVAILABLE`
- [x] 同一命令末尾的 `licenses:check` 通过。Linux 不安装可选的 darwin-arm64 包，仓库原先缺它的 vendor LICENSE，检查会在测试之后 ENOENT。已按同目录其他平台补上，正文与锁文件 tarball 一致，`THIRD_PARTY_NOTICES.md` 未改

### 怎么回滚

撤回本变更即可。没有数据迁移，也没有运行时开关。

### 备注

单独的 macos job（S2）和把 DockerSandbox 放进默认 CI（S3）未做。
