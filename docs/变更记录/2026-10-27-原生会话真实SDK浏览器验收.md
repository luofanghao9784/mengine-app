## 验收中发现并修正

- DH 的超时提问返回正常 `tool/result`，正文 `{pending:true,callId,...}`。原前端将其误判为已回答，隐藏迟答入口。现按实际结构保留待回答，迟答事件才结束它。
- 尚在 10 秒新鲜期的旧 idle 状态不能覆盖更新的 turn/start。状态观察时间须不早于最近生命周期事件，否则沿事件状态。Esc 在原生会话内部消费，不触发外层页面关闭。
- SDK 终止一轮时不保证每个等待卡片先收到单独 closed 通知。真实 aborted 事件使该轮未答的前台提问和未决审批取消；此前已经超时、允许迟答的问题保留原语义。

补充单测覆盖实际 pending 工具结果、迟到回答、新旧状态时序以及中止后的卡片清理。浏览器脚本明确等待发送回执、消息计数增长及当前轮结束；不能以旧按钮一闪而过当成下一步成功。

## 可重复运行

前提：Node 依赖、Playwright Chromium、Java 21、PostgreSQL 工具和专用 Colima 已安装。首次切换含迁移改名的源码需 Maven clean，避免旧 target 中 V176 与 V178 历史产物混用；这是构建残留，不是删除数据库迁移。

```bash
# 若本地没有基础镜像，先按 engine/native/Dockerfile 构建固定依赖镜像。
docker --context colima-dh120 build -f engine/native/Dockerfile -t dreamcore-dh-b123:local engine
docker --context colima-dh120 build --pull=false -f engine/native/BrowserAcceptance.Dockerfile -t dreamcore-dh-browser:local engine
colima ssh --profile dh120 -- getent hosts host.lima.internal
# 用上一步核验的宿主地址替换；本机本次为 192.168.5.2。
NATIVE_BROWSER_IMAGE=$(docker --context colima-dh120 image inspect dreamcore-dh-browser:local --format '{{.Id}}') \
NATIVE_SDK_PLATFORM_HOST=192.168.5.2 \
python3 scripts/with-test-postgres.py ./apps/api/mvnw -B -f apps/api/pom.xml \
-Dtest=NativeSdkBrowserIT#fullBrowserAcceptance clean test
```

脚本使用独立 5217 Vite，合成用户名 `sdkbrowser`，仅在临时数据库中创建。临时口令固定用于该隔离测试，不是用户账号凭据。结果、截图与失败诊断写入 `.local/native-sdk-browser/`，不提交浏览器会话、运行密钥或业务数据。测试结束清理自建浏览器、Vite、host、容器及本次数据卷，临时 PostgreSQL 自动销毁。
