# DH 原生会话后端 B1–B3（#120）

实施始于 2026-10-26，最终验证于 2026-10-27。目标为[对齐清单第二节](../技术/DH原生会话前端对齐清单.md#二后端前提交-codex前端各批依赖)，只完成本轮后端前提；不把前端合成事件测试当成真实联调验收。

## 实现

- B1：平台统一游标、SSE、Last-Event-ID、分页冷历史；根和子会话事件按原语义保留，系统指令和内部请求头脱敏。桥接层 SQLite outbox 在平台断开期间持久保存，镜像去重，冲突拒绝。
- B2：消息/获权资料引用、停止当前轮、提问作答/跳过/超时后迟到回答、一次审批允许/拒绝、计划通过/退回；操作先登记 requestId，再派发，未知结果不自动重派。评价写入既有 feedback_entries/feedback_versions 的 NATIVE 目标，绑定真实 AI 消息。
- B3：从桥接层预算台账读取已结算、未决预留、总占用、软硬阈值与日预算；当前轮耗时与预算累计时间分开。无回执或超时不冒充空闲/零费用。
- 安全边界：平台每次复核本人、企业、空间、资料和旧会话来源；运行环境每两秒复核授权。平台/宿主服务密钥与单实例控制能力、模型/企业工具能力分离，控制能力只通过 stdin 交给外层进程，不传入 agent 子进程环境。模型工具不能自行审批或写事件/预算。
- V178：新增事件、操作凭据，扩展现有反馈目标；不改变旧任务/画报数据含义。没有生产迁移或部署。

接口最终差异集中在[清单附录 C](../技术/DH原生会话前端对齐清单.md#附录-cb1b3-后端定稿2026-10-26120)，类型在 `contracts/public-api/native-conversations.ts`。没有修改本轮前端实现。

## 本地配置

继续使用已有专用 Native Web host，但 SDK 操作需新增双端一致的私有控制密钥：

- API：`dreamcore.native.web-url` 指向宿主本机监听地址；`dreamcore.native.control-token`（环境变量 `DREAMCORE_NATIVE_CONTROL_TOKEN`）为至少 32 字符的独立随机值。
- host：同一个 `DREAMCORE_NATIVE_CONTROL_TOKEN`，仅在私有环境配置。它不进入 agent 容器环境、不发给浏览器、不写入仓库。
- `DREAMCORE_NATIVE_PLATFORM_URL` 是宿主可访问的 API；`DREAMCORE_NATIVE_PLATFORM_CONTAINER_URL` 必须是桥接容器可访问的 API，不能假定容器中的 localhost 是宿主。此次 Colima 容器无法解析 `host.lima.internal`，使用 `colima ssh --profile dh120 -- getent hosts host.lima.internal` 核实的宿主 IP 完成联调；其他环境须各自核实。API 对相应受控网卡可达，不能开放任意公网访问。
- 镜像仍要求不可变 sha256 ID；构建入口 `docker --context colima-dh120 build -f engine/native/Dockerfile -t dreamcore-dh-b123:local engine`。新进程从 SDK profile 启动，在同一持久卷保留根会话；Web 与 SDK 两种运行模式不能同时占有同一会话。已有 Web 独立窗口继续使用原入口，不能把旧 Web 历史说成已镜像的 SDK 历史。
- 缺控制密钥时操作接口明确 503，不影响平台已有冷历史读取；不自动切换现有实例。

## 验证命令与证据

使用合成数据、独立临时 PostgreSQL、合成模型。真实 DH SDK/服务与 Docker 隔离运行，未调用收费模型。

```bash
npm --prefix engine run test:native
python3 scripts/with-test-postgres.py ./apps/api/mvnw -B -f apps/api/pom.xml -Dtest=NativeConversationStreamIntegrationTest test
npm run build
./apps/api/mvnw -B -f apps/api/pom.xml -DskipTests package
```

容器联调显式启用，`NATIVE_SDK_PLATFORM_HOST` 由上文网络核验得到；不要复制旧 IP 到其他机器：

```bash
NATIVE_SDK_PLATFORM_HOST=<容器可达的宿主IP> \
NATIVE_SDK_IMAGE=<刚构建的sha256镜像ID> \
python3 scripts/with-test-postgres.py ./apps/api/mvnw -B -f apps/api/pom.xml \
-Dtest=NativeSdkContainerIT#realContainerEventsBudgetColdReadAndScope test
```

测试覆盖：SSE 实际登录与重连、分页与并发重复事件、跨企业/跨员工拒绝、资料版本绑定及撤权、同请求回放及未知结果不重派、状态过期、评价版本；真实 SDK 的发送/停止/重启、审批允许/拒绝、问题答案校验、超时/迟到回答、计划通过/退回；真实容器的事件镜像、预算回执、关闭后冷读取，以及工具凭据访问控制/伪造事件的拒绝。

最终检查结果见本文件末尾。初次联调发现 Java HTTP/2 升级与现有 WebSocket 入口不兼容，平台客户端已明确 HTTP/1.1；随后发现 Colima 容器 DNS 不解析宿主别名，按实际网关地址重验。首次完整镜像构建成功；后续 Docker Hub 元数据访问挂起，增量验收镜像复用同一次构建的本地镜像与相同依赖，只重拷当前源码/脚本并编译，不改变原 Dockerfile 固定基础镜像。
