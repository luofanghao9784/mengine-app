# 2026-10-27 · 企业锁与版本读取成本重构

**改动级别**：L1 本地改动。延续本人认领 #204，扩展 PR #205；本轮不操作生产。

## 改了什么

Scene 使用企业独立的公平读写锁，等待和持锁调用都计入引用，空闲后回收；慢企业的写操作不再阻塞其他企业。同企业仍保持读写互斥和撤权后的再次校验。保留同企业外部 I/O 期间的锁，未引入多实例一致性保证。

原生资料详情把目标 ID 下推到 CollectionService / MaterialService 的现有授权查询，跳过无关目录，不改变汇总权限与列表行为。简报指纹复用版本收据；首次计算保持原算法值，后续读取只查当前授权、元数据、快照状态与收据，不读原始数据行。元数据或快照变化使用新键；清理快照同时清理收据。删除每日简报分支中重复计算后丢弃的行排序结果。

正常 READ_COMMITTED 指纹冷缺失按企业、数据集、快照、元数据哈希合并计算。REPEATABLE_READ 冷缺失按该事务自己的快照计算且不插入收据，避免等待后仍不可见的并发收据引发 40001；已有其他证据种类行为不变。

## 验证依据

已观察旧实现的回归失败：慢企业写阻塞其他企业读写；同一收据并发冷缺失重复计算；单条详情调用全目录读取。在真实临时 PostgreSQL 中补充两事务 REPEATABLE_READ 测试，观察到序列化冲突后修复。

功能与工作量验证包含：

- 同企业读写互斥、撤权与异常后锁释放；不同企业慢写期间可继续读写。
- 保持历史指纹值；元数据及版本变化重新计算；缓存命中在隐藏原始行列后仍能完成；跨企业/撤权/清理后拒绝读取。
- 大于 100 条无关数据集时，目标详情完成且不能调用任何全目录读取；文档详情跳过数据集目录。预算守卫围绕真实数据库及实际详情输出，不以模拟返回冒充业务完成。
- 保留 PR #205 的两个企业各五个任务派发、并发防重、消费完成后下一轮补位及配额回归。

独立审查没有发现新增权限或锁回收回归；指出隔离级别验收缺口，已新增失败再通过的两事务用例并限定合并计算范围。
