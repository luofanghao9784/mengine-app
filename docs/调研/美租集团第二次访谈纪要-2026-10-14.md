## 2. 核心摘要

第二次访谈从第一次的整体需求讨论，深入到行政与财务人员的日常工作。行政侧最占用时间的三项是**房源备案、电话回访、水电费核对**；财务侧重点是**工资及业绩计算、收款核对与账单核销**，同时涉及业主付款安排、逾期催收和到期提醒。

本次进一步明确：业务员与管家通常是同一人；“存房人”是取得并对接房源的角色，可以与出租业务员重合，也可以由不同内部人员承担。业务经理和区域经理既承担管理职责，也可能亲自开展业务。

财务工作的复杂性来自多种业务模式和跨期变化，而不只是表格录入：兜底、轻托管、保租项目的收入与提成基数不同；租客服务费另有计算规则；免租期、空置期、存房人与出租人的分配、未收齐款、退租、违约金和费用扣减都影响结果。业务员底薪还与等级和有效开单数有关。

会谈末尾提出，先查看**一个保租项目的全房通后台及钉钉流程**，了解数据取得方式和现有操作。会中说明查看流程时不作调整。本次没有重新确定首批交付清单、报价、验收标准或新的完成日期。

## 4. 业务角色与工作链条

### 4.1 角色关系

| 角色 | 会中描述的职责 | 需要保留的区别 |
| --- | --- | --- |
| 存房人 | 对接业主，取得托管房源，协商租金、装修及家具等，准备好后进入出租系统；后续联系业主续约 | 公司内部人员可承担此角色；不一定就是最终出租该房的人 |
| 出租业务员／管家 | 发布房源、带看、签约、入住交接、跟进付款、协助报修及退房 | 两个称呼对应同一人；跟随其服务的租客承担工作 |
| 业务经理 | 管理团队、处理升级问题、参与相关审批，也可亲自开展业务 | 具有管理身份不意味着只拿管理提成；团队实际人数不一致 |
| 区域经理 | 管理区域、处理团队无法解决的问题，向更高管理层负责 | 具体区域及完整汇报关系需以组织资料核实 |
| 行政人员 | 考勤报备、人员变动、排班、备案、回访、部分费用核对与支付等 | 行政与财务存在交叉工作，不能按岗位名称直接推断所有职责 |
| 项目财务 | 收款核对、核销、台账、业绩工资计算、业主排款及催收提醒 | 日常逐笔处理主要在各项目完成 |
| 财务统筹人员 | 管理、汇总各项目财务与工资数据 | 不等于本人逐笔承担全部核销操作 |

### 4.2 房源到出租、售后的流程

1. 业主委托房源，存房人对接相关条件和配套事项。
2. 房源进入全房通等现有出租管理系统，内部人员可开展出租。
3. 业务员拍照、拍视频、发布信息、接待咨询及带看。
4. 达成交易后签约，确定租期、支付周期和费用，办理入住交接。
5. 租客入住后由原业务员／管家跟进；维修可通过公众号报修，由维修人员处理。
6. 管家无法解决的问题向业务经理、区域管理层升级。
7. 退房时办理交接、电子退房表、审批及财务退款；业主托管关系是否结束另行处理。

## 5. 行政岗位访谈

### 5.1 房源备案：及时性与逐条操作是主要障碍

企业需要向对应派出所报送租住信息。早段介绍了按月导出资料发送的做法；随后补充，不同接收方要求不完全一致，部分要求入住、退房后及时更新，并涉及扫码后逐条填写，而不只是发送一张全量表格。

备案信息主要来自全房通的租客登记，提到姓名、证件信息、联系方式、地址、入住及到期时间等字段。由于房源多、变化频繁，人工逐条填报耗时；把任务交给业务员，也未完全解决问题。

**讨论建议：** 识别新增入住和退房变化，按接收方需要组织数据；研究减少重复填报的方式，也讨论了提供查询接口的可能性。

**待核实：** 具体接收平台、二维码对应系统、不同辖区要求、报送字段、频率及是否接受接口。会中的接口设想并未得到接收方确认。

### 5.2 电话回访：独立监督服务与收费

电话回访由行政侧承担，而非让管家回访自己的客户。会中提到每月约有数百个需要联系的对象，具体数量应以台账核实。

回访主要关注：

- 管家服务态度及租住满意度。
- 是否存在额外收费、乱收费或费用说明不清。
- 已反馈的问题是否处理，维修是否跟进。
- 租客实际付款与公司所掌握信息是否一致。

**重要区分：** “多收了费用”和“已经收款但未交回公司”是不同问题；租客真实获准延期付款又是另一种情况，不能仅凭欠款状态认定业务员违规。

会中讨论了人员违规后的处理办法，但本纪要仅记录风险场景，不将口头描述直接写成可执行的人事或扣款制度。

### 5.3 考勤、排班与人员变动

- **每日考勤报备：** 向负责人汇报当天上班情况，原因是负责人不希望每次自行进入钉钉查看。
- **工资用考勤表：** 汇总出勤、请假及相关奖扣信息，支持财务计薪；与每日人数报备不是同一份结果。
- **排班：** 主要安排休息日，具有变动和调休需求，不能按永久固定班表处理。
- **人员变动：** 入职、离职、调岗、招聘等按实际发生处理。

考勤、排班及相关审批目前使用钉钉。会上讨论从现有数据提取日报，具体权限、字段和规则待查看系统。

### 5.4 宽带核对：先处理房源与账号对应关系

部分房源由公司提供宽带，公司按账单向运营商付费。新增安装、房源退出或停用后，需要相应增加、减少核对项。

当前难点是运营商账单中的安装地址或房号与企业实际房源不一致，部分可能源于安装时录入错误。受访者反映已核查过一部分，仍有数十条对应关系不清，并担心存在多付费用。

**整理判断：** 自动核对之前，需要核准“宽带账号—实际房源—启停状态”的关系。不能把地址近似匹配直接当成确认，也不能将受访者的多付担忧写成已查实损失。

### 5.5 水电核对、费用申请与交叉职责

部分房源由公司收取租客水电费，再向对应收款单位支付。行政需要核对房源增减、账号及费用，人工逐户查询耗时，可能发生遗漏。

行政还承担部分介绍费、办公或维修用品采购及费用支付工作。会中说明相关费用申请、报销与付款经过钉钉审批；不能将付款权限简单归结为“只有财务岗位可以操作”。现有登记与回访等资料主要保存为电子表格。

另一行政岗位涉及公众号、投标、民宿相关工作及停车费等。本次认为其中部分事项不是当前主要矛盾，公众号归入宣传业务继续考虑。

## 6. 财务岗位访谈

### 6.1 收款核对与核销的实际流程

当前工作链条可归纳为：

**业务员在收租群报备 → 核对支付渠道实际到账及合同 → 登记收租台账 → 在全房通处理账单核销 → 登记业绩计算台账 → 月末汇总工资。**

报备内容按新签、续期等情形有所不同，涉及房号、区域、租期、月付／季付等支付方式、租金、各类押金、服务费及付款截图。

| 收款方式 | 会中描述的处理 |
| --- | --- |
| 全房通线上付款 | 系统可完成部分自动核销，财务仍需核对实际到账、合同及报备是否一致 |
| 线下扫码付款 | 到对应收款平台确认到账，再到全房通核销；截图不能单独作为到账依据 |
| 租客经公众号自主付款 | 公众号与全房通连接；可能出现已付款但业务员未报备的情况，需要结合后台记录核对 |
| 其他渠道 | 台账还提及现金等来源，需准确记录渠道及归属 |

线上、线下均存在实际使用。手续费承担差异是部分租客选择渠道的原因之一，具体费率及承担规则未形成可靠统一口径，本纪要不固定数值。

会中提到截图可能出现错误、重复或被修改等情况。核对还要处理“合同设置的付款周期与实际报备不一致”“收到了款但未明确对应租客或房号”等问题。

**讨论建议：** 将群内自由文本报备改为更便于统计的结构化记录，曾讨论利用钉钉；工具与入口尚未最终确定。

### 6.2 工资结构及两类岗位

业务人员工资包含底薪与业绩提成。业务经理、区域经理可能同时拥有个人业务和团队管理收益。

行政、财务等后勤岗位工资相对固定；本次复杂计算主要集中在业务人员。项目财务负责各自项目的工资，统筹人员再汇总。

**后段澄清：** 业务员等级主要影响底薪；底薪还与当月开单数有关。早段出现“等级不同、提成比例不同”的理解，不能不加区分地沿用。具体等级、单量门槛、底薪金额应取得正式规则表，录音中的举例不构成完整档位。

### 6.3 三类业务模式的提成基数

| 模式 | 收入或业绩基数的口头说明 | 需要核对的事项 |
| --- | --- | --- |
| 兜底 | 公司对业主承担约定租金，以出租收入与对业主成本之间的差价等核算 | 成本周期、免租与空置、费用扣减、违约处理 |
| 轻托管 | 公司按约定收取业主侧管理服务费，会中以租金的 15% 举例 | 各合同实际比例，以及与租客服务费分开核算的方式 |
| 保租 | 公司按项目约定取得运营服务收入，访谈认为计算相对简单、与轻托管有相似之处 | 各项目公司收入比例、业务员提点和计提基数需分别核准，不能把项目收入比例直接当成个人提成比例 |

在讨论兜底、轻托管时，明确出现业务员 **18%**、业务经理所管团队业绩 **3%**、区域经理所管区域业绩 **2%** 的口头规则。后段又说明这些提点与底薪档位是不同概念。

**使用限制：** 上述比例仅记录本次对应场景；保租部分出现多组比例和连续追问，尚不足以整理成全集团统一计算公式。应以项目规则及历史结算样例核实。

### 6.4 两种“服务费”必须分开

1. **业主侧管理服务费：** 例如轻托管按租金一定比例收取，是公司管理房源的收入。
2. **租客侧服务费：** 针对签约及租住服务另行收取，访谈反复以每份合同 200 元举例，存在特殊减免或不同实际收取金额。

租客侧服务费的口头说明包括：

- 正常收取时，另有单独的业务员提成计算；会中以收取 200 元、业务员取得 50% 举例。
- 低于 200 元时，受访者说明不发放该项 50% 提成。
- 未收取时，后续澄清为从相应业绩计算基数中扣减，再计算业务提成；不等于从业主应得款中扣减。
- 特殊不收或少收涉及向管理人员报备。

**需要重点复核：** 对“轻托管未收租客服务费是否扣减”，会中先说“不扣”，随后区分业主结算与业务员提成，澄清为后者需扣。200 元边界、少收时扣多少、上限、续约及特殊减免规则均需样例确认，不宜仅凭这段对话直接编写计算规则。

### 6.5 存房人与出租人的分配、免租期和空置期

受访者说明，存房人与出租业务员为不同人员时，对应租客周期产生的业绩按双方各一半分配；空置期的相关损益归属则跟随存房人。适用收益项及跨团队提成如何衔接，仍需规则表核对。

免租期、空置期讨论前后有补充，应结合第二段约 44 分钟处的说明理解：

- 会中以年度有 **1.5 个月免租期**为例。
- 若全年空置 **2 个月**，后段解释为相抵后有 **0.5 个月亏损**。
- 若全年空置 **1 个月**，则相抵后有 **0.5 个月正收益**。
- 提到按天核算，结果影响业绩基数。

**关键区别：** 不能把早段的局部例子概括成“每空置一天都在免租额度之外另扣一天”，也不能把“扣业绩基数”直接写成“按同额扣个人工资”。年度或合同周期、月内确认、分段核算及跨年结转方式，需要通过实际账表核实。

### 6.6 实收、收齐与业绩确认

受访者说明业绩跟随实际收款，但又明确补充：如果合同约定按季度付款，只收到一个月、该期尚未收齐，则暂不计入对应季度的业绩，待收齐后再计算。

因此本次口头规则不是简单的“到账多少立即计提多少”。应区分：收款已经登记、该账单周期是否收齐、是否达到业绩确认条件。付款周期变更、跨月收齐、退款后重新计算等细节仍待样例核实。

### 6.7 退租影响：退款、业绩与底薪分开处理

现行退租流程描述为：

1. 租客联系业务员／管家，办理房屋交接。
2. 在全房通制作电子退房表，与租客核对并签署。
3. 业务经理审批。
4. 项目财务接收、核对退房表，安排退款。

退租可能同时影响三个结果：

- **租客退款：** 根据退房表、实际租住时间及对应约定处理。
- **业绩提成：** 已计提后又退还的租金，需要调整，访谈提到可在次月扣回。
- **底薪档位：** 不满一个月等不符合有效开单条件的退租，可能导致有效单量减少，进而影响当月底薪档位；已发放时需要后续调整。

会中讨论了通过临近月底开单、随后退租来跨越底薪门槛，以及人员间转单等情况。前者已有次月核对冲回的口头做法；后者被认为难以完全通过现有记录识别，未形成新的治理规则。

不满一个月的具体判定、是否扣押金与有效单量的关系、自然月及跨月处理，均需取得明确规则。不得把讨论中的极端例子推定为某位员工已经违规。

### 6.8 为什么业绩台账需要日常维护

项目财务每天或隔几天登记业绩，并非只在月底一次性计算。原因是需要及时掌握同一房源相邻租客之间的空置、上一期违约、当前收款及费用情况，一个月内可能发生多次租客更替。

除租金及服务费外，会中还补充：

- 上一租客违约形成的款项可能在后续周期计入相关业绩。
- 公司承担或需扣减的费用影响基数。
- 维修责任费用在未按要求与业主沟通等情况下，可能由具体人员承担，需按个案处理。

**待核实：** 押金转为违约金的条件、归属人员和确认期间。正常可退押金不能因本次提到“违约金算业绩”而一律视为收入或业绩。

### 6.9 业主排款、到期提醒与催收

项目财务还需根据账户余额及应付事项安排业主款项，维护未收款、租客到期和业主合同到期等信息，向业务员、存房人提供表格并跟进。

兜底业务提到提前联系业主续约；是否续约未明确时，支付节奏可能调整。具体提前期限和暂停或改为按月支付的条件，需要结合合同及制度确认。

轻托管侧介绍了向业主呈现出租状态、发送相关通知，以及在平台查看后续收款计划的做法。是否所有项目都已执行、通知覆盖哪些事件，本次未独立核查。
