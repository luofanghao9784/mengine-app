# 空谷无界 Demo 调研与内容设计

本轮目标是为真实空谷老板准备有企业语境的演示内容，重点展示**资料能够汇到一起，AI 能依据资料分析，并把结果变成可继续处理的工作**。本文件保留研究依据；用户随后确认按本资料替换，已实现前端演示，见[使用说明](../../产品/空谷无界Demo使用说明-2026-09-20.md)。尚未接入收银、会员或真实模型，当前AI分析为编写的样例。

## 1. 已确认的演示边界

2026-09-20 用户提供：贵阳空谷无界，室内外合计约 **300㎡**，装修精美、有格调，客单价 **30—40元**；经营、新品、客户、销售、活动均可覆盖，不单独偏重一项；对老板突出信息整合与 AI 分析。

这里的面积和客单价按用户信息采用，不用检索报道的其他面积替代。网上有更大生态场景及扩张计划的描述，指向范围、日期和现状均不能与本店直接等同。本稿不推定门店数、座位数、租金、人员规模、现行菜单、外卖渠道、会员工具和实际经营表现。

模拟底表暂用“每单净销售额”表示演示客单，区间落在30—40元内；这不证明真实门店的客单按人还是按订单计算。所有销量、营收、客户、新品与供应商情境明确标记“模拟经营数据”。真实新闻则保留来源、发布时间和事件时间。

## 4. 一套能对齐的模拟经营口径

所有下列数字均为人工编制，目的是测试分析过程，**不代表对空谷经营能力的估计或判断**。底表：[模拟经营底表](模拟经营底表.json)。冻结演示时间为2026-09-20 09:00，完整销售数据截至9月19日；当日9月20日不造完整营业额。

| 指标 | 合成值 | 口径 |
| --- | ---: | --- |
| 9/13—9/19 零售净销售额 | 48,178元 | 模拟折扣、退款调整后的含税展示额，活动套餐除外 |
| 同期完成零售订单 | 1,307单 | 不是顾客人数或咖啡杯数 |
| 同期每单平均净销售额 | 36.86元 | 48,178 ÷ 1,307；不与包场大单混算 |
| 上一可比7天零售额 | 42,788元 | 9/6—9/12，同样7天、星期结构一致 |
| 零售额环比 | +12.60% | 仅描述合成结果，不能证明增长原因 |
| 本期已履约活动收入 | 11,400元 | 两场合成活动；套餐饮品不重复记零售 |
| 本期零售＋已履约活动 | 59,578元 | 只在“综合销售”卡显示，不当作零售额或银行到账 |
| 本期活动收款 | 10,500元 | 已履约活动收款8,100元＋未来活动订金2,400元 |
| 已履约活动未收款 | 3,300元 | 到期日9/22，截至9/20未逾期 |
| 月内截至9/19综合销售 | 135,614元 | 零售120,014元＋已履约活动15,600元；不是完整月营收 |
| 本期购买会员 | 640人 | 去重会员，不包括未识别顾客；不能据此推算全店客流 |
| 30天新客复购率 | 30% | 8/1—8/15首次购买的180名合成会员中54人30天内再购；完整观察窗截至9/14 |

产品和渠道构成金额均回到48,178元同一分母。客群按互斥规则分组。问卷为40份自愿样本，主题可多选，不把主题次数相加当作人数；没有向任何真实顾客发送消息。

营业额增长不能仅靠这个底表归因。缺少历史促销、天气、逐时订单、排班等依据时，AI应该给“下一步核查”，不生成确定原因。本轮未计算利润、实际毛利、坪效或座位利用率：对应租金、人工、税费、损耗、座位与占用数据尚不存在。

## 5. 展示信息整合与分析的六条主线

| 主线 | 汇合的信息 | 画报给出的价值 | 会话继续什么 | 沉淀成果 |
| --- | --- | --- | --- | --- |
| 经营复盘 | 日销售＋渠道＋活动台账 | 看清增长来自哪个业务口径，避免订金充收入 | “拆开零售与活动，列出还不能解释的变化” | 一页经营复盘与核查清单 |
| 新品研发 | S07资讯＋反馈问卷＋三款拟议新品＋配方成本 | 解释为什么先试哪一款，同时保留小样本限制 | “设计下一轮试饮，列出通过条件” | 试饮表、配方版本对照、试售准备清单 |
| 客户经营 | 订单关联＋去重会员＋完整复购队列 | 区分客单、购买频次与复购，不混用指标 | “比较老客和新客，起草一份回访方案” | 客群分析与未发送的回访文案 |
| 企业活动 | 历史活动报道＋合成需求纪要＋报价＋排期 | 提醒人数、场地、时间和服务范围缺口 | “按30人活动整理需求和待确认项” | 场地方案初稿、执行清单、复盘模板 |
| 采购与备货 | S06行情＋本店合成烘焙豆报价＋配方＋库存 | 识别生豆/熟豆差异，量化影响和补货缺口 | “按未来7天销量假设算需要多少豆” | 询价对照与采购建议，未生成真实订单 |
| 内容与品牌 | 门店真实历史图＋授权状态＋活动素材＋品牌介绍 | 选出能发布的内容及缺失依据，复用既有成果 | “起草本周内容计划并标明待确认素材” | 4条待审内容与2条资料缺口 |

其中“AI分析”先用有依据的编写样例体现；现有Demo是预设规则回复，不能把这些样例描述为已完成真实模型验证。

## 6. 工作空间及资料库组织建议

继续沿用项目的工作空间、资料版本及个人/企业资料库模型，不新增强制部门树。

| 工作空间 | 建议资料集 | 典型资料 |
| --- | --- | --- |
| 门店经营 | 销售与运营、经营复盘 | 日销售摘要、渠道构成、客单口径、值班记录模板 |
| 产品研发 | 秋季新品、配方与试饮 | 行业风味札记、拟议新品卡、试饮记录、成本比较 |
| 客户与营销 | 客群与反馈、内容计划 | 会员分析摘要、复购口径、反馈主题、回访草稿 |
| 活动与企业合作 | 商机与需求、活动交付 | 合成企业需求、报价与服务清单、排期、历史活动报道 |
| 采购与财务 | 采购与库存、收款核对 | 供应商比价、豆耗测算、活动收入/订金对照 |
| 品牌与知识 | 企业资料、行业观察、运营模板 | 公开事实卡、新闻索引、图源台账、开闭店检查模板 |
| 个人空间 | 老板演示笔记、未共享草稿 | 演示会话、待确认方案，不冒充正式品牌文件 |

这是内容分组建议，不表示门店有六个部门。人员用“店长（合成角色）”“研发负责人（合成角色）”等，避免给真实创始人分配虚构待办、财务责任或对话。

## 7. 图片核验结果与使用方式

见 [图片预览](图源预览.html)、[核验截图](图源核验.png)、[加载结果](图源加载核验.json)。9个候选链接均成功加载；逐图检查后保留8个候选，其中4张空谷历史活动照片、1张展会宣传图、2张行业报道照片、1张报告图表。I08实际是无关广告，已排除。

已完成的是来源追溯、加载验证与视觉核对，不等于取得再分发许可。当前研究预览直接加载原站，不下载或打包原图。转发包中的门店主视觉优先采用老板提供或获准使用的门店照片；新闻候选保留原文、图注和署名，具体使用方式在实现时落实。原文含多个品牌的照片不能无依据认定是空谷。模拟新品可先用文本、配方卡与色块，不拿他店实物照冒充研发成品。

本轮未找到能核实授权与现状的Logo、标准菜单、门店外立面及无人物室内全景素材。此缺口不影响当前调研和内容原型。

## 8. 后续实现需要保持的边界

现有入口为 `src/model.ts`、`src/workspaceExamples.ts`、`src/briefingExamples.ts`、`src/briefingV2Examples.ts` 与 `src/briefingMedia.ts`。现有图片映射仅覆盖特定资讯来源，替换时需要同时检查新闻来源、资料关联、卡片快照与会话上下文，不能只改卡片标题。

建议独立增加空谷场景数据版本，提供可恢复的场景切换或独立存储键；如何替换当前浏览器数据属于后续实现选择。本轮不重置localStorage，不覆盖旧演示资料或会话。

落地验收关注四件事：卡片数字与底表一致；能追到资料版本或真实新闻；分析不跨越证据；会话能继续形成可复用成果。实际获取新闻、同步业务数据、执行营销与真实AI均需独立实现和验证。

## 9. 待下一轮补足的具体信息

优先补足：当前菜单与产品价位；实际销售/会员工具及可导出的字段；门店当前活动业务范围与资料；老板允许使用的门店照片与品牌素材。它们影响“更像空谷”，但不阻止按当前模拟边界完成数据设计。

最小验证建议：先让老板看一条“资讯＋反馈＋成本→新品试饮建议”的完整链和一条“销售＋活动台账→经营复盘”的链，再确认哪些日常资料最值得接入。该建议属于展示策略，不是用户已确认的业务范围。
