# 美租集团钉钉审批数据接入核查

核查日期：2026-10-14。状态：公开接口可行性调查及接入准备，未登录美租钉钉、未调用客户数据接口、未部署采集器。

业务依据：[首次访谈](美租集团谈话纪要-2026-10-13.md)、[第二次访谈](美租集团第二次访谈纪要-2026-10-14.md)。归档入口：[美租集团接入资料索引](美租集团接入资料索引.md)。

## 1. 结论

钉钉原生 OA 审批提供正式读取接口，梦擎具备通过专用 API 采集器接入的可行路径。可以按获准审批模板和时间范围查询实例，再读取单据详情；附件有独立下载授权接口。接口存在不等于美租当前应用已获权，也不等于任意钉钉内第三方流程的数据都由 OA 接口提供。

梦擎现有数据基座支持受控采集、字段解释和空间权限；通用读取器当前支持 SQLite、PostgreSQL、MySQL。钉钉需要新增专用适配器，不能直接当作上述数据库配置。本轮未实现该适配器。参见[数据基座部署协议](../技术/数据基座部署协议与字段解释.md)。

## 2. 官方接口依据与核验深度

| 能力 | 官方文档 | 本轮确认 |
| --- | --- | --- |
| 获取审批实例 ID 列表 | [钉钉：获取审批实例ID列表](https://open.dingtalk.com/document/development/operation-to-retrieve-a-list-of) | 官方页面说明明确为获取权限范围内相关部门的审批实例 ID |
| 读取单据详情 | [钉钉：获取单个审批实例详情](https://open.dingtalk.com/document/development/obtains-the-details-of-a-single-approval-instance) | 官方页面说明列出审批表单、操作记录、操作人、抄送人及审批任务列表 |
| 下载附件 | [钉钉：下载审批附件](https://open.dingtalk.com/document/development/download-an-approval-attachment) | 官方页面说明提供审批文件下载授权并生成下载链接；不能仅凭实例可读就假定附件已可下载 |
| 按模板、时间分页查询的历史规范 | [阿里开放平台：分页获取审批实例id列表](https://developer.alibaba.com/docs/api.htm?apiId=39471) | 历史接口列出 process_code、start_time、end_time、cursor 等参数，并说明受部门权限限制；历史页的页大小和费用标记不作为当前版本承诺 |

现代单据详情接口路径另有实施方的一手集成文档佐证：`GET https://api.dingtalk.com/v1.0/workflow/processInstances?processInstanceId=...`，请求使用 `x-acs-dingtalk-access-token`，见[华为云钉钉集成：查询审批实例](https://support.huaweicloud.com/bestpractice-sparkpack/zh-cn_topic_0000002490433954.html)。正式实现时仍应在钉钉当前 API Explorer 核对权限和响应契约。

本轮钉钉官方页面为动态页面，网页读取器未取得完整参数表；直接读取其官方 HTML 可核对标题及接口功能描述。故确认上述能力存在，但不把未完整核验的权限标识、分页上限、历史查询跨度、回调事件、调用额度和收费写成确定规格。未使用非官方 SDK 或社区示例作为生产实现依据。

## 3. 与美租实际业务的关系

第二次访谈明确钉钉用于考勤、排班以及费用申请、报销和付款审批。行政也承担部分支付工作，不能按岗位名称推断付款权只属于财务。退租审批在访谈中与全房通电子退房表相连，尚不能认定归钉钉。

| 数据或问题 | 钉钉审批能贡献什么 | 仍需其他来源或核对 |
| --- | --- | --- |
| 费用申请、报销、付款申请 | 表单中实际填写的事由、金额、人员、项目，以及流程处理记录 | 实际模板及字段；金额单位、币种、项目归属；是否已付款 |
| 审批效率与待办 | 在详情返回相应状态、任务和时间后，可统计待处理及流转情况 | 状态完整性、退回/撤销/重提规则，不能仅按标题判断 |
| 房源或项目费用归集 | 若表单有可靠的房源、项目或合同标识，可与主数据关联 | 全房通项目/房源/合同主键；自由文本地址不能直接视为可靠关联键 |
| 考勤日报、计薪出勤 | 请假等审批可补充原因 | 打卡、排班和考勤结果需另查对应接口，不属于审批接口自动覆盖范围 |
| 收款对账、业绩提成 | 可提供获准例外、减免或相关申请依据（以实际表单为准） | 支付渠道实际流水、合同、账单、收齐条件和正式提成规则 |

**审批同意不等于实际支付，付款截图不等于到账证明。** 初步业务链应保持“业务发生/申请 → 审批 → 实际收付款 → 核销 → 业绩确认”的区别；不是每一条收款都必经钉钉审批。钉钉是数据基座的一项来源，不能覆盖全房通、支付平台和现有财务台账。

## 4. 管理员配合事项

建议首个美租试点采用企业内部应用；这是接入建议，尚未创建应用。后续多企业产品化授权方式另行评估。

1. 确认使用原生 OA 审批、宜搭还是第三方应用。界面位于钉钉内不足以证明数据属于 OA 审批。
2. 确认美租各公司/项目是否处于同一钉钉组织；多个组织分别核对授权和来源身份，不能按公司名称合并。
3. 由有资格的管理员创建或配置采集应用，开通审批读取所需 API 权限与相应数据范围。具体权限项以当前后台及 API Explorer 为准；按需另开附件或人员身份映射权限。
4. 列出获准模板名称及 processCode、部门/人员范围、历史起点、可输出字段和梦擎目标空间。后台管理员能看单据，不证明应用凭据能读同样范围。
5. 通过私有部署环境配置应用凭据，核对访问令牌、网络及后台适用的 IP 限制。密钥不放纪要、聊天正文、Git 或模型输入。
6. 核实美租当前版本的 API 额度、频率限制及是否需付费扩容。不得据历史接口的“免费”标签承诺接入没有费用。

## 5. 建议的最小验证

先选一个保租项目、一个实际使用的费用报销或付款申请模板、最近 30 天，读取 5—10 条获准样例。模板、范围及样例读取授权落实后执行，当前尚未执行。

- 按当前接口规定拆分查询时间、完整分页，对照后台列表核对数量及 ID，不能只证明第一页可读。
- 覆盖已通过、拒绝、撤销及进行中记录（若实际存在）；核对状态、表单、明细、处理记录及时间，缺少的状态记录为未覆盖。
- 选择一条带附件的记录，独立验证附件授权与获取；不把临时下载链接作为长期档案地址。
- 核实房源/项目/合同标识，以及金额含义、精度、币种、单位和空值；保留源值，不猜测实收或擅自分转元。
- 验证部门/模板范围之外的内容被排除，并在梦擎验证企业、空间和受众隔离。若同一空间的权限过宽，先调整获准投影或目标空间，不发布敏感审批快照。
- 验证同一实例重复读取不产生重复计数，进行中转终态能更新，失败不覆盖上一份完整数据；部分分页失败不得发布为完整快照。

验收记录至少包括：源组织、模板、查询范围、后台与接口数量对照、字段字典、状态覆盖、权限边界、请求回执和未解决项。输出按批准投影去敏，不把客户原始业务数据写入可复用技能或调研说明。

## 6. 适配器设计方向（待实施）

建议沿用现有 CollectionAdapter 和调度器：钉钉只读 API → 专用采集器 → 固定字段及获准范围 → 梦擎不可变数据快照 → 获权分析。

实例以“源组织 + 审批实例 ID”定位；一张单据与多条明细、操作记录分别保留粒度，避免将头部金额随明细重复汇总。字段含义附依据并区分 SOURCE_DOCUMENTED、DEPLOYMENT_INFERRED、UNKNOWN；访谈中的口头规则不自动标为源系统事实。

历史导入后可采用周期补拉，并持续复查尚未结束的实例及必要重叠区间，避免按发起时间增量时漏掉较早单据的状态变化。事件订阅可作为后续优化，需另行核验当前事件文档、验签、重复和乱序处理；本轮未确认或实施。源删除、撤权及附件留存策略也须在上线前验证，不能把“不在本次分页中”直接解释为已删除。

后续正式采集器设计与实施决定写入现有开发决策记录；本文件是可行性和验证准备，不代表架构已实装、客户已接入或用户已验收。
