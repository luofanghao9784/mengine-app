## 决策演进

以下按讨论顺序整理，不为各次讨论补造具体发生日期。

| 主题 | 早期考虑 | 当前选择或保留方向 |
| --- | --- | --- |
| 企业 AI 转型的对象 | 建设 AI SaaS 或交付预制智能体 | 重点是员工使用 AI，企业提供可积累、可维护的资源与协作环境 |
| 多智能体协作 | 容易理解为系统内部子代理协作 | 用户明确指不同员工、不同部门使用的 AI 围绕企业工作协作 |
| 产品与服务路线 | 自研工作台、WorkBuddy 合作或经销 | 当前采用产品与诊断、搭建、培训、陪跑结合；未确认任何经销合作关系 |
| 资料部署 | 云端、企业本地或局域网盘都曾讨论 | 当前明确云端方案，共享基础设施并隔离企业数据与任务 |
| 产品技术基础 | 探索不同 Harness 与工具能力 | 用户表达以 DeepSeek Harness 为基础的意向；具体接入、版本和许可需后续验证 |
| 启动门槛 | 先由 FDE 建好完整企业资料底座再使用 | 希望可以从基础功能开始使用，深入治理与落地逐步通过服务完成 |
| 进入管理系统的深度 | 担心是否必须同时建设管理系统 | 先提供办公环境，出现明确需求后逐步增加流程与业务能力 |
| 自然语言搭建 | 员工使用现成工具 | 进一步希望员工描述需求即可配置仪表盘、审批等功能，优先复用组件，必要时 AI 辅助开发 |
| 跨部门协作 | 人向人提需求，再各自调用 AI | 保留员工向另一职责的 AI 发起请求，经相关人员许可与确认后交付的方向 |
| 后台系统能力 | 主要围绕员工对话调用资料 | 增加闲时或周期性主动整理、冲突检查、过期检查和工作改进建议 |
| 智能体状态展示 | 提出独立的智能体状态大厅 | 进一步结合空间工作记录与资料修改动态；具体界面采用统一动态的整合建议 |
| 客户端 | 桌面端、移动端或同时开发 | 电脑优先，网页起步；后续希望扩展 App 与小程序 |
| 核心入口 | 工作台与 AI 功能的层级曾讨论 | AI 会话优先级至少与工作台同级 |
| 资料与项目 | 项目与资料空间的关系不清 | 用统一工作空间兼容部门和项目，项目资料纳入整体资料体系 |
| 进展与仪表盘 | 用空间资料更新理解项目推进 | 保留工作记录，增加可选的空间仪表盘；文件更新本身不足以证明目标完成 |
| 空间共同维护 | 单独记录工作执行情况 | 用户要求扩展记录上传、修改和系统整理，让成员看到共同维护过程 |

## 已确认的经营与交付条件

- 可接触多个行业的小微企业；首发行业与客户尚未确定。
- 首批客户按 10—30 名实际使用者、1—2 个部门起步考虑。
- 用户本人负责技术、产品与 FDE，合伙人主要负责商务与培训。
- 可投入资金约 5 万—10 万元，时间较充裕；尚无具体开发排期。
- 用户本人劳动成本暂按每月 1.5 万元核算。
- 首期服务为配置产品、建立关键资料底座、培训并跑通典型工作。
- 持续服务采用固定频次复盘与培训，新增实施另行收费。
- 基础费、席位、存储扩容等是收费设想，尚未形成标准报价。

详细口径见 [企业AI办公系统 服务与收费边界](<../商业/服务与收费边界.md>)。

## 尚未成为结论的内容

- 对 WorkBuddy、飞书、钉钉、企微等产品的观察不能视为完整、持续有效的能力调查；本项目尚无已验证的竞争优势结论。
- 框架组合、云规格、模型成本、具体页面和阶段顺序未在本次整理中被当作开发冻结。
- “梦境”、跨部门协作、仪表盘生成和业务功能生成是方向，尚未承诺同时首发。
- “AI 可以补齐组件”不等于任何功能均可无审核生成并投入业务使用。
- “有 AI 转型需求的客户可接触”不等于已签约、已有自然获客或已证明持续付费。
- 原先探讨的本地资料方案仍有讨论价值，但不属于当前已选的首期部署形态。

## 本轮入库结果

本轮建立项目地图、立项说明、需求基线、技术待确认事项和服务收费边界，并在知识库总览增加入口。本归档保存本轮方向演变；后续修改优先更新活动文档，重大变化另建快照，避免覆盖历史判断依据。
