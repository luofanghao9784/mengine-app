> 本文件只保留「待办池」「冲突记录」和 2026-10-25 之前的**历史认领记录**，不再作为认领登记点。

---

## 使用方式

**认领一个任务**（由 AI 执行，你只需要说"我要做 X"）：

1. 在 GitHub 开一个 Issue：标题「认领：X」，正文写认领人和涉及范围（改哪个端、哪个功能），assignee 指派给自己
2. 开之前搜一下 Issue，确认没人认领同一功能；有重叠就先商量顺序
3. 确认无重叠后，开任务分支开工；PR 合并后关闭认领 Issue

认领走 GitHub Issue，不经过 Git，不会和"禁止直推 main"冲突。

## 状态说明

> 上表的状态仅适用于历史记录。新任务用 GitHub Issue 表达状态：Issue 开着 = 进行中，assignee = 认领人，关闭 = 已完成；需要暂停时在 Issue 里留言说明原因。

| 状态 | 含义（仅历史表格） | 谁改 |
|---|---|---|
| `待认领` | 已想好要做，还没人认领 | 任何人 |
| `进行中` | 已认领并推送，正在做 | 认领人 |
| `待合并` | 分支已推送，PR 已开，等对方合并 | 认领人 |
| `已合并` | 已进 `main` | 合并的人 |
| `已暂停` | 中途停下，原因写在备注 | 认领人 |
