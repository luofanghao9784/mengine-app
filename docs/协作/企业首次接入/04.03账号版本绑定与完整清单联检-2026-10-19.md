# 04.03账号版本绑定与完整清单联检

## 本轮实际结果

只使用现有本地文件和合成测试，没有访问云端、采集新数据、启用连接或写入实际权限。

- 从本地既有成员回执匹配本轮八位参与者的账号主键，核对企业、姓名唯一性和回执中的启用状态；没有刷新实时账号状态。
- 将106条旧资料版本草案绑定到上述账号主键，保留来源快照和内容指纹。此处106是资料记录数，与旧连接106张表不是同一指标。绑定均禁用，源ACL尚未验证，不是实际授权。
- 生成新版完整投影清单：107张表、1325列（旧清单106表、1312列，加已确认13列及公告可见范围表）。保留已确认字段边界，不扩大人员或原件下载范围。
- 新清单清空旧远程批次路由，保持preparationOnly=true、transportReady=false，防止新投影误用旧云端配置。原禁用安装包未替换。
- 新增离线入口local_preflight.py，联检暂存包哈希、连接清单、企业、账号和版本绑定；返回OFFLINE_PREFLIGHT_PASS，activationReady=false、networkExecuted=false。

私有工件在`.local/ninepop-onboarding-20261019/prepared-next-installation/`：next-connection.json、account-version-bindings.json及readiness.json。姓名、账号主键、真实行标识和凭据不复制到协作文档。

## 安装和入口的实际边界

本轮完成的是离线命令入口联检，不是业务系统API端到端联调。新版清单仍需转换/登记为正式来源及数据集版本，并把逐条授权和历史归属规则接入实际读取入口；不能仅凭本地绑定文件宣称服务端权限生效。既有系统的其他合成验收结果也不能替代新版107表验收。

```sh
python3 scripts/ninepop/local_preflight.py .local/ninepop-onboarding-20261019/prepared-next-installation
python3 -m unittest discover -s tests/ninepop -p 'test_*.py'
```

本轮53项测试通过，包含未知接收人拒绝、启用旧版本绑定拒绝及正常离线联检。没有真实来源执行结果。

## 历史证据与接续清单

| 事项 | 现有材料能确认什么 | 剩余处理 |
|---|---|---|
| 本地账号与资料版本 | 八人本地回执及106条旧版本可绑定 | 实际入口登记、版本失效和读取控制仍须联调；缓存状态不代替当前状态 |
| 课程余额及特殊课额度 | 已有快照时点校验逻辑；旧材料只提供有限归属候选 | 缺覆盖的记录继续隔离，不从创建时间或当前店倒推 |
| 转店和撤销 | 源码已明确生效、撤销与关闭关系 | 既有候选尚不能证明全部历史期间；需完整关系链并排除时点冲突 |
| 教练等级和提成锁 | 必须通过获准工资/课时/销售引用具体版本 | 没有引用证据的记录不分发，不按当前任职开放全部履历 |
| 分批旧快照 | 可以保留来源和指纹，不能证明一致状态 | 不将候选写成有效proof；未来一致性快照核验需要另行允许取数 |

本轮没有新增真实历史行证据，也没有把候选升级为已验证归属。已确认的人员、用途和字段无需重复确认。
