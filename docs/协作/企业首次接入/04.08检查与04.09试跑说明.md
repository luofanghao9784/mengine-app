# 04.08 检查与 04.09 试跑说明

状态：04.08 检查与 04.09 试跑方向已认可；具体企业样例、口径与验收结果待确认。仅说明流程和验收边界，不代表已执行具体企业检查或批准新增系统功能。

## 04.08：检查任务能否取得所需内容与执行能力

负责人是部署人员，执行者可以是部署 Codex；使用获准测试账号或由首批员工配合，不冒用员工身份。业务负责人确认问题、口径及预期输入。先记录企业、账号角色、空间、任务来源范围和各组件版本。

| 检查对象 | 现在可独立检查的现有路径 | 等同事交付后联调 |
|---|---|---|
| 数据 | 数据集登记及成功快照 → dataset_search → dataset_read；核对列、字段解释、覆盖期、版本、分页／样本限制和权限 | 新治理结果、字段口径与方法所需数据的关联是否完整 |
| 企业背景 | 企业信息 → profiles/profile_read；核对版本、来源、人工／推断状态及实际读取记录 | 04.05 背景作为内部来源，参与 04.06 知识生成、版本引用及变更追踪 |
| 资料与知识 | 已解析资料、已同步知识 → search_sources；核对内容、引用和源权限 | 新知识是否发布、同步、可发现；首次 Codex 产物与后续模型运行是否沿同一约定消费 |
| 方法与工具 | 已有方法、技能、固定计划和计算工具的可见性、版本及使用条件 | 04.07 的方法发现、输入输出、工具调用及知识／方法版本衔接 |
| 证据及异常 | 任务背景读取、快照记录、来源引用、工具回执；检查缺项、拒绝访问和版本失效 | 新知识／方法变化后的任务失效、复核及失败接续 |

操作顺序：确认身份与任务范围 → 发现所需内容 → 核对实际读取版本及完整性 → 检查方法与工具条件 → 保存真实使用证据 → 检查缺失、失效与撤权处理。

“仅选定资料”会限制其他背景和方法的读取，应先确认任务来源模式；不能把符合范围规则的拒绝读成接入失败。背景可读不等于知识已引用背景，知识可检索不等于已经能执行方法。模型自述不是实际调用证据。

现有通道可以先查，但 04.08 整体完成必须等所需新链路联调通过。前轮合成测试只作为旧能力证据，不冒充真实企业或同事交付版验收。没有新增预检中心的前置要求。

## 04.09：完整执行一次工作（方向已认可）

04.08 检查所需条件是否可用；04.09 在明确范围内完整运行一次，核对结果和证据；第五阶段再由真实使用者判断业务可用性。

负责人为部署人员，Codex 可协助操作与取证；业务负责人提供预期结果。用合成或明确获准的数据，选择输入与期望可核对的一件工作，不预设任意跨表对账已支持。

1. 准备试跑单：一个具体问题、日期与来源范围、预期输出、对照结果、账号角色、所用版本；注明合成模型或真实模型。
2. 在现有员工会话／处理入口发起，使用已获准的方法和工具；按正常任务链运行，不手工拼结果充当成功。
3. 等待真实任务状态并查看回复或产物。核对数据快照、背景和知识版本、方法、工具调用及计算依据；任务成功状态不单独证明业务正确。
4. 按预期核对行数、金额、范围、缺失和引用。出现不支持、无权、失效时应明确失败／待补条件，不偷偷换来源或省略步骤。
5. 记录通过、部分通过或未通过，以及问题层级和接续人。关键条件不满足时不进入该工作的第五阶段；独立工作可继续验证。

现在能做：准备样例与对照结果，试跑已具备的独立能力并明确覆盖范围。依赖 04.06／04.07 的完整新链路，等 04.08 联调通过后再试跑。业务口径不足先请业务方确认，不能让 AI 自行决定。

现有系统有任务状态、回复、资料引用、处理过程和后端工具回执。普通界面未必展示完整计算依据，本期部署人员可从受控记录取证，不必先开发新的试跑页面。若真实使用者验收需要直接查看完整回执，再确认前端改造范围。

试跑交接最少包含：任务 ID、代码与输入版本、测试身份范围、问题、预期与实际结果、读取和执行证据、模型性质、限制及下一步。一次试跑成功不代表线上部署完成、后续自动运行已启用或用户业务验收通过。

## 04.09 通过标准与结论

逐项核对，不以任务成功状态替代结果验收：

1. 范围清楚：试跑问题、日期、来源、账号角色、所用版本、模型性质及对照结果有记录，所需 04.08 检查已通过。
2. 真正执行：按现有正常任务链完成，有任务 ID、真实读取与工具执行证据；没有越权、擅自换来源或手工拼装结果。
3. 结果可核对：约定输出齐全，数量、金额、过滤及期间与对照结果一致；如需容差，事先由业务方确认，不能事后放宽。
4. 依据可追溯：记录实际需要且使用的数据快照、背景／知识／方法版本及计算依据；不要求与本工作无关的内容也必须读取。
5. 异常明确：缺失、截断、未知口径和能力限制如实表达；权限、版本失效和计算错误不能被“成功回复”掩盖。相关异常检查引用 04.08 证据，试跑新暴露的问题另外记录。

“通过”只适用于注明的工作与范围；“部分通过”必须拆出可独立通过的子工作，其余保持未通过。关键条件不满足的工作不交第五阶段；若缩小目标，先取得业务方范围确认，再复验该范围。合成模型通过不代表真实模型效果通过。

准备与独立能力试跑现在可做；依赖新治理／方法的完整试跑等待 04.06、04.07 交付及 04.08-INTEGRATION 联调通过。通过后由 04.10 打包交接，再进入第五阶段本人账号业务验证。普通回执 UI 改进保持候选，不作为部署人员从受控记录取证的前置。
