# 历史权限规则与最小字段增补

## 用户确认与实施边界

2026-10-19 用户确认前轮Q1—Q3和姓名最小方案：转店仅交接必要服务信息，跨店按用途分开，店长只读取本店承担薪酬期间的计算依据。三位股东和郑西的已确认全企业财务/薪酬/分红阅读资格不因此缩减。企业管理员仍不自动取得所有空间维护权。敏感原件不开放。

本轮修改部署侧 `scripts/ninepop/history_scope.py`，新增已审用途投影及最小姓名解析；没有修改业务API或云端。调用者必须使用可信部署配置、同一企业数据包及授权名单，再由平台执行资源/空间权限。不能接受用户或模型提交任意列/规则。新函数尚未接入禁用的真实采集运行入口，不能视为106表完整运行链已交付。

## 已实现规则

| 规则 | 本地行为 | 剩余条件 |
|---|---|---|
| 跨店服务 | 分别以授课店、费用承担店等单一用途选择记录，只输出该用途白名单字段；不合并两店权限 | 每个真实来源的字段解释及用途清单须审定后安装 |
| 转店交接 | 仅专门整理的service_handover事实可给接收店；同一会员、唯一转店、effective且已到生效时间；待生效/撤销/重复关联均不放行 | 原始转店和课程表到服务交接事实的适配还需制作，不能直接把整张原表交接 |
| 历史薪酬依据 | 通过有效期间关联；半开区间，重复/重叠关联不放行，不读取员工当前店替代历史 | 源系统完整任职/费用承担历史映射必须有依据；未知期间保持隔离 |
| 敏感权限 | 用途绑定salary/dividend/service，要求显式门店授权；撤权后拒绝，跨企业数据包拒绝 | 平台空间、来源版本及共享权限继续独立校验 |
| 姓名 | 只解析已授权输出行引用的ID；教练通过staff_id取员工姓名；不返回名册、手机号或登录字段；缺映射不回退猜姓名 | 新姓名列未增权；调用时身份字典必须来自同企业可信包 |
| 缺项 | 缺白名单/必要字段整批失败；重复主键失败；未知用途拒绝 | 不会把部分错误输出覆盖正式快照 |

这是规则执行能力的合成验证；62表源码已核查不等于62张表所有规范化适配已经实现。原本地连接继续禁用，原41直接+3关联策略不变，剩余62表仍隔离。接续先实现可证明的逐表适配，再测试，再申请真实接入，不跳过步骤。

## 最小字段增补清单（未执行源端授权）

| 表 | 拟新增列 | 必要性 / 使用限制 |
|---|---|---|
| members | name | 已确认必要会员姓名；仅解析获准记录引用的ID |
| staffs | name | 已确认必要员工姓名；coaches.staff_id复用此姓名 |
| t_course_refund_finance_entry_links | effect_type | 区分收入冲减/退款费用/其他影响，避免重复退款统计 |
| finance_position_events | effect_direction | 区分往来变化方向，不从金额正负猜测 |
| finance_reconciliation_variance_items | reason_type | 解释差异类型，不生成臆测原因 |
| payroll_commission_payout_transfers | from_recipient_coach_id、to_recipient_coach_id | 区分原/新提成收款人，与销售教练分开；薪酬授权后使用 |

本轮最小候选为6表7列；其中两列姓名用途已确认，其余5列是代码核查发现的技术需要，尚未执行源端增权。不加入phone、username、证件、银行账户原件、全文JSON或文件下载链接。

条件性候选不计入上述7列：coaches.name仅在未来获准核验发现员工关联无法补齐时申请；公告范围映射表需整理owner类型/owner ID/store ID最小投影后另审；产品快照、销售配置JSON、手册全文不直接整列开放，按用途拆字段或复用已批准文档来源。

原1312列定义不变。未来增补应新建数据集版本及字段说明，并保留旧任务来源含义；不是原地悄悄扩列。源端授权与取数执行本轮均未进行。
