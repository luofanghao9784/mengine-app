# 新版本地服务与权限接续 · 2026-10-18

## 本次范围与结论

用户授权接通本地新版数据服务、修正成员与空间入口和错误提示，保留已完成接管与加入的演示数据，核验权限后继续流程。只修改本地开发与运行配置；未部署线上、未接真实短信、未调用真实模型、未提交或推送 Git。

默认入口是 `/tenant-admin/#tenant=<企业ID>`。成员操作在新版“成员与权限 → 账号、空间与职责交接”内完成，复用既有业务组件，不需要进入 `?view=business`。入口默认选择账号与空间，另有明确说明：加入企业、空间只读/维护、数据资源权限是不同环节。

## 原因与实现

- 原本地试用脚本仅启动主 API、任务引擎及前端，没有配置新版依赖的 Mengine 桥接。真实请求返回 `SCENE_NOT_CONFIGURED`，不是企业或员工消失。
- 前端原先优先显示统一错误 message，遮住具体 code。现在区分服务未配置、企业未绑定、上游连接失败、操作无权和只读状态；列表同时显示原因，说明由部署人员处理，不阻断账号与空间管理。
- `scripts/local/trial.py --scene-tenant` 在原实例目录启动独立 Mengine 数据库及服务，读取主库有效企业负责人，首次建立本地演示映射。普通员工仍通过已有签名桥接以 member/L0 初始化；不继承管理员角色或资源读取权。
- `scripts/local/scene-trial.mjs` 不加载 `.env`、不导入默认演示种子、关闭真实模型。仅首次初始化空的本实例数据服务；重启复用映射、成员、授权与资料，不覆盖已有状态。绑定企业或负责人不一致时拒绝自动覆盖。
- 主库原账号、企业、邀请、两个共享空间和只读授权保留。数据服务桥接配置、密钥及 SQLite 仅存本地 `.local` 私有目录，不进入 Git。

## 同事如何运行

先按 README 安装依赖、构建主系统，并安装构建 `integrations/mengine-wiki`。只在自己的本地演示实例使用：

```sh
npm --prefix integrations/mengine-wiki run build
npm run trial:build
python3 scripts/local/trial.py stop --directory .local/<演示实例>
python3 scripts/local/trial.py start --directory .local/<演示实例> --phone-local --scene-tenant <已接管企业UUID>
```

首次必须选择已经开通且有效负责人接管的企业。后续同一实例重启会复用已保存的数据服务配置；不重新开企业、不重新邀请、不删除库。该开关仅支持模型 off 的本地演示，不是生产初始化或真实模型运行方案。
