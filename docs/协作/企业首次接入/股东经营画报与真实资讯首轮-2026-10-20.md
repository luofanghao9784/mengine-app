## 首次接入规范与实现

- 03.01：将真实外部资讯单列为来源，说明用途、来源机构和行业/地域；不混入内部三表。
- 03.02：明确 PAGE/RSS/ATOM、公开URL、原文读取与时效；外发只使用公开网址或已批准行业词，不发送企业背景、人员或经营数据。
- 03.03：来源登记/企业选用不改变业务资料授权；画报仍按任务所有者和来源权限读取。
- 04.03—04.04：总台来源登记、企业选中；用共用读取器验证候选和原文、时间、摘要哈希。不绕过 TLS、私网地址限制或读取失败。
- 04.08—04.09：Codex承接首轮作者工作，共用任务背景读取、选题和交付链路；资讯必须有真实原文，不允许只把内部分析标成 INFO。
- 06：正式模型服务商的自动搜索/生成和定时刷新另外验收，不因这次本地交付自动启用。

本轮修复候选发现将“无障碍浏览”等导航误认文章的问题。新增本地部署原文凭证入口，校验已选来源、同域候选、正文哈希、30天新闻窗口与检索时间；来源撤销时禁止交付。已交付文章写入 URL/hash 记录，后续相同内容拒绝重复导入。

入口仅可经现有 local + verification 主机命令执行，不新增公网接口。原文凭证来自可信部署脚本，不是模型自行声称“读取成功”。当前接通的是固定官方来源 PAGE 方式，不代表通用搜索供应商可用或任意网站均可读取。

## 可复用操作

1. 总台 `/api/platform-admin/v1/news-sources` 登记；企业 `/api/v1/tenants/{tenant}/news-sources` 选用。复用已有身份，不创建额外管理员。
2. 构建 engine 后运行 `node engine/scripts/first-news-evidence.mjs <已选来源URL> <该来源发现的原文URL> <私有证据文件>`。不覆盖旧凭证；原文不进 Git。
3. 原有 `--run-reconciliation-task` 本地首轮入口：prepare 使用 `businessType=INFO`；新 action `news` 提供 `news.sourceId / discoveredUrls / pages`，再 select、deliver。输入为可信主机文件，最大64KiB，结果私有0600文件。资讯执行进程显式设置 `AGENT_PUBLIC_WEB_ENABLED=true`，不改变常驻服务或云端配置。
4. 在账号画报详情展开“网络来源”，核验链接和日期；查看任务原文哈希与交付状态；撤销选用后复验拒绝行为。

本次没有接入付费网络服务，没有发送企业资料到外部。没有修改云端、成员权限或原件下载范围。正式模型服务商未调用；页面保留“联调验证”标记。
