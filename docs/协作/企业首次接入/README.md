# 企业首次接入 · Git 协作看板

这是项目开发协作文档，不是业务系统页面或接入配置服务。不连接业务数据、不含凭据；Sites 不再同步。方向已认可不等于细节已确认，任务完成不等于已部署或客户验收。

协作启动：[双方 Codex 协作约定](双方Codex协作约定.md) · [可转发的同事启动提示词](同事Codex启动提示词.md)

## 打开和生成

在项目根目录运行：

```sh
python3 docs/协作/企业首次接入/build.py
python3 docs/协作/企业首次接入/build.py --check
python3 -m http.server 5197 --bind 127.0.0.1 --directory docs/协作/企业首次接入
```

浏览器打开 http://127.0.0.1:5197/ 。若端口已占用，先确认现有服务，不要误停业务进程；可另选端口。同事拉取仓库后在自己的电脑运行。localhost 不是同事可远程访问的共享网址。生成的 index.html 也可直接打开阅读，handoff 相对链接要求目录文件完整。

## 两类记录分别维护

| 文件 | 用途 |
|---|---|
| [flow.json](flow.json) | 当前六阶段、节点内容、稳定 nodeId 和流程修订号 |
| [handoffs/](handoffs/) | 每个节点一份 Markdown；JSON 区块是该节点开发状态唯一来源，下方记录上下文、代码范围、接口约定、验证和更新历史 |
| [CHANGELOG.md](CHANGELOG.md) | 流程内容及看板变更记录，与开发进度分开 |
| [template.html](template.html) | 展示模板与保留的历史讨论；历史方案不是已确认的开发任务 |
| [index.html](index.html) | 自动生成、随 Git 保存的只读看板，不直接手改 |

状态从 handoff 构建进入节点右栏，不做在线编辑、搜索或评审意见系统。不增加服务端或数据库。更新后运行构建并刷新，页面不会自动侦测 Git 修改。

## 认领与接续

1. 先拉取并查看目标节点 handoff、当前流程和已有变更，检查该任务是否已被认领。
2. 将任务 owner 写为实际开发者；节点 owner 可填写协调人。填写 updatedBy、带时区 updatedAt、真实状态、代码范围和共享接口约定；追加更新记录。不要冒用另一位开发者的身份。
3. 初始 60 项是前后端核查／候选调整，不是 60 项已批准改造。核查无缺口填“不需开发”并给依据；有缺口写清复现、范围和验收，细节未确认填“待确认”。经确认的任务再进入开发。可以将候选拆为更细任务，但保留已使用的任务 ID，不复用或重编号。
4. 在 dependsOn 中填写具体任务 ID；blockers 写待谁处理什么。跨节点任务尽量引用原任务，不重复建立同一能力。构建检查不存在的依赖与循环依赖。
5. 更新 handoff 的接续说明、实际代码文件、提交或 PR、验证命令及结果。已完成／不需开发必须填写 evidence。实现、验证、部署分开记录，不能只因代码写完便标全部完成。
6. 运行 build.py 及 --check，提交业务改动、对应 handoff 和生成的 index.html。按明确路径暂存，避免带入他人文件或凭据。不要把真实客户资料、账号或连接配置放进看板。

推荐状态：待核查 → 待确认／待开发 → 开发中 → 待验证 → 已完成；也可以转阻塞或不需开发。右栏完成数按任务计算，排除项单列；不是已部署百分比。字段校验不能替代人工审查证据。

## 修改流程本身

修改 flow.json，保持 nodeId 不变；序号是展示顺序，nodeId 是身份。增加节点时使用新 ID 并增加对应 handoff。调整节点边界或验收时增加 revision，在 CHANGELOG 追加更新人、时间、原因、节点及影响。

旧 handoff 的 flowRevision 不自动升级，右栏会提示“流程已修订，请复核任务范围”。负责人检查任务与验收是否仍成立后更新 flowRevision；不受影响的节点也要明确检查后同步。删除节点前先处理任务迁移／归档，避免静默遗失 handoff。

历史讨论仍在 template.html 折叠区；如调整历史文本要保留历史含义，不把尚未采纳的新页面方案混回当前操作流程。

## 多人 Git 协作边界

双方各用独立克隆，克隆内顺序工作，main 集成；不同时修改同一个共享工作目录，不创建新 worktree。先推送认领，再开始授权范围内的开发。共享文件与接口重叠先协调；认领记录不是分布式锁。具体操作以《双方 Codex 协作约定》为准。

节点 handoff 独立文件可以降低冲突。生成的 index.html 冲突时，先合并 flow.json、template.html 和 handoff，再重新构建，不手工合并生成 HTML。没有自动发布或推送；发布业务系统仍走原授权与验收流程。

## 当前基线与建议

流程迁自 2026-10-17 临时看板，保留六阶段确认状态。现有能力参考此前 V147 增量部署核查，本地 main 与运行产物并非完整同版。每项开发开始前应记录实际代码基线，不把历史文档当成当前部署证明。

已包含：固定节点／任务编号、负责人、更新人、时间、任务状态、依赖、阻塞、验收证据、流程版本提醒，以及独立的实现／验证／部署状态。暂不增加评论、搜索、在线编辑、通知或复杂权限。后续可按需要把 build.py --check 接入 CI，或关联现有 GitHub PR；本轮未配置外部服务。
