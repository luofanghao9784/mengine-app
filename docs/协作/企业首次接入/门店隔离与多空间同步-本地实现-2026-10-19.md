# 门店隔离与多空间同步 本地实现

本轮实现首次接入需要的受控门店投影、敏感资源读取名单、多空间同步及企业端配置入口。初始切片使用合成数据；随后按用户授权配置本地客户实例并接入已获准的本地历史快照。没有连接或修改云端，没有部署。客户姓名、账号和真实授权表留在本地私有接入记录，不提交本文件。

## 业务边界

空间按组织和持续业务建立，企业治理是全局目标，不创建同名空间。企业管理员与股东业务查看资格分开。门店经理只能读取获准门店范围；薪酬、分红分别配置读取名单，不由“在同一空间”推导全部可见。读取不授予修改源工资、分红、审批、付款能力。中心负责人、财务人员和店长的职责以对应客户确认记录为准。

## 实现与调用

### 1. 部署采集范围

通用 `scripts/data-foundation/collector.py` 私有 datasets 配置增加可选 `rowScope`：

```json
{"column":"store_id","values":["store-example-a"]}
```

只接受安装配置中的固定列和非空字符串值集合，使用数据库绑定参数执行 IN 条件；任务请求不能携带或覆盖过滤器。原有列投影、只读事务、TLS、容量和原子输出限制保留。条件列不必对用户输出，但必须存在于源表。字段、门店范围变化必须按现有协议建立新数据集身份，不原地覆盖旧ID。

原生来源 `scripts/ninepop/full_collector.py` 支持同一物理表生成多个独立来源：`name` 为投影名称，`sourceTable` 为实际表名，`rowScope` 为固定门店条件。条件列必须在投影内；名称必须以 `_` 加 `scope_fingerprint(t)` 的12位摘要结尾，摘要绑定物理表、列和范围，范围变化不能继续使用同一名称。分页计数、分页读取均使用同一过滤器，组装时再次拒绝越界行。CLI MySQL值编码为UTF-8十六进制字面量，不拼接用户文本。范围投影默认 owner-only，需由来源授权入口显式配置读取者。

两种采集器均不根据员工当前门店猜测历史工资归属。不具备稳定归属列的关联数据先由部署人员定义受控视图/适配规则，不能删除过滤器放行；本轮没有创建云端视图。全历史仍可采集，未增加一周限制。网络MySQL范围SQL尚未在真实客户源库执行。

### 2. 来源到空间与读取名单

新增 V152（migration-common，两条迁移历史共用）保存 `scene_routing_configs`。

企业管理端 → 治理成果同步 → **按来源配置目标空间与读取人员**。每项来源选择一个已有共享空间和读取名单，知识沿来源路由，无须复制到每个中心。列表不包含源正文或凭据。

- GET `/api/tenant-admin/v1/tenants/{tenant}/scene/routes`：返回 revision、routes、来源标题、有效成员；目标空间沿原 binding 接口。
- POST 同路径：完整替换配置，要求企业管理员及数据基座管理员资格。示例：

```json
{"revision":0,"routes":[{"sourceId":"synthetic-salary-a","workspaceId":"00000000-0000-4000-8000-000000000001","readers":["00000000-0000-4000-8000-000000000002"]}]}
```

目标必须为本企业且绑定的同步身份拥有发布权限的共享空间，读取名单必须为本企业有效成员。独立发布清单启用后不再要求日常维护权；未配置清单的旧实例保留原维护权限检查。修订冲突拒绝；同内容重放不增加修订。

尚无显式配置时兼容旧单空间同步。首次保存后，未列出的来源不再同步；空清单撤下全部同步资源。保存立即使旧同步副本权限租约失效，成功同步才恢复。前端明确显示该影响，不自动执行同步。

同步前后核对路由修订，在事务中按企业锁校验，避免旧同步覆盖新配置。数据表范围身份包含目标空间与读取名单；资料换空间创建新对象、撤下旧对象；知识跟随来源空间和名单。源权限、目标名单、空间权限取交集，不给管理员补内容读取权。未配置来源不回落到默认共享空间。

### 3. 敏感资料及历史结果

`scene_asset_readable` 增加目标读取名单检查，并保留原历史数据刷新连续性规则。`file_dataset_readable`、资料权限和任务来源可读性继续调用此门控；撤权后旧任务正文不能因缓存或旧快照保留可见。源系统授权仍独立配置：本地名单只能收窄，不能使未获源权限的人员读到原生数据基座正文。

普通采集清单虽支持每个数据集指定workspaceId，但不会因此自动获得本轮场景资源名单门控；需敏感资源独立名单时应走本轮场景同步链路，不可把通用直采与场景同步当作同一个接口。

- 前端请求模拟：7项通过，含配置表单、完整清单提交、目标必选、保存不自动同步和失效提示。接口模拟不代替服务端权限证明。
- 前端生产构建通过；看板构建校验另记最终结果。
- 旧本地迁移路径（migration-local + migration-common）：隔离PostgreSQL中5项路由/历史连续性测试通过，确认迁移141、148、152按该历史应用。

## 客户实例接续与回退

先核对批准的源数据、门店稳定ID、薪酬/分红资源和人员映射，接通本地数据服务，再创建获准空间并配置双侧授权与完整路由。首次同步后按真实测试身份逐项验证，不能把合成回归当作客户接入验收。初始开发时59339演示库未变；后续实际配置进度见下方接续记录。

配置失败保留原配置；成功保存后不同步会维持拒绝读取，不静默回退为全员可读。回退使用当前revision提交上一份获准完整清单并重新同步；不要删除路由配置以退回旧默认模式。迁移不自动开启真实企业配置、不删除历史数据。

### 已实现系统切片

- V153保存独立发布空间清单。企业管理端→治理成果同步→“同步发布权限（独立于资料维护）”，GET/POST `/api/tenant-admin/v1/tenants/{tenant}/scene/publication` 使用revision防冲突；只允许企业管理员及基座管理员配置。
- 发布身份必须为当前绑定且有效的企业管理员。只向本企业有效共享空间发布已配置来源；不修改成员维护标志，不授予阅读、手工上传、编辑、删除或空间成员管理。
- 内部SceneMaterialWriter只用于同步来源/知识，校验发布范围、旧来源关联、版本及事务回退；普通资料接口保留原权限。采集执行前后也复核发布范围。
- 原基座出口默认忽略restrictedContent资料。新增签名内部请求的显式restrictedSourceIds清单，仅接收已可读的受限来源；浏览器不能使用该出口或借清单越过源授权。未启用路由的旧单空间模式仍默认不导出受限来源。知识沿相同来源清单与权限同步。
- 撤回发布权限立即使旧副本权限租约失效；相关同步被拒绝。恢复精确原清单并重新同步后恢复读取。来源、目标名单及空间权限仍取交集。
- 本地运行脚本支持本实例私有0600来源注册文件，校验所属用户/企业和非软链接；未使用真实模型、短信或云端连接。
- 修复历史快照时间语义：基座导出保留sourceReadAt；采集coverageThrough只采用源明确声明的覆盖时刻，不用口径更新时间/本次导入时间冒充数据覆盖时间。未知保持null。
