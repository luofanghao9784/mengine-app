# 04.08 员工任务工具与回执联调

## 本轮结论

首批三表的任务消费链路已在本地验证通过。首轮由部署 Codex 执行，使用八位既有参与者的实际账号身份和原授权空间；没有调用产品运行时模型，不等于员工自然语言会话或第五阶段业务验收通过。

## 实现

- `task_context` 增加 `reconciliation_catalog` 与 `reconciliation_execute`。任务发现限已安装规则和任务获权空间；参数只有门店、期间，不接收执行者或 SQL。
- 服务端从 task/attempt 取得执行者；三份数据通过既有 DatasetTaskContext 读取和固定版本。WORKSPACE 不能借另一空间数据计算；SELECTED 不自动获得额外背景。
- 按部署配置读取16条企业背景实际正文并保存 PROFILE 证据；使用既有检索服务按任务身份检索“收款 退款”，保留知识来源授权记录。无结果会明确返回 knowledgeRead=false，不用“绑定版本”替代实际读取。
- 金额、期间和跨表核查复用04.07固定规则。回执绑定 task/attempt、规则版本、期间、输入快照、背景正文、知识读取及计算结果；由 V155 公共迁移建立 task_reconciliation_receipts。重试不重复写同一回执。
- 完成前再次校验读取权限、背景版本及固定输入是否变化；撤权或版本变化拒绝交付。未扩大任何账号授权。
- 本地主机入口 `--run-reconciliation-task` 只支持 local + verification，记录 EXTERNAL_DEPLOYMENT；模型用量留空，不冒充模型调用。输入/输出放私有目录，输出权限0600。
