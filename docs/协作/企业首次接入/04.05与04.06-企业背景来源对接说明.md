使用合成企业和术语：术语 v1“到账指银行确认到账，不等于应收”；生成或登记一条引用 v1 的知识。修改为 v2 后能定位受影响知识、明确待复核或更新结果，并能追溯历史 v1。撤回／撤权后，未经授权的任务与知识读取不能继续取得其内容。

### 已实现接口（本地，待同事接入）

- `GET /api/v1/tenants/{tenant}/company-information/source`：返回 `tenantId`、稳定 `sourceId=company-background:{tenant}`、`type=COMPANY_BACKGROUND`、`state`、`version`、`knowledgeIntegration`、`entries`。
- `state=AVAILABLE` 表示当前身份有可读条目；`NO_READABLE_ENTRIES` 只表示当前没有可读条目，不泄漏其他无权内容是否存在。
- `version` 是当前可读条目 ID／版本 ID 集合的 SHA-256 指纹；不是全企业顺序版本或变更事件游标。再次读取可发现集合变化，但不返回删除或撤权原因，不授权缓存继续使用旧内容。
- `entries` 复用原 `id`（profile entry）、`versionId`、`revision`，并提供 `field`、`label`、`meaning`、`origin`、`humanProtected`、`provenance`、`updatedAt`。引用以条目和版本为准。详细原资料证据仍走现有 evidence 接口并重新验权。
- `GET .../source/entries/{id}?expectedRevision=N`：只读取当前仍有效且获权的背景；版本不符返回 409 `COMPANY_BACKGROUND_VERSION_CHANGED`，不存在／撤回／不可读返回 404，跨企业或成员资格失效拒绝访问。旧版本历史仍通过原背景历史入口，不用本接口绕过撤回。
- 复用客户身份与企业权限检查，响应 `private, no-store`；本适配不新增 worker 身份、凭据或开放接口。服务端内部消费可复用服务，但运行身份及调用契约需与 04.06 核对，不能伪造用户身份。
- `knowledgeIntegration=PENDING_INTEGRATION` 明确尚未接通引用接口；当前不返回假引用数量、不伪造知识处理完成。后续状态枚举和引用接口由 04.06 与本机共同约定。
- 直接读取原记录，无第二份可编辑背景、无同步队列、无数据库迁移。读取事务保持一致快照，并保留原权限检查的共享锁；不是只读数据库事务。
