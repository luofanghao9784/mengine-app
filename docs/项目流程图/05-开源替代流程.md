# 开源替代接入流程（候选方案）

本文件与当前实现分开记录。方案优先级、许可和具体取舍见 [开源替代研判](04-开源替代研判.md)。

## O01 哪些能力适合用开源替代

这是拟议方案总览，不代表已接入。优先做解析与检索的局部验证；同类检索路线先择一。账号、权限、业务口径和成果发布继续由三端业务层管理。

```mermaid
flowchart TD
  product["保留：三端入口、企业与空间业务"] --> inputs["资料与业务数据进入"]
  inputs --> parser["优先验证：Docling 复杂文档解析"]:::ossPriority
  inputs --> collector["按需：dlt 采集 / GX 规则校验"]:::ossConditional
  parser --> policy["保留：来源版本、权限与治理门禁"]
  collector --> policy
  policy --> retrieval["优先比较：WeKnora 或 pgvector"]:::ossPriority
  policy --> calculator["按需：DuckDB 计算执行内核"]:::ossConditional
  retrieval --> agent["保留当前 Harness 与受控工具"]
  calculator --> agent
  agent --> delivery["保留：画报规则、确认、发布和回执"]
  delivery --> chart["按需：ECharts 详情图 / Tiptap 编辑区"]:::ossConditional
  delivery --> ppt["已采用：PptxGenJS 文件生成"]:::ossExisting
  agent -.-> trace["优先补强：Langfuse 运维追踪"]:::ossPriority
  product -.-> later["后置条件项：Keycloak / OpenFGA / Temporal"]:::ossConditional
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[当前解析边界](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/DocumentParser.java)、[既有依赖](../../engine/package.json)、[Docling](https://github.com/docling-project/docling)、[WeKnora](https://github.com/Tencent/WeKnora)、[pgvector](https://github.com/pgvector/pgvector)。

## O02 资料解析与检索：替换执行部分

Docling 可以只替换复杂 PDF 解析。检索服务路线优先比较 WeKnora 与同库 pgvector；RAGFlow 是备选，不同时装三套。新解析和索引不得改写旧引用或扩大权限。

```mermaid
flowchart TD
  upload["现有上传入口与获权版本"] --> input["平台提供本次允许的原件字节"]
  input --> parse["候选：Docling 仅处理目标格式"]:::ossPriority
  parse --> adapt["适配为 locator / chunks / warnings"]
  adapt --> commit["平台复查权限并保存新解析批次"]
  commit --> choose{"选择一条检索路线"}
  choose -->|"服务整合"| weknora["WeKnora 索引、召回与重排"]:::ossPriority
  choose -->|"复用数据库"| vector["pgvector 向量索引；其余编排自研"]:::ossPriority
  choose -.->|"对照备选"| rag["RAGFlow 分块与检索"]:::ossConditional
  query["用户或任务发起检索"] --> scope["平台算出非空获准版本集合"]
  scope --> retrieval["只向所选检索路线发送获准范围"]
  weknora --> retrieval
  vector --> retrieval
  rag -.-> retrieval
  retrieval --> check["映射片段并二次校验权限与版本"]
  check --> result["现有界面展示内容与固定引用"]
  revoke["来源撤回、删除或权限变更"] --> deny["立即拒绝读取；异步清理或重建索引"]
  deny -.-> check
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[知识检索](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/KnowledgeService.java)、[旧核查记录](../../docs/技术/M3-A1本地解析与WeKnora接入边界.md)、[Docling](https://github.com/docling-project/docling)、[WeKnora](https://github.com/Tencent/WeKnora)、[pgvector](https://github.com/pgvector/pgvector)、[RAGFlow](https://github.com/infiniflow/ragflow)。

## O03 数据采集、质量与计算：三处局部替换

采集、质量判断、计算分别有独立替换边界。dlt 不能自动解释业务字段，GX 不能决定治理审批，DuckDB 不能决定谁能看哪些数据。当前小规模流程够用时维持原实现。

```mermaid
flowchart TD
  allowed["部署确认来源与获准范围"] --> collect["条件候选：dlt 读取与增量游标"]:::ossConditional
  allowed -.-> cdc["低延迟确有需要：Debezium CDC"]:::ossConditional
  collect --> snapshot["适配平台数据集 ID 与不可变快照"]
  cdc -.-> snapshot
  snapshot --> quality["条件候选：GX 执行确定性质量规则"]:::ossConditional
  quality --> govern["保留：字段口径、问题隔离与复检审批"]
  govern --> metric["保留：已发布指标版本与固定计划"]
  metric --> access["核查全部来源、行范围和治理租约"]
  access --> compile["可信编译器生成受限查询"]
  compile --> compute["条件候选：DuckDB 聚合与连接"]:::ossConditional
  compute --> receipt["精度、粒度、来源与权限再校验"]
  receipt --> deliver["现有会话或画报收到可信计算回执"]
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[采集协议](../../apps/api/src/main/java/com/dreamcore/workspace/collection/CollectionAdapter.java)、[治理规则](../../integrations/mengine-wiki/apps/api/src/structured-governance.ts)、[融合计算](../../apps/api/src/main/java/com/dreamcore/workspace/analysis/governed/FusionCalculator.java)、[dlt](https://github.com/dlt-hub/dlt)、[GX Core](https://github.com/fivetran/great_expectations)、[DuckDB](https://github.com/duckdb/duckdb)、[Debezium](https://github.com/debezium/debezium)。

## O04 会话执行与诊断：哪些能替换，哪些先不动

Langfuse 适合先接运维旁路；LiteLLM 在多供应商增长时引入。Temporal 与 LangGraph 分别涉及任务持久编排和 Agent 内部循环，迁移代价较大，不推荐现在一起重构。

```mermaid
flowchart TD
  request["现有会话 / PPT / 系统画报请求"] --> business["保留：权限、预算、任务与 requestId"]
  business --> worker["现有 Worker 领取任务"]
  worker --> harness["现有 Harness 内部执行循环"]
  worker -.-> temporal["后置候选：Temporal 接管持久编排"]:::ossConditional
  harness -.-> langgraph["后置备选：LangGraph 替换内部循环"]:::ossConditional
  harness --> tool["工具回调继续由平台校验权限"]
  harness --> gateway["供应商增加时：LiteLLM 统一模型接入"]:::ossConditional
  gateway --> model["已配置模型"]
  model --> harness
  harness --> outcome["保留：真实回执、未知结果与用户确认"]
  outcome --> product["现有会话、画报、文件与用量页面"]
  harness -.-> scrub["筛选与脱敏遥测，不默认复制正文"]
  scrub -.-> trace["优先补强：Langfuse 追踪、评测与诊断"]:::ossPriority
  trace -.-> operator["内部运维查看；不作为业务成功凭证"]
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[Harness](../../engine/src/runtime/harness.ts)、[计量](../../engine/src/runtime/metered-model.ts)、[Langfuse](https://github.com/langfuse/langfuse)、[LiteLLM](https://github.com/BerriAI/litellm)、[Temporal](https://github.com/temporalio/temporal)、[LangGraph](https://github.com/langchain-ai/langgraph)。

## O05 登录与权限：只替换通用判定部分

这是有明确 SSO 或复杂授权关系需求后的候选接法。Keycloak 负责身份认证，OpenFGA 可承担关系授权；二者都不能直接替代企业负责人激活、治理版本和来源撤回等业务规则。

```mermaid
flowchart TD
  login["三端现有登录入口"] --> idp["有企业 SSO 需求：Keycloak 认证"]:::ossConditional
  idp --> map["映射到现有统一账号"]
  map --> business["保留：企业状态、成员资格和端会话隔离"]
  business --> action["用户读取、下载、执行或发布"]
  action --> relation["关系复杂时：OpenFGA 查询关系权限"]:::ossConditional
  relation --> policy["保留：企业/空间/对象与行范围约束"]
  policy --> version["保留：版本、治理租约、来源有效性"]
  version --> decision{"本次动作是否允许？"}
  decision -->|"是"| run["执行并保留真实审计"]
  decision -->|"否或服务不可用"| reject["拒绝；不靠前端隐藏"]
  revoke["离职、撤权、暂停或来源变化"] --> invalidate["现有业务立即失效并同步外部关系"]
  invalidate -.-> policy
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[总台身份](../../apps/api/src/main/java/com/dreamcore/workspace/identity/PlatformIdentity.java)、[对象检索门禁](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/KnowledgeService.java)、[Keycloak](https://github.com/keycloak/keycloak)、[OpenFGA](https://github.com/openfga/openfga)。

## O06 页面与成果：只复用一个组件也有价值

不重做三端产品。组件从现有界面获得已授权、已验证的数据；保存、导出、发布仍调用现有业务接口。PptxGenJS 已使用，其他项只是按需求引入的候选。

```mermaid
flowchart TD
  entry["现有三端导航与主题"] --> admin["新增普通管理页"]
  admin --> refine["候选：Refine 表格、表单与数据请求"]:::ossConditional
  entry --> briefing["画报详情读取已验证的数据"]
  briefing --> chart["候选：ECharts 复杂详情图"]:::ossConditional
  entry --> doc["个人文稿编辑"]
  doc --> editor["候选：Tiptap 替换编辑输入区"]:::ossConditional
  entry --> ppt["PPT 需求、大纲与用户确认"]
  ppt --> renderer["已采用：PptxGenJS 生成 PPTX"]:::ossExisting
  refine --> api["现有接口：权限、版本与幂等"]
  editor --> api
  chart --> read["保留：原始精确值、口径和来源"]
  renderer --> files["现有成果校验、下载和授权"]
  api --> publish["保留：私人保存与明确共享发布"]
  classDef ossPriority fill:#e4f6eb,stroke:#2e8052,color:#154b30,stroke-width:2px
  classDef ossConditional fill:#fff3d9,stroke:#ac7b27,color:#604417,stroke-width:1.5px
  classDef ossExisting fill:#f0eaff,stroke:#8063ad,color:#4a3672,stroke-width:2px
```

依据：[文稿输入区](../../src/documents/DocumentCard.tsx)、[画报详情图](../../src/briefing-live/DetailChart.tsx)、[PPT 渲染](../../engine/src/runtime/presentation-render.ts)、[Refine](https://github.com/refinedev/refine)、[ECharts](https://github.com/apache/echarts)、[Tiptap](https://github.com/ueberdosis/tiptap)、[PptxGenJS](https://github.com/gitbrent/PptxGenJS)。
