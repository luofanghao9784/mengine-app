# 三端功能实现流程

以 `8dabacf1` 开发基线为准。每节列出真实代码入口；图中省略参数校验细节，但保留影响业务结果的授权、版本、确认与异常路径。具体表名仅在已经核对时使用。

## I01 总体技术架构

三端共用 React 前端和 Spring Boot 业务平台；Node 引擎通过内部协议执行 AI 任务。数据基座/Wiki 有独立 Fastify 服务与 SQLite，通过签名桥接把治理后的输入同步到平台。不是一个前端直接访问所有数据库的结构。

```mermaid
flowchart TD
  n_platform["React 总台"] --> n_api["Spring Boot 平台 API"]
  n_tenant["React 企业端场景与完整管理页"] --> n_api
  n_employee["React 员工客户端"] --> n_api
  n_api --> n_security["身份、企业、空间与对象权限"]
  n_security --> n_pg[("PostgreSQL：身份、任务、版本与回执")]
  n_api --> n_workers["后台 Worker：解析、采集、任务、画报等"]
  n_workers --> n_engine["Node 引擎：AgentTasks 与 Harness"]
  n_engine --> n_models["已配置模型适配器"]
  n_engine --> n_internal["平台内部工具与授权接口"]
  n_internal --> n_pg
  n_workers --> n_parser["Python 本地文件解析器"]
  n_parser --> n_objects[("本地原件与文件存储")]
  n_api --> n_bridge["SceneService 与签名桥接"]
  n_bridge --> n_wiki["Fastify 数据基座与 Wiki"]
  n_wiki --> n_sqlite[("Wiki SQLite 与资料文件")]
  n_wiki --> n_sources["已配置的业务数据库来源"]
  n_wiki --> n_wikiModel["Wiki 模型与处理器"]
  n_bridge --> n_sync["来源映射、权限租约与快照同步"]
  n_sync --> n_pg
```

依据：[入口](../../src/identity/main.tsx)、[引擎服务](../../engine/src/server.ts)、[场景桥接](../../apps/api/src/main/java/com/dreamcore/workspace/scene/SceneService.java)、[Wiki 服务](../../integrations/mengine-wiki/apps/api/src/server.ts)。

## I02 登录、端选择与会话隔离

统一账号记录和浏览器登录会话是两层概念。总台使用独立会话及 CSRF；企业管理端和员工端共用业务会话。企业选择按账号和端记忆，最终权限由服务端重查。

```mermaid
flowchart TD
  n_root["identity/main.tsx 识别入口"] --> n_realm{"访问哪一端？"}
  n_realm -->|"总台"| n_platform["PlatformApp 专用账号密码"]
  n_platform --> n_pa["platform-admin/v1/auth/login"]
  n_pa --> n_ps["PlatformIdentity 校验资格与凭据"]
  n_ps --> n_pc["签发独立总台 Cookie；令牌哈希存储"]
  n_pc --> n_pm["总台 me 与总台 CSRF"]
  n_realm -->|"企业或员工"| n_phone["PhoneAuth 业务账号登录或邀请流程"]
  n_phone --> n_ca["业务身份接口与业务会话"]
  n_ca --> n_cm["查询成员资格与企业状态"]
  n_cm --> n_choose["按端记忆或选择企业"]
  n_choose --> n_permitted{"目标入口和操作有权？"}
  n_permitted -->|"否"| n_deny["拒绝或显示暂停状态"]
  n_permitted -->|"是"| n_page["渲染工作页并调用获权 API"]
  n_pm --> n_page
  n_pc --> n_po["退出总台只结束总台会话"]
  n_ca --> n_co["退出业务端，两业务入口同步退出"]
```

依据：[业务入口](../../src/identity/AccessApp.tsx)、[总台入口](../../src/platform/PlatformApp.tsx)、[总台身份服务](../../apps/api/src/main/java/com/dreamcore/workspace/identity/PlatformIdentity.java)、[会话隔离说明](../../docs/技术/三端登录会话隔离-2026-10-14.md)。

## I03 企业开通、邀请和首位负责人激活

创建请求携带 requestId，重试同一请求不得重复创建企业。接受邀请时同时处理身份复用、成员关系、负责人职责与企业激活。短信或邮件真实投递不由本地邀请页面自动获得。

```mermaid
flowchart TD
  n_form["PlatformHome 开通表单"] --> n_post["POST platform-admin/v1/tenants"]
  n_post --> n_check["校验总台资格、投递配置、参数和 requestId"]
  n_check --> n_repeat{"相同请求已处理？"}
  n_repeat -->|"是"| n_receipt["返回原有开通结果"]
  n_repeat -->|"否"| n_create["持久化待激活企业和初始邀请"]
  n_create --> n_delivery["按配置投递邀请；本地模式显示邀请链接"]
  n_delivery --> n_user["受邀者核验手机号或既有身份"]
  n_user --> n_valid{"邀请有效且对象匹配？"}
  n_valid -->|"否"| n_fail["过期、撤销、身份不符等拒绝"]
  n_valid -->|"是"| n_accept["明确接受负责人职责"]
  n_accept --> n_tx["事务内创建或复用账号、成员与职责"]
  n_tx --> n_activate["企业 ACTIVE 与首位负责人同时生效"]
  n_activate --> n_audit["记录邀请接受与管理事件"]
  n_audit --> n_enter["返回可进入的端和企业"]
```

依据：[企业页面](../../src/platform/PlatformHome.tsx)、[总台企业接口](../../apps/api/src/main/java/com/dreamcore/workspace/identity/PlatformAdminController.java)、[业务身份接口](../../apps/api/src/main/java/com/dreamcore/workspace/identity/IdentityController.java)、[手机号身份接口](../../apps/api/src/main/java/com/dreamcore/workspace/identity/PhoneIdentityController.java)。

## I04 企业场景桥接与双系统同步

场景界面不能提交任意上游 URL。平台检查白名单路径、企业成员和绑定；桥接检查签名、时间与 nonce。权限或治理变更先让旧治理租约失效，再同步新状态。

```mermaid
flowchart TD
  n_ui["foundation-api.ts 请求场景操作"] --> n_csrf["写请求取得业务 CSRF"]
  n_csrf --> n_dispatch["SceneController dispatch"]
  n_dispatch --> n_gate["企业成员、绑定与路径白名单检查"]
  n_gate --> n_mutation{"权限或治理写操作？"}
  n_mutation -->|"是"| n_invalidate["先清空 governance_valid_until"]
  n_mutation -->|"否"| n_signed["SceneBridgeClient 签名请求"]
  n_invalidate --> n_signed
  n_signed --> n_upstream["platform-bridge 校验签名、时效和 nonce"]
  n_upstream --> n_delegate["映射企业与操作者，执行允许的上游接口"]
  n_delegate --> n_result["返回真实结果，再检查平台访问资格"]
  n_result --> n_sync["需要时执行 synchronize"]
  n_sync --> n_export["校验 scene-export 合约与 allowedActors"]
  n_export --> n_changed{"来源指纹改变？"}
  n_changed -->|"否"| n_lease["续 5 分钟治理租约，必要时补采集"]
  n_changed -->|"是"| n_map["更新来源映射、资料版本和数据集"]
  n_map --> n_collect["发起新快照采集并刷新租约"]
  n_collect --> n_record["scene_processing_runs 记录成功或失败"]
  n_lease --> n_record
```

依据：[前端桥接](../../src/admin/prototype/foundation-api.ts)、[场景服务](../../apps/api/src/main/java/com/dreamcore/workspace/scene/SceneService.java)、[桥接客户端](../../apps/api/src/main/java/com/dreamcore/workspace/scene/SceneBridgeClient.java)、[签名接收](../../integrations/mengine-wiki/apps/api/src/platform-bridge.ts)。

## I05 数据库采集、字段口径与治理

业务连接通过部署工具配置；采集和治理针对托管快照。字段解释必须满足当前来源版本与校验要求，不能把 AI 解释直接当成已核实经营事实。读取原业务数据库不等同于写回原系统。

```mermaid
flowchart TD
  n_deployment["外部部署配置连接与数据范围"] --> n_scheduler["定时或有权用户立即取数"]
  n_scheduler --> n_adapter["受控数据库适配器读取"]
  n_adapter --> n_snapshot["保存表结构、记录与来源版本"]
  n_snapshot --> n_dictionary["字典任务生成或接收字段解释"]
  n_dictionary --> n_validate["核对字段、单位、关系、证据和指纹"]
  n_validate --> n_current{"口径当前有效？"}
  n_current -->|"否"| n_waiting["待解释、待确认或重试"]
  n_current -->|"是"| n_rules["执行质量、敏感信息与关联规则检查"]
  n_rules --> n_safe{"允许提供和 AI 使用？"}
  n_safe -->|"否"| n_quarantine["隔离、暂停或要求治理"]
  n_quarantine --> n_fix["有权者处理，记录措施并重新校验"]
  n_fix --> n_rules
  n_safe -->|"是"| n_export["仅导出就绪且获权的来源"]
  n_export --> n_platform["平台 CollectionWorker 领取采集任务"]
  n_platform --> n_datasets["持久化业务数据集与不可变快照"]
  n_datasets --> n_consumer["知识、指标和会话按固定快照读取"]
```

依据：[连接实现](../../integrations/mengine-wiki/apps/api/src/database-connections.ts)、[字段字典](../../integrations/mengine-wiki/apps/api/src/data-dictionary.ts)、[结构化治理](../../integrations/mengine-wiki/apps/api/src/structured-governance.ts)、[采集 Worker](../../apps/api/src/main/java/com/dreamcore/workspace/collection/CollectionWorker.java)。

## I06 资料上传、版本解析与检索

原件、资料版本、解析任务和检索片段分别保存。解析器只负责实际提取；无法识别或 OCR 质量不足应显示限制，不能标为已验证业务事实。表格结构化是解析后的专门分支。

```mermaid
flowchart TD
  n_upload["UploadManager 和批量上传队列"] --> n_api["MaterialController"]
  n_api --> n_access["检查企业、目标空间与写入权限"]
  n_access --> n_store["保存原件和资料版本"]
  n_store --> n_run["建立可持久追踪的解析任务"]
  n_run --> n_worker["KnowledgeWorker claim"]
  n_worker --> n_verify["重新检查任务与来源可读性"]
  n_verify --> n_parser["DocumentParser 调用 Python 解析器"]
  n_parser --> n_type{"文件类型"}
  n_type -->|"文档或文本"| n_chunks["提取文本、定位与引用片段"]
  n_type -->|"表格"| n_table["提取表结构与数据；文件表格接入"]
  n_type -->|"需 OCR"| n_ocr["OCR 提取并标记需要核对"]
  n_chunks --> n_finish["保存解析状态和固定版本依据"]
  n_table --> n_finish
  n_ocr --> n_finish
  n_finish --> index["可选：WeKnora 持久化索引队列"]
  index --> scoped["获准片段映射远端 ID；空范围不请求"]
  scoped --> hybrid["混合召回与重排；仅接受范围内结果"]
  hybrid --> n_retrieval["重查当前权限与版本；返回本地原文引用"]
  n_finish -->|"开关关闭"| legacy["原关键词检索与权限过滤"]
  n_parser -->|"失败或超限"| n_error["记录失败或部分结果，允许时重试"]
  n_access -->|"无权"| n_deny["拒绝上传或读取"]
```

依据：[上传管理](../../src/material/UploadManager.tsx)、[资料接口](../../apps/api/src/main/java/com/dreamcore/workspace/material/MaterialController.java)、[解析 Worker](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/KnowledgeWorker.java)、[解析器](../../workers/parser/parse.py)、[文件表格场景](../../apps/api/src/main/java/com/dreamcore/workspace/scene/FileTableSceneService.java)。

## I07 Wiki：场景知识与平台共享知识两条路径

场景 Wiki 从独立知识服务读取有依据的学习结果；平台原有 Wiki 则有本人学习草稿和明确发布流程。两条链路有各自的对象和发布规则，不能把“私人草稿”直接画成自动对所有人共享。

```mermaid
flowchart TD
  n_scene["场景知识库读取 scene-knowledge"] --> n_pending{"存在待学习来源且能力可用？"}
  n_pending -->|"是"| n_sync["调用 scene-knowledge/sync"]
  n_sync --> n_kind{"来源类型"}
  n_kind -->|"资料"| n_learn["learned-wiki：基于当前原文生成"]
  n_kind -->|"业务数据"| n_business["business-knowledge：基于受控统计生成"]
  n_learn --> n_evidence["核对来源版本与引用证据"]
  n_business --> n_evidence
  n_evidence --> n_cards["形成有效知识卡与依据"]
  n_cards --> n_relations["过滤可见知识关系，展示星图"]
  n_cards --> n_bridge["平台桥接同步知识与原来源权限"]
  n_platform["完整管理页选择来源学习"] --> n_task["WikiLearningService 创建本人任务"]
  n_task --> n_harness["引擎生成并验证学习草稿"]
  n_harness --> n_draft["本人草稿"]
  n_draft --> n_publish["有权者明确确认发布"]
  n_publish --> n_article["WikiArticleService 共享知识版本"]
  n_article --> n_maintain["校订、下架、恢复与历史"]
  n_article --> n_knowledgeGraph["WikiGraph 与 WikiInsight 分析"]
  n_evidence -->|"来源变更或无权"| n_invalidate["旧结果失效或不展示"]
  n_article -->|"来源变更或无权"| n_invalidate
```

依据：[场景知识](../../integrations/mengine-wiki/apps/api/src/scene-knowledge.ts)、[业务知识](../../integrations/mengine-wiki/apps/api/src/business-knowledge.ts)、[学习服务](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/WikiLearningService.java)、[共享知识](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/WikiArticleService.java)、[关系图](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/WikiGraphService.java)。

## I08 指标定义、治理计算与多表融合

自动候选指标由规则生成，不是每个候选都调用模型。默认候选需核查；仅在显式委托自动定义并满足约束时，技术口径才可自动发布。治理数据计算使用已发布指标的固定 executionRequest；无适用定义应返回待确认，不能从样本外推全量业务数字。

```mermaid
flowchart TD
  n_source["获权且治理租约有效的数据集"] --> n_candidate["MetricDraftGenerator 生成规则候选"]
  n_candidate --> n_mode{"是否显式委托自动定义？"}
  n_mode -->|"否"| n_human["有权者核查粒度、单位、范围与排除项"]
  n_mode -->|"是"| n_auto["MetricAutomaticDefinition 按受限规则定义"]
  n_human --> n_plan["校验 COUNT 或 SUM 与固定执行计划"]
  n_auto --> n_plan
  n_plan --> n_ready{"计划与来源可执行？"}
  n_ready -->|"否"| n_wait["保留草稿或撤下失效发布版本"]
  n_ready -->|"是"| n_publish["发布指标编号和版本"]
  n_publish --> n_task["任务固定数据快照和指标版本"]
  n_task --> n_compare["compare_dataset 使用原 executionRequest"]
  n_compare --> n_match{"计划、来源权限和快照匹配？"}
  n_match -->|"否"| n_reject["拒绝执行，返回口径或权限原因"]
  n_match -->|"是"| n_calc["确定性计算并保存计算回执"]
  n_calc --> n_result["会话与数据画报引用同一结果依据"]
  n_task --> n_fusion["多表分支：受控关系与固定融合计划"]
  n_fusion --> n_intersection["复核全部来源权限交集和结构身份"]
  n_intersection --> n_deterministic["FusionCalculator 执行并生成可追溯结果"]
  n_deterministic --> n_result
```

依据：[指标目录](../../apps/api/src/main/java/com/dreamcore/workspace/scene/MetricCatalog.java)、[规则生成](../../apps/api/src/main/java/com/dreamcore/workspace/scene/MetricDraftGenerator.java)、[固定计划](../../apps/api/src/main/java/com/dreamcore/workspace/scene/MetricPlan.java)、[数据计算](../../apps/api/src/main/java/com/dreamcore/workspace/conversation/DatasetCalculationService.java)、[融合服务](../../apps/api/src/main/java/com/dreamcore/workspace/analysis/governed/GovernedFusionService.java)。

## I09 会话请求如何进入 AI 执行

任务先由平台持久化，再由 Worker 领取。引擎只能通过平台提供的内部工具读取业务数据，不能依靠模型自述跳过权限。模型运行使用实际接入的 DeepSeek Harness 核心组件；模型供应商由适配配置决定。

```mermaid
flowchart TD
  n_ui["Conversations 提交 prompt、范围与 requestId"] --> n_controller["ConversationController 分派普通、画报讨论或 PPT"]
  n_controller --> n_submit["ConversationService 校验身份、来源和幂等"]
  n_submit --> n_db[("会话、任务与初始状态持久化")]
  n_db --> n_claim["ConversationWorker 按并发槽位 claim"]
  n_claim --> n_runtime["EngineTaskRuntime 发送 taskId、attemptId 与 prompt"]
  n_runtime --> n_agent["AgentTasks 校验任务协议与重复尝试"]
  n_agent --> n_context["向平台读取获权任务上下文"]
  n_context --> n_tools["按能力装配检索、计算、文件等工具"]
  n_tools --> n_harness["Harness 在次数、时间和取消边界内执行"]
  n_harness --> n_model["计量包装的模型适配器"]
  n_model --> n_call{"模型需要工具？"}
  n_call -->|"是"| n_authorize["内部 API 再查任务租约和来源权限"]
  n_authorize --> n_tool["执行受控工具并记录真实回执"]
  n_tool --> n_model
  n_call -->|"否或完成"| n_validate["校验回复、来源、产物和执行回执"]
  n_validate --> n_finish["平台保存最终任务状态和尝试历史"]
  n_finish --> n_client["客户端同步最终回复与文件"]
  n_harness -.-> n_stream["流式文字与过程事件，仍待最终核定"]
```

依据：[请求控制器](../../apps/api/src/main/java/com/dreamcore/workspace/conversation/ConversationController.java)、[任务 Worker](../../apps/api/src/main/java/com/dreamcore/workspace/conversation/ConversationWorker.java)、[平台引擎适配](../../apps/api/src/main/java/com/dreamcore/workspace/conversation/EngineTaskRuntime.java)、[AgentTasks](../../engine/src/runtime/agent-task.ts)、[Harness](../../engine/src/runtime/harness.ts)。

## I10 暂停、补充、取消、重试与未知结果

这是主要用户操作的状态流，省略系统恢复的内部细分。操作必须带 requestId 与 expectedRevision；结果未知时须先根据服务器回执核对能否安全重试，不能仅因超时就重复执行。

```mermaid
flowchart TD
  n_queued["QUEUED 排队"] --> n_running["RUNNING 执行"]
  n_running --> n_succeeded["SUCCEEDED 成功"]
  n_running --> n_failed["FAILED 失败"]
  n_running --> n_input["WAITING_INPUT 待输入"]
  n_running --> n_partial["PARTIAL 部分结果"]
  n_queued --> n_capability["WAITING_CAPABILITY 待能力"]
  n_running --> n_unknown["RESULT_UNKNOWN 结果待核对"]
  n_queued --> n_pause["PAUSE 请求"]
  n_running --> n_pause
  n_pause --> n_paused["PAUSED；实时执行先发送停止请求"]
  n_paused --> n_resume["RESUME：复核来源、能力和版本"]
  n_input --> n_supplement["补充输入或 PPT 专用确认"]
  n_supplement --> n_resume
  n_partial --> n_resume
  n_capability --> n_resume
  n_resume --> n_queued
  n_queued --> n_cancel["CANCEL：取消并保留历史"]
  n_running --> n_cancel
  n_unknown --> n_reconcile["RECONCILE：依据工具回执核对"]
  n_reconcile --> n_safe{"服务器确认可安全重试？"}
  n_safe -->|"是"| n_failed
  n_safe -->|"否"| n_blocked["继续等待核对，不允许盲目重试"]
  n_failed --> n_retry["RETRY：新尝试，保留旧记录"]
  n_cancel --> n_retry
```
