# 开源组件替代研判 · 2026-10-17

结论：可复用的重点是执行内核和通用组件。建议先验证 Docling，以及 WeKnora / pgvector 两条检索路线，再补内部运行追踪；保留三端业务入口、权限与治理规则。没有证据支持为“全开源化”重写三端。

本次只做公开官方仓库/文档核查与本项目源码映射，没有安装候选项目、迁移数据或替换运行服务。优先级、适配方案和收益判断属于本次技术研判，不是用户已确认的架构决定。2026-10-18 按用户要求纳入项目文档，未改变技术建议的确认状态。

## 优先顺序与退出条件

1. **资料解析**：先把复杂 PDF 作为 Docling 的唯一替换切片；若中文表格与定位没有改善，继续用现有解析器。
2. **知识检索**：以同一授权语料对照 WeKnora 和 pgvector；前者省检索编排但增加服务，后者复用数据库但仍需实现嵌入与重排。先定主路线，不同时维护多套索引。RAGFlow 仅作复杂文档备选。
3. **运行诊断**：先把 Langfuse 接成内部观测旁路，证明能找到当前难定位的故障后再扩展。
4. **组件与数据工具**：ECharts、Tiptap、dlt、GX、DuckDB 按已确认功能或性能瓶颈逐项引入；每项先证明减少重复开发，不能把工具能力反推成新增产品需求。
5. **身份、权限与编排**：Keycloak、OpenFGA、Temporal、LangGraph 仅在明确增长条件下评估；现有链路已实现，迁移成本和语义风险大于接一个库。

未做工时实测，不给“节省百分之多少”或精确迁移天数。所有候选都需计入适配、回归、升级与运维成本。

## 逐项研判

### OSS01 Docling · P1 · 局部替换

**当前实现：** 平台通过 DocumentParser 调用 Python 解析器；PDF 使用文字提取和 OCR，复杂版式能力有限。

**可以交给它：** 复杂 PDF 的布局、阅读顺序、表格结构和扫描件解析；可以只替换 PDF 分支。

**仍由本项目负责：** 上传、原件与版本、解析任务、状态、权限复核和固定引用；CSV/XLSX 原值与公式缓存语义先保留。

**接法：** 独立受限进程或服务接入 DocumentParser，将结构化结果适配回 chunks/locator/status/warnings；新 parserVersion，不覆盖旧批次。

**代价与通过条件：** 中：模型资源、进程隔离和定位符适配。用获准中文扫描件、跨页表格及混合版式对照原解析器；检查页码定位、表格值、超时、取消和撤权。

**许可范围：** MIT；模型单独许可。代码 MIT 不等于全部模型同许可；按实际选用模型与镜像核验。

**流程位置：** F01、F04、F08、O02、O01。

源码依据：[parse.py](../../workers/parser/parse.py)、[DocumentParser.java](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/DocumentParser.java)。

官方依据：[Docling 官方仓库](https://github.com/docling-project/docling)；本次仓库快照 [0e542942](https://github.com/docling-project/docling/tree/0e54294231b69bc2cf7a39873235495788f76b57)（提交时间 2026-10-16T09:00:46Z）。这是调查快照，不是批准部署的版本。

### OSS02 WeKnora · P1 · 局部替换

**当前实现：** 本地检索按授权范围做关键词包含匹配；旧记录只核对过 WeKnora v0.8.0 API，未实机接入。

**可以交给它：** 索引、语义与混合召回、重排等检索服务；其 Wiki 编译可另作知识草稿生成器候选。

**仍由本项目负责：** 本系统企业/空间/文件版本映射、已授权来源集合、引用身份、Wiki 发布和来源撤回。

**接法：** 通过服务端适配器接检索 API，不嵌入其完整前端。先发非空获准版本范围，结果映射后再校验；当日主分支能力与旧 v0.8.0 契约需重新对齐。

**代价与通过条件：** 中至大：索引映射、模型服务和双系统生命周期。同一批问题与现有检索盲测；跨企业、空授权集合、撤权、删除、旧版本、索引重建必须不泄漏。

**许可范围：** 主项目 MIT；第三方逐项。只选择所需组件；模型与可选存储的许可和运维成本另算。

**流程位置：** F01、F04、F06、F08、O01、O02。

源码依据：[KnowledgeService.java](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/KnowledgeService.java)、[M3-A1本地解析与WeKnora接入边界.md](../技术/M3-A1本地解析与WeKnora接入边界.md)。

官方依据：[WeKnora 官方仓库](https://github.com/Tencent/WeKnora)；本次仓库快照 [e6dc60be](https://github.com/Tencent/WeKnora/tree/e6dc60be3278a598064a667369eb698d6c819eda)（提交时间 2026-10-17T14:37:58Z）。这是调查快照，不是批准部署的版本。

### OSS03 pgvector · P1 · 补强 / 替代检索内核

**当前实现：** 已有 PostgreSQL 保存资料片段，当前关键词匹配使用 strpos(lower(...))。

**可以交给它：** 替换检索中的向量近邻计算和索引部分，复用现有数据库；是 WeKnora 服务路线的轻量备选。

**仍由本项目负责：** 嵌入生成、分块、重排、中文关键词策略、授权 SQL、引用、索引失效与更新仍需开发。

**接法：** 在片段版本旁建立向量映射，查询前限定企业和许可范围，返回前重查；优先比较同库方案与独立检索服务，首轮二选一。

**代价与通过条件：** 中：运维增量较小，但检索编排仍需自研。按真实允许集合评测召回率、过滤后结果不足、中文查询和索引更新；不把向量距离当正确答案。

**许可范围：** PostgreSQL License。

**流程位置：** F01、F04、F06、F08、O01、O02。

源码依据：[KnowledgeService.java](../../apps/api/src/main/java/com/dreamcore/workspace/knowledge/KnowledgeService.java)。

官方依据：[pgvector 官方仓库](https://github.com/pgvector/pgvector)；本次仓库快照 [f37c13f6](https://github.com/pgvector/pgvector/tree/f37c13f68b57d2c3472b2214fbcff699d6d34876)（提交时间 2026-10-01T17:26:23Z）。这是调查快照，不是批准部署的版本。

### OSS04 dlt · P2 · 局部替换

**当前实现：** 已存在只读数据库适配器、定时采集和平台快照协议；不是从零搭采集系统。

**可以交给它：** 新增连接器时的读取、分页、增量游标、规范化及落地流水线。

**仍由本项目负责：** 获准数据范围、源库只读账号、字段业务口径、平台数据集 ID、快照回执及退出清理。

**代价与通过条件：** 中：跨语言适配与持久游标。验证重复采集不重复入库、游标回滚、空数据、字段变化和撤销连接；新增来源才优先考虑。

## 不作为无条件开源替代的项目

以下是实际选型需要区分的许可边界，按拟嵌入组件、版本与交付方式确认；不把这些项目笼统归为“不能商业使用”。

- **[Dify](https://raw.githubusercontent.com/langgenius/dify/main/LICENSE)**：修改版 Apache-2.0，附加条件。其许可对多租户使用要求书面授权；使用其前端还有限制品牌/版权修改的条款。我们是多企业产品，不能按无附加条件 Apache-2.0 直接规划整体嵌入。可在核清商业授权后再评估，不据此断言所有后端使用都被禁止。
- **[n8n](https://raw.githubusercontent.com/n8n-io/n8n/master/LICENSE.md)**：Sustainable Use License；ee 商业许可。当前许可限制为内部业务或非商业/个人用途等范围；作为向客户提供的产品能力与内部自动化用途须区分。不列入可自由嵌入商用多企业产品的首选清单。
- **[Airbyte 主仓库](https://raw.githubusercontent.com/airbytehq/airbyte/master/LICENSE)**：Elastic License 2.0。当前主仓库对向第三方提供可访问实质功能的托管/管理服务有限制。单独连接器、CDK、不同版本可能许可不同，不能把整个平台视为无条件开放的采集积木；本轮先评估 dlt。

## 应保留的核心

- 企业开通与负责人激活、成员/空间/职责交接、总部支持访问和企业暂停。
- 来源授权、版本固定、治理租约、权限变更、检索与工具二次校验、派生内容失效。
- 画报选题、五类内容、证据校验、关注板、反馈与经验准入规则。
- 私人文稿与共享成果分离，PPT 大纲确认，发布动作与可追溯任务回执。

这些能力也能用通用库实现其中的计算、存储或界面部件，但没有发现可不加业务适配直接接管全部语义的开源项目。

## 调研依据与限制

只使用官方仓库、许可和文档；当日仓库元信息及提交 SHA 保存在 opensource-sources.json。没有以星数推断安全或稳定性，没有对候选项目做漏洞审计、压测、模型质量或部署验收。主仓库许可不代表可选模型、依赖、企业模块及镜像打包许可相同。

既有开源复用还包括 React、Spring Boot、Fastify、数据库驱动、Mammoth、PDF 工具等；本次聚焦用户可感知功能的替代点，不把已有基础框架重新算成待替代工作。
