# 采集与知识生成架构修复实施计划

> 执行方式：superpowers:executing-plans，在独立克隆顺序实施，完成后独立代码审阅。用户已授权六项修复、验证和 PR 合并，无需再次确认同一范围。

目标：知识事实不能被模型改写，采集/接收语义一致，重复读取不重复计算，自动链路等待和失败可解释，新来源统计和跨组综合有清晰依据。

架构：保留 Spring/PostgreSQL 持久任务、TypeScript 模型执行及独立 Python 采集器。选择在现有模块内深化，不重写为微服务；使用版本绑定回执而非缓存权限；模型提供事实引用和解释，程序呈现计算事实。依据为 2026-10-27 架构评审及用户本次执行指令。

约束：不改生产；不放宽企业/空间权限；不静默漏表；不恢复人工批准白名单；不将 MODEL_DETERMINED 标为来源事实；不对结果未知任务盲重试；模型预算沿用现有上限。

## Review Focus
- 旧报告/运行中旧任务不得在升级后继续把模型文字当事实；失败需要可解释。
- 快照/定义/背景/权限变化必须即时阻止旧结论；持久回执只缓存确定性计算。
- 两端协议对空值、日期、小数、规则总数及未知规则一致。
- 全来源分组综合不能漏表、超预算或因一组失败冒充完成。
- 新表的单位、粒度、期间未声明时不推算财务指标。
