# 引擎消费就绪数据与调度解耦 · 改造方案 V0.2

**状态**：V0.2；本轮实施批次 A+B（仅平台 API，**前端代码不动**）  
**日期**：2026-10-28  
**范围**：美租验证中暴露的画报调度问题；原则适用于全平台  
**相对 V0.1**：收紧「就绪」定义；区分手动与自动；选空间「轮转 + 单张预检」；同批失败放行；不新增 `BLOCKED`；写明**可批量出图**  
**约束**：员工端 / 管理端前端本轮不改；后端返回既有 `status` + `reason`，现有前端文案即可展示失败原因  
**相关**：数据基座 AI 可用闸门、画报生成调度、引擎任务编排

---

## 1. 要解决什么

员工端已触发画报生成，但长时间停在「正在生成 / 排队 / 等待资料就绪」，引擎看板「执行中」多为 0。两类问题被混在一起：

1. **展示**：阻塞仍写成「正在生成」。
2. **调度**：未就绪空间或来源占住同一次多张的队列，拖住本可开跑的任务。

本方案固定边界与分批做法。自动画报「等人补资料再继续」的等待保留；要改的是**手动生成**的假排队，以及同批里一张卡住导致其余张永远不派发。

---

## 2. 原则

### 2.1 引擎只消费已授权、且达到约定可用态的数据

引擎不直连业务库，只凭任务令牌回调 `/internal/v1/agent-access/…`。

- 数据集：须过分析就绪（`analysisReadiness`；知识侧还有 `datasetKnowledgeReady`）。画报治理集只用已发布固定计划（`fixedPlanOnly`）。未治理快照不进入分析授权。
- 上传资料：解析到 `READY` 或已定义的 `PARTIAL` 后，才进入检索与分析。`PARTIAL` 是允许的可用态，不是未解析完的半成品。
- 资讯类走公开检索，不依赖企业资料库是否为空。

### 2.2 流水线顺序不变

```
采集 / 上传  →  解析与治理（至 AI 可用或资料可用）  →  平台按任务授权开放  →  引擎执行
```

AI 可用是资格闸门，不是「再去源系统取一次数」的开关。引擎由任务驱动，不监听「又多一条 AI 可用」去拉数。「AI 可用后自动开一轮画报」不在本方案实施包内，另开需求。

### 2.3 未就绪只挡住自己，不拖死已就绪

某一空间无资料、某一来源口径未确认、某一表治理失败，不得阻塞其他已就绪空间或来源上的任务。同一次手动「生成 N 张」里，各张在数据上应能各自结束：不合格的该张立即失败并写清原因；合格的继续派发。这是平台调度的事，不是让引擎去读半成品。

自动生成可以停在 `WAITING_DATA`，等人补岗位、资料或口径后再跑。手动生成不把这种等待当成默认结果。

### 2.4 看板只反映任务状态

「执行中」只计真实 `RUNNING`。`QUEUED`、`WAITING_*`、任务 `PARTIAL` 不点亮执行中。目标是该跑的跑、该停的说清原因，不是让球一直转。

## 3. 现状（与代码对齐）

| 环节 | 现状 |
|---|---|
| 引擎读数 | 经 agent-access 与就绪/授权检查，符合 2.1 |
| 采集 | 先采后治，符合 2.2 |
| `chooseSpace` | 已有软偏好：优先「来源全部 READY/PARTIAL」的空间，否则退到「有任意来源」的空间；仍可能选中空空间。多张会在授权空间间轮转，不是永远绑最满的一个空间 |
| `generateSelection` | 先建 `QUEUED`，资料与治理检查在后续调度 |
| `selection_id` | 后一张要等前一张进入成功、无新内容、失败、取消或权限撤销；前一张停在 `WAITING_*` 时后一张不派发 |
| 手动 `NO_MATERIALS` 等 | 可长期 `WAITING_DATA`，并占用手动额度预留 |
| 岗位门禁 | `WORK_GOAL_REQUIRED` 同样会停住自动/手动派发 |
| 唤醒 | 依赖轮询与 idle 退避 |
| 前端 | 已在本地把阻塞从「正在生成」里分开（待发布） |

生产复现（美租，2026-10-28）：集团财务 `NO_MATERIALS`；个人空间 `SOURCE_GOVERNANCE_REQUIRED`；同 selection 的后续张排队。全房通已有 AI 可用表，仍被这套编排挡住。

旁路、本方案不展开：任务 `PARTIAL` 要人「查看并决定」；`EQUIVALENT_ANALYSIS_EXISTS` 取消重复分析；采集端 `SOURCE_SCOPE_CHANGED` 等源站交付。

## 4. 目标行为

1. **可以批量出画报**。员工一次请求仍最多 6 张（受当日剩余额度限制）；`generateSelection` 一次原子建齐本批各张。做好的依次出现。本方案不取消批量，只改「不合格的那张怎么结束、会不会堵住后面」。
2. **手动提交即可知**。`GENERATE_MORE` 在建批当刻做预检（岗位/经营目标；资料是否 `READY`/`PARTIAL`；若主要是数据集则 `analysisReadiness`）。明显不可跑的该张**立即 `FAILED`**（带既有 `reason`），不进入无限 `WAITING_DATA`。幂等重放返回同一结果。
3. **轮转保留，单张预检**。未指定或指定空间无可用证据时，在授权空间间落到有 `READY`/`PARTIAL` 可读来源的空间，优先把图画出来；只有所有授权空间都不可用时才该张 `FAILED`。不把空筛选写成长期排队。
4. **同批失败放行（串行派发）**。同一 `selection_id` 下按张派发模型任务：前一张成功或失败后，后一张继续。不做多张同时打满模型的真并行（受现有会话并发上限）。批量 = 一次下多张单；串行 = 派发节奏。
5. **自动等待保留**。初始化/定时批次缺资料、缺岗位、缺口径时仍可 `WAITING_DATA`。不把自动任务改成「一缺就失败」。
6. **引擎输入不变**。不放宽半成品进入 agent-access。
7. **状态沿用现有枚举**。不新增 `BLOCKED`。前端本轮不动，靠已有 `FAILED` + `reason` 文案展示。
8. **条件变化可续跑**（批次 D，可选，本轮不做）。

已定默认：

- 手动不可跑：**建批并立即失败（带 reason）**。整单每张都会失败时仍一次返回这些失败批次。
- 同批：**失败放行的串行派发**，保留批量下单。
- AI 可用后自动开任务：**另案**。
- **前端本轮不改**。

---

## 5. 非目标

- 不让引擎直连数据库，不把 AI 可用改成采集触发器。
- 不伪造 `RUNNING`。
- 不取消治理闸门，不把 `PARTIAL` 以外的未解析资料放进分析。
- 不在本方案里改采集端范围校验失败。
- 不把自动画报改成「缺资料即失败」。

## 6. 分批实施

### 批次 A · 手动预检（优先）

- 仅 `GENERATE_MORE`（含 `generateSelection`）：建批时预检岗位、目标空间资料、将用到的数据集分析就绪。
- 不合格：该张 `FAILED` + 既有 `reason`（如 `NO_MATERIALS`、`SOURCE_GOVERNANCE_REQUIRED`、`WORK_GOAL_REQUIRED`），`finished_at` 立刻写下。
- `chooseSpace`：保留轮转；候选空间预检失败则换下一个；都失败则该张立即失败。
- **验收**：在「集团财务」无资料、「全房通」有可用资料时，手动生成不会把空空间挂成长期等待；员工马上看到失败原因。全房通侧的那张能进入后续派发。岗位为空时手动请求立即失败并提示去填写，而不是转圈。

### 批次 B · 失败放行（A 之后，范围应收小）

- 调整 `selection_id` 放行条件：前一张若是 `FAILED`（含 A 产生的立即失败），后一张可派发。
- 若仍存在人手未改完的旧 `WAITING_*` 手动批次：对「人侧条件且短期内不会自愈」的手动批次，调度改为失败并放行后张（与 A 的立即失败对齐，避免存量单继续堵队列）。自动 `WAITING_DATA` 不因此被改成失败。
- **验收**：一次生成 2 张，一张空间不可用、一张可用时，不可用张失败并带原因；可用张在合理时间内获得 `task_id`，并进入 `RUNNING` 或明确成功/失败。不要求测试时一定「看见球上的执行中」（该窗口很短，且受任务并发上限限制）。

### 批次 C · 展示口径（本轮不做前端）

- 后端不新增状态。前端改文案另开任务；本轮仅保证 `FAILED`/`WAITING_*` + `reason` 正确。
- 立即失败的手动批次不得再计入 `reserved`（`FAILED` 本就不在 reserved 查询里，回归确认即可）。

### 批次 D · 就绪唤醒（本轮不做）

- 岗位保存、解析完成、治理发布时提前 `next_idle_check_at`。

## 7. 改动面

| 层 | 方向 |
|---|---|
| 平台 API | `BriefingGenerationService`：仅手动路径预检、`chooseSpace` 跳过不合格空间、selection 在前张失败后放行；可选唤醒 |
| 契约 | 不新增状态；补文档说明 `WAITING_*` 即阻塞 |
| 引擎 | 不改读数模型 |
| 前端 | **本轮不动**；既有 `status` + `reason` 文案即可展示失败 |
| 测试 | 空空间 + 就绪空间同一次手动生成；岗位为空立即失败；自动缺资料仍 `WAITING_DATA`；失败放行；额度不再预留已失败手动批次；权限与 AI 可用回归 |

---

## 8. 总验收

- 引擎输入仍仅为授权且达到约定可用态的数据。
- 手动生成不再因空空间或未治理来源长期停在「正在生成」。
- 同一次多张里，失败的一张不永久堵住后面可用的一张。
- 自动任务仍可等待资料、岗位或口径，条件满足后继续。
- 用户能区分正在跑、排队、因何等待或为何失败，并可取消仍打开的等待。

## 9. 产品含义（供对照使用习惯）

见文末不单列实施任务。实施时以第 4–6 节为准。

- 手动点「生成」：能做就做；不能做马上说明原因（去补资料、去数据基座确认口径、或去填岗位），而不是转圈。
- 一次要多张：做不了的那张标失败，做得到的继续，不用整单作废，也不用等空空间「自己长出资料」。
- 没人点、系统自己出的画报：缺条件就等着，补上了再出，避免半夜把「还没上传」记成失败。
- 部门空间仍然会轮到：空部门不会偷偷改去只给资料最多的空间出图，而是这张明确失败，下次有资料再生成。
