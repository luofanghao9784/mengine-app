# 总台工作循环接通（2026-10-14）

用户确认补齐数据接入后的总台模型执行、自动处理和运行展示。本轮在既有企业权限与数据保留基础上实施，不更换模型供应商，也不把演示动画当作任务执行。

## 原因与改动

此前本地总台以 `agentMode=off` 启动。企业分析执行器只在有效模型模式下发现来源和调度，因此虽然有 917 个符合条件的资料片段，队列一直为空。Mengine 的知识处理使用另一条已配置模型的接口，记录在 `scene_processing_runs`，原总台遥测没有读取这些记录。

现在：

1. 将现有 Mengine 的百炼北京工作空间、密钥和 `qwen3.8-max-0902` 配置适配到总台已有 Bailian 运行器。私有配置只保存在 `.local/model-private/bailian.json`，0600，凭据不进入数据库业务表、浏览器、文档或 Git。
2. 启用真实模型及已有自动处理器。企业分析继续通过 `company_analysis_current_chunks` 发现当前有效来源，按文件和有界片段批次调度；新解析版本自动进入队列，旧来源失效会取消或隔离结果；已成功版本不重复分析。
3. 增加 `SCENE_KNOWLEDGE` 遥测通道，覆盖业务知识、资料知识及星图处理的真实运行、成功和失败状态。加入工作循环的处理轨道和详情。
4. 企业分析排队/重试等待从 `company_analysis_items` 读取，运行/完成从 `company_analysis_attempts` 读取；不会把同一批片段重复计为并发运行任务。
5. 每分钟无变化的 `SYNC_INPUTS` 检查不算成模型处理，避免没有业务工作时动画仍伪装繁忙。成功仅显示近 5 分钟；历史失败保留可见，不能因后来成功而抹掉原记录。

## 本地启动与保留

新增显式 `--automatic-work` 启动参数，仅能与 `start --live` 一起使用，保存自动处理偏好；没有模型配置时拒绝。默认启动仍为原有离线模式，不读取环境中碰巧存在的密钥。

本机 `.local/start-three.sh` 已改为：

```sh
python3 -u scripts/local/trial.py start --phone-local --live --enable-live --automatic-work
```

同一数据库目录和账号继续使用，15 张表、62 份资料、87 条知识保留。后续本机重启使用该脚本；`--enable-live` 支持既有本地实例切换真实模型，`--automatic-work` 明确覆盖仅手工验收的自动任务关闭设置。自动工作偏好会随实例保存，不是每次启动自动默认开启。

自动分析、经验提炼/核验、通用经验清洗和已配置计划使用已有调度器。没有触发条件的功能保持空闲；独立自进化执行器仍显示“待接入”，本次没有虚构其运行能力。

## 验证

- Java：15 项通过，包含企业分析批次、并发槽、来源变化、重试和结果保护；新增两项真实 PostgreSQL 遥测测试验证场景处理进入轨道、无变化同步不冒充处理、企业隔离及排队转换无重复计数。
- 前端/契约：16 项通过，包含新增通道、处理轨道、严格通道列表、无任务时无光子。
- 启动配置：18 项通过，包含私有配置、模型/自动模式隔离与显式自动处理覆盖。
- 企业/总台前端生产构建、引擎构建、API 打包通过。
- 本地真实模型执行：已观察到 `qwen3.8-max-0902` 返回成功批次，`company_analysis_items` 从 QUEUED → RUNNING → SUCCEEDED；第一轮验收时已有 11 批成功、112 个片段成功，并有正在执行及进入 RETRY_WAIT 的真实任务。数量会随后台处理继续变化。
- 浏览器“繁忙演示”为关；总台已显示执行中任务、真实企业分布、排队数、近期完成和失败记录。“业务知识与星图”出现在工作循环详情。

模型分析成功可以返回“没有可提炼的企业信息”；成功批次数不能当成新增知识/标签数量。本轮没有把空候选伪造为输出，也没有清除失败记录。已有业务知识仍沿原知识接口收纳。首次启用会处理历史积压，模型调用会产生实际用量；失败沿既有次数上限和退避重试。
