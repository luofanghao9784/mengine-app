# 画报引擎对齐新卡面开发任务书 V0.1

日期：2026-10-11。状态：任务说明，尚未开始实现。用户已确认画报卡面与详情页的新样式标准并合入主线（[#75](https://github.com/dimmm1125-coder/dreamcore-workspace/pull/75)，提交 `861d062`）；本文说明引擎与平台需要配合的改动，交由主线排期。沿用 CUI-05、AI-11—AI-13、DASH-01—DASH-04，不新增需求编号。

设计参考：`tests/fixtures/briefing-expression/home.html`（定稿样张）与 `tests/fixtures/live-magazine/?faces`（真实组件的合成样例）。

## 1. 背景

新样式只改了前端怎么画。卡片内容、图表样式、版式仍由引擎交付时决定，所以引擎不调整，新生成的卡只能部分达到新标准。

前端现在按下表把核验数据画成卡面（`src/briefing-live/card-face.ts` 的 `faceKind`）：

| 引擎交付的情况 | 卡面图形 |
| --- | --- |
| 图表样式为 `TABLE` | 小表格（未改） |
| 期间汇总（`periodMode=SUMMARY`）或 `CURRENT_BAR` | 名次榜 |
| `DELTA_BAR` | 正负细条 |
| 其余，且两端是期间、不超过 6 组 | 斜率图，涨幅最大的一组领读 |
| 其余（两种类别，或多于 6 组） | 每组两根细条对照 |

“两端是期间”的判断：`periodMode=MONTH`，或两个列标签都像期间（如 `2026-08`、`9月`、`2026 Q3`）。`GROUPED_BAR` 与 `DUMBBELL` 在卡面上不再有区别。有图形的数据卡，卡面不显示摘要，只显示标题、图形和页脚。

## 2. 现状中与新标准不符的地方

以下是 2026-10-11 在云端实例真实卡片上观察到的情况，以及对应的代码位置。

1. **数据卡没选样式时默认为表格。** `engine/src/runtime/briefing-delivery.ts` 的 `normalizeArguments` 在模型未提交 `presentation` 时补 `chartStyle: 'TABLE'`。表格在新标准里没有新图形，这部分卡等于用不上新样式。
2. **给模型的选图说明仍按旧图形描述。** 同一文件的工具说明写的是“少量分组用 GROUPED_BAR、很多分组用 DUMBBELL”等。模型不知道前端现在按“期间还是类别”“几组”来决定图形。
3. **版式几乎都是默认的 EDITORIAL。** 页面上没有出现 STEPS、COMPARISON、KEY_METRIC。新做的大号步骤序号和重点数字领读因此基本不出现。
4. **标题有时说不出结论。** 例如“门店订单金额分布与支付完成情况分析”。卡面不显示摘要后，这类标题的卡读不懂。
5. **图上直接显示状态码。** 分组名与列标签（`active`、`on_leave`、`finance_confirmed`、`canceled`）来自核验计算，不经过模型，写作规则里的翻译要求管不到。
6. **两种状态被当成“两期”比较。** 多张卡的两列其实是“财务已确认”与“已取消”。前端已避免把它画成变化，但这类问题本质是构成，需要相应的计算。
7. **有无效卡。** 一张订单卡的数值全为 0 或缺数据，正文只说“大部分订单金额为 0”。前端已改为不画图，但这类卡本不该生成。

## 3. 任务

按改动范围从小到大排列。E1—E4 只涉及提示词、默认值和已有校验；E5、E6 涉及计算、契约与平台。

### E1 数据卡的默认图表样式

- 模型未提交 `presentation` 时，数据卡默认样式不再是 `TABLE`。建议：期间汇总默认 `CURRENT_BAR`，两列对比默认 `GROUPED_BAR`。
- `TABLE` 只在模型明确选择时使用。
- 验收：未提交版式的两列对比卡，卡面为斜率图或细条对照；未提交版式的汇总卡，卡面为名次榜；平台 `BriefingPresentationPolicy` 仍接受这两个默认值。

### E2 更新给模型的选图说明

把工具说明里的图表部分改为按业务问题描述，并说明卡面的实际效果：

- 两个期间比较同一指标：`GROUPED_BAR`。不超过 6 组时卡面是斜率图，会突出变化最大的一组，因此标题宜落在“谁变化最大”或整体方向上。
- 只想强调增减：`DELTA_BAR`。
- 看本期谁高谁低，或期间汇总：`CURRENT_BAR`。
- 读者需要逐个核对精确数值：`TABLE`。
- `DUMBBELL` 与 `GROUPED_BAR` 在卡面已无区别，说明中合并，协议枚举保持不变以兼容旧卡。
- 验收：说明文字不再出现已不存在的图形描述；引擎现有 schema 子集校验通过。

### E3 标题必须独立表达结论

在 `engine/src/runtime/briefing-writing-rules.ts` 增加并提升版本号：

- 数据卡标题是一句带结论的话，尽量含关键数字或方向，不用“……分析”“……分布”“……情况”这类只说主题的写法。
- 标题建议不超过 28 个字（卡面两行以内）。超长不拒绝，但作为交付前检查项。
- 验收：补充规则文本与对应的规则测试；用合成模型联调时，交付前检查能指出只说主题的标题。

### E4 加强版式引导

- 建议类卡有两条以上明确行动时用 `STEPS`；有两个以上实际方案时用 `COMPARISON`。
- 数据卡结论落在单个数值上时用 `KEY_METRIC`，并指定 `focusGroup` 与 `focusValue`。
- 仍遵守现有约束：版式只引用已有段落，不新增事实，不把观察改标成行动或方案。
- 验收：说明文字更新；平台现有的版式合法性校验不放宽。

### E5 图表标签的中文显示

- 需要一张“原始取值到中文显示名”的对照，范围包括分组值与列标签。来源可以是数据集的列值字典或企业配置，由平台提供，不由模型临场翻译。
- 显示名只用于呈现，核验计算、哈希、去重指纹和依据区域继续使用原值。
- 未知取值按原值显示，不猜测含义。
- 这一项需要先由用户确认 9POP 各状态的中文叫法，以及对照表放在哪一层维护。**未确认前不实现。**

### E6 新增两类核验计算

样张里的趋势线和比例带需要新的数据形状。目前 `compare_dataset` 只有两期对比（`COMPARE`）和分组汇总（`SUMMARY`）。

| 计算 | 输出 | 用途 | 关键规则 |
| --- | --- | --- | --- |
| 多期序列 | 同一指标按周或月的 3—24 个点，可选按一个维度分组 | 趋势线、重点数字旁的走势 | 期间连续，缺失期间保留为缺失，不补零；注明时区与归期口径 |
| 构成占比 | 同一范围内按类别的合计及其占总量的份额 | 比例带 | 各类别相加必须等于核验总量；份额由平台计算，不接受模型填写 |

- 需要相应扩展 `contracts/public-api/briefing-content.ts`、平台内容校验与计算回执。属于跨引擎契约变化，按协作规则需要双方评审。
- 写作规则中“分组金额计算不证明占比”的限制，在构成占比计算可用后才对该类卡放开。
- 前端的趋势线与比例带在契约确定后再做，本任务书不包含。

### E7 不生成无内容的数据卡（可与 E1 合并）

- 2026-10-26 按已确认业务口径修订：有实际匹配记录、必需数值完整的真实零值可以交付为有价值业务基线；没有匹配记录或必需数值为NULL时不能补零，沿现有“暂无新内容”协议说明缺口。缺失期间保留为缺失，不将正负相抵的合计零误判为无数据。
- 验收：有实际匹配记录的真实零值得到 `PREPARED` 回执；空数据、NULL金额和必需日期缺失不能产生伪造零值计算或画报。事实标题与正文采用平台核对后的持久化内容。

## 4. 边界

- 不改变卡片生命周期、权限、来源授权、去重与额度规则。
- 版式与图表样式仍是视觉选择，不参与内容指纹；存量卡不重新生成，旧附件继续可读。
- 模型仍不提交数字、URL、HTML、CSS 或代码。
- 规则更新只对之后的新生成生效。
