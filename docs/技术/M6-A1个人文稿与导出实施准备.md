## 已确认范围

系统生成的文稿可在网页编辑，Word/PDF 导出；表格成果可下载 Excel。原 Office 文件继续下载编辑后上传新版本。个人成果不自动同步企业资料，共享需明确选择目标和满足维护权限；共享成果不公开私人会话。首期前端保持轻量，三个入口使用共用组件。

第一条已实施流程为：完成 Agent 任务 → 明确保存为个人文稿 → 修改标题/正文 → 保存新版本 → 下载指定版本的 Word/PDF。保留成功任务及原产物，不回写模型回复；用户修改属于新的文稿版本。导出由平台可替换的确定性文件服务执行，不再调用模型，不依赖开发工具的本机专有运行库。

## 已确认的来源权限规则

例：员工读取获准的财务空间资料，生成报告并保存到个人空间，编辑后被撤销财务空间访问权。这份已保存报告是否仍可查看、编辑、导出？

| 选择 | 具体行为 | 对实现的影响 |
| --- | --- | --- |
| 跟随来源权限（建议） | 记录保留，但失去任一必要来源空间权限后不可继续访问报告；恢复权限后可恢复访问 | 文稿及每一版本保存来源依赖，所有读写/导出复核当前来源权限 |
| 明确保存后独立保留 | 已保存的个人报告继续可用；原资料、引用全文和原会话按原权限拒绝 | 保存是持有独立成果副本的业务边界；必须在操作中说明，来源链接不授予原资料访问 |

2026-09-24 用户选择第一条：跟随来源权限。第二条仅保留为已排除方案，不再等待确认。

本问题针对新保存和编辑的个人文稿。当前会话及工具产物仍按照已有规则检查来源空间，未更改为永久保留访问。租户停用、成员停用或账号停用始终拒绝访问，两条选项都不允许跨企业或管理人员访问私人内容。本次授权不扩大来源资料的共享范围。

## 本批接口设计

- 文稿 ID 与不可变版本 ID 分开；最新版本号由平台维护。初次保存来自本人已成功任务，绑定确切任务 ID，可选原产物 ID。正文和来源清单由平台读取，客户端不能自报他人任务的正文作为系统成果。
- 保存请求使用 requestId 和 expectedRevision。重复同请求返回已写版本，不重复建文稿；相同键不同内容拒绝。两端同时编辑时提示版本冲突，不静默覆盖，也不把“最后写入”当合并。
- 网页只在明确点击保存时写版本；未保存编辑可按账号、企业、文稿区分暂存本标签页草稿，恢复时先核对服务端权限及版本。关闭标签页和跨设备同步不在本批承诺范围。
- 导出明确指定版本，下载返回摘要和长度，前端核验；导出失败不生成成功记录。服务不可用时保留已保存正文并提示，禁止回退成扩展名正确但内容错误的文件。
- 初批文稿以标题、段落、基础标题层级和列表为范围。Markdown/HTML 只作为受控文字或有限样式处理；图片、脚本、外部资源、宏、复杂模板不得因正文出现标签而被执行或联网读取。复杂表格与正式模板另按样例验收，不把 DOCX/PDF 扩展名当全面支持。
- 平台接口需要保持引擎独立；文稿修改和导出不改 Agent 协议。前端可复用已有文稿组件，但真实读写不回退 Demo 数据或浏览器 localStorage 权限。

按已确认的第一条实现数据库来源关联与访问复核；编辑不能去除来源依赖。发布到共享资料将作为后续独立写动作，复用目标维护权限、版本和幂等规则；不自动发布历史会话或动态详情。

## 验收准备

1. 从同一个已成功任务反复保存，不产生意外重复文稿；版本来源及用户编辑事实可区分。
2. 保存、版本冲突、响应丢失重试、刷新恢复与另一个标签页编辑有明确结果。
3. 普通成员、共享空间同事、企业管理员和总台均不能读取其他用户个人成果；停用、撤权和重新授权按确定后的规则验证。
4. 中文、英文、长段落、分页、特殊字符和纯文字 HTML 样例分别导出；校验 DOCX 结构、PDF 文本/字体与文件摘要，并实际渲染逐页检查，不以 HTTP 200 当成可用文件。
5. 历史文稿版本导出不变；生成新版本不改旧任务、旧资料或旧导出来源。多个租户的缓存、临时文件和文件服务任务隔离。
6. 三端共享样式，窄屏可编辑保存和下载；浏览器仿真不替代手机真实文件打开体验。

实施阶段选用 Java PDFBox 3.0.8 与受限 OOXML，未引入 ReportLab。字体与组件的固定版本、限制及实际产物验证见[技术边界](M6-A1个人文稿与导出边界.md)和[验证记录](../交接/M6-A1个人文稿与导出验证-2026-09-24.md)。
