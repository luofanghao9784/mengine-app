# 画报阶段与工具规则统一：实施计划

> **执行说明：** 后续实施使用 superpowers:executing-plans，按任务逐步执行；如用户另选子代理执行方式，再使用 superpowers:subagent-driven-development。当前文档仅为计划，不表示运行代码已修改。

**目标：** 让画报提示、工具选项和执行前阶段校验使用同一份具体动作许可，保留现有预算、权限、计数与终态。

**架构：** 引擎内新增画报执行策略模块，读取本次执行的只读状态，输出阶段、允许动作、拒绝原因与提示说明。三处消费者共用结果，执行前按最新状态重新生成；真实工具、扣额、授权与回执仍走原路径。

**技术栈：** 现有 TypeScript 引擎、Node 测试、Java/Spring Boot 平台及临时 PostgreSQL 集成测试；不引入新依赖。

**设计依据：** [设计记录及 Q1—Q6](画报阶段与工具规则统一-设计记录.md)。对应 #178、BQ-03、BQ-06。

## 全局约束

- 仅现有画报生成链路；普通会话、知识工作流及原生 DH 不接入本策略。
- 保留三个粗阶段、现有能力协商、选题与计算要求；不额外增加可执行动作。
- 数据查找和资料检索的三次门槛分别保留，不能合并成共享三次。
- 补证仍为一次申请、两次读取，原有执行前扣额与失败耗额保持；不得换题、重算或延长预算。
- 保留真实计算尝试的原计数时机，不把本地参数错误混为真实执行；不因重构重新赠送次数。
- 当前画报分支的 55 秒、8 次模型调用、8 次工具调用及有公共研究技能时的 7 次工具调用变体保持；10 秒收尾窗口与交付格式错误的现有停止条件保持。实施前对照当时配置及分支确认，不把这些值推广到其他工作流。
- 预算仍属于当前已有 run/attempt/任务计量机制，各自范围不变。不新增持久化阶段表，不重置计数、租约或 attempt。
- 平台身份、权限、来源版本、用量、计算及交付凭据检查不删除；引擎许可不等于平台授权。
- 结果不明、取消、待核对及已有回执恢复不触发隐式付费重放。NO_NEW_CONTENT 的正常终态保持。
- 不新增公开协议字段、数据库迁移或生产配置开关；使用现有提示及错误处理通道表达受限反馈。
- 全部示例和测试用合成数据；本地真实验证另记，不以模拟测试声称真实模型已通过。

## 文件职责与内部约定

| 文件 | 职责 |
| --- | --- |
| 新增 `engine/src/runtime/briefing-execution-policy.ts` | 画报阶段、具体动作许可、原因与当前可行下一步的集中判断；无副作用 |
| 修改 `engine/src/runtime/agent-task.ts` | 从当前变量构造只读状态；同一入口供提示、工具选项及执行校验消费；保留执行与计数 |
| 修改 `engine/src/runtime/briefing-topic-strategy.ts` | 保留选题内容；将旧阶段导出迁移或临时委托至新模块，不维护第二套阶段规则 |
| 必要时修改 `engine/src/runtime/briefing-evidence-budget.ts` | 仅提供只读状态或复用读取资格，避免重复维护补证动作名单；不改变 request/consume 语义 |
| 新增 `engine/tests/briefing-execution-policy.test.mjs` | 同状态具体动作许可、拒绝原因、无副作用测试 |
| 修改现有 `briefing-topic-strategy`、`briefing-evidence-budget`、`briefing-delivery` 测试 | 锁定实际接线、计数、边界与交付行为 |
| 必要时补充平台既有测试 | 验证引擎允许后仍会被真实平台撤权、来源或凭据检查拒绝；不修改平台规则 |

以下名称是可逆的工程约定，不增加产品策略。新模块只有一个求值入口，消费者不自行解释阶段。

```ts
export type BriefingPhase = 'RETRIEVAL' | 'CALCULATION_OR_DELIVERY' | 'DELIVERY';
export type BriefingAction = Readonly<{ tool: string; action?: string }>;
export type BriefingPolicyReason =
  | 'ALLOWED' | 'TOPIC_REQUIRED' | 'RETRIEVAL_CLOSED'
  | 'CALCULATION_CLOSED' | 'SUPPLEMENT_UNAVAILABLE'
  | 'CAPABILITY_UNAVAILABLE' | 'EXECUTION_STOPPED' | 'UNSUPPORTED_ACTION';
export type BriefingPolicyState = Readonly<{
  calculated: boolean;
  datasetLookups: number;
  sourceQueries: number;
  retrievalClosedByPlan: boolean;
  topicRequired: boolean;
  topicSelected: boolean;
  calculationRequired: boolean;
  calculationAttempts: number;
  executionStopped: boolean;
  supportedActions: readonly BriefingAction[];
  supplement: Readonly<{
    requestAllowed: boolean;
    readableActions: readonly BriefingAction[];
  }>;
}>;
export type BriefingActionDecision = Readonly<{
  allowed: boolean;
  reason: BriefingPolicyReason;
  nextActions: readonly BriefingAction[];
}>;
export type BriefingPolicy = Readonly<{
  phase: BriefingPhase;
  allowedActions: readonly BriefingAction[];
  modelInstructions: string;
  decide(action: BriefingAction): BriefingActionDecision;
}>;
export function briefingExecutionPolicy(state: BriefingPolicyState): BriefingPolicy;
```

`sourceQueries` 是既有资料检索计数的只读映射，不能与 `datasetLookups` 合并。`supportedActions` 由当前协商能力和具体动作目录形成，不是让模型自报能力。补证资格复用原预算对象的只读判断，禁止在生成策略、提示或工具选项时调用 consume。`executionStopped` 只反映现有取消/预算/时间结果，策略不另设时间窗口。

动作清单以当前画报分支的实际工具和具体 action 为准，任务 1 将锁定完整清单。不能从“核对”这个标签推导出原本没有的通行资格。新内部 reason 与原错误通路做显式映射，不把内部原因名直接替换原公开错误码。

## 审查重点

| 风险 | 归属测试 |
| --- | --- |
| 同名工具的目录核对被误当新检索，或数据读取被误放行 | 任务 1、2、3：动作级正反例 |
| 计算后补证重开计算、换题或重置额度 | 任务 1、2、3：计算/补证交叉状态 |
| 提示已生成后状态变化仍沿用旧许可 | 任务 3：执行前重新求值 |
| 引擎允许被误当平台授权 | 任务 3、4：撤权、来源变更、无效凭据 |
| 普通会话受影响，或失败/回执恢复造成隐式重放 | 任务 3、4：非画报与恢复/计量回归 |

## 任务 1：建立当前行为对照

**文件：** `engine/tests/briefing-delivery.test.mjs`、`engine/tests/briefing-topic-strategy.test.mjs`、`engine/tests/briefing-evidence-budget.test.mjs`；新增策略测试文件先记录案例，不依赖尚未存在的导出。

**消费：** 当前引擎真实执行入口及合成平台 fixture。**产出：** 有明确预期的状态/动作对照表，供任务 2、3 使用。

- [ ] 记录工具全集及其具体 action，标注当前支持条件、次数消耗时机与拒绝路径；包括固定计划、新闻和非数据画报分支，不只检查 DATA。
- [ ] 增补 `metadata_reads_remain_usable_after_three_lookups`：三次成功查找后，在已安装业务计划的既有条件下核对目录和读取计划可执行，额外普通数据检索被拒绝。
- [ ] 增补 `supplement_does_not_reopen_calculation`：一次申请得到两次读取，执行前扣额；读取失败不返还；完成计算后补证不恢复计算或换题资格。
- [ ] 增补 `missing_topic_and_no_new_content_keep_existing_outcomes`：保留选题前计算拒绝、有效 NO_NEW_CONTENT 正常结束。
- [ ] 运行下方“定向引擎检查”。现有修复已生效的用例可以直接通过，不制造无意义的失败；预期差异必须先归因。
- [ ] 提交行为对照测试，运行逻辑不变。

## 任务 2：实现无副作用的策略求值

**文件：** 新增 `briefing-execution-policy.ts` 和 `briefing-execution-policy.test.mjs`；必要时只增加补证预算只读视图。

**消费：** 任务 1 对照表及上文内部类型。**产出：** `briefingExecutionPolicy(state)`；尚不接管实际任务。

- [ ] 先写新入口测试并确认因入口未实现失败：0、2、3 次查找及计算成功后的 phase，独立资料搜索计数，固定计划提前关闭检索。
- [ ] 增加具体动作断言：相同工具的 `reconciliation_catalog`、`briefing_plan` 与 `dataset_search` 不能被当成同一许可；其结论与任务 1 对照一致。
- [ ] 增加 `policy_evaluation_never_consumes_budget`：重复求值、读取 allowedActions、生成 modelInstructions 均不执行工具、不改计数、不调用补证 consume。
- [ ] 实现统一求值和决定查找，拒绝未知动作；由同一判断生成 allowedActions、modelInstructions 与 decide 结果，不在三个输出中分别重写规则。
- [ ] 验证每个 allowedActions 条目在同一个策略快照中 decide 为允许；拒绝反馈的 nextActions 只能来自此时允许的条目。全部停止时 nextActions 为空。
- [ ] 运行策略与任务 1 对照测试并提交。没有新运行开关，不把本步骤单独部署为半接线版本。

## 任务 3：同一次变更接入三个消费者

**文件：** `agent-task.ts`、`briefing-topic-strategy.ts`、相关引擎测试；平台规则保持原样。

**消费：** 任务 2 的求值入口。**产出：** 当前画报执行路径统一消费策略；其他工作流继续走原路径。

- [ ] 先增加集成用例 `advertised_actions_match_execution_policy`，对任务 1 的边界状态同时验证提示、工具 action 选项和实际执行；证明新消费者尚未接通时测试能发现不一致。
- [ ] 在 `AgentTasks.run` 内用一个状态采集位置映射现有变量；预算与计数仍在原执行处更新。提示、工具筛选/参数枚举、执行前 guard 都调用同一求值入口。
- [ ] 执行前根据最新状态重新求值；测试旧提示生成后额度已消耗，不能靠旧提示执行第三次补证读取。补证读取失败仍只扣原有一次。
- [ ] 把拒绝原因与当前合法动作接入既有提示/错误通道；允许既有循环在原预算内正常纠正，不在循环之外追加模型调用、重开任务、重选题或变更原公开错误码。
- [ ] 删除被替换的重复阶段判断。旧阶段导出如仍有调用方，临时只委托新实现，并在同一改造末尾清理可删除的兼容入口。
- [ ] 增加非画报、新闻/公开研究、资料学习与经营知识分支回归，证明它们没有被普通数据画报的许可矩阵误伤。
- [ ] 验证平台仍可在引擎允许后拒绝撤权、来源变更或无效计算/交付凭据；沿原终态处理而非放宽条件。
- [ ] 运行定向引擎检查；三处消费者一起提交。此步骤不可拆成上线的“先改提示、以后改执行”。

## 回退与完成标准

替换提示、工具声明及执行校验的提交作为同一回退单元。发生回归时恢复整套旧版本，不能只退一个消费者。停止或完成在途任务后按原本地部署流程替换；原来源、权限、快照、用量与历史回执不改写，也不为验收清库。

本轮无数据库迁移和新增长期配置，因此无需数据回滚。完成标准是设计记录验收项有实证、旧重复规则已移除、平台资格与其他工作流行为保持、PR 说明区分合成测试/真实模型/部署范围。
