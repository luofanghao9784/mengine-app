# 梦核工作空间：三端架构与管理权限 V0.1

> 2026-09-30 当前管理专题已形成[三端管理与共用平台首轮任务书](三端管理与共用平台-开发任务书-V0.1.md)，统一承接输入、处理、输出、评估及自进化需求，整理对象/动作/范围、页面分组及共用能力；经验维护双入口方向获认可（DEC-092）；[第 12 节](三端管理与共用平台-开发任务书-V0.1.md#12-组织角色与授权生命周期)新增职责、管理员任命/自授权及交接建议，[第 13 节](三端管理与共用平台-开发任务书-V0.1.md#13-企业初始化与-ai-工作配置)已提出初始化、有限主动辅助和配置生效建议，[第 14 节](三端管理与共用平台-开发任务书-V0.1.md#14-运行与改进工作区及待处理流程)补三端运行/待处理视图、责任分流及解决依据；下一专题为数据保留/删除/导出/恢复，再做管理汇总。新增方案仍为建议，本文已确认权限和历史实现边界保持有效，管理员自授权和任命问题尚未确认。

> 2026-09-28 新架构方向已确认：保留三端，企业管理端逐步扩展本企业 AI 使用配置，总台内部增加引擎管理职责，当前不另建第四端；复用现有工程，自进化后接入。见[开发范围与管理端规划](新架构下开发范围与管理端规划-讨论稿-V0.1.md)和 DEC-080。具体菜单、权限及交付拆分继续设计，不改变本文已确认的内容访问边界，也不代表新增功能已实现。

用户在 M1-A1 工程基线完成后提出，系统应包含现有客户端、企业管理端和平台总台，并询问是否需要提前设计。本稿将三类入口纳入任务书；以下具体菜单、权限和交付拆分为实施建议，尚未全部成为用户确认。

用户随后确认总台默认不能查看客户资料和会话，首期也不提供内容访问入口；总台只提供企业状态、用量和脱敏运行信息，内容排障授权不进入首期。账号入口已确认采用管理员邀请＋邮箱密码（DEC-043）。本设计在 M2 身份、租户和资料模型正式实施前对齐，已有平台与独立引擎连接基线继续适用。

## 1. 三端的职责

三端按使用与管理职责组织，同一人可承担多个角色，各入口不代表固定权限集合；此前网页、移动 App、桌面 App 是设备维度。客户端优先完成网页再扩展 App；两个管理端建议先提供网页，优先桌面操作，不新增管理端原生 App 承诺。

| 入口 | 面向谁 | 第一阶段建议内容 | 后续扩展 |
| --- | --- | --- | --- |
| 客户端 | 员工、管理者作为工作使用者 | 会话、画报、资料库、个人空间、共享空间和成果 | 按已定顺序扩展移动/桌面 App，协作与业务应用按场景推进 |
| 企业管理端 | 某个企业的负责人及获授权管理员 | 企业信息、成员邀请/停用、基础角色、空间与资料权限、企业用量和管理操作记录 | 部门细分、自定义角色、企业级工具/连接器、配额分配、更多审批与交接 |
| 系统管理端（总台） | 梦核平台内部运营及技术人员 | 企业开通/停用、初始企业管理员、基础额度与用量、服务/组件运行状态、平台操作审计 | 套餐收费、账单、工单、细分运营角色、灰度和更完整的平台配置 |

角色按能力组合，同一人可以使用多个入口；有企业管理资格不代表所有企业的管理员，平台角色也不自动成为客户成员。业务管理者（例如 9POP 管理者）可在客户端分析资料，不必因职业是管理者就获授企业系统管理权。

菜单只能呈现已完成并有真实数据的能力。模型、Harness、WeKnora、引擎版本和运行状态可以形成总台运维视图；首期不把供应商完整管理界面嵌入，也不提供未经授权的任意脚本执行入口。

## 2. 应先确定的身份与权限模型

| 对象 | 边界与实施建议 |
| --- | --- |
| 账号 | 一个登录身份；邮箱密码认证与后续企业身份提供方经统一接口接入 |
| 企业/租户 | 一个独立使用主体的数据、成员、额度与管理边界；本项目、9POP、群力按各自独立主体配置，具体组织映射在开通时核实 |
| 企业成员身份 | 账号加入某企业形成成员关系；角色、状态与企业绑定。模型允许一个账号有多条成员关系，跨企业加入需分别邀请，切换体验随需要实施 |
| 平台角色 | 与企业成员角色分开授予、检查和撤销；仅用于运营接口，不通过伪造企业管理员身份进入客户业务 |
| 工作空间 | 属于企业，承载个人/共享资料、成员与权限；同一企业新增项目或部门空间不另建租户 |
| 支持访问授权 | 用户已确认首期不提供内容访问入口，不开发该类授权；未来如需增加，另行确认产品规则并设计专门授权与审计 |

建议先使用少量角色：企业负责人/管理员、空间负责人、普通成员；总台先有受控的平台管理员，运营/支持/财务等拆分在相应功能加入时实施。M2-B3 已实现最后一名有效企业管理员不可停用的保护；企业负责人转交、管理员任命/降级和离职交接仍需明确规则，不能简单把删除账号当作完成交接。

账号停用与某企业成员停用是不同动作。成员退出企业不应影响其在其他企业的合法身份；平台停用账号则按全局身份规则处理，不能由某客户管理员执行。

## 3. 数据可见范围与管理动作

| 主体 | 默认管理范围 | 内容读取边界 |
| --- | --- | --- |
| 普通成员 | 本人工作及明确获授权的共享资源 | 只读获准资料/会话/成果 |
| 空间负责人 | 指定空间成员、资料及空间权限申请 | 按空间内容授权；不越过其他空间或个人范围 |
| 企业管理员 | 本企业成员、组织、基础配置和企业级授权 | 管理资格与内容读取分开；私人会话不因开通企业服务或管理资格而自动向全员/管理员展示 |
| 平台管理员 | 企业开通、状态、资源额度、平台配置和运行信息 | 已确认：默认不能查看客户资料和会话，首期无内容访问入口；仅企业状态、用量与脱敏运行信息 |

企业管理者是否可授权自己读取特定企业共享空间，以及离职交接中的个人工作资料处理，属于需显式记录的业务动作；不实现一个能绕过全部内容检查的全局超级角色。已有私人会话与成果明确共享的要求继续有效。

用户已明确选择首期不提供内容访问入口。因此不实现总台代入员工身份、读取客户正文/附件/提示词/会话或内容导出，也不提供“临时支持授权”绕过该边界。API、错误日志、追踪与导出均须遵守，不能仅隐藏页面。未来如需内容排障，另行确认规则、适用内容及授权主体，再实施审计与撤销。应用权限不能约束直接持有数据库或存储管理员凭据的基础设施运维；生产部署还需对应的基础设施权限和审计，不能把隐藏入口当作完整保证。

### M2-B3 当前实施规则（2026-09-22）

- 管理端仅列本企业成员、邀请及共享空间元信息，不列他人个人空间、不提供内容读取入口。创建共享空间不自动赋予创建者内容访问权；客户端只列个人自有空间与有明确成员授权的共享空间。
- 成员停用只改本企业成员状态；保留资料及授权记录，恢复后既有授权继续生效。这是本轮可逆实现选择，待用户体验；资料/下载/检索/长任务撤权仍在各自模块验收。
- 最后一名账号和成员状态均有效的企业管理员不可停用，并发写入在企业范围内串行校验。管理员自授权、把其他成员设为管理员两个问题已提出，仍未收到确认；当前不开放相关新增权限，不将其记作用户选择了永久禁止。
- 新增空间授权要求目标是本企业有效成员、账号有效；停用成员的旧授权可撤销，不可新增。授权记录独立于管理员身份与创建者字段；V4 将升级前既有共享空间创建者的隐含访问权显式回填，以保持迁移前权限，不给新建空间自动授权。
- 管理记录只覆盖成员/邀请/共享空间/企业名称变更，保存操作人、目标 ID、授权对象 ID 和时间；展示名称读取目标当前名称，不是历史名称快照。无私人工作动态、会话或内容日志。

### M2-C1 资料权限（2026-09-22 用户已确认）

共享空间查看与维护分开：既有 `workspace_members` 迁移为只读，新增访问授权也默认为只读；企业管理员通过独立管理动作授予或取消维护。取消维护保留查看/下载；撤销空间访问同时移除维护，重新加入仍默认只读。成员或企业暂停期间授权保留但不能使用。

维护权目前包含上传原件、创建子目录、追加新版本；旧版本不可覆盖。个人空间仅本人可读写；管理者无默认私人或共享内容权，总台不增加资料查询/下载入口。自授权与管理员任命仍按原未决状态关闭。管理操作元信息记录授予/取消维护，私人文件操作不进入企业管理记录白名单。

## 4. 共用后端与前端组织

继续使用模块化 Spring Boot 平台。身份、成员、租户、空间、资料和用量为共用业务服务；客户端、企业管理端和总台有分别声明权限的接口边界。暂定入口可按 `/api/v1`、`/api/tenant-admin/v1`、`/api/platform-admin/v1` 分组，实际路径在接口实现时固定；路径本身不构成授权。

- 每次企业资源操作都由服务端核验登录身份、企业成员状态、目标资源归属及动作权限。客户端提交的租户/空间 ID 只是请求参数。
- 总台开通企业、停用租户等跨租户管理动作使用专门服务和平台权限，不给普通业务查询增加“平台管理员跳过 tenant_id 过滤”的分支。
- M2-B1 采用 Vite 多页面构建：`workspace/index.html`、`tenant-admin/index.html`、`platform-admin/index.html` 共用 `src/identity/` 的身份流程和 `src/shared/` 的主题、控件、布局。原根路径 Demo 保留独立入口，其业务状态不进入管理端。
- 当前三个真实入口同源共用服务端 Cookie 会话；总台权限由服务端独立校验，不用企业选择值获得平台权力。当前统一构建/交付，不宣称已独立部署或实现跨域单点登录；未来拆分域名、独立发布或加强总台认证时单独验证 Cookie、CSRF 和登录上下文。
- 平台持有管理规则和审计。梦核引擎、Harness、WeKnora 均遵从平台授权，不能通过总台配置自行扩大文件或工具权限。

### 4.1 已确认的三端前端设计原则

用户明确要求两个新增管理端与当前客户端风格统一，尽量复用组件与样式，排版遵循客户端已有逻辑；首期功能简单、围绕核心工作，后续在测试中持续优化三端功能和页面。这是开发约束，具体页面随对应切片实现和验证。

- **视觉统一**：沿用现有客户端的浅色画布、蓝色强调、白色内容卡片、字体层级、圆角、留白、图标及交互反馈。以当前客户端实际样式为依据，公共样式调整同步评估三个端。
- **布局统一**：沿用现有导航、单一主标题、顶栏集中操作、正文列表/卡片与按需展开详情的组织方式。管理页以成员、企业和空间等当前任务为中心，表格与表单按信息量安排；详情打开/返回时保留必要的筛选、滚动与编辑状态。
- **组件复用**：优先复用按钮、图标按钮、状态标记、字段、空状态、弹窗、浮层及页面操作区。现有起点为 `src/components/ui.tsx`、`AnchoredPopover.tsx` 及 `src/styles.css` 中的公共样式；列表和资料卡片布局参考现有资料库。业务相关组件先明确依赖，再按实际需要提取共用部分，避免把客户端 Demo 状态带入管理端。
- **首期精简**：企业管理端先覆盖成员邀请/停用、基本空间授权；总台先覆盖企业开通/停用、初始管理员及必要运行信息。用量、审计随真实服务就绪提供基础查看。操作采用必要字段、清晰状态和简短流程，复杂角色配置、商业账单及深层设置仍按原计划后续细化。
- **反馈迭代**：每次交付一个可运行的核心流程供用户测试，按反馈逐步优化三端。常规布局和操作优化可持续进行；涉及权限、数据归属或操作含义的改动同步更新接口与验收。

实现时先提取本批实际需要的公共样式和基础组件，由三个入口引用同一份实现；抽取与业务页面接入分开检查，验证客户端原有交互。M2-B1 已提取 `src/shared/theme.css`、`ui.tsx` 和 `layout.tsx`，旧控件路径保留兼容导出；客户端导航/标题已复用。两个管理端已建立身份入口，M2-B2 已接总台核心管理动作，M2-B3 已接企业成员/空间核心管理动作，并复用 `src/shared/admin.tsx` 的请求状态、分页和重试表单；没有额外发布 npm 组件包。M2-B4 导航携带当前企业上下文；若该企业不具备目标端角色，则进入本人可管理的企业。接受邀请后选中新加入的企业；页面重新聚焦复核身份后重新读取空间范围，授权判断仍由服务端执行。

## 5. 第一阶段交付顺序

任务采用 `M2-A1` 形式，M2 拆成可分别验收的子项；新旧编号见[任务书编号索引](开发任务书-V0.1.md)。两个管理端已在[任务书第 4.1 节](开发任务书-V0.1.md)分别列为 M2-B2（总台）和 M2-B3（企业管理端），共享前端为 M2-B1，三端联调为 M2-B4；均包括对应接口、服务端权限和真实状态。M2-B1 共用界面与身份入口、M2-B2 总台核心管理页面已实现，M2-B3 企业管理核心页面也已实现；自授权与管理员任命待确认、尚未开放。M2-A1 身份接口已完成本地验证，见[验证记录](../交接/M2-A1身份与租户基础验证-2026-09-22.md)；其余管理动作随对应任务补齐。

1. **M2-A1 身份与授权基础**：邀请与邮箱密码、平台角色/企业成员区分、企业上下文、最小审计；使用两个合成企业和多角色验证，第一位平台管理员通过受控初始化建立，不在代码中预置通用密码。
2. **M2-B1—M2-B4 三端管理最小流程**：总台创建企业并指定初始企业管理员；企业管理员邀请成员、管理基本空间范围；成员从客户端进入所属企业。邀请的发出、接受、过期、撤销和重复接受有确定结果，不实际发送未经授权的外部邀请。
3. **M2-C1 资料真实接入**：客户端上传、列表、下载、历史版本；企业管理端设置相关权限；总台仅核对存储用量/状态，不读取客户内容。
4. **M2-D1 撤权与停用验证**：成员停用、空间撤权和企业暂停后，前端、业务 API、下载、检索及异步任务分别落实检查；任务相关验证随 M3-A1、M4-A1 实现补齐。

首个真实自用应具备最小总台和企业管理入口。M8-A1 调整为第二个独立试点前补齐管理能力并做跨租户验收；它不再承担首次开发全部多租户管理的职责。完整账单、支付、自定义复杂角色和商业套餐不因三端划分自动进入当前范围。

## 6. 可验收行为

- 两个管理端与客户端的导航、标题、操作位置、基础控件和样式保持一致；共用组件修改后验证受影响的三个端。首期可完成核心流程，空状态、加载、错误、成功反馈与窄屏基本操作可用。页面完成不等于用户体验确认，后续持续收集测试反馈。

- 普通成员直接请求企业管理/总台接口被拒绝；隐藏菜单之外有真实接口测试。
- 企业 A 的管理员不能用企业 B 的 ID 邀请成员、读资料、改额度或查审计；切换企业后不沿用前一企业的授权和缓存。
- 平台管理员可执行获准的企业管理动作，访问客户资料正文、附件、提示词和会话的请求被拒绝；首期无代入员工或支持内容访问入口，日志/追踪/导出不间接暴露客户内容。
- 企业停用优先阻止新访问和新任务；已运行任务、下载凭证及索引的撤销语义在相关切片验证，不能只修改企业状态字段便声称完成隔离。
- 配额变更和任务用量可归属到对应企业；失败、取消、重试不造成重复记账。实际费用和收费规则另定。
- 资料权限、成员变更和平台管理记录包含真实操作者、目标、动作、时间及结果；运营日志避免记录正文和凭据，管理端只展示有权查看的记录。

本稿区分目标设计与实际进度；当前可运行结果见[M1-A1 工程记录](../交接/DEV-001工程基线与验证-2026-09-22.md)、[M2-A1 身份记录](../交接/M2-A1身份与租户基础验证-2026-09-22.md)和[M2-B1 三端前端记录](../交接/M2-B1三端共用前端与登录验证-2026-09-22.md)。M2-B2 总台的当前验证见[总台记录](../交接/M2-B2总台管理与验证-2026-09-22.md)：已实现企业查询、开通、停用/恢复、未接受的初始管理员邀请更新及管理记录；停用保留账号与其他企业身份，恢复不自动启用已停用成员。M2-B3 企业管理当前验证见[企业管理记录](../交接/M2-B3企业管理与验证-2026-09-22.md)：成员与共享空间管理、企业名称和操作记录已接真实服务；两项权限规则未确认。M2-B4 已完成两企业完整流程与持久环境的本地验证，见[联调记录](../交接/M2-B4三端联调与验证-2026-09-22.md)；可按[试用指南](../交接/本地三端试用指南.md)测试。用户体验、生产部署及目标设备验收仍未完成。
