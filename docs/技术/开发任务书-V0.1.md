独立自进化专题至少覆盖：

- **观察和触发**：能读取哪些运行证据，怎样发现退化、机会或模型升级的适配需求；定期、事件触发和资源边界。
- **调整对象和范围**：规则、检索/索引、经验维护、排序/呈现、脚本、模型与流程，以及更大架构调整的候选；不只限于调权重，也不把当前三段内部实现永久固定。
- **候选与验证**：形成改进假设、适用范围和可比较版本，调用共用评估取得证据；不把生成改法或模型自评视为提升。
- **授权与采用**：按平台/企业/空间/个人作用范围划分试验和生效权；已预授权范围内可设计自动试验与采用，具体类别和条件在专题确认，当前不授予实际运行权限。
- **持续观察与恢复**：上线后退化、无效候选、依赖不兼容、在途任务、停止与已验证的恢复方案；停止自进化应停止相应试验和后续变更，不自动撤销已生效版本或真实业务动作。架构变化处理接口及迁移，不承诺所有变更都能无条件原路回退。
- **独立运行**：自进化未部署、停用或失败时，基础流程仍可使用持久的有效方法及自身正常维护能力；试验资源不挤占已约定业务交付，不为独立板块另建一套权限、评估或管理端。

以上目录已在独立自进化任务书中分轮展开并形成阶段汇总；DEC-091 认可触发与预授权方向，不代表所有具体方案、实际自动授权或效果已经确认。评价方法也可单独提出改进，但每轮方法比较须保持可比依据，不能通过同次放宽评价口径证明候选进步。

2026-09-30 范围补充（DEC-088）：首版业务触达限定系统内，外部渠道接入、账号绑定、多渠道恢复与真实送达验收留到后续 App 版本，不作为下方历史任务中“推送/通知”表述的默认首版范围。任务仍可在后台运行并保存成果；身份邀请及账号安全流程按原独立范围维护。

每份任务书统一记录：目标与责任；本期范围/后续范围；已有能力与新增任务；输入输出和依赖；三端动作与权限；异常与恢复；验收场景及证据；可替换方法与观测；已确认、设计建议和待讨论事项。沿用已有需求编号和模块任务映射，避免各任务书重复建设同一资产。

## 3. 前后端并行与逐步联调

先约定接口，再由前端、平台与引擎按模块并行，每完成一段真实能力就接入现有页面。首条联调先完成总台开通企业、企业管理员邀请、成员登录，再接资料上传、列表和下载，随后接引用资料的会话与画报。最终阶段做完整验收，联调贯穿各批次。

```text
页面与交互 → 页面状态及数据访问接口
                       ├─ Demo 实现（开发和演示）
                       └─ 真实 API → 平台 → 引擎 / 执行环境 / 资料服务
```

两个数据实现遵守同一契约，按明确环境或开发配置切换。真实环境后端失败时显示失败与重试，不能静默回退演示数据或预置回复。业务操作按接入切片迁出 `change()`，避免浏览器与服务端各自产生一套业务事实。

前端负责展开、焦点、滚动、动画和未发送草稿等交互状态；企业身份、权限、资料版本、任务终态、发布和用量以服务端为准。跨设备草稿和偏好的同步细节另定。

影响取决于操作含义而非代码行数：移动“发布”按钮通常独立；将“保存草稿”改成“保存并发布”涉及权限和状态。调整排序如果涉及分页，需与后端规则一致。

保持稳定的是身份、权限含义、状态和操作结果，界面无需全部冻结。契约可以演进，优先兼容新增字段；破坏性变更同步迁移调用方并回归后启用。

## 6. 必须对齐的接口边界

下表保留工程边界，并与[第 10.2 节共享对象与交接](#102-共用对象与交接清单)共同作为增量依据；详细字段、事件和存储随任务实现，避免重复状态来源。

| 边界 | 首批约定 |
| --- | --- |
| 网页 ↔ 平台 | 登录态、企业/空间、资源版本、分页排序、权限结果、错误与并发控制；请求接受和任务完成分开 |
| 平台 ↔ 引擎 | 契约版本、目标、授权资料句柄、引擎/方法版本、事件、结果、用量、取消和恢复；引擎不直接操作业务表 |

| 资料 ↔ 检索 ↔ 引用 | 原件与衍生内容、具体版本、权限及解析状态；引用不因最新版本变化而悄悄改变 |
| 会话/引擎 ↔ 画报 | 结构化卡片类型与版本、来源、时间、受众、状态和继续会话入口；样式布局由前端决定 |
| 目标/计划 ↔ 调度/运行 ↔ 待办 | 有效委托、触发与范围、真实计划/运行/尝试、缺口和原对象动作；画报和管理事项引用同一业务状态 |
| 反馈 ↔ 档案/任务/经验 | 原始评价和对象版本、当前纠正/偏好/新委托/候选分别归属；改评、撤销及后续回执不重复执行 |
| 经验/方法 ↔ 评价/发布/采用 | 实际方法和证据版本、内容/执行资格、比较依据、平台发布及范围采用；自进化以后复用同一链路 |
| 原对象 ↔ 生命周期/索引/导出/恢复 | 生效权限、删除/停用状态、派生清理及独立副本规则；恢复和迟到任务不能复活已撤销状态 |

不预编造 Harness SDK 或全部接口路径，首批通过实际原型形成可运行契约和样例。其他客户端以后复用业务接口，呈现可分别适配。

- 引擎通过版本化业务契约取得能力及状态，不直接操作平台业务表。日常规则只保留必要导航/约束，资料与经验按需检索，不把以上全表堆入主模型常驻提示词。

## 11. 首轮具体方案：基础范围、授权与主动工作

2026-09-30，承接第 10.6 节前三组决定。本节将既有建议具体化为可一次审阅的首版方案，尚未成为用户已确认的新权限或默认策略。当前仍只讨论任务书，不任命管理员、不配置企业、不启动后台分析，也不因此获得收费调用或部署授权。方案确认后再同步相应决定和任务范围。

### 11.1 基础范围与完成依据的推荐

推荐采用第 10.1 节八类基础能力、沿第 10.4 节任务和批次增量交付：输入与资料、档案/规则/冷启动、真实任务、有限主动工作、经验闭环、输出/待办/两类反馈、三端与数据维护、评价和正常方法更新均有可运行的初始实现。首个基础版本以 Web 三端共用服务为产品形态，沿本项目先自用、再开展已规划试点的方向推进；云端实际部署环境和预算在后续资源方案确定，本地可运行不冒充云端交付。

首批验收推荐采用三组代表工作，具体资料随开发取得授权后选取，不冻结唯一业务模板，也不要求先指定一个客户：

| 代表工作 | 必须贯通的行为 | 用来证明什么 |
| --- | --- | --- |
| 从资料完成一次工作 | 选择/批量上传资料，说明版本和缺口，分析/计算/起草，补充后继续，交付可查看/编辑/导出的成果并接收纠正 | 系统能完成实际工作，缺口/部分失败可恢复，成果与真实依据关联 |
| 对选定范围持续辅助 | 在已启用范围内发现资料变化、缺口或相关问题，形成结果/待办；按保存的计划或条件再检查，支持停止 | 系统在用户没有每次发问时也能工作，且范围、资源、状态及交付可控制 |
| 在后续工作中复用经验 | 使用有依据的初始方法或先独立完成，形成获准候选；核验/发布后在类似工作中判断适用，吸收纠正与反例并由两端维护 | 经验真实参与工作并可持续维护；命中不适用时能跳过，空库不阻塞任务 |

三组工作共同覆盖画报和会话反馈、权限变化、重复触发、来源失效、删除/恢复及正常方法更新。合成的两企业、多职责测试用于证明隔离与并发；真实模型和实际业务质量另按获准条件验收。用户任务成功不直接证明主动发现或经验闭环合格，各组分别留证据。

完整基础版本的完成条件建议包括：全部约定任务已贯通；必要权限/状态/异常检查通过；代表工作在实际获准模型和目标环境中可用；约定的质量、资源及恢复条件达到要求；已知限制和未纳入范围有准确说明；未部署自进化时能够运行和维护。仅完成本地合成检查、一个样例或全部页面不满足完整验收。实际交付形态、质量指标及资源条件在第 10.6 节后续三组方案中落定，不能在缺少这些依据时提前标记完成。

授权 Web 批量导入按已定方向交付目标浏览器支持的选择、扫描预览、筛选和逐文件回执；能力不足的客户端明确缺口并保留文件上传路径，App 补足部分继续单列。App、系统外业务触达、全行业连接器/经验、复杂协作和独立自进化实际实验继续沿既有分期，不成为基础版的无限前置。

### 11.2 授权与角色的首版推荐

沿[管理第 12 节](三端管理与共用平台-开发任务书-V0.1.md#12-组织角色与授权生命周期)，推荐四类可组合职责。同一人可兼任，企业无需为使用系统凑齐四个人；维护者通过客户端或企业端的获权工作区处理同一对象，个人工作照常保留。

| 职责 | 首版建议可以做什么 | 默认不随身份附带的能力 |
| --- | --- | --- |
| 普通成员 | 本人任务、获准资料/经验使用、成果和反馈、本人明确偏好 | 维护他人或企业资产、给他人授予权限 |
| 范围内业务维护者 | 查看/维护被授予的资料、经验或评价依据；处理对应业务问题，可进入企业端相应集中维护入口 | 管理全企业成员、任命管理员、读取私人源会话或裁决范围外业务口径 |
| 企业配置管理员 | 在获准范围内维护成员/邀请、空间和 AI 使用配置，执行被明确委托的授权管理 | 任命同级管理员、任意自增内容权、授予超过委托上限的权限或查看全部企业正文 |
| 企业授权负责人 | 任命/调整配置管理员，指定维护与可授予范围，维护允许的授权政策并安排责任交接 | 他人私人内容、其他企业、平台技术权限，以及企业本身无权扩大用途的来源 |

首版建议每家企业明确一名主要授权负责人，新企业可由初始管理员在接受邀请时同时接受这一职责；允许多人担任配置管理员和不同范围维护者，先不建设多层授权委托或多人联签。负责人的“主要”身份用于保持清晰的任命与交接责任，不覆盖内容权限或业务决定规则。

**任命与共享自授权建议：** 主要授权负责人可直接任命配置管理员，不要求每次平台批准；普通配置管理员默认没有任命同级的资格。负责人可按企业允许的政策，显式为自己取得指定共享空间的查看或维护权，可与创建空间一起表达，无需单人企业再找一人审批；普通管理员只有已有有效政策或明确委托覆盖时才能执行相应授予，不能自行决定扩大范围。取得查看不同时取得维护、发布或执行资格，私人空间和源会话始终不包含在此范围。

限制同时覆盖相互授权、再转授和改授权政策等路径。若某共享范围要求限制管理者访问，其政策维护和授权资格也须相应约束；不能让一个拥有全部政策修改权的角色仅靠隐藏“自授权”按钮受到限制。任命、授权及读取各保留真实记录。

**正常交接建议：** 原负责人指定有效企业成员，接任者接受后完成责任转交；历史记录保留原操作人，原有个人工作、资料和任务不批量换所有者。正常停用/降级前处理最后有效管理途径；账号因安全原因确需停用时仍应切断访问，再走恢复，不能为保持负责人数量保留失效身份。

**唯一负责人失联建议：** 首版提供受控人工核验恢复，不做自动接管。本人账号恢复与更换企业责任人分开；更换时由企业提供可核对的指定依据，平台依开通时登记的授权联系人/企业指定记录及预先约定的独立核验途径处理，记录核验和转交结果。不能仅凭控制某邮箱、已知企业名称或管理员字段判断接班资格；平台不选择企业接班人、不代入旧账号，也不读取私人内容。依据不足时仅该恢复保持待核验。具体核验清单、处理资格及记录保留在相关功能交付前定稿，不承诺当前已有人工恢复服务。

**存量企业建议：** 从已记录的企业指定依据确认主要负责人；没有可靠记录的，先走上述核验路径。确认前原管理员继续已有获准工作，新任命/自授权能力保持关闭；不从 owner 字段或旧管理员身份自动升级。确认后补相应责任与授权记录，不重建账号、不无依据扩大或撤掉既有合法内容权。

本节只推荐职责和资格，不授予实际权限，也不把企业配置管理员等同于收入、采购、用工等业务事项的决定者。内容/业务决定资格仍落在具体对象和范围上。

### 11.3 默认主动工作的首版推荐

沿[管理第 13 节](三端管理与共用平台-开发任务书-V0.1.md#13-企业初始化与-ai-工作配置)，推荐把明确任务、基础维护、主动发现和持续交付分别说明，但不要求四套程序或四个总开关。“有限”限定数据用途、作用范围、资源及可产生的业务影响，分析方法、选材、工具组合及范围内节奏由模型结合实际决定，不固定成统一步数或候选数量。

| 工作类型 | 推荐默认方式 | 后续自主程度 |
| --- | --- | --- |
| 用户明确任务 | 具备当前动作条件就直接开展，不依赖主动辅助开关 | 自主分解/检索/计算/起草/调整方法，按已有执行授权完成；资料不足先推进独立部分 |
| 基础资料与记忆维护 | 在原上传、来源和维护授权内运行，形成真实解析/索引/版本及获准偏好维护 | 正常更新、安全重试、补资料后继续及政策覆盖的经验整理自动完成，不逐项索要确认 |
| 所选范围的主动辅助 | 企业开通不直接扫描全部内容；有权者一次启用明确空间/来源、用途、接收者和资源，之后生效 | 自主发现变化、缺口、问题/机会，选择有价值结果，必要时保存范围内后续检查或等待条件，无新发现也可正常结束 |
| 明确持续交付 | 根据有效职责或用户明确委托保存真实计划，例如“每周按这些资料汇总” | 条件明确且已有授权覆盖就直接保存和运行，缺少关键条件仅补相应内容，不重复整套启用流程 |

读取权限与允许后台处理的用途分别核对。企业配置管理员可编辑所管配置，但启用涉及的数据/动作必须有相应授权主体和用途依据；没有正文权时配置界面只返回获准元信息，不能借后台任务代读。个人空间的辅助由本人在其获准范围启用，企业设置不代替其他成员的私人资料授权。

推荐提供一张简洁的“基础辅助设置”卡，展示以下初值；初值是本轮建议，数值资源限额和调度周期由后续资源方案补齐后方可启用：

| 设置项 | 建议初值及含义 |
| --- | --- |
| 处理范围 | 启用者明确选择的空间/来源中，已允许相应用途的现有内容及后续新增/更新内容；未来新空间不自动纳入，受限子对象仍逐项受其规则约束 |
| 工作目的 | 理解工作背景，核查相关变化/缺口，形成有依据的分析、建议或草稿；经营目标不完整时可先调查，不将行业常见问题当成本企业事实 |
| 触发与检查 | 获准资料达到可用条件或出现实际更新时触发，合并重复变化；按有效策略保存必要后续检查。明确持续交付仍按其计划执行，纯索引重建不伪装新业务发现 |
| 结果接收 | 个人辅助默认本人；共享范围在启用时选择有权接收的人，不默认发给全企业。成果保存在对应任务/成果入口，适合时进入其画报 |
| 允许动作 | 当前用途内分析、计算、检索、生成草稿和必要维护；公开检索或其他工具沿既有能力/网络/数据授权，不凭这个开关新增外部传输资格 |
| 资源与停止 | 使用已配置且能执行的资源上限，展示当前是否可运行及停止入口；上限未配置或不足时保持受影响工作待就绪，不按无限资源运行 |

上传到已启用且覆盖该内容的范围，可以触发后续分析，无需每次再问；其他上传仍按原任务和输入维护处理，不新建永久委托。没有明确经营目标时，AI 可以在已启用用途内调整分析重点、查资料及形成候选重点；将其变成新的正式职责、改变业务口径或新增交付承诺，需要已有对应委托或相应有权者决定。

AI 可以保存获准调查的后续检查、等待资料或范围内节奏调整，平台接受并记录版本后才算安排成功。新资料范围/用途、接收者、发布共享、业务系统写入、资源上限或重要承诺有变化时，先核对已有授权；已覆盖就执行，未覆盖才提交具体方案供相应有权者决定，其他获准部分继续。共享范围里的分析结果不因生成就自动覆盖权威资料或修改正式方法。

停止控制推荐保持四种明确含义：关闭一般主动发现停止相应新探索及其后续安排；暂停某个持续计划停止该计划后续触发；取消某次任务影响该次尚可取消的动作；关闭提醒只改变告知。界面列明在途任务和明确委托受到的具体影响，不用一个“关闭 AI”开关默默替代全部控制，也不保证撤回已经发生的业务动作。

日常基础维护与独立自进化继续分开。上述辅助不包含自主改引擎架构、自动试验或方法发布的无限授权；正常已获准的方法更新继续沿原机制，自进化仍在约定基础版本完成后接入测试。

### 11.4 本轮待确认范围与后续

本轮供判断的具体推荐为：采用第 10.1 节完整基础范围及三组代表验收；首版一名主要授权负责人、可组合维护/配置职责及显式共享自授权；明确任务和基础维护按原授权自动进行，主动辅助一次按范围启用后自主运行。任命/自授权、失联核验、存量责任、启用初值和接收范围均保持建议状态，不能因写入任务书而修改真实权限。

三组方案的接受、调整或拒绝应分别回写第 10.6 节及相应管理任务书，不将本轮讨论扩展为对全部期限、费用、部署或自动发布的同意。具体恢复核验依据仍需在相关功能实施前补齐，不能把它消失在已完成清单中。

后续三组继续按首批实际对象和验证场景收口；其中保留/回收/导出与退出已在[第 12 节](#12-数据保留与退出的首版具体方案)提出具体推荐，随后明确真实模型及部署的资源条件、业务评价与正常方法采用条件。目标是在统一执行前形成可落实的业务选择；不继续增加无关的大板块或要求用户决定每个内部算法。当前仅文档整理，未编码或开展任何真实运行。

## 12. 数据保留与退出的首版具体方案

2026-10-01，承接第 10.6 节第四组决定及[管理第 15 节](三端管理与共用平台-开发任务书-V0.1.md#15-数据保留删除导出与恢复)。本节给出可审阅的默认值和动作资格，全部为待确认的产品方案；DEC-094 已确认的生命周期方向不等于确认这些天数、离职处置或服务承诺。当前未改变任何保存策略，也未执行删除、导出、备份或恢复。

### 12.1 保留对象与默认期限

推荐以用途区分正式资产和临时数据。用户保存的工作不因近期少用而自动消失；候选、诊断和临时包则不能因没有清理规则而一直积累。正式资产采用明确的持续保留条件，仍受有效来源、删除要求、企业退出及容量政策约束，不把未填写期限当作永久保存。

| 对象 | 首版推荐默认值与起算点 | 到期或失效时的动作与例外 |
| --- | --- | --- |
| 正式资料及必要历史版本、已保存私人会话/文稿/成果、独立发布的企业成果和可用经验 | 服务有效且有持续用途时保留，不按最后访问时间自动删除 | 按对象删除、来源条件及退出政策处理；已发布副本继续按独立规则核对。容量不足应提示和按政策处理，不能悄悄删旧工作腾空间 |
| 企业/用户档案、明确偏好、已采用方法及正式评估样例 | 保留当前有效内容和支撑使用、对照、恢复所需版本；失效后核对依赖及用途 | 私人内容不因成为档案而开放。旧偏好、无依赖旧方法及已失效样例进入有权维护/删除流程；最小变更记录适用下方记录政策，不将全部旧正文无限保留 |
| 未发布经验候选 | 创建后 90 天 | 到期清理候选正文及受其约束的临时附件；确有维护需要时按 12.2 节延期，不能只靠补标签、复制或重复提炼续期 |
| 原始画报/会话反馈 | 每次真实提交的版本保存 180 天 | 到期清理原文及不再有用途的派生内容；明确形成的偏好、独立核实问题或获准经验分别按其依据管理，见下文 |
| 临时评测/试验的详细中间产物 | 每次形成后 90 天 | 到期清理临时正文；正式选入且有独立有效用途的样例，以及支撑正在采用方法的必要比较依据，按对应资产政策维护；标明历史复核覆盖的变化 |
| 详细技术诊断日志 | 事件发生后 30 天 | 到期清理；默认不全量记录提示词、资料正文或模型内部推理。必要异常调查按范围延期，不能把全部运行记录都当长期案例 |
| 已结案任务回执、已失效授权及管理/方法变更的最小记录 | 结案或失效后 180 天 | 正文另按各自规则处理；仍承担授权约束、去重、未知结果核对或恢复校验的必要事实不受机械到期清理，见 12.2 节 |
| 可恢复删除的对象 | 从删除生效起进入 30 天回收期 | 删除后停止正常读取、检索、模型使用及下载；恢复管理需另按当前资格。期满按已采用政策彻底清理在线内容，无需逐文件再批准 |
| 批量导出生成的临时包及可重建导出缓存 | 生成后 7 天 | 到期清理临时包，仍有效的业务成果可按权限重新导出。用户正式保存的 Word/PDF 等成果本体不属于这项临时数据 |
| 解析片段、检索索引及其他派生缓存 | 跟随有效来源和用途，缓存设可重建的有限期限与容量 | 活跃资料的索引不套用诊断日志 30 天；删除/撤权优先令相关副本失效，重建不能绕过来源状态 |

上述“已保存”指服务端明确保存的对象；浏览器未提交草稿继续采用已有本地恢复规则，不因此变成云端长期资产。用户设备上的下载文件也不在服务器自动清理范围。

原始反馈到期不自动撤销用户明确保存的长期偏好，例如“以后用表格呈现”。但用户明确撤回反馈/偏好时，需核对依赖：仅靠该反馈建立的推断不能继续冒充有效依据；独立核实的事实不因原文过期一律删除。提炼、去敏或转成正式资产都不能自动扩大原用途，也不能作为保留完整原会话的变通方式。

正式评测样例、方法历史和必要反例不能仅因使用少被淘汰。维护时允许替换或清理不再有效的依据，但保留比较结论所需的最小说明，明确哪些历史结果已无法完整复现；不通过删失败样例制造质量上升。

### 12.2 期限起算、配置与必要例外

推荐首版提供默认策略和少量可选期限，不建设任意编程的保留规则平台。企业有权政策维护者可在产品实际支持的选项中调整候选、原始反馈和回收期；首批选项及容量约束在实现时结合成本确定。平台负责诊断和共享基础设施的备份政策，单个企业不能改变其他企业保留方式。调整保存时间不授予正文查看权或新模型用途。

期限由服务端事件时间计算，界面显示准确截止时间及所在时区。查看、下载、重建索引、重新打标、重试清理、复制备份不重置对象期限；实质新增的候选或用户提交的新版本单独计时，不顺带延长全部旧版本。进入回收站及已明确退出后的期限也不能被后台活动静默延长。

缩短期限默认作用于随后产生的数据；若要处理存量，先给有权者显示受影响范围、数量和最早清理时间，再按明确选择生效。延长期限仅影响仍存在、仍获准保留的内容，不能恢复已清理数据，不能推翻明确删除请求或悄悄延长退出窗口。展示影响预览也不得泄露未获权内容。

未决执行、当前有效授权、撤权/删除决定及仍被旧备份需要的校验依据，只保留完成约束所需的最小事实。已清理回执的旧请求超过支持的重放窗口后应拒绝或重新核验，不能当作一个新请求再次执行。相关记录须与仍可恢复的备份窗口衔接；它们不保留被删除的业务正文，也不供模型日常检索。

某次调查确需延长候选、原始反馈或诊断保存时，应有范围、理由、负责者以及截止或复核日期，并受容量约束；原用途不足时补齐用途依据。有效政策已覆盖的延期可直接执行，缺少授权才补对应决定，不能由 AI 为潜在未来用途保留所有原文。

### 12.3 删除、恢复与导出的职责

沿第 11.2 节可组合职责，推荐不新增必须由不同人担任的“删除专员”或“导出专员”，将能力授予已有人员及明确范围：

| 动作 | 推荐资格 | 必须保持的限制 |
| --- | --- | --- |
| 普通资料/草稿等可编辑对象移入回收站、恢复 | 本人获准私人范围，或该共享对象维护权按政策包含此动作 | 有待处理依赖时说明影响；恢复遵守当前来源、版本及权限，不恢复旧授权或自动继续任务 |
| 共享资产提前彻底删除、跳过回收期 | 单独明确授予的对象/范围彻底删除能力 | 普通维护权不默认附带；显示不可恢复影响及相关派生范围，不允许顺带抹掉必要最小记录 |
| 日常原件下载、单份成果导出 | 继续复用已有对应资格 | 生成、缓存访问和下载时复核当前权限；文件名、清单、摘要也受控 |
| 批量或企业资产导出 | 对象读取资格与相应批量导出资格同时具备 | 企业管理身份不自动包含所有空间或成员私人数据；不能代用其他成员身份生成包 |
| 已采用政策规定的到期清理 | 平台按有效政策执行 | 无需为每个对象重复批准，也不需要给操作者或平台人员正文阅读权；清理失败有真实状态和重试 |

恢复普通内容、恢复正式方法版本、重新启用方法和改变授权是不同动作；经验草稿的维护权不自动成为正式方法采用权。客户端与企业端对同一对象使用同一资格、删除记录和回执；总台只呈现必要技术状态及清理/备份进度，不提供客户内容或全实例备份下载入口。

首版企业退出导出建议覆盖获权范围内的共享资料原件、当前已发布企业成果、可独立导出的经验内容及必要版本/来源说明；历史版本由有权者明确选择。私人资产只能由本人在当时有效权限和用途内取得，企业资产包不默认收录私人会话、个人文稿或受限反馈。生成清单如有缺项须说明获准可披露的原因，不能把部分包称为完整迁移。

权限配置、凭据、平台诊断和所有底层数据库内容不作为普通企业资产包输出；需要重建运行环境的灾备另行处理。当前任务成果中受来源约束的内容仍检查来源，独立企业副本沿目标权限。7 天导出期限不覆盖撤权：当前授权失效或退出窗口先截止时，立即按更早条件阻止下载。

### 12.4 成员离职与企业退出

推荐把暂时停用、明确离职和终止企业服务分开。停用不是删除指令，也不自动启动退出计时；允许停用期间执行必要撤权、结果核对和维护，不因此重新开放业务任务。

明确离职处置和终止企业服务都会启动后续清理，其操作资格须单独纳入有效授权，并显示对象范围、清理后果与截止时间；普通成员停用权、组织配置权或管理员身份不自动包含这两种资格。能力可授予已有负责人或受托管理员，不要求新增角色；已有授权覆盖时直接办理，不逐次再向平台申请。

**成员明确离职的建议：** 先切断该企业访问和持续计划的有效执行资格，处置在途任务及责任交接。独立发布的企业成果、企业资料和获准经验继续按目标规则维护，不随作者离职一律删除，也不把原私人空间转交管理员。

首版建议离职私人内容隔离保留 30 天后按范围清理，起点是明确离职处置生效时间；这是本轮新提出、尚待确认的具体业务政策。30 天期间不自动赋予本人离职后的登录/导出通道或他人查看权，需要本人导出/分享的交接应在离职前有权完成。若企业在窗口内明确撤销离职处置，按当前有效资格核验恢复，不能恢复已被另行删除的数据、撤销的来源授权或自动重启旧任务。共享资产的责任交接只处理相应资产和职责。

**企业正式退出的建议：** 在有权主体明确终止并确定时间后进入以下流程，普通租户停用按钮不承担此含义：

| 阶段 | 推荐行为 | 可核对的结果 |
| --- | --- | --- |
| 退出生效 T | 停止新增业务/模型工作，停止有效持续计划；核对在途任务和已发生动作；开始 30 天受限导出窗口 | 生效时间、截止时间、有效导出负责者及范围、未决事项；不把已执行动作标成未发生 |
| T 至 T+30 天 | 仅已指定且资格仍有效的主体导出约定资产；保留必要撤权、清理和技术维护 | 导出清单、真实缺项与有效期；临时包截止取生成后 7 天、窗口截止及当前授权中更早条件 |
| T+30 天起 | 关闭导出，执行在线内容及相关派生清理，不再自动叠加一轮 30 天回收期 | 请求接受、停止访问、各组件清理完成/失败分别记录；实际在线清理完成时间记为 D |
| 在线清理后 | 剩余旧备份按其实际期限失效并清理，最小退出/删除事实按用途及记录政策保留 | 在线清理完成与备份清理完成分别出具状态，不以到达某个日期冒充所有副本已清除 |

退出期不重新启用全企业、不恢复离职成员、不扩大私人内容访问，也不影响同一账号在其他企业的合法身份。首版不提供无期限退出归档或自动重新订阅；延长窗口须另有明确约定且仅作用于仍存在的获准内容。

### 12.5 备份窗口与恢复要求

首版建议以**滚动 30 天备份保留窗口**作为部署方案的设计目标，按快照生成时间起算，备份仅用于获准恢复。现有本地停机备份/新目录还原工具没有证明自动轮转、在线生产恢复、这一天数或恢复时效；备份频率、覆盖、保护方式和可接受的数据损失/恢复时间仍随资源方案确定，不能提前写成已具备的服务承诺。

正常在线删除与备份到期分开。例如企业退出 30 天后在线清理完成，如果清理前的备份仍保留 30 天，最后旧副本可能到退出后约第 60 天才清理；若在线清理完成较晚，则按实际 D 及快照期限核算。设计目标是在 D 后最多再保留 30 天的旧备份窗口，并在技术选型中核验；回收站期限与备份期限也可能叠加，不承诺回收站到期即所有副本消失。

备份轮转必须核对增量链、复制、存储版本及实际最早可恢复内容。回收期内仍在线保存的内容可进入正常快照；完成在线清理后，复制、重打包或延续备份链不能使其中旧数据重新获得 30 天寿命。如链依赖导致旧字节保留更久，应改实现或明确实际上限后重新确定承诺。共享实例备份不承诺逐企业即时物理抹除，但过期数据不得重新用于正常业务。

恢复前从独立可靠来源补齐快照之后的删除、撤权、停用及有效配置变化；依据不足时保持受影响范围隔离，不开放读取、模型检索或重建索引。最小决定记录覆盖所有仍可恢复的相关备份，不随一次旧快照一起退回。恢复内容不自动重放业务动作、发布成果或续跑原计划。

已下载到用户设备的副本不由本系统远程清除；外部数据源和模型供应商持有的数据按实际接入条件另行核实。平台只报告自己实际覆盖的清理结果，不能用在线数据库清空证明外部副本也已删除。

### 16.4 第二项讨论：如何发起会话工作（已确认；会话视窗进入实施）

讨论时的现状：新会话没有已存模式时默认 `SOURCE_LOOKUP`，输入框要求资料关键词；用户需切换到 `AGENT` 才按完整工作需求处理。当前 live 会话没有普通附件上传入口，原件选择仅供 verification。画报底部按钮目前只转入会话草稿，并不发送任务。以上是当前实现事实，不视为应继续保留的产品交互。

- 暂不要求用户预先选择模型、经验条目、规则或技术执行方式。需求关键部分缺失时，AI 在会话中追问；不为每次正常发送增加确认步骤。涉及共享、持续执行等独立决定时，在对应动作处确认。

本轮不确定默认跨空间检索范围，也不把会话归属等同于资料读取范围或结果共享范围。这三者应在下一讨论中明确后再设计具体控件与服务端契约。

| 直接使用回答或继续追问 | 普通回复保留复制与继续对话；次级操作收起 | 原会话可再次找到，不要求先存文稿；“继续修改”带入目标结果引用供编辑，不自动提交新任务 |
| 留下可维护成果 | 成果卡提供“保存到资料库”，默认个人空间 | 为所选成果保存确切内容/版本，并保留可追溯关联；保存后显示“已保存”和“在资料库查看”，保持当前会话及草稿 |
| 下载到本机 | 在结果附近选择“下载”及实际支持格式 | 已生成文件直接下载；文本导出复用既有能力，用户不必先跳转文稿页。是否内部需要建立文稿快照应在实现时明确，不能产生无提示的重复持久资料 |
| 给团队共同使用 | “共享成果”打开所选内容预览，选择有权发布的空间/位置，再明确发布 | 确认可见范围和版本；只发布选中成果，后台可复用已有文稿/企业副本机制。成功后提供共享资料入口，不打开私人会话给读者 |

| 稍后发现值得关注的信息 | 输出板块选取获准候选进入本人或相应受众画报 | 无需先人工保存；是否呈现由价值、时效、重复和当前工作需要决定，推荐不替代稳定的会话/资料入口 |

“保存到资料库”为已确认的统一用户入口，个人文稿入口收束到资料库的成果使用流程，不要求本轮先合并后端文稿、文件和发布对象。首轮个人保存默认私人范围；放入共享空间按“共享成果”的发布动作处理，避免用同一个保存按钮悄悄扩大可见性。共享也不以先手动保存个人文稿为界面前置步骤。

普通回复不铺满成果管理按钮；有可保存内容或文件的成果卡优先显示“保存到资料库”和“继续修改”，下载、共享及来源/版本放在紧邻的次级操作中。确切图标、排列在后续实施时按固定 Demo 收口，不新建第四个日常主导航。

#### 16.7.3 已确认的画报衔接方向

- AI 回答、执行成功、形成候选与被推荐分别表示不同事实。问候、简单确认、重复文字和单纯执行日志默认不占推荐卡片；任务有价值的发现、报告、行动方案和待决事项可以成为候选。
- 候选可来自用户会话、既有主动任务或获准企业成果，不将“必须手动保存”或“只接受成功状态”固定为所有画报内容的门槛。部分成果及资料缺口按真实状态表达；需要用户处理的事项走已有待办规则，不伪装成完整成功报告。
- 任务既定交付始终可在原会话/成果找到，低推荐分不应隐藏交付。人工关注是用户明确的保留意图；关注不代表启动持续执行，取消关注/隐藏也不删除成果。
- 私人结果只能用于原有获权私人受众；发布后企业副本才可能进入相应获权成员的推荐范围。岗位偏好与模型推荐不能授予读取权限。
- 首轮不在本节冻结具体分数、阈值、模型或每个会话的卡片数量；在智能画报专题结合五类内容、去重、版本更新和经营图表统一设计。候选判定方法应可版本化替换，供后续评估与自进化优化。

#### 16.7.4 修改、版本与失败处理

- 会话继续修改生成新结果；已保存或已发布的版本不能被后续聊天静默覆盖。系统识别已保存关联后可提供“更新已有成果”，按确切版本形成新版本；“另存一份”是独立的次级选择。
- 更新个人成果不自动更新企业副本。明确更新共享内容时，展示目标及本次差异，沿既有版本冲突和发布权限处理；更新不自动重发所有旧转发。
- 保存、导出、发布/转发各自依据服务端实际回执显示状态。保存成功而发布失败，应准确显示已保存、共享未完成；原请求不确定时按既有幂等机制重试，不能反复生成副本。
- 读取来源、保存个人成果、发布共享版本和接收人可读资格继续按各自业务规则核对。来源撤权后，私人派生文稿沿既有保护规则；独立发布副本沿已有发布语义处理。

### 16.8 第四项讨论：智能画报的内容组织（规则已确认）

2026-10-01。承接 DEC-107，用户明确“认可”主题卡按独立阅读价值拆分、待办区位置与默认展示、洞察保留产生时依据三个增量规则，记录为 DEC-108。关联 AI-11—AI-13、DASH-01—DASH-04；复用[输出任务书](输出板块-开发任务书-V0.1.md)的推荐、权限、反馈与待办规则，以及[卡片规范](../产品/智能画报卡片规范讨论稿-V0.1.md)的类型与生命周期。本轮固化设计，不修改运行实例，不冻结推荐算法或经营指标口径。

#### 16.8.1 沿用的页面与内容基础

- 智能画报是默认首页；保留推荐／关注／日期／类型／空间入口及固定 Demo 的杂志卡面、详情和反馈交互。五类内容是资讯、数据、洞察、建议、成果，会话类型继续暂时隐藏。
- 待办放在智能画报内，可完全收起、以最多两排概览、完全展开（DEC-093）。本轮确认放在推荐内容上方，首次有待办时展示最多两排概览，无待办时不占大块空白，后续记住本人选择；收起不改变实际待处理状态。
- 推荐用于发现当前值得看的内容；关注用于保留本人明确关注的内容，支持既有手动布局。关注不自动创建持续任务，任务安排仍需明确约定。日期／类型／空间沿现有入口查找内容，不各建一套内容库。
- 五类是内容含义，待办是实际需要处理的事项，来源是内容从哪里来；三者分开表达。AI 建议不因使用行动句就变成已派给用户的待办。

#### 16.8.2 五类内容如何接真实业务

| 主类型 | 用户要理解的内容 | 示例（仅说明设计，不是当前真实数据） | 接入要求 |
| --- | --- | --- | --- |
| 资讯 | 外部发生了什么 | 行业新政策、获准来源的市场消息 | 可追溯来源与日期，区分原文与 AI 解读 |
| 数据 | 当前业务表现如何 | 本月收入、转化率及趋势 | 明确指标口径、周期、单位与实际更新时间；有可核对数据才显示图表 |
| 洞察 | 发现了什么、可能意味着什么 | 某环节转化下降，与客群或时间段有关 | 关联依据，区分事实、推断和不确定性 |
| 建议 | 可以怎样行动 | 调整跟进顺序或比较两个方案 | 说明理由与适用前提；不自动执行或派发任务 |
| 成果 | 已经形成了什么可用内容 | 周报、方案、统计表 | 可打开确切内容及可用文件，注明状态；不以已手动保存到资料库为唯一门槛 |

一条内容按主要阅读目的确定一个主类型，允许正文包含其他形式。一次经营分析包含指标、发现和建议时，默认形成一张可完整阅读的主题卡；只有各部分具备独立阅读价值时才拆分，不为凑齐五类制造重复推荐，也不限制一次分析只能产生一张卡。会话可以贡献上述业务内容，但不直接将整段会话或最新回复换个标签当作成果卡。

类型应来自明确的内容生成/审核契约；模型可建议分类，但不能靠前端关键词猜测历史回复类型。无法确认类型的历史任务保持原会话可读，迁移策略另行设计。私人结果、明确发布副本和获权主动任务分别沿原有权限进入候选，不能因重新分类扩大受众。

#### 16.8.3 时间与工作衔接

沿用数据卡展示最新状态、同一身份不重复生成的规则；资讯、建议、成果保留产生时内容及依据，不被今天的数据静默改写，资料版本仍独立保留。洞察按产生时依据保留，本轮已明确为产品规则（此前只是可逆实施选择）；后续数据变化可以产生新洞察，不悄悄改写旧判断。数据卡无数据或更新失败时如实显示缺口/时间，不填示例数字；日期查找不将最新数据伪装成历史状态。

点击内容先阅读详情，进一步工作进入关联会话或新会话并保留确切引用；反馈沿既有有用、没用及改进建议。待办卡直接进入真实待处理事项，完成与否以对应业务回执为准。同一事项如还具有推荐价值，可关联内容卡，但处理状态应来自同一业务记录，不形成两份待办。

本轮三个增量规则已确认，五类含义及既有页面入口继续沿用。具体推荐权重、指标口径、历史迁移、更新节奏及接口设计继续留待后续细化；分类与去重契约的实施选择也不因本次认可全部冻结。设计确认不等于五类生产能力、经营图表或新的候选判定已经实现。

#### 16.9.1 已确认的统一使用路径

#### 16.9.2 后台实施依据：数据、计算与更新

以下要求由内容生成、数据服务和已有权限机制承接，不转化为用户发起会话前的必填步骤。共享副本读者只带入获准发布内容及允许公开的说明，不能因准备上下文获得私人会话或原始明细权限。真实来源/口径可在现有详情中查阅，不增加必须逐项经过的管理页面。

| 问题 | 建议规则 | 用户能看到的说明 |
| --- | --- | --- |
| 数字算的是什么 | 同一指标有明确名称、统计范围、周期、单位和计算依据；比例说明分母，对比说明基准 | 如“本月新增客户”，不把累计客户或成交客户混用；本月未结束时不直接把与完整上月的差额称为业绩下降 |
| 数据来自哪里 | 可来自获准系统、导入的业务表格或可核对资料，计算关联实际来源版本；无可靠结构数据时先交付文字/数据缺口 | 单次上传只覆盖文件已有数据，不显示成已接入实时系统；空值不当作零，未知不补造数值 |
| 什么时候更新 | 展示数据截止范围与实际更新状态；当前数据卡用同一身份更新，固定报告内图表保留报告依据 | 页面刷新读取已有最新结果，不自动重新执行 AI；暂无新数据、更新失败和没有权限分别表达，失败不显示为最新成功 |

这些规则约束事实与访问边界。AI 可以选择和改进表达、查询及处理方法，不能未经明确变更就把同名指标的口径改掉。跨来源数据无法对齐时保留差异，不能只为画完整曲线而合并。

#### 16.9.3 首轮收束与后续事项

建议先选一项有真实可核对数据的经营主题，完整走通“获准资料/系统 → 结构化数据与可复核计算 → 会话交付 → 候选/画报 → 详情及来源 → 继续追问”。主题及数据范围在接入时与用户确认；9POP Demo 数字只作交互参考，不复制到正式企业数据。

图形优先复用已有数字、趋势、对比、构成等组件，按数据选择，不要求所有企业都具备同一套指标。没有适合图形时可以呈现清晰表格或文字；AI 生成新组件的安全与发布方式沿 DASH-04 另行处理，不因这一讨论开放任意前端代码执行。

#### 16.10.3 搜索、状态与维护如何保持简单

- 搜索默认跟随所在位置：个人根目录搜索本人资料，企业根目录搜索本人可见的企业共享资料，进入具体文件夹后搜索该目录及子目录。范围在搜索框附近说明；扩大范围须由用户主动切换。此处只决定人工资料搜索，不决定主模型的默认跨空间检索范围。
- 名称与正文共用入口；尚未解析或不支持解析的资料仍可按名称找到，不能因正文索引缺失而像文件不存在。正文搜索缺失/失败不能显示成完整搜索后“没有结果”。个人文稿并入后的搜索也要遵守原来源权限，跨对象结果统一分页及去重属于待实施契约。
- 日常状态围绕“正在上传／已保存、正在处理／可用于 AI／部分可用或处理失败”表达，以实际原件和解析结果为准；“可用于 AI”仅表示已具备相应处理能力，不承诺模型能完整理解所有内容。用户不需要手工管理分段、索引或解析批次，异常详情与获权重试入口按需展开。
- 更新版本、整理、删除/恢复等维护操作按对象与实际权限出现在次级菜单或资料属性卡中。客户端维护者和企业管理端继续操作同一资料；普通使用者以阅读、下载和提问为主。界面收起维护入口不删除原有能力，也不授予新权限。
- 引用资料不改变资料或会话归属；共享范围不会因在会话使用而扩大。发送及实际读取重新核验当前权限，历史引用也不能绕过撤权。

经授权的目录批量上传方向继续沿 DEC-085；Web 能力不足的持续本地采集由后续 App 评估。WeKnora 或其他解析/检索方案属于可替换后台，不增加用户必经页面。本轮未对本机目录执行扫描，未上传文件，也未重新评估供应商版本。

1. 从个人或获权共享目录上传，提交前能看清目标；保存后在原位置找到资料，处理失败不丢失原件或伪装为 AI 已可用。

7. 多份资料各自的属性卡关联正确，关闭或切换其中一张不会把另一份资料的属性、权限或版本套入；全屏、收起、关闭及返回顺序清楚，焦点与阅读位置恢复。

#### 16.10.5 补充确认：跨页面共用卡片交互

用户明确的是交互规则和按需卡片承载；以下操作约定作为实施与验收依据，具体卡片尺寸、排列和动画复用已有组件后收口：

- **正文阅读卡**：从资料库打开资料，与会话中的资料卡复用同一阅读和操作逻辑。资料库、会话及画报中的资料引用共用卡片组件与状态语义，按实际入口保留背景和返回位置；不要求用户进入会话才能阅读。
- **属性卡按需出现**：点击当前资料的“资料属性”，在同一视窗中打开与其关联的属性卡；基本信息、版本、来源、共享与权限等可在属性卡内组织，不默认将所有属性同时铺满页面。关闭属性卡只收起辅助信息，正文阅读卡保留。属性卡按文件和查看上下文准确关联，不把 UI 卡片建成新的资料副本。
- **统一卡片操作**：复用会话卡片的标题与操作区、按需展开/收起、宽度调整、层叠切换及全屏/返回规则；各类卡片只呈现其实际支持的操作。全屏阅读和返回保持原资料与版本、滚动位置，窄屏采用同一套卡片切换方式，不为不同入口单独发明关闭和返回路径。
- **会话接续**：从阅读卡“基于资料提问”进入会话后，继续使用对应的资料卡、属性关系和引用，保留原有草稿及阅读状态；用户发送后才执行。具体组件承载可适配背景变化，不强制重复打开一份无关联阅读副本。
- **范围与实现差异**：`DeckCard` / `LiveConversationDeck` 已有共用卡片尺寸、层叠、全屏等基础；旧 `MaterialView` 的属性是内嵌侧栏，正式 `LiveLibrary` 阅读为正文/历史版本/资料信息标签。它们不是本次新增“属性按需卡片”要求已经实现的证据；实施时统一关联和交互，不只更换圆角或颜色。旧文档中固定侧栏宽度/覆盖正文等描述保留历史含义，冲突处由此规则替代。

本次统一范围为当前客户端的资料阅读与相关辅助信息，主流程确认不改变资料访问、发布或维护权限；不把所有管理页面或确认表单自动扩展成本轮改造任务。

#### 16.11.3 AI 默认读取哪些资料

- 优先理解本次问题、当前会话上下文及用户明确带入的附件/引用，不把全部资料直接塞入模型上下文。
- 需要补充依据时，允许按问题检索**当前企业内本人有权读取且允许 AI 使用的个人资料库与共享资料**。这是本轮确认的新默认，不把现有单空间 API 视为已支持；“用户要求时可跨空间引用”的既有方向保留，早期仅按空间补查的默认建议由本条替代。
- 用户明确“只用这几份资料”时，对本次任务施加可核验的资料范围限制；不要求再点一个重复确认。必要时可在按需上下文卡查看/调整范围，常驻输入区不摆多组模式选择。约束的结构化解析与后端执行属于待实施契约，不能只靠一句提示词绕过或限制工具。
- 会话工作归属继续用于组织工作，不自动限制到单一资料空间，也不授予任何资料权限；共享目标仍由单独的发布动作确定。本人其他私人会话正文、未入库的其他会话附件、他人私人资料及其他企业不进入上述默认检索范围。
- 实际采用的来源可从回答与相关资料卡查看；冲突、过期或缺失依据如实说明。检索前与读取时由服务端检查当前范围及权限，撤权后不从缓存继续读。公开联网及原件执行能力沿各自既有范围，本次确认不自动扩大外部检索或工具执行权限，也不自动扩大已有持续计划的后台处理范围。

#### 16.11.5 统一实施与重点验收

按 DEC-111 纳入本轮客户端统一实施清单，不提前改动运行实例。

- 会话内接入本地上传、已有资料选择和准备状态；上传不丢草稿，未发送不启动问答任务，失败可重试或移除，关闭卡片不移除引用。
- 私有附件、确切版本引用及按需入库共用追溯关系；本会话可反复使用，其他会话默认不检索未入库附件，保存不悄悄扩大受众。暂存生命周期、重启恢复及重复请求处理在实施时收口，不沿界面精简擅自确定保留期限。
- 分开工作归属和资料读取范围，贯通任务、检索、读取、引用及缓存校验；验证获准跨空间读取，以及跨企业、他人私有资料和撤权后的拒绝。
- 将明确的“只用所选资料”落实为任务及工具层约束；发生资料缺失或范围解析不清时如实提示，不静默扩大搜索。实际使用来源可查看，过期与冲突信息不伪装为可靠依据。

#### 16.12.1 当前差异与建议主路径

只读核对 `a5e635e`：`Plans.tsx` 已有本人计划、草案、启停、真实运行记录及任务链接；新建要求填写目标、用途、资料空间、执行行为、查询、触发、时区、间隔、次数和结束时间，再保存草案并另开启用弹窗勾选确认。日常页面同时展开配置详情及运行历史。当前契约支持每日约定时间、资料版本变化；自然语言建立计划、周/月等其他周期并不是现有能力，不能仅凭模型回复宣称安排成功。

建议主路径：**在会话中说清持续需求 → AI 整理计划卡，必要时只补缺少的条件 → 平台接受后显示真实生效状态 → 按约定执行，从卡片查看结果或调整。** 例如“本月每天早上 9 点，根据销售资料整理经营简报给我”。临时问题照常处理，不先要求建计划。

- 已有明确委托，且范围、时间/触发、接收者、结束条件和资源政策足够明确并获准时，直接保存生效并返回计划卡，不再让用户重复填表和勾选同一授权。
- AI 提议或关键条件不足时，卡片显示待确认/待补充。只询问会影响执行的缺口；整理完整后用一次“启用计划”完成用户决定，不强制“保存草案 → 打开另一个弹窗 → 再勾选”。普通“这个问题很重要”等表述不自动建立无限持续任务。
- 卡片说明“做什么、何时做、用哪些资料、结果给谁、持续到何时”；已有有效的资源限制可继承并按需查看，额度或费用承诺未确定时不能默认无限运行。仅隐藏技术表单不构成授权证据，平台须记录被接受的计划版本及依据；保存失败或结果未知不得显示已生效。

#### 16.12.3 精简操作但保留含义

- 常用操作随当前状态显示，例如运行中可暂停、暂停后可恢复；修改要求可直接在会话中表达，也可从卡片进入简洁编辑。停止及提醒偏好放次级操作，不常驻一整排按钮。
- 暂停/停止整个计划与取消某一次任务分开；卡片说明对在途工作的实际影响，不能宣称已发生的动作被撤回。暂停保留后续恢复入口，停止后不自动复活。恢复核对当前权限、条件及待核对结果，不盲目重做未知执行。
- 关闭提醒只改变告知，关闭卡片或网页不停止后台工作。已明确的低风险指令沿现有授权处理，只有目标不明或确实超出范围时补充决定。
- 修改时间、资料或交付要求，返回更新后的计划摘要和真实版本；没有变化的字段沿用，重复提交不建立多个计划。超出原授权的范围、接收者、资源或业务动作仍需相应有效决定。

#### 16.12.4 与资料范围及真实执行衔接

DEC-112 的会话默认检索不自动赋予永久后台读取资格。计划把本次委托的资料来源、用途和接收者保存为可执行范围，允许范围内后续版本按约定触发；未来新空间不因用户有权读取就自动加入旧计划，撤权后不能沿历史许可继续执行。

明确周期交付即使没有新变化也按约完成；缺资料、未执行与已核查无变化分别显示。中断后按交付义务处理错过的周期，不能把未执行日期显示为已完成。当前仅支持每日/资料变化的实现是能力起点；其他周期、会话建计划、范围契约及卡片接入需在确认后的统一清单中明确开发与验收，不能靠前端文案模拟。

本轮待确认：持续计划以会话建立和调整、统一卡片查看为主，集中列表作为次级入口；条件与授权明确就直接生效，有缺口才补充或确认；正常计划不挤占待办，成果按价值进入画报。具体组件布局、周期表达及后端接口留待实施细化。
