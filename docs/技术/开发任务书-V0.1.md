# 梦核工作空间：开发任务书 V0.1

> 2026-09-24 用户要求将各开发目录整合为一个版本并提交。当前已实现切片与最新前端共同收敛至主目录 `main`，旧分段 PR/工作目录用于历史追溯，详见[统一版本记录](../交接/开发目录整合与统一版本-2026-09-24.md)。本轮不新增业务功能，不改变真实模型、WeKnora、云环境和用户体验的待验收状态。

本任务书将已有决定转为任务、依赖与验收。用户于 2026-09-22 要求继续下一步，询问是否进入任务书确认及后端开发期间能否继续优化前端。用户随后明确要求按计划开始整体开发，本任务书进入执行；未决业务规则和具体工期仍按对应切片确认。2026-09-23 用户进一步授权自行完成既定开发任务和模块，常规实现无需逐步索取确认；遇业务权限、费用、资料外发或范围等需要拍板的事项再提问。

## 1. 建设目标和边界

先让本项目真实自用：对话、画报、资料库围绕同一批获准资料与实际任务运作；引擎按初始设定结合项目进展产生成果，用户边开发边使用、边调优。具体场景持续探索，每次交付仍有明确的输入、行为、成果和验收依据。

已确认范围：

- 用户提出客户端、企业管理端和平台总台三类入口，职责和权限应在身份模块实施前对齐，见[三端架构与管理权限](三端架构与管理权限-V0.1.md)；具体管理功能分批交付。
- 两个新增管理端与当前客户端保持统一风格和排版逻辑，优先复用组件与样式；首期聚焦简单、核心流程，三端功能与页面随用户测试持续优化（DEC-045）。
- React 网页持续演进；Spring Boot 业务平台按模块组织；独立梦核引擎通过版本化契约构建、发布、升级及回退。
- 网页覆盖 macOS、Windows、iOS、Android、HarmonyOS 的目标浏览器。后端共用，移动和桌面 App 后置；云端为主，草稿恢复及文件上传下载先行。
- 首期管理员邀请成员，使用邮箱和密码登录；企业微信等通过统一身份接口后续接入。
- 当前共用服务。企业归属和隔离从基础平台开始落实，第二个独立试点接入前完成多租户管理及隔离验收；9POP 面向管理者，群力面向全员。
- 默认文件范围沿 DEC-040，表格按任务、模型和工具实际能力处理；默认范围外查找技能/工具，可信目录内自动使用，公开候选经隔离试验、检查通过后用于当前任务。
- 首期公开搜索与阅读，业务系统经授权接口接入。网页编辑系统文稿并导出 Word/PDF，表格成果可下载 Excel；原 Office 下载修改后上传新版本。
- Harness 和 WeKnora 优先原型验证；Jev 是可关闭的可选判断候选，不阻塞核心流程。平台持有原件、版本、权限与任务事实，是否采用具体组件以验证为准。

后续另行安排：原生 App、客户私有部署、完整离线同步、本地 Agent、登录后网页自动操作、完整 Office 在线协同编辑。复杂跨部门协作、业务应用生成和外部系统写入按具体场景确认；Demo 已有入口不代表首期全部承诺实现。

## 2. 当前起点

2026-09-22 核对主线 `1743fce`：已有 React/TypeScript/Vite 页面、演示数据与测试；尚无真实业务后端、数据库或产品模型调用。

`src/store.tsx` 的 `DemoProvider/change()` 将演示业务状态保存在 localStorage；`Conversation.tsx`、`LibraryDialogs.tsx` 等直接修改演示状态。因此第一批需要建立数据访问边界，不能只填入后端 URL 即视为接入完成。演示权限、预置回复和本地成功状态不能沿用为真实服务端事实。

Git 普通主线已可协作，旧 CI 提交单独保留且远端授权待补。新任务从当前 `origin/main` 开始，不携带未授权工作流；照常执行本地检查，不能报告未运行的远端 CI 已通过。

## 3. 前后端并行与逐步联调

先约定接口，再由前端、平台与引擎按模块并行，每完成一段真实能力就接入现有页面。首条联调先完成总台开通企业、企业管理员邀请、成员登录，再接资料上传、列表和下载，随后接引用资料的会话与画报。最终阶段做完整验收，联调贯穿各批次。

```text
页面与交互 → 页面状态及数据访问接口
                       ├─ Demo 实现（开发和演示）
                       └─ 真实 API → 平台 → 引擎 / 执行环境 / 资料服务
```

两个数据实现遵守同一契约，按明确环境或开发配置切换。真实环境后端失败时显示失败与重试，不能静默回退演示数据或预置回复。业务操作按接入切片迁出 `change()`，避免浏览器与服务端各自产生一套业务事实。

前端负责展开、焦点、滚动、动画和未发送草稿等交互状态；企业身份、权限、资料版本、任务终态、发布和用量以服务端为准。跨设备草稿和偏好的同步细节另定。

| 同期前端改动 | 例子 | 协作方式 |
| --- | --- | --- |
| 表现和操作优化 | 按钮位置、卡片尺寸、动效、触控容差、焦点、滚动、同含义文案 | 可持续独立优化，验证受影响交互 |
| 数据需求变化 | 新筛选字段、跨页排序、统计数字、持久保存偏好 | 核对现有接口；需要新查询/存储时共同更新契约与样例 |
| 业务行为变化 | 共享对象、默认保存位置、自动发布、批量操作、取消任务、覆盖版本 | 前后端一起调整规则、状态与验收；新业务授权范围另行确认 |

影响取决于操作含义而非代码行数：移动“发布”按钮通常独立；将“保存草稿”改成“保存并发布”涉及权限和状态。调整排序如果涉及分页，需与后端规则一致。

保持稳定的是身份、权限含义、状态和操作结果，界面无需全部冻结。契约可以演进，优先兼容新增字段；破坏性变更同步迁移调用方并回归后启用。

## 6. 必须对齐的接口边界

| 边界 | 首批约定 |
| --- | --- |
| 网页 ↔ 平台 | 登录态、企业/空间、资源版本、分页排序、权限结果、错误与并发控制；请求接受和任务完成分开 |
| 平台 ↔ 引擎 | 契约版本、目标、授权资料句柄、引擎/方法版本、事件、结果、用量、取消和恢复；引擎不直接操作业务表 |
| 执行环境 ↔ 工具 | 任务身份、文件范围、允许动作、网络出口、资源限制、产物和失败记录；工具不能自行提升权限 |
| 资料 ↔ 检索 ↔ 引用 | 原件与衍生内容、具体版本、权限及解析状态；引用不因最新版本变化而悄悄改变 |
| 会话/引擎 ↔ 画报 | 结构化卡片类型与版本、来源、时间、受众、状态和继续会话入口；样式布局由前端决定 |

不预编造 Harness SDK 或全部接口路径，首批通过实际原型形成可运行契约和样例。其他客户端以后复用业务接口，呈现可分别适配。
