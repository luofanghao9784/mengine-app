# 企业端权限改造与验收（2026-10-14）

> 2026-10-15 用户再次明确：Claude 最新前端接入采用本文权限版本。此前 10 月 13 日原型中不含密级/审批的规则保留历史含义，不作为本轮场景实现依据；总台与员工端保持原范围。见[整合记录](../交接/Claude企业端本地整合与验证-2026-10-15.md)。

## 范围与现状差异

按用户最新要求，本次只改企业端数据基座场景及其必需的接口鉴权，不改造总台或员工端的权限产品流程。入口为 `/tenant-admin/` →「成员与权限」。保留现有数据、知识星图、模型配置、企业间输入接口和总台处理链路。

原有场景按管理员/治理角色粗粒度开放，签名转发默认借用来源管理员；本次改为中央身份验证成员关系、来源侧按企业和成员建立独立映射。新成员首次进入初始化为 L0 岗位成员，不继承服务管理员。既有萌物志宠小屋测试账号明确映射现有企业管理员。企业身份映射不改变中央账号的总台身份或员工端角色。

## 权限矩阵

所有角色均不能在线编辑正文、标题、摘要、业务标签、表结构或记录，也不能通过旧编辑接口和工具绕过。只读约束不阻止获授权的系统导入、来源同步或模型生成任务。

| 能力 | 企业管理员 | 数据治理负责人 | 部门负责人/岗位成员 | 审计员 |
|---|---|---|---|---|
| 企业内内容读取 | L3；包含私有资源 | 密级 + 范围/显式读取授权 | 密级 + 范围/显式读取授权 | 密级 + 范围/显式读取授权 |
| 修改读取权限与密级 | 直接生效，记录原因及前后值 | 提交读取权限申请 | 提交读取权限申请 | 提交读取权限申请 |
| 审批读取权限 | 可批准本人旧申请 | 独立审批范围内，禁止自批 | 无 | 无 |
| 治理元信息 | 本企业 | 独立治理范围 | 无 | 无 |
| 治理复检 | 本企业、状态校验 | 治理范围 + 密级 | 无 | 无 |
| 隔离正文检查 | 原因 + 审计 | 独立检查范围 + 密级 + 原因 + 审计 | 无 | 无 |
| 连接维护/来源同步 | 本企业 | 指定连接；同步另校验治理范围 | 无 | 无 |
| 资料导入 | 有 | 独立导入能力 | 独立导入能力 | 无 |
| 部门、成员与职责管理 | 有 | 无 | 无 | 无 |
| 审计记录与链完整性 | 有 | 无 | 无 | 有 |

读取仍要求账号启用、同企业、资源 ready。管理员不越过隔离/归档、AI 暂停、模型输入保护和版本校验。治理元信息不授予正文；检查隔离正文不使其进入检索/模型。审批范围与治理范围独立，审批列表和待处理数量使用同一过滤结果。

## 企业页面

- 资源权限：资源版本、权限版本、读取范围、L0–L3、成员/部门/角色 read 授权；填写原因后管理员直接保存，其他角色提交审批。
- 审批中心：批准、拒绝、本人撤回；生效时再次验证审批资格、申请状态、两类版本及授权对象是否启用。失效申请不能恢复为有效旧版本。
- 部门与成员：稳定部门 ID；重命名保留授权，仍有成员、资源、职责或待处理申请引用时禁止删除；管理员可调整角色、密级、启用状态及独立职责，不能停用或降级最后一名管理员。
- 操作审计：按企业显示追加式哈希链。隔离检查需原因和审计，检查内容显示 60 秒后清除。权限状态每 15 秒刷新，失败清除本页缓存；所有实际操作仍实时由服务端校验。

保留用户此前去掉的导入数据集、连接数据库入口，以及表记录更正/删除入口的隐藏状态。独立导入和连接能力属于后端授权与职责配置，不重新添加这些业务入口。

## 接口能力与调用链

企业会话 → Java 企业成员鉴权 → 带时间戳/随机数的 HMAC 请求 → 来源企业/成员映射 → Mengine 当前用户鉴权 → 资源能力与版本校验。模型和连接凭据保留服务端。

| 接口 | 校验 |
|---|---|
| GET `/scene-access` | 当前身份；按资源能力裁剪；成员与连接目录仅管理员 |
| POST `/scene-access/policy` | 当前资源、内容/权限版本、read 授权对象；直接生效或 pending |
| POST `/scene-access/proposals/:id/resolve` | 当前审批职责、非管理员禁自批、状态、版本、授权对象 |
| POST `/scene-access/proposals/:id/withdraw` | 当前企业、本人、pending |
| POST `/scene-access/departments` | 管理员、稳定 ID、所有引用 |
| POST `/scene-access/members/:id` | 管理员、同企业、有效部门/职责目标、最后管理员保护 |
| POST `/scene-access/resources/:id/inspect` | 独立检查能力、隔离状态、密级、原因与审计 |
| GET `/scene-access/audit` | 管理员/审计员、当前企业 |
| 原编辑/字段/记录接口 | 明确拒绝人工内容修改，不依赖按钮隐藏 |
| 受控同步/字典生成 | 独立系统能力；任务前后重查身份、来源及版本 |
| 知识/星图 | 当前可读且 AI 可用的来源；变更或撤权使依赖结果失效 |

普通客户签名请求不能直接调用整企业导出；总台原有系统调用继续使用自己的受控身份。同步任务列表和执行同样校验指定连接及治理范围。

## 迁移与保留

`access-migration.ts` 使用事务与版本账本，可重复启动：

1. 给现有部门建立稳定 ID，迁移成员、资源及部门授权。
2. 管理员有效密级为 L3；历史 edit 授权降为 read，不增加任何隐含治理职责。
3. 原有 pending 方案全部失效，避免旧内容编辑方案继续生效。
4. 仅在知识来源指纹完全匹配“加入部门 ID 前/后”的资源时迁移指纹表示；实际内容或权限变化不会被伪装为未变化。部门更名不使知识失效。
5. 追加迁移审计。原始资料、行记录和知识内容不清空，不重建测试企业。

本地迁移前备份位于来源工程 `.runtime/backups/before-permissions-20261014.db`；凭据和备份不入库。回退须停止写入后成套恢复源码及数据库备份，不能只回退数据库后继续运行新代码。

## 验证与适用边界

- 权限专项 11 项：五角色只读、企业/密级/状态隔离、立即授权、审批、自批限制、过期版本、停用授权对象、旧写接口封堵、隔离检查、稳定部门、最后管理员、旧授权迁移，以及普通成员知识读取和独立职责。
- 数据库/字典 10 项：真实只读 SQLite、凭据与路径保护、来源变更、模型失败保留、同步增删改及幂等、后台撤权。模型生成采用测试替身，不等于真实模型效果验收。
- 知识/星图 6 项：来源权限、撤权、失效缓存、处理中变更、失败重试及越界引用。
- 签名桥接 1 项：签名、防重放、跨企业拒绝、数据保留、新成员默认 L0、禁止客户整库导出及停用身份。
- TypeScript 检查、企业前端生产构建和 Java 打包通过；浏览器验证真实企业「成员与权限」及组织管理。
- 本地真实接口验证：77 个来源（15 表 + 62 资料）、87 条知识；共 164 个来源/知识同步条目。第二企业访问第一企业返回 403，无来源绑定返回 404，重复同步不改变映射/修订。知识处理接口在一次上游失败后复测成功。

本轮不是总台与员工端全平台 ACL 重构，也不是整个历史测试库的全量验收。已有来源同步仍为定时快照，不提供 CDC 强实时一致性；现有文件接入保留其处理流程，未新增在线版本编辑器。权限与 UI 配套源码已落本地，未执行本轮 Git 推送。
