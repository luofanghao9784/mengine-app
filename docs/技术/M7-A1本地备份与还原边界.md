# M7-A1 本地备份与还原边界

> **历史记录提示（2026-10-01）：** 本文保留 2026-09-24 首轮实现及验证事实。当前恢复已改为“隔离还原 → 当前权威状态核验 → 显式开放”，生成新登录凭据，不再沿用备份时密码或 V14 固定版本假设。现行命令、30 日轮转与恢复边界以[当前恢复契约](../../contracts/local-backup/README.md)和[本地试用指南](../交接/本地三端试用指南.md#m7-a1-本地备份与新目录还原)为准。

日期：2026-09-24。对应 M7-A1、POS-03/POS-06 与需求第 13—14 节。此批实现本地试用恢复链路，使用合成数据验证；不代表云灾备、生产上线或整个 M7 完成。

## 备份单位与一致性

备份整个本地试用实例：全部企业、账号及密码散列、成员/空间权限、资料目录与版本、解析/检索片段、会话/任务/引用、私人产物、画报偏好、文稿历史与缓存导出、共享发布及审计记录。共享动态由恢复后的版本数据投影。多租户共用数据库的实例级备份包含各企业内容，仅作为本机操作者命令，**没有总台内容读取/导出 API 或页面**。

工具 `scripts/local/backup.py` 复用本地启动器的工作树绑定、私有目录和进程锁。原应用必须正常停止；持锁期间拒绝启动，也不主动结束正在使用的服务。数据库必须无现存 `postmaster.pid`，工具不会删除 PID 文件或接管进程。内部短暂启动该实例的 PostgreSQL，通过私有 Unix socket 读取，关闭 TCP 监听，不启动平台、引擎或任务执行器。存在排队/运行中解析或会话任务时拒绝备份，先在原环境处理完成或取消。

数据库用 PostgreSQL 18 的 custom 格式逻辑备份；外部原件只复制 `material_versions` 引用的 UUID 对象，并验证大小和 SHA-256，不清理原目录的孤儿文件。两者都在业务停止期间读取。`conversation_artifacts`、`private_document_exports` 的 bytea 内容随数据库备份。除登录会话表外，每个 public 表按 JSON 行排序后生成流式摘要；恢复后在任何业务改动前逐表比对。

## 来源与完整性

备份目录含 `database.dump`、`objects/`、`manifest.json`。清单有格式版本、创建时间、源码提交、迁移文件摘要、表行数/摘要与文件大小/摘要；不写资料名称、正文或原配置密码。清单用单独保存的 32 字节随机密钥做 HMAC-SHA256 验证。目录须归当前用户、权限 0700，文件 0600；不接受符号链接、未知路径、额外文件、缺失文件、校验失败或不兼容的格式。首批限制 10000 个原件、备份文件合计 2 GiB；这是工具上限，不是已验证的容量承诺。

来源密钥不能放在备份内部。恢复先验证清单和全部文件，再复制到新私有目录并重新验证，之后才让 `pg_restore` 读取快照。数据库备份可以包含可执行 SQL，因此只接受本工具生成、由原独立密钥验证的自有备份，不接受陌生数据库归档。HMAC 证明掌握该密钥的备份来源与完整性，**不提供加密**；本机账号或密钥失守不在其防护范围。备份含全部业务资料及密码散列，应按原始资料同等保护。

## 恢复后的身份与运行状态

- 只接受不存在的新目标目录，原试用和备份不覆盖；与当前迁移文件不一致时拒绝恢复。首批支持同版本 PostgreSQL 18/当前 V14；不是跨版本升级工具。
- 重建独立数据库，生成新的数据库密码与三端随机端口；不复制原 `accounts.json`、`database.json`、环境变量、第三方密钥、邀请投递文件、日志或执行工作目录。原账号仍用备份时的登录密码。
- 不备份 Spring Session 数据；恢复后所有人重新登录。将恢复副本中的 PENDING 邀请标为 REVOKED，已接受的成员关系保留。该离线恢复选择由 `restore.json` 记录，不改变原环境的邀请状态，也不新增日常邀请业务政策。
- 原文件中的明文初始密码没有备份；使用者需自行保管账号凭据。本批不新增找回密码流程。
- 数据库和原件验证通过、旧会话校验及邀请处理完成后，最后才写可启动的 `config.json`。失败不产生可启动配置；若临时数据库停止失败，保留其目录以便排障，禁止清除仍可能运行的数据。
- 浏览器未提交的草稿不在服务器备份中。工作树代码、依赖、模型/WeKnora 配置及外部服务数据也不在此包内；恢复主机要先准备对应代码与运行依赖。

## 替换及尚未覆盖的范围

公开业务 API、引擎 0.9.0、Agent 1.4、资料/文稿与 Activity 契约和 V14 结构均不变；网页不增加管理备份入口。替换对象存储或数据库时，仅替换运维备份适配，并复用业务快照/字节/权限恢复验收。

首批实测 macOS 本机；不承诺 Windows 原生启动器或 Linux 云端灾备。在线一致性备份、自动排程、加密及异地保存、保留/删除政策、点时恢复、故障断电耐受、容量/RPO/RTO、跨版本升级回退与客户私有部署仍需单独设计及验证。没有实际调用云模型、部署服务、改动已有自用数据或写入客户系统。

操作见[本地试用指南](../交接/本地三端试用指南.md)，证据见[验证记录](../交接/M7-A1本地备份与还原验证-2026-09-24.md)。数据库方案依据 PostgreSQL 18 官方 [pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html) 与 [pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html)，选择 custom 格式与单事务/遇错终止恢复。


## 2026-10-04 总台只读观测接入

这是独立管理端分支的观测增量，旧章节 V14 等保留历史含义。当前完整恢复适配、迁移重排及真实恢复仍待重新验证；本节不授权对现有实例执行备份/恢复或切换。

部署侧为同一实例维护一个独立私有观测文件，父目录 0700、文件 0600，路径与业务备份、签名密钥分别管理。对原本获准执行的 `backup.py` 命令附加 `--status-file` 即可；不附加时行为不变。以下仅展示一次获准校验的命令格式，所有路径须由部署人员替换，不能指向客户或其他实例：

```sh
python3 scripts/local/backup.py verify \
  --bundle /absolute/owned-backup \
  --key-file /absolute/private-key.json \
  --status-file /absolute/private-monitor/backup-status.json
```

平台服务启动配置 `BACKUP_STATUS_FILE` 指向同一个文件，读权限只授予对应服务账号；文件不得暴露给静态站点。`BACKUP_STATUS_STALE_SECONDS` 默认 900，可设 60—604800，按实际观测频次配置，不是备份周期。未配置默认显示未接入。`scripts/local/trial.py` 会过滤来自调用环境的 `BACKUP_*`，不自动接入其他实例报告；本轮未调整其启动配置或正在运行实例。需要试用接入时应单独显式配置并验证归属，不绕过隔离过滤。

报告最多 40 个部署操作，原子替换且不包含位置、表名、资料、凭据、错误正文。只读取原命令明确成功后的签名元信息；失败还原不能用提前写入的 `restore.json` 推断完成。监测写入失败仅给出静态提示，不改变实际命令回执、不自动重试实际命令；进程终止可能只留下开始记录，超过窗口显示结果待核对。观测文件属于部署可信元信息，不代替签名备份校验；命令历史也不代替当前恢复点存在性检查。

生成、完整性校验、隔离还原、当前权限核对及开放恢复实例独立展示。有效期取签名清单历史事实，不改变项目保留政策；备份文件可能在观测后被删除或损坏，因此 UI 明确要求重新校验。下次计划、全量备份大小和部署策略尚未接入；报告清单大小不可当作全部存储占用。页面无配置、覆盖生产、恢复或整包下载入口。

本轮验证包含合成签名归档的实际 CLI 校验/损坏失败回执、有限投影、并发/私有文件边界、后端读取与平台 HTTP 隔离、页面显示。完整 `pg_restore`、跨版本升级/还原及当前权限清理适配未在本轮执行，后续按完整迁移链单独演练。
