# M4-A1 候选工具隔离试验边界

日期：2026-09-23。第五个实施切片，沿用 AI-01—AI-04、AI-12—AI-13、POS-05。落实用户已确认的“公开候选自动隔离试验，通过后用于当前任务”方向。本批为可逆的本地原型：**npm 小型、无运行依赖的 JavaScript INI 解析包**，通过自有 `ini-to-json-v1` 配方验证；没有将需求缩减成永久只支持 INI，也没有交付任意软件安装或所有陌生格式处理。

## 调用与权限

平台仍持有企业、空间、发起人、任务与授权输入；引擎不能访问业务库。`candidate_tool` 是本项目的 TaskTool，Harness 驱动其 `discover / trial / run`，不直接热装第三方包到共享引擎主进程。下载器只发送固定公开查询及包的名称/版本，不接收私有资料；子进程执行器只接收包字节与本次输入，不持有平台或模型凭据。

平台 `AGENT_CANDIDATE_TRIALS_ENABLED=false` 默认关闭；开启要求 `AGENT_TASK_MODE=verification` 且 `AGENT_PUBLIC_WEB_ENABLED=true`。逐步授权回调返回 `candidateTrialsAllowed`，还需任务已明确填写公开检索内容。该授权和原查询必须在整个尝试中保持不变，撤权/取消由每步核验和运行中检查中断。引擎必须配置独立候选适配器，并启用固定版本、摘要核验的 `candidate-trials` 指南后才展示和执行工具；指南本身不能扩大权限。

当前只通过合成联调入口构造候选适配器。正式 `engine/src/main.ts` 不装载它，误设候选开关为 true 会拒绝启动；`AgentTasks` 也拒绝 live 模式配置候选或本地脚本沙箱。普通本地试用环境继续默认关闭模型和候选执行。

## 发现、准入与安装

1. 使用用户单独填写且已持久化的公开关键词访问固定 `https://registry.npmjs.org/-/v1/search`，最多取 3 个合法候选。查询不是从工作要求或资料片段生成，模型不能指定查询、包名、版本或地址，只能使用本次返回的随机 ID。
2. 按精确名称和数字版本读取元数据，tarball 必须是同一 npm 主机上的规范地址。全部请求沿用 HTTPS、全 DNS 答案检查及固定地址连接；候选请求拒绝所有跳转，不发送 Cookie、凭据或私有文件。
3. 必须带 SHA-512 integrity，下载后逐字节摘要核验。元数据及包内 package.json 都要求身份/许可一致，MIT 或 ISC；拒绝运行/可选/peer/捆绑依赖、安装/prepare 等生命周期脚本、bin 和原生扩展。包含 LICENSE 原文并保留其 SHA-256。开发依赖不安装、不运行。
4. 自有解包器将 gzip/USTAR 作为数据解析，不调用 npm install 或系统 tar。压缩包最多 512 KiB、展开最多 1 MiB、最多 80 个条目/64 个普通文件及 512 KiB 文件内容；拒绝穿越、链接、PAX、大小写重复、非允许文件类型及缺失入口。只支持保守子集，不做通用包管理器。
5. 所谓安装是把已校验的包文件放入独立任务目录的只读模块区，不修改工作空间 node_modules，不执行任何安装钩子。包首次执行发生在离线子进程内；试验只给固定合成 INI，绝不给业务资料。父进程比较实际 JSON 与固定预期，失败记为 REJECTED，成功才为 READY。
6. READY 包可在当前尝试内复用原先校验的同一批字节，每次新建执行环境，只挂载一个当前授权的 UTF-8 资料片段。当前片段来自检索，不是整份上传原件；上限 16 KiB，成功产生转换 JSON。最多试验 2 个候选、执行 2 次，沿用每任务各 8 次模型/工具及 25 秒总时限。

候选的 SHA/许可字段来自源站元数据和下载内容，未验证 npm registry 签名或构建 provenance；摘要一致不证明发布者可信、程序安全或结果全面正确。一次合成样例通过不等于完整 INI 规范验收、业务数值审计或所有格式可处理。失败不能通过去掉隔离继续执行，任务内成功不会自动进入企业/平台可信目录。

## 执行与结果

macOS 本地后端沿用 Seatbelt、Node 权限限制、干净环境、独立进程组、时限与输出限制。子进程不能读宿主业务文件、改写输入/模块、创建其他进程或访问网络；结束、异常及取消等待进程退出后删除任务目录。当前没有完整内存/磁盘硬配额和引擎崩溃后的孤儿目录回收，**不能用它承诺云端生产多租户恶意代码隔离**。Node 权限模式只是额外限制，OS 隔离仍是必要边界。

成功运行的转换文件与固定代码生成的 `candidate-report.json` 使用既有私人产物接口。报告保留 registry/包 URL、名称/版本、归档与许可摘要、实际试验输出摘要、状态、已用片段句柄和许可原文；不保存包源码或共享安装。报告同名冲突被拒绝，防止其他工具产物混淆该记录。拒绝是可报告的真实结果，模型收到 REJECTED，不能称之为可用；取消/失权不发布迟到回复或半成品。会话任务成功代表回复交付，具体候选是否通过以报告状态为准。

平台校验模式、公开输入、指南启用、工具回执与产物摘要后，在任务结果事务内保存。产物只能经会话所有者的现有企业/空间授权下载，管理员和总台没有内容旁路。React 复用现有任务卡、指南记录和下载按钮；不把包管理操作放进员工主流程。候选详情本批提供报告下载，尚无独立管理界面或逐步骤进度 UI。

## 协议、替换与剩余工作

引擎 0.5.0，Agent 协议 1.2 增加候选工具回执；旧 1.0/1.1 Agent 请求拒绝。公开会话 API 保持 1.2.0、数据库仍为 V9，无新迁移；来源检索和能力协议继续 1.0。本批升级需关闭 Agent 提交、排空或取消旧任务，再协调替换平台与引擎；回退同样排空，不删除历史产物。没有生产升级/回退验收。

配方、包目录策略、下载适配器和执行后端都在引擎内部；在既有协议与授权范围内优化可单独发布引擎。新增业务写入、原件授权、外部服务或资源计量仍要更新相应接口和验收。

下一步继续 M4-A1：Linux/云端隔离后端与硬配额、崩溃回收，随后扩展任务原件最小授权和更多工具配方，补真实模型/实际搜索服务验收。WeKnora 留在 M3-A1；画报主动分析和成果共享仍按 M5/M6 推进。本批未完成整个 M4。
