# 会话实时交互与 Harness 接入开发任务书 V0.1

日期：2026-10-03。状态：**已完成首轮实现及确定性验证；运行实例升级、真实模型与用户验收尚未完成。**

本任务让员工在会话中知道 AI 正在做什么、逐步读到回复，并能在执行期间补充要求、停止任务、回答 AI 的问题。沿用现有会话卡片、平台任务记录及 DeepSeek Harness，不另建一套执行系统。

依据本轮用户确认及 DEC-125，延续 AI-01、AI-02、AI-04、AI-12 和现有客户端会话要求。RT 编号仅用于拆分开发工作，不替代产品需求编号。本文细化实时交互；资料权限、成果共享及其他处理板块范围仍以原需求为准。

## 1. 已确认的产品要求

| 场景 | 首期行为 |
| --- | --- |
| 开始工作 | 立即显示真实的排队或运行状态；有实际进展时更新简短说明，不编造进度百分比 |
| 执行过程 | 默认展示简短进展和工具操作；详细记录按需展开，避免占满会话 |
| 输出回复 | 最终回复随模型输出逐步出现；尚未完成时明确标记，不提前作为完整成果 |
| 途中补充 | 输入区保持可用，补充进入同一个任务；分别显示“已收到”和“已采用” |
| 停止任务 | 保留明确停止入口，先显示“正在停止”，收到执行确认后显示“已停止”；保留已经完成的操作及结果 |
| AI 提问 | 在会话内显示问题卡，可选答案也可自由输入；需要答案才能继续时显示等待，独立工作可继续时如实说明 |
| 工作完成 | 默认收起过程，以最终回复、依据和成果为主体，仍可展开查看记录 |
| 阅读历史 | 用户在底部时跟随新内容；向上阅读时保持位置并提示有新内容 |
| 页面恢复 | 切换会话、刷新、短暂断线后能恢复任务状态与内容，不重复提交任务 |
| 配置与布局 | 不提供面向员工的“流式输出”开关；保留现有横向卡片带、来源卡和资料卡及最新已确认样式 |

“实时看到思考过程”在本期指可读的进展说明、工具执行状态及逐步输出的答案。供应商明确支持的推理摘要可作为后续可折叠信息验证；完整内部推理不作为产品承诺，也不直接展示 `reasoning_content`、系统提示词或原始模型请求。

| 等待与恢复 | 当前产品已有 WAITING_INPUT、取消及恢复等任务路径 | 将 AI 问题卡、运行中补充和现有任务状态贯通，避免重复建设或混淆语义 |

已安装的 DeepSeek Harness 固定版本为 `0.1.5-rc.2`。本轮检查包类型确认存在 `agent/assistant-stream`、`steer()`、`cancel()` 和带持久化条件的 `resume()`；事件订阅、取消传播、采用确认及恢复条件仍须以原型证明。特别注意：

- `steer()` 面向最近可接收输入的步骤边界；调用成功或进入 inbox 不等于本步已经采用。
- 目前每次执行创建独立会话并释放，已有平台上下文连续性不等于 Harness 会话已持久化恢复。
- 现有执行预算含 55 秒超时及模型/工具调用上限。用户等待问题不能一直占用执行预算；不能通过无限加大超时掩盖生命周期缺口。
- Harness 原始类型不泄露到公共 API；平台仍负责企业隔离、任务事实、授权和最终结果。

## 3. 实施边界与技术决定

已确认的是第 1 节的产品行为。下列为可逆的实现方案，实施时记录验证结果和必要调整，不重新扩大业务范围。

1. **模型输出、执行过程、业务状态分层。** 开启模型流只解决答案增量；工具状态、提问、停止与补充依靠 Harness 和平台协议。不要用逐字播放完整回复模拟真实流。
2. **平台作为客户端事实入口。** 浏览器不直接连接模型或 Harness；引擎不能直接写平台数据库。沿现有受鉴权回调扩展过程事件，最终结果仍通过现有业务校验提交。
3. **浏览器优先使用 SSE。** 同源鉴权下按游标订阅；具体选择 EventSource 或 fetch 流以现有认证方式验证。保留已有轮询作为兼容降级，不复制两套状态处理。
4. **文本增量暂态、结果提交权威。** 批量保存文本增量及定期快照，避免每个 token 一次 SQL；关键状态、输入和工具回执持久化。未经最终校验的文本不能触发共享发布或冒充已完成成果。
5. **不替换 Harness。** 不引入新的 agent loop，不将 Codex 内部协议视为本项目 SDK；只借鉴其可读进展与可介入的交互方式。
6. **不顺带扩展。** 不新增多任务并发编排、任意检查点恢复、完整推理展示或通用审批平台；本次问题卡不绕过既有授权和确认规则。

## 4. 任务、内容和事件约定

在现有 conversation/task/attempt 之上增加内容项和用户输入记录。字段和事件名在 RT-01 定稿，以下是语义草案，不代表现有接口。

| 对象 | 必须表达的信息 |
| --- | --- |
| 事件信封 | schemaVersion、会话/任务/尝试身份、单调 seq、事件种类、产生时间、内容项身份与版本 |
| 内容项 | 进展说明、工具操作、最终回复、问题；草稿/完成/中断状态；增量序号及快照版本 |
| 用户补充 | 唯一输入 ID、客户端幂等键、目标任务/尝试、文本、收到时间、采用时间或未采用原因 |
| 问题 | 唯一问题 ID、选项与自由文本规则、是否阻塞、有效版本、回答记录及失效原因 |
| 控制指令 | 目标尝试及执行所有权版本、幂等键、请求/接收/完成状态、超时或结果未知 |

建议事件语义包括：任务状态改变、进展更新、工具开始/完成、答案增量/提交/中断、补充收到/采用/未采用、问题发出/回答/关闭。命名复用现有契约风格，不能仅将任意模型 JSON 转发给前端。

必须保持以下不变量：

- 事件只能归属获准的企业、会话、任务和当前有效尝试；拒绝跨企业、跨会话、过期执行写入。
- 任务终态由平台确认；展示的“已完成”不由模型文本或流连接关闭决定。
- `seq` 负责去重和恢复；不同内容项的文本不可按抵达顺序混拼。遗漏事件应重拉或回到权威快照。
- 最终快照与暂态文本按内容项身份替换，不重复出现整段答案；流未正常结束时标记中断。
- 原始工具参数、密钥、完整检索材料及诊断栈不得直接进入员工可见事件。工具名转换为业务可读名称。
- 订阅鉴权与现有读取权限一致；撤权后终止订阅、停止重放并清除对应客户端缓存。长连接需要撤权检查，不能只在建连时检查。
- 断开浏览器仅断开观察，不取消任务；刷新页面不得自动重放写操作或模型执行。

## 5. 途中补充、停止和问题卡

### 5.1 运行中补充

运行时输入区显示“补充要求”，发送按钮与停止按钮分开。保留 IME、附件和草稿的现有行为；本期最低闭环为文本补充，执行中附件是否支持须在 RT-01 根据现有附件权限和输入快照机制明确，未接通前不得显示可发送状态。

平台先持久化补充并返回“已收到”，再交给持有当前尝试的执行器。执行器在合法步骤边界将补充交给 Harness；只有确认输入已进入后续实际模型调用的上下文，才记录“已采用”。如 SDK 缺少该确认，必须补齐受控观测或调整文案，不得以 `steer()` 返回替代。

- 多条补充有序且幂等；重连/重试不重复采用。
- 当前步骤可以完成，但新输入不能被静默带入另一个任务或丢失。
- 任务恰好结束、停止或换尝试时，返回可识别冲突并保留文本，提示“本次未采用”；由用户决定后续发送，不自动启动新任务。
- 输入不自动扩大资料权限、跨空间读取或共享授权。

### 5.2 停止任务

收到停止请求后平台进入可观察的“正在停止”阶段，向正确执行实例发送取消；取消模型连接并阻止尚未开始的后续工具调用。已开始的外部操作按真实结果记录，不把停止解释为回滚。

停止完成必须有执行器确认或明确的失效处置证据。回执超时显示“停止结果待确认”，不虚报完成。完成与停止并发时，用平台版本及终态规则裁决；旧尝试的迟到回包不得覆盖新状态，已经确认完成的成果也不能被迟到取消抹除。

保留可见的部分回复并标记中断，已成功工具回执继续可查。再次执行通过明确动作进入新的尝试，不能自动重复可能有副作用的操作。

### 5.3 AI 提问与等待

复用当前 WAITING_INPUT 和恢复入口，定义结构化问题能力，不从普通回复标点中猜测问题。

- 缺少必须信息时发出阻塞问题，保存可恢复的业务上下文与问题记录，释放当前执行资源，进入等待。
- 回答后重新校验权限、问题版本和任务状态，通过同一业务任务的合法恢复/新尝试路径继续。首期不承诺保留任意进程内检查点。
- 对非阻塞问题，只继续原授权内独立且不依赖答案的工作；问题旁明确显示“其余工作继续”。
- 回答提交成功与执行采用分开反馈；重复点击幂等；已取消、已完成或过期的问题不能再次驱动执行。
- 不预选并自动提交答案，不把等待超时视为用户同意。普通澄清答案不能替代有权限含义的授权确认。

## 6. 会话呈现和恢复体验

一个任务对应一组可折叠过程。运行时默认显示最新简短进展及当前工具操作，展开后按顺序查看；连续同类更新合并，避免每个 token 或事件生成一条消息。任务完成后自动收起未被用户主动展开的过程组；主动展开状态应保留。

最终回复逐步渲染在独立内容项中。Markdown、代码和表格尚未闭合时保持可读，终稿到达后稳定替换；引用、文件下载与画报成果只有取得有效对象和访问权限后才能成为操作入口。

阅读过程中保持滚动锚点：底部自动跟随，上滑后显示“有新内容”，点击回到底部再继续跟随。卡片宽度调整、横向双指滑动、软键盘与输入法组合输入不得被更新打断。沿用客户端任务书最新样式，包括已确认的输入区遮罩规则，不因本功能恢复旧版特效。

断线显示“连接恢复中”，保留已有内容；恢复时先重放游标后续事件，游标过期则读取快照。重连退避并限制并发连接；不同会话、多个标签页共享同一任务事实，不重复发送输入。降级轮询显示真实状态，不做假流式动画。

## 7. 开发拆分与顺序

| 编号 | 交付内容与主要位置 | 完成门槛 |
| --- | --- | --- |
| RT-01 契约和最小原型 | `contracts/`、引擎 runtime ports；确认事件版本、身份、幂等、状态转换与协议兼容。用合成模型跑通一条文本增量和一次真实工具回执投影 | 明确 Harness 事件订阅、steer 采用观测、cancel 路径；对未支持项有证据和替代路径 |

| RT-05 补充和停止 | 平台控制接口、执行器路由、Harness 边界及输入区；收到/采用/未采用状态与停止确认 | 运行中补充真实影响后续执行；停止与完成竞态不误报、不重复写 |
| RT-06 问题、恢复及验收 | 问题能力、WAITING_INPUT、恢复路径、问题卡、端到端证据和运行交接 | 阻塞等待释放执行资源、回答恢复同一业务任务；真实模型最小验收及文档完成 |

按 RT-01 → RT-02/03 → RT-04 → RT-05 → RT-06 集成，先证明一条完整通路再扩展。每批均保留已有完整结果模式可用；协议升级通过能力协商或版本检查，不要求三端瞬时同步升级。后台管理端仅在确有诊断需要时展示已有任务事实，不新增员工设置入口。

RT-02 必须按供应商真实协议解析流，不能简单把现有 `postJson` 换成字符串切分。工具调用按调用 ID 累积，参数完整并验证后才执行；统计缺失标为未知，不记作零。所有流和回调保留输出大小、调用次数、时间预算及取消上限。

## 8. 验收矩阵

| 编号 | 场景 | 可判定的通过条件 |
| --- | --- | --- |
| RT-A01 | 慢速文本输出 | 响应未结束时客户端已显示真实增量；终稿只出现一次 |
| RT-A02 | 工具执行 | 开始、成功、失败与执行回执一致；无回执时不显示成功 |
| RT-A03 | 混合流与格式 | 文本、分片工具参数、多工具 ID、中文跨字节均正确；不执行半截 JSON |
| RT-A04 | 补充采用 | 先收到后采用；合成执行明确证明后续步骤读取新要求；重复请求仅采用一次 |
| RT-A05 | 补充与终态竞态 | 结束/停止/切换尝试时不丢文本、不冒称采用、不自动创建新任务 |
| RT-A06 | 停止 | 模型连接取消、未开始工具不启动；已完成操作保留；未确认停止不显示已停止 |
| RT-A07 | 问题恢复 | 选项与自由文本可用；阻塞等待不消耗执行预算；回答后继续原业务任务 |
| RT-A08 | 过期或重复回答 | 回答幂等；已关闭问题不能恢复任务；缺省选项和超时不会自动同意 |
| RT-A09 | 断线及重复事件 | 重连、刷新、游标过期能恢复；重复/乱序事件不重复文本或工具操作 |
| RT-A10 | 执行器重启 | 活跃输入和任务有可解释状态；不将重新执行称为检查点恢复，不自动重做副作用 |
| RT-A11 | 权限 | 跨企业、跨用户私人会话、失去空间权限均不可订阅/重放/补充/控制；长连接撤权生效 |
| RT-A12 | 阅读与可访问性 | 上滑不跳底、返回底部能跟随；键盘/IME/窄屏/减弱动态与卡片横滑不回归 |
| RT-A13 | 完成与异常 | 成功后过程收起可查；中断保留部分内容并明确标记；部分文本不变成完成成果 |
| RT-A14 | 兼容与降级 | 旧引擎或断开 SSE 时仍有真实状态及最终结果；无逐字播放伪装，不重复订阅和提交 |
| RT-A15 | 脱敏与监测 | 客户端无原始凭据/内部推理/未授权工具材料；日志可关联任务和事件且不泄密 |

流畅度目标作为工程验收建议：在本地确定性测试中，平台接收事件到页面显示通常不超过 1 秒；连续更新可短时合批。分别记录首个进展、首个答案及完成耗时，不把供应商思考耗时算成前端延迟，也不承诺真实模型固定响应时间。

### 11.1 代码与实现决定

在 `codex/platform/conversation-realtime` 独立 worktree 实现。起点为 `6499e39`，并携带开工时主工作区尚未提交的会话/画报/附件变更作为依赖快照。主工作区仍在并行修改，未覆盖它，也未将这些依赖快照混入一个实时交互提交。该记录描述初始开发状态；本次主线集成已从经 SHA-256 校验的开工基线提取实时功能增量，未收录后续并行界面修改。以后集成界面任务时不要直接复制覆盖 `Conversations.tsx`、`conversation.css`、公共契约和开发决策记录。

- **真实流读取**：模型适配改为 `stream:true`，有界解析 SSE、UTF-8、工具参数分片及 usage；兼容供应商返回完整 JSON，缺失 usage 保持未知。文本增量可在模型响应结束前进入 Harness。保留既有时间/调用/输出限制及取消传播。
- **平台协议**：现有 `check` 返回 `realtimeVersion:1.0` 时启用新增 `live/*` 回调。旧平台/旧执行协议仍走完整结果链路。公共会话契约升至 1.6.0；底层 Harness 固定 `0.1.5-rc.2`，未替换 agent loop，也未调用原始推理内容。
- **内容持久化**：V50 新增草稿、补充、问题表及停止标记。正文按模型步骤保存累计快照和单调版本，约 250ms 合批；不将每个 token 写入数据库。不完整文本不触发成果发布。
- **SSE 恢复**：首期采用带版本的完整会话实时快照，重新连接即恢复当前事实，不另建 token 事件重放日志；普通任务事件继续用既有游标。服务器每 300ms 检查变化、连接最长 25 秒，客户端断开旧连接后重连；失败时快照轮询降级。HTTP 明确声明 `text/event-stream` 并刷新响应缓冲区。该方案是对第 3/6 节事件重放草案的实现收敛，不声称保留逐 token 历史。
- **持续权限**：首个订阅及后续快照都校验私人会话/空间权限，长连接另校验会话存续、账号和凭据版本；撤权后关闭推送并清空实时内容。来源绑定资料仍遵循既有可读任务视图。
- **补充采用**：输入保留请求 ID 和目标尝试，幂等入账；Harness `steer` 入队后，只有后续真实模型请求包含输入标记才确认“已采用”。任务结束后未采用的补充保留并如实标记；提交冲突不自动新建任务。
- **停止**：先记录停止请求，拒绝新模型计费/新工具开始回执；执行器取消模型与 Harness 并回报后才结束任务。已经完成的工具和使用记录保留；旧执行器继续旧取消路径。
- **AI 问题**：新增 `ask_user` 工具，每次尝试最多一张问题卡。阻塞问题通过 Harness `concludeTurn`、平台 WAITING_INPUT 释放执行资源；回答后同一业务任务新建尝试，首个真实模型请求开始才确认采用。问题刚出现但尚未落入等待状态时先禁用提交，避免回答竞态。非阻塞问题继续独立工作，回答作为途中补充。
- **前端**：新增可折叠进展、工具状态、增量答案、问题选项/自由输入、补充收到/采用提示。向上阅读时保持位置，点击“有新内容”恢复跟随；已完成终稿替换草稿，避免重复显示。执行中的补充首期只接收文字，不夹带新附件或更改搜索授权。
- **生命周期/恢复**：资料或对象清理时，V50 触发器同步删除新增私密文本。恢复备份保留隔离机制，将未完成流标为 INTERRUPTED，未采用输入不伪造采用。已从全新合成数据库实际 dump/restore 生成覆盖清单至 V50；未对用户数据库执行恢复。
