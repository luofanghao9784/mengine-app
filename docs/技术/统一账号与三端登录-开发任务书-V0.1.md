# 统一账号与三端登录开发任务书 V0.1

日期：2026-10-10。状态：本地实现及合成验证完成；运行实例未迁移、未部署、未用户验收。

沿 POS-03、WS-02、WS-06—WS-16、M2 身份与三端管理范围细化，不替换原需求编号。本文覆盖 DEC-106、DEC-123 及 2026-10-04 三端身份独立方案中冲突的账号、登录和开通规则；其他业务权限继续有效。

## 1. 用户已确认的规则

1. 一个人使用一个统一账号，可同时拥有总台权限、多个企业的管理权限及多个企业的客户端成员身份。账号统一不代表企业、空间或内容权限统一。
2. 统一入口采用手机号和密码登录。暂不提供验证码登录，包括“快捷登录”和以验证码换取登录会话的旁路。
3. 总台允许设置专用登录名及专用密码，登录名可以是手机号。专用凭据关联同一个用户身份，不再创建独立的平台用户；专用密码仅在总台专用登录入口验证。
4. 未设置专用凭据但拥有总台权限的用户，可从统一入口登录并选择总台。专用入口登录成功直接进入总台，后续可免重复登录切换本人获权的其他端。
5. 统一入口登录成功后，存在多个可用端时选择端；仅一个端时直接进入。总台与其他端都有权限时必须先显示端选择，不因上次端偏好跳过。选项仅显示本人有权限的端。
6. 选择企业管理端或客户端后，仅列该端本人获权企业：一家直接进入；多家且无有效上次选择时选择企业，有有效上次选择时直接进入该企业。两个端分别记忆企业。
7. 企业管理端和客户端均可在当前端切换获权企业；同企业跨端切换保持企业、不重复登录。没有目标端权限时不显示快捷入口，直接访问也须拒绝。
8. 不同标签页保持各自企业、端、页面和草稿，另一标签页切换不强制跳页；退出及权限失效同步生效。
9. 保留邀请制，不增加公开自助注册或自主开通企业。企业发起开通时指定初始负责人；第一个企业成员必须是初始负责人。企业正式开通与负责人落实必须同时成功。
10. 初始负责人接受页以“接受并开通企业”明确接受职责，取消可选职责复选框。新用户在邀请内建号，已有用户验证原身份后复用账号，匹配的已登录用户直接确认。
11. 企业管理员从已有有效成员中由负责人任命，不增加注册或接受环节。普通员工邀请可选择初始共享空间，加入时按当前有效授权落实；管理身份本身不扩大资料权限。
12. 总台首位管理员采用一次性受控初始化，后续人员由已有管理员邀请；不开放公开注册。已有平台账号保留，不重走首位初始化。

## 2. 目标流程与状态

### 2.1 登录与导航

统一登录 → 获取服务端身份及可用端 → 必要时选端 → 必要时选企业 → 进入目标页面。

| 场景 | 结果 |
| --- | --- |
| 仅总台权限 | 进入总台，不选择企业 |
| 仅客户端权限 | 按客户端有效企业及上次选择进入 |
| 企业管理员，无总台权限 | 选择企业管理端或客户端，再确定企业 |
| 总台及客户权限同时存在 | 先选择本人可用端；选择总台不经过企业选择 |
| 总台专用入口验证成功 | 直接进入总台；后续按本人权限切换端 |
| 上次企业失权 | 删除失效偏好，多家重新选择，一家直接进入 |
| 明确企业或工作链接失权 | 展示无权访问，不静默改为另一企业的同名页面 |
| 账号有效但无可用角色或企业 | 展示暂无访问资格和接受邀请入口，不循环登录 |

明确工作链接在登录前保留并校验为站内安全目标；多端用户按已确认规则先选端，选中与链接一致的端后再恢复获权目标，其他选择采用该端正常路由。不得将邀请令牌或会话凭据放入跨端 URL。

### 2.2 开通企业

总台填写企业名称和负责人手机号 → 待负责人激活 → 受邀本人验证/登录 → 点击“接受并开通企业” → 原子建立成员、个人空间、唯一负责人及企业管理资格，并正式开通。

- 待激活状态不允许普通员工加入、正常业务执行、自动任务或采集启动，不能视为服务已开通。
- 接受前可撤销或更换初始邀请；撤销后保留开通申请，重新发出有效邀请后才能激活。
- 接受事务失败应整体回滚；并发和重复提交只产生一名初始负责人、一份成员关系及一个个人空间。
- 接受成功后，总台不能使用“重新邀请初始负责人”绕过正式负责人交接。
- 首位负责人激活后进入该企业管理端；员工加入后进入该企业客户端。
- 已开通企业保持现有生命周期，不因本次改造重新初始化；存量无负责人企业单列核对，不能猜测负责人。

### 2.3 注册、邀请及初始化

邀请先识别统一用户：新用户填写姓名及密码并完成适用身份核验；已有用户验证原账号，不覆盖姓名/密码；已登录且身份匹配仅确认；账号不匹配时切换后恢复邀请意图。

平台邀请授予总台角色，员工邀请授予企业成员身份，初始邀请授予唯一负责人身份。平台角色不要求必须先设置专用凭据；专用凭据由本人在已认证的账号设置中维护，不允许邀请人代设本人正式密码。

首位平台管理员初始化仅允许预先配置的对象，通过一次性受控入口建立统一身份及平台角色；成功后永久关闭普通初始化路径。手机号持有权未验证不能写入已验证标志。存量平台账号继续兼容原登录名，不能强行要求重新注册或伪造手机号。

## 4. 实施决定与权限边界

以下为可逆技术选择，不作为额外业务确认：

- 以统一主体关联多个认证凭据，业务权限仍来自平台角色、企业成员关系和空间授权。优先复用现有账号 ID；确需关联历史双账号时增加可追溯映射，不批量重写历史作者和审计主体。
- 总台专用登录名采用独立凭据命名范围；手机号按现有规则规范化。统一登录只验证统一密码，总台专用入口只验证专用密码，不在同一输入框悄悄尝试两种密码。
- 统一会话保存主体和认证来源，不把活动企业写成全局会话权限。每个请求显式核对企业、端、对象及动作；密码仍按现有 6—128 字符规则。
- 退出当前浏览器登录时，三端当前会话一起失效。修改任一种密码或执行密码恢复时，使该主体旧会话失效并要求重新登录，避免旧路径复活；不自动修改另一套密码。
- 撤销总台角色仅撤销总台访问；撤销某企业成员关系仅影响该企业。全局停用账号才影响所有端与企业；相关后台任务、缓存及延迟请求继续复核撤权。
- 上次企业按账号、端持久保存，不存储凭据；标签页当前上下文独立。存储不可用时退回企业选择，偏好只用于导航，不作为访问授权。
- 现有总部支持访问保留专门入口、支持上下文、实际操作者及权限审计，不混入“本人企业”列表，不把负责人支持权限写成个人成员关系。统一身份不能产生额外支持授权或绕过既有撤权规则。
- 初始空间授权在接受时重新验证邀请人资格及当前空间状态；授权失效则明确失败并让管理员调整，不静默增加权限或把未落实授权说成已完成。

## 5. 身份核验与真实交付边界

“暂不做验证码登录”不取消原有注册、手机号绑定和密码恢复的身份核验。保留 JOIN/BIND/RESET 用途隔离，新增 STAFF 用于总台邀请及初始化核验，不新增 LOGIN 用途；找回密码完成后回到密码登录，不直接获得已登录会话。

当前源码 `LocalInvitationDelivery`、`LocalPhoneDelivery` 仍为本地测试能力，缺真实通道应明确失败。开发可使用合成身份/邀请/验证码，不标记为真实手机核验或真实投递成功。

上线前需落实的交付条件（不阻止本地开发）：

- 注册、绑定及初始化所需的真实核验通道与供应商配置；费用或新外部服务启用另行落实，不因本文自动开通。
- 邀请链接的真实交付方式。建议由有权管理员复制并自行发送受控链接，或后续接投递服务；本轮不自动发送外部消息。链接仍有有效期、撤销与身份匹配校验，不能单独当成手机持有证明。
- 无法验证旧账号或手机时，沿已有系统外核验及受控维护流程处理，不新建公开申诉系统，不允许管理员直接绕过验证认领账号。

## 6. 存量迁移与回退

1. 先在获准范围只读盘点：旧客户账号、旧平台账号、角色、成员关系、负责人、手机号验证状态、有效会话和引用数量。输出脱敏映射及异常清单。
2. 新表/字段及兼容读取先部署到隔离验证库，旧账号 ID、密码散列、成员、资料与历史保持。总台旧登录名继续识别，不能把旧平台占位邮箱当成真实联系方式。
3. 同名、同手机号或相同展示信息仅作为关联候选，不能自动合并；本人分别验证原账号或通过既有受控核验后关联。冲突、无法核验、负责人缺失的记录保持待处理，不扩大权限。
4. 关联时处理登录名唯一性、统一手机号归属、相同企业成员冲突及历史实际操作者；事务重试不能重复授权。平台专用密码不覆盖原客户密码。
5. 切换认证时废止旧客户/平台会话，清理旧 Cookie 并重新登录；恢复工具也须识别统一身份与凭据，旧备份不得复活旧会话、已撤销角色或失效绑定。
6. 迁移演练保留迁移前快照、版本、对象引用统计及回退记录。新身份映射启用后，旧应用不保证可直接读取；出现问题先关闭新入口/关联写入并前向修复，完整恢复仅按明确冻结点协调执行，不能丢弃切换后的新增业务数据。

本轮不连接真实数据库核对或迁移，不删除旧身份，不调整现有实例启动参数。

## 7. 单主线实施顺序

| 批次 | 工作闭环 | 完成依据 |
| --- | --- | --- |
| B1 统一身份底座 | 统一主体/凭据/角色契约、兼容迁移、会话及 CSRF；保留独立支持上下文 | 合成多角色身份、凭据隔离、撤权和旧会话失效的后端验证 |
| B2 登录与跨端导航 | 统一登录、专用总台登录、端选择、企业选择及记忆、同企业跨端、退出 | 单/多企业及混合权限真实 HTTP 与浏览器旅程 |
| B3 企业开通与邀请 | 待激活企业、强制初始负责人、已有账号复用、员工邀请及初始空间 | 原子性、并发、重试、撤销、更换、过期及授权变更验证 |
| B4 平台人员与账号维护 | 首位初始化、平台邀请复用主体、专用凭据设置、密码维护及资格撤销 | 初始化仅一次、最后管理员保护、凭据命名冲突与全端退出验证 |
| B5 存量兼容与交付 | 合成历史双账号关联、重启/恢复回归、文档和部署检查 | 不丢历史、不扩权；真实切换前完成核验/投递和映射确认 |

均在本目录 main 顺序开发，不创建新开发 worktree、不派发其他会话。每批修改契约、实现和必要测试；已通过的检查仅在新增变更、失败或具体风险需要时扩大。
