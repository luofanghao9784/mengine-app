# 结构化数据统一接入与 AI 验收

2026-10-26 用户明确目标：数据进入本地梦擎后能由 AI 实际查询，并让同一处理流程兼容文件导出、数据库及其他平台的结构化数据。具体数据库、房友、钉钉采集器后续开发。

## 一个核心，多种来源适配器

```text
文件导出 / 数据库只读查询 / 平台 API
              ↓ 来源适配器
获准的标准化表快照 + 字段定义 + 可选来源证据
              ↓
梦擎既有采集接收 → 结构保存 → 治理草稿 → 核对发布 → 获权 AI 查询
```

取数、分页、导出限制、游标、重连、认证以及源字段转换属于连接器；企业权限、快照版本、字段证据、治理执行和 AI 查询属于共用核心。核心不根据“全房通”“美租”或某个业务字段名选择流程。

## 复用的真实契约

部署继续使用 `CollectionDeployment.Manifest` 1.0：`tenantId`、`connectionId`、连接名称与范围、时区，以及数据表清单。每张表包含 `id`、`workspaceId`、`key`、`name`、`description`、`columns` 和 `fieldDefinitions`。采集执行沿现有 `CollectionService` 和部署收集器协议，不新增绕过权限的导入接口。参考[数据基座部署协议](数据基座部署协议与字段解释.md)。

| 项目 | 通用处理要求 |
| --- | --- |
| 标识 | `tenantId + connectionId + datasetId` 绑定实际来源与授权；表名只是展示名称，不能用来唯一标识来源 |
| 表结构 | 列顺序固定、列名唯一；记录按相同顺序输出，每个单元格是原值字符串或 `null` |
| 大整数、金额 | 用字符串传递，避免经过 JavaScript 浮点数损失精度；编号保留前导零；币种和金额单位必须有依据 |
| 日期、时间 | 明确日期与时间戳区别；有时区时保留时区，没有时区时保留原值及未知说明 |
| 布尔、枚举 | 只有源端定义明确时才转换；不擅自把空值、0、未填写、未知合并 |
| JSON、嵌套数组 | 可以保留 JSON 字符串；需要按子项查询时由适配器生成独立子表并说明关系，不能无说明地展开后改变记录粒度 |
| 空表 | 有列定义、零行也是合法快照；不把零行解释为企业没有相关业务 |
| 来源约束 | 只有提供明确证据的主键、非空、外键才执行相应约束检查；没有约束不代表所有规则已通过 |
| 来源变化 | 字段、字段定义或权限范围改变依现有规则部署新数据集身份；同名表不能复用旧口径或扩大旧快照访问权 |

当前部署最多 1,024 张表、每张表 100 列。超宽表应在适配层按获准业务范围划分，或另行升级契约；不静默丢列。目标采集接受完整快照，数据库 CDC/API 增量必须先在连接器中正确合并成快照；本轮没有实现增量写入协议。目标按连接调度，不同刷新周期可分连接/采集任务组织。

## 来源证据不再依赖数据库源码

`dreamcore.governance.source-evidence` 使用本地受控证据文件，按企业隔离。字段依据可以是数据库注释、API 定义、官方导出字段说明或源码片段。新接入必须写 `datasetId`；旧证据只有在企业内表名唯一时才回退按表名匹配，出现同名表则不采用这些无绑定的证据。

以下仅为合成格式示例，不是可直接部署的业务定义：

```json
{
  "tenantId": "00000000-0000-4000-8000-000000000001",
  "entries": [
    {
      "datasetId": "00000000-0000-4000-8000-000000000002",
      "sourceKind": "PLATFORM_API",
      "column": "record_id",
      "sourceMetadata": {
        "description": "来源接口说明：record_id 为该接口返回记录的唯一标识。"
      },
      "proof": [
        {
          "locator": "官方接口文档的字段定义章节及版本",
          "snippet": "来源接口说明：record_id 为该接口返回记录的唯一标识。"
        }
      ]
    }
  ],
  "schema": []
}
```

`sourceKind` 用于说明来源，不授予任何权限。`sourceMetadata` 的 `comment/default/generated/description/definition` 或 `proof[].snippet` 可作为逐字引用依据；模型不能自行补造证据。主键/非空等结构约束仍按现有 `schema` 契约提交。没有来源证据的字段保留 `UNKNOWN`，不强制所有来源都有数据库结构。

证据文件不得包含凭据或业务明细。模型请求只带已获权元数据、统计与背景，输入限定 512 KiB；过长证据需由适配器裁选可追溯片段，不静默截断业务定义。模型失败不丢弃已保存快照，未知执行结果不自动再次付费调用。

## AI 可用的验收方式

发布状态与真实使用分别验证。已发布但有未知口径的表，可以在原有权限内按源字段查询、筛选和计算；不能因列名推断货币单位、支付完成状态、主键或“一行等于一张账单”。没有质量回执的质量和可用行数显示未知，不能填成 0 或总行数。

每个真实连接至少验收：

1. 来源范围、快照行数/列数及接收结果匹配。
2. 当前企业、当前空间和撤权场景遵守原权限。
3. AI 实际调用数据工具，返回至少一次记录统计及一次分组统计；底层快照独立复算一致。
4. 来源版本、治理依据、模型执行和工具回执可追溯，不能只凭模型说“查询成功”。
5. 缺少字段定义、空数据、重复键、来源变化、失败及重试按实际能力与证据呈现。

美租当前已通过真实查询验收：全房通“财务-流水账”11,684 条、30 列；AI 实际 `compare_dataset` 汇总返回源取值“收”4,633 条、“付”7,051 条，与 PostgreSQL 快照独立分组完全一致；执行为 live，工具和模型调用均有回执。治理已发布，30 项字段仍保留未知口径。首次 AI 回答曾额外推断记录粒度，已补通用解读规则；第二次真实查询复算结果一致，并明确更正“记录数等于账单数”的无依据推断。后续仍须按证据约束业务结论。

数据库/API 目前只验证**适配后的标准化表**，不是已经完成真实数据库或第三方账号接入。三类合成输入覆盖不同列名、大整数、高精度小数、时间戳、JSON、布尔和空值，接入后共用相同的治理流程。
