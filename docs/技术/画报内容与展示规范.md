# 画报内容与展示规范

2026-10-21：用户要求将本轮画报调整固化。本文记录已确认的规则方向和开发约束；局部视觉实现仍可继续迭代，不等同于整套产品验收。延续现有 DASH / AI 需求编号，不新增业务范围或权限。

## 一、生成规则负责什么

表达唯一来源为 [briefing-contract.json](../../engine/src/runtime/briefing-contract.json)，当前版本为 **1.5.5**。完整可读版本由 [导出脚本](../../scripts/docs/export-briefing-rules.mjs)生成：[画报生成规则审阅稿](画报生成规则-审阅稿.md)。不能只修改审阅稿或在多个提示词复制另一套规则。

- 正文写业务发现、解读、建议和必要限制，不写工具调用、内部标识、计算回执解释或未点名的系统判断。证据不足对业务的影响仍须说明。
- 历史核对卡优先突出待核对事项，已确认数量作为背景。状态分类不是排名；互斥与可加性未经依据确认时不得求和。历史记录不直接等于当前待办。
- 资讯把原文事实与解读、AI建议、决策前需确认的条件分开，用现有段落角色表达；不扩展交付字段，不把推断伪装为原文。
- 建议按步骤组织，由组件生成一次序号，段落不重复手写序号。
- 原文无图时，可用检索能力允许查找相关真实照片；需核实内容、来源、作者和许可，注明非原文配图、非新闻现场。禁止 AI 生图。无能力或无合适图片时不得假造来源。
- 正文不生成查看依据、下载附件、展开按钮等界面文案，不添加装饰分割线。

规则进入运行时任务提示词、交付工具与 API 首次制作入口。源文件修改不代表运行实例已加载：必须重新构建、打包并重启对应服务。新规则不重写历史成果，也不自动重新生成。

## 二、开发组件负责什么

### 卡片

- 复用现有四种尺寸 1×1、2×1、1×2、2×2，按内容和可用空间编排，避免大面积无效留白；不能只按业务类型一律大卡。
- 短的两步建议适合 2×1 并排，长步骤适合 1×2 顺排；以内容可读为前提。已有尺寸测量与用户指定尺寸优先，不由模型随意输出 CSS。
- 资讯 2×1 宽卡可用左右图文结构，避免将主体裁成顶部细条。保留详细页图片出处与许可，配图失败仍有回退。
- 步骤列表只由 Composition 的列表计数器输出序号；标签只保留“行动”等语义。
- 联调验证提示只保留在详情的详细执行记录，不在每张卡重复展示。
- 整张卡片打开详情，不另加“查看记录与接续建议 →”式伪链接、底部分割线或新的装饰入口。

### 详情

| 内容 | 入口与默认状态 | 约束 |
| --- | --- | --- |
| 结论、图表、分析、建议、必要限制 | 正文，展开 | 原文解读与 AI 建议区分 |
| 完整图表数据 | 查看数据明细，折叠 | 有数据才显示；保留单位、合计与口径 |
| 来源、统计范围、数据版本和计算口径 | 查看依据，折叠 | 内部普通标题和列表分组，不为每段再套折叠卡 |
| 系统说明、技术文件、实际执行回执 | 依据内的详细执行记录，折叠 | 原始记录不删除，读取失败保留重试，不宣称执行成功 |
| 实际交付文档或表格 | 成果附件，折叠 | 合为一个入口，按稳定 ID 去重，无附件隐藏 |

统一使用 [Disclosure](../../src/components/Disclosure.tsx)：原生 details/summary 语义、整行点击、Enter/Space、可见焦点、箭头和展开状态、简短用途说明、数量单位、展开内容缩进。允许多个面板同时展开以便核对；不添加装饰边框、分割线。不得把隐藏面板的内容继续暴露为可聚焦控件。详细执行回执仅在展开时请求，权限与重试继续由原数据层处理。

技术附件通过 [editorial-policy.ts](../../src/briefing-live/editorial-policy.ts)明确命名分类：briefing 的已知产物、dataset-comparison、business-plan.json、chain-calculation.json。不能把所有 JSON 一律隐藏。技术文件保留会话查看下载入口。来源按资料与版本去重，不能合并不同版本；撤权应继续移除正文、数据及引用。

## 三、历史内容适配与尚未通用的边界

- 两张指定建议卡的 2×1 / 1×2 尺寸集中登记在 editorial-policy.ts，仅精确匹配用户已审阅的标题。其他卡继续使用原尺寸测量，不能宣称已完成所有新卡的智能布局选择。
- 梵华里 4 笔状态摘要由 pending-receipts.ts 读取既有图表，要求指定标题、三个已确认的状态和完整非负整数。未知或缺失值回退原图，不通过文案相似度推断状态可加。
- 荔星系统处理段落通过 editorial-evidence.ts 精确迁移至执行说明；不泛化删除所有涉及限制的段落。
- 资讯相关照片为已核实的人工选图映射，保存本地来源与许可。当前没有自动检索选图流水线；生成规则不得冒充该能力已经实现。
- 历史成果不可变，适配仅作用于展示，不修改源数据、来源哈希和原始任务记录。进一步通用化需明确结构字段、服务端证据校验和兼容测试。

### 2026-10-21 选题覆盖与去重进入共享生成规则（1.5.4）

- 先按核心事实、业务问题、范围、期间合并，再选择输出；同一事实的结论、解释、行动、限制放在同卡，换标题、标签、类型不能规避去重。对照本批候选与可读近期卡片，无新增事实、实质状态变化或独立决策价值就合并/跳过。同来源的不同事实仍可分别输出，保留指标各自口径。

- 资料不足时少生成或零张，不用职责介绍、泛泛建议、缺口卡凑数。岗位背景只帮助确定接收人和责任，不单独构成新发现。未支持的候选在规划/任务结果说明，不作为卡片发布。
