# 三端统一权限与敏感输出设计

日期：2026-10-18。状态：设计基线，尚未完成代码改造、迁移或部署，不代表现有系统已执行下述新增规则。

## 1. 已确认范围

用户要求三端统一以部门、岗位角色、密级区分权限，所有输出（含画报）受权限控制，敏感性影响推送。

- 企业负责人拥有本企业全部**共享**内容及管理权限，不能读取其他企业内容。
- 员工私人会话、个人空间、未发布私人草稿仍仅本人可见。负责人身份不能绕过此边界。
- 普通及高敏感内容，对有权接收的人可以推送正文。
- 最高密级推送必须经本企业负责人审批。审批不替代接收人的阅读权限。
- 本轮推送指站内推荐、画报分发及通知，不包含短信、邮件或其他外部渠道。

本设计沿用 WS-02、WS-03、WS-06—WS-08、WS-12—WS-14、WS-16、ACT-01、ACT-04，及 LIB-03、LIB-04、LIB-07、LIB-08、LIB-09、LIB-10、AI-01、AI-11—AI-13、DASH-01—DASH-04。负责人共享内容全权是对旧“管理身份不自动产生阅读权”的明确例外；其余管理员继续管理权与阅读权分离。

## 2. 三端职责

| 端 | 维护内容 | 不能因此获得的权限 |
| --- | --- | --- |
| 总台 | 平台运维角色、全局能力范围、模型服务安全属性、企业开通、策略版本及脱敏运行状态 | 不因平台管理员身份读取客户资料、画报、私聊；不能代替企业负责人审批 |
| 企业管理端 | 部门、岗位、角色、成员任职、密级许可、共享对象授权、密级复核、最高密级推送审批、审计 | 普通企业管理员不能扩大自己的阅读权限；不能读取员工私人内容 |
| 员工端 | 查看本人有效权限、获权资料、私人任务、共享成果；申请权限、提交共享和审批申请 | 无权看到的标题、摘要、计数、图表、引用、附件和搜索提示不得泄露 |

一个账号可在不同企业承担不同角色。所有任职、许可、规则和审批绑定 tenant_id；平台身份不参与企业内容许可的隐式继承。

## 3. 权限模型

三种维度分别承担不同职责，不能仅凭某一维度放行：

- 部门：决定业务归属和数据范围。复用已有多部门动态成员关系；首期保持平级部门，不默认继承子部门权限。
- 岗位与角色：岗位表达任职，角色表达操作能力。岗位可绑定多个角色，任职指定部门/空间范围和有效期。财务、店长、前台等是可配置模板，不直接写死到用户账号。
- 密级许可：限制可读取内容的最高等级，不自动赋予某个部门或对象的访问权。

建议角色模板：企业负责人、企业权限管理员、部门负责人、数据治理员、知识维护员、普通员工、只读审阅员。模板可调整；负责人保留唯一的最高密级推送审批资格，其他角色的管理员名称不等同负责人。

操作能力至少拆分 READ、USE_FOR_AI、EDIT、DOWNLOAD、EXPORT、SHARE、PUBLISH、MANAGE_PERMISSIONS、CLASSIFY、APPROVE_PUSH、RECEIVE_PUSH。阅读不自动包含下载、公开发布、使用外部模型；密级许可也不自动授予操作能力。

服务端判定顺序：

1. 账号、企业与对象处于允许访问状态，tenant 一致；删除/清理、离职封禁等生命周期限制先执行。
2. 私人对象仅本人可读写；负责人例外不适用于私人对象。
3. 共享对象的有效企业负责人拥有全部共享内容能力；仍执行密级推送审批、模型外发限制、版本与生命周期校验。
4. 其他成员必须同时满足岗位角色操作能力、对象/部门/空间范围、密级许可；显式拒绝优先于允许。
5. 输出对象还要校验全部来源的当前可读性和来源版本约束；审批不能豁免这一步。

继承、独立范围、跨部门授权继续复用既有资料权限模型，不新建第二套互相矛盾的授权表。调岗即时取消原任职带来的动态许可；明确保留的个人授权仍受密级和操作能力约束。

## 4. 密级与敏感性

建议四级（名称为可逆实现选择，不代表已给现有资料定级）：

| 密级 | 含义与例子 | 正文推送 |
| --- | --- | --- |
| L0 普通 | 经确认的通用资料 | 对有权接收者可推送，不自动公开到互联网 |
| L1 内部 | 日常内部制度、工作说明 | 对有权接收者可推送 |
| L2 敏感 | 客户联系信息、经营明细、人事资料 | 对有权接收者可推送正文 |
| L3 严格保密 | 企业明确指定的最高保密资料 | 获权且负责人对版本/范围审批后推送 |

敏感类型（个人信息、薪酬、财务、商业秘密等）与密级分别保存。规则检查和模型识别只能提出升级/复核建议，不能自动降低人工密级或扩大权限。不能把“敏感词检查未命中”解释为已可公开。

字段和记录有独立限制时，查询、聚合、导出先裁剪获权范围，再计算。只有表级权限的第一阶段不得宣称支持字段级保密：混合密级表暂按最高密级整体约束，禁止先将整表交给模型再遮挡页面。

未定级对象保留 UNKNOWN 状态：不自动推送、不共享扩散，进入企业治理待办；不擅自把所有旧资产降为 L0。切换前先形成存量定级清单。

## 5. 输出继承与私人边界

适用对象包括画报、AI 回复、知识文章、经验、经营报表、PPT、附件、封面图、图表及下载文件。

- 输出密级不低于所用来源的最高密级；结合生成内容扫描可升级。
- 普通接收人的来源授权取交集，不取并集；同时考虑任务上下文、历史会话、计算快照和间接引用。
- 原始输入、模型上下文、工具结果都登记来源。来源链缺失或循环不能按无来源普通内容放行。
- 私人任务产生的内容仍是私人内容，不能只因来源为共享资料就自动推送给同部门。
- 从私人草稿发布共享副本须作者明确发布；重新校验来源，仅剥离私人工作草稿的所有权不代表可剥离其私人资料/私人会话依赖。依赖私人来源的副本不得共享，须先由本人另行共享获准来源或重新生成不含私人依赖的成果。
- 负责人可以读取已经合法发布的共享副本；不因此获得原私人任务或草稿访问权。
- 脱敏摘要是新版本，独立复核和授权，不能单凭模型声称脱敏就下调密级。
- 来源撤权、提密、删除或不再有效时，同步阻断输出阅读、推荐、引用及下载；已发送给用户的文字无法物理收回，因此审计要区分停止后续访问与已交付事实。

## 6. 生成与推送流程

生成前：以实际任务发起人或自动任务归属人评估可读范围和 USE_FOR_AI，选择已获准模型端点；以固定来源版本创建任务。每次工具检索、取原文和计算均重检。WeKnora按获权对象过滤，不能先全库检索返回片段再由模型过滤。

生成后：记录内容版本、来源依赖、密级、敏感类别、分类依据和策略版本；校验交付结构及事实计算凭据。无权限或未完成定级的结果不能进入正常推荐池。

推送前按每个接收人分别计算：

1. 内容是否可读、任职是否有效、密级是否允许、来源是否仍有效、是否允许接收。
2. L0—L2符合条件可推送正文；L3进入负责人审批。
3. 审批记录固定内容版本、内容摘要哈希、密级、接收人清单或已冻结的范围、渠道、有效期与策略版本。动态部门新增成员不自动扩大已批准范围。
4. 发送时再次检查当前权限和审批；任何不符者跳过并记录原因。重复执行按内容版本、接收人、渠道幂等。
5. 页面打开、摘要查询、附件下载时仍执行当前权限，不能只依赖发送时判断。

建议状态：PENDING_CLASSIFICATION → ELIGIBLE / BLOCKED；L3额外 NEEDS_APPROVAL → APPROVED / REJECTED / EXPIRED；实际交付记录 SENT / SKIPPED_REVOKED / FAILED。批准不等于送达；审批只决定是否可推送，不是阅读授权。

最高密级的本人私人画报可以在本人获权的私人任务中查看，但不自动推送，不交给企业负责人查看审批正文；如需共享推送，须先满足共享副本的来源条件。负责人接收自己的最高密级共享成果也需显式审批，不由后台自动批准。

## 7. 模型与日志边界

阅读权限不自动允许外发到云模型。端点能力配置包含可处理的最高密级和敏感类别、是否云端；任务按“用户许可 ∩ 来源许可 ∩ 端点许可”放行。现有 DeepSeek、百炼端点不能因本次设计被默认为允许处理所有 L3 资料；新策略切换前单独核定端点数据范围。

联网检索禁止携带内部敏感正文作为关键词。Langfuse、总台遥测和错误日志只保存必要运行元数据，避免客户正文、密钥和私有标题。审批审计保留决定、版本与对象引用，正文读取仍受权限控制。

## 8. 与现有实现的衔接

| 现有位置 | 改造要求 |
| --- | --- |
| LibraryPermissionService、library_mask、部门与对象授权 | 复用部门/对象权限，新增岗位任职、密级许可与负责人共享例外，保留私人边界 |
| MaterialAccess、KnowledgeService、WeKnoraRetrieval、数据计算服务 | 同一策略判定；过滤列表、检索、原文、下载、固定快照和计算输入 |
| BriefingGenerationService | 候选、排队、执行各阶段重检，登记分类与完整来源链 |
| BriefingService、RecommendationService | 区分私人结果与共享分发，列表/摘要/推荐/未读计数均受策略过滤 |
| DocumentPublicationService、知识和经验发布链路 | 共享副本与私人原任务分离，禁止借发布降密或扩大来源权限 |
| 企业端成员与权限、数据治理、输出管理 | 部门岗位角色维护、成员有效权限解释、定级待办、推送审批及记录 |
| 总台身份和场景统计 | 平台角色单独维护，客户正文不得随管理权限或计数钻取泄露 |

建议新增组织岗位/任职、角色能力、人员密级许可、对象分类、输出来源依赖、推送申请/审批/逐人交付和策略版本记录。全部使用租户复合约束。分类绑定内容版本，审批绑定分类版本；缓存键包含租户、成员及策略版本，撤权后失效。

统一判定返回允许/拒绝、原因码、当前策略版本；面向普通用户的错误不暴露无权对象信息。后端、SQL列表过滤、异步worker应使用同一语义，禁止界面和下载接口各写一套规则。

## 9. 实施与验收顺序

1. 先实现统一策略和组织/密级模型，合成测试验证；不直接替换真实实例许可。
2. 接通资料、数据、检索、计算和外部模型入口，禁止来源层绕过。
3. 接通生成物、发布、历史结果、推荐、计数、下载与审批分发；新策略未覆盖的入口默认拒绝，不回退旧规则放行。
4. 完成三端页面和负责人/普通管理员/部门角色/跨部门/私人内容的完整旅程。
5. 在宠小屋合成数据上形成逐对象迁移差异清单、完成定级，再启用；不改动真实外部企业。

验收必须覆盖：跨企业拒绝；负责人可读全部共享但无法读取员工私人内容；平台管理员不可读客户正文；跨部门有明确授权才可读；角色允许但密级不足拒绝；多来源取交集；私人来源无法借画报共享；字段限制不被聚合绕过；L2获权正文推送；L3无审批拒绝、有效审批允许；过期审批/新内容版本/新增接收人失效；排队后撤权/调岗/提密不发送；下载和旧链接同样阻断；幂等无重复发送；审批记录与真实送达分开；未授权云端模型没有收到受限文本。

开发与验证结果另行追加，不以本设计文档代替实现或验收。
