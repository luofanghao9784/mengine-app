## 1. 目标与责任

独立自进化负责在有效业务目标和授权范围内，持续发现系统工作方法的改进机会，形成候选、组织验证、按权限采用并观察实际效果。既可减少错误、遗漏、成本和用户负担，也可提出更有效的新流程或能力组合。目标是改善实际工作，不以改动次数、生成规则数量、经验数量或模型自评分作为成功依据。

自进化的职责重点是可复用的方法改进，但不要求等同一问题重复多次才启动研究；一次重要失败、新业务需要或能力升级也可能值得调查。它可以质疑现有三板块内部划分及其实现，提出重组方案；方案仍需说明如何履行原有输入、执行、交付、权限和观测责任，并处理兼容与迁移。

这里的自进化以系统方法、配置、工具及工程实现的改进为主，不意味着主模型权重必然在线训练。模型更换、适配、训练或微调可作为不同候选方向，按实际数据、能力、成本及发布条件另行验证；本轮不选择专项模型、模型厂商或训练方案。

### 1.1 与基础能力怎样区分

| 工作 | 基础系统本来就应能完成 | 自进化以后可以优化什么 |
| --- | --- | --- |
| 单次任务 | 理解目标、选择工具、根据结果调整计划、核实与交付 | 更适合一类任务的规则、上下文组织、工具组合和执行方法 |
| 资料与档案维护 | 按已授权规则更新资料、解析和索引，保存明确偏好及其变更 | 解析/分类/索引方法、偏好识别与维护机制的准确性和效率 |
| 经验使用与维护 | 检索、判断适用性、记录使用反馈、按既定权限形成及维护经验 | 经验结构、归档/失效方法、检索算法和复用方式 |
| 异常与日常运维 | 既定范围内的安全重试、等待恢复、限流及获准备用方案 | 系统性减少故障、改善调度或替换不合适的方法 |
| 评估及人工研发更新 | 读取可信记录、维护样例、检查质量、比较版本及正常发布 | 主动提出改进假设、组织获准试验与采用；也可提议改进评价方法 |

同一个 AI 或同一套执行设施可以承担以上不同任务，按本次职责和权限区分，不必为每类工作增加模型。普通纠正和已获准维护不等待自进化批准；它未部署时，基础工作仍能完成。

早期讨论稿将个人适应、索引和上下文维护列为可优化对象。本任务书沿后续输入/处理/输出设计区分“执行既有维护规则”和“改进维护方法”，不把前者重新划回自进化的专属职责。

## 2. 独立运作具体意味着什么

建议独立的是职责、触发、授权、资源和停止范围。可以复用平台、队列、执行环境、模型及管理页面，不强制另设物理服务、常驻模型或第四个管理端；共享设施的容量及故障影响仍需实际设计和验证。

| 接入要求 | 对基础系统和自进化的含义 |
| --- | --- |
| 基础运行无需等待它 | 普通任务不必先经自进化审阅，也不等待新方法生成；使用已经持久保存且当前有效的方法 |
| 候选与生效方法分开 | 试验中的规则、脚本、索引或配置不能被正式任务误用；发布与指定范围采用取得实际回执后才算生效 |
| 采用后的运行依赖归基础系统管理 | 方法及必需文件、配置、索引、工具和服务依赖进入相应运行/版本/运维体系；不从自进化临时目录或进程内存取得生产唯一副本 |
| 通过受控入口改变系统 | 读取证据、运行评测及提交变更分别使用相应接口与权限，不借优化身份直接改全部业务表或租户配置 |
| 资源及故障范围可控 | 自进化有自己的任务、预算及并发范围，仍受平台总量约束；失败、滞后和无新方案不得耗尽已承诺的业务资源 |
| 停用不撤销运行事实 | 停止相关优化活动和后续变更，保留当前有效方法、正常维护和真实业务记录；需要撤销方法时单独走停用/恢复机制 |

如果某个候选仍要求自进化进程每次在线作出决定，发布前应把这项能力明确设计为基础运行依赖，或调整方案使其满足独立性；不能隐瞒依赖后宣称“随时关闭完全无影响”。共享数据库、模型服务或平台自身故障仍可能影响基础系统，独立性不是对一切基础设施故障的免疫承诺。

关闭自进化不代表已经采用的坏方法自动消失。基础平台保留有权者停用方法和执行已验证恢复方案的能力，即使自进化不可用也能处理。已发生的业务动作、未知执行结果和数据迁移须分别核对；不能保证所有结构性变更都能瞬时、无损、原路回退。

## 3. 可以优化哪些对象

建议不要只允许调参数，也不把所有对象预先划为必须人工逐项处理。**能够提出的方案范围，与当前允许自动执行的范围分别定义。**

| 优化对象 | 可提出的改进 | 采用时主要核对什么 |
| --- | --- | --- |
| 输入方法 | 接入适配、解析/校验、分类、映射、索引和缓存策略 | 来源及真实业务口径、数据版本、权限、重建与兼容；不能为匹配新方法篡改原始事实 |
| 处理与主规则 | 精简或重组规则、上下文选取、检索/工具协作、Skill、脚本和执行流程 | 目标与完成要求、实际效果、工具边界及依赖；不以复刻旧步骤作为唯一正确标准 |
| 资料库与经验库方法 | 标准结构、标签和索引、适用性判断、归档、失效及维护算法 | 检索覆盖和质量、内容来源/用途、历史兼容与迁移；不能把企业私有经验自动发布为通用经验 |
| 输出方法 | 候选提炼、价值排序、推荐算法、表达、合并和站内提醒节奏 | 有效职责、受众权限、直接交付与用户负担；不能优化掉已承诺的工作或重要事项 |
| 调度及能力组合 | 触发筛选、任务安排、模型/工具选择、并行方式和资源分配方法 | 实际能力及版本、截止承诺、总量约束、公平性、未知结果及恢复；不能自授更高预算 |
| 评估方法 | 样例维护、检查程序、量表、模型评判及复核方式 | 标准来源、独立验证及比较口径；评价变更单独版本化，不同轮次标准的分数不能伪装成方法提升 |
| 工程实现与架构 | 代码、接口、数据结构、模块职责及服务组合，包含权限机制的设计改进建议 | 通过对应研发和发布机制处理测试、部署、迁移与恢复；提出权限机制改进不等于可以自行扩大当前权限 |

企业目标、业务事实、人的评价及当前授权不作为“为了分数更好可直接改写”的对象。AI 可以指出目标或制度存在问题、提出建议；改变这些内容仍使用对应的事实维护或业务决定机制。方法变更也不能夹带新的外部触达；首版系统外业务触达仍按 DEC-088 后置 App。

对同一对象同时说明适用范围：个人、空间、企业、获准行业方法或平台共用能力。改动小不等于影响小，一句共享规则可能影响所有企业；多个小改动的累计影响也需受到采用策略约束。具体自动采用类别在后续讨论，不由本表自动授予。

自进化自身的观察、候选筛选和试验组织方法也可以提出改进，仍使用相同的版本、评估及授权机制；不能通过修改自身策略扩大权限、预算或解除停用。改进判断允许指出当前评估的盲点，但未覆盖的实际效果仍需补充证据。

## 4. 观察范围与判断依据

主要复用[评估与运行观测任务书](评估与运行观测-开发任务书-V0.1.md)中的运行事实、结果质量、反馈、资源及比较记录。还可以在授权范围内观察新业务要求、依赖和模型能力变化、人工提出的优化请求，以及尚未暴露为故障的改进机会。

证据应能关联相关目标、任务/尝试、来源和成果版本、实际方法组合、工具结果、用户纠正、成本/耗时口径及适用范围。没有足够证据时可以提出调查假设或建议补充观测，不能编造根因、假称已查看未获权的资料，或为一次诊断默认开启永久全量日志。

不同优化任务按各自身份和范围读取内容。平台通用改进使用获准通用证据、合成/公开或明确许可用途的样例；企业专属判断在本企业获准身份与范围内进行。共用计算设施不等于总台操作者可以查看客户原文，完整会话、提示词、样例和错误正文不能先集中到总台再靠界面隐藏。

读取、试验、维护和采用分别授权。只有汇总状态时，可以判断技术趋势及提出进一步检查建议，但不能据此声称已核实私人任务的内容质量。缺少内容依据不通过管理员自授权补齐；脱敏也不自动产生跨企业复用权。

AI 接触到的资料、经验、反馈和待评方法可能包含指令文字，它们是相应任务的数据，不得据此修改优化授权、评价标准或发布范围。独立检查样例的题目/答案不作为候选生成过程的普通检索材料，沿评估任务书第 11.5 节维护用途边界。

## 5. 一次改进的责任链

首轮先约定交接含义，不要求所有小改动都经过同样的阶段或人工审批：

| 环节 | 自进化要完成什么 | 由共用能力提供的依据 |
| --- | --- | --- |
| 观察与诊断 | 发现问题或机会，区分事实、推断、替代解释和数据缺口 | 当前权限下的运行记录、业务要求、反馈和评估覆盖 |
| 提出候选 | 明确要改什么、依据什么、预期改善、适用范围和可能退化 | 方法/配置当前版本、依赖及对应维护权限 |
| 组织验证 | 按影响选择适当样例和比较方式，说明资源及结果限制 | 共用评测、隔离执行和基准/候选记录；不另建一套可自行改分的评价真相 |
| 按授权采用 | 提交可审阅的差异及验证依据，使用已有发布和范围内采用入口 | 当前授权、兼容条件、生效记录、恢复方案及实际执行回执 |
| 持续观察与结束 | 判断保留、继续观察、停止扩展、停用或提出下一项候选 | 真实质量/资源表现和约定条件；记录无效候选、退化和证据不足 |

可审阅不等于每项都等人工点击。有明确预授权且条件满足时，可以自动验证并采用；未覆盖的范围和实质业务决定再取得相应决定。拆分候选、增加子任务或连续小改不能绕过总预算、作用范围及累计影响检查。

找到更好方法不是每次运行必须达到的结果。允许没有有价值的新线索、现有方法已经足够、试验失败或证据不足并正常结束；不能为证明“在进化”不断改动。评价收益时同时考虑后续实际使用及观察、试验、迁移、维护带来的投入，不用一次任务节省的调用数忽略长期优化成本；具体衡量方式后续细化。

影子或回放比较不重复真实发布、写入或通知。已经需要在线有界试用时，必须明确由哪个有效方案执行真实动作，不能让新旧候选各执行一遍。试验环境和候选产物与有效方法保持明确边界，不把验证通过自动解释为全平台已经采用。

## 6. 停止、失败和恢复的首轮约定

建议后续分别设计观察/诊断、试验和采用的启停范围，并提供明确的整体停用行为，具体开关及权限在本专题后续与三端专题共同细化。停用至少需要阻止对应范围的新优化工作和新采用动作，并处理已排队任务、在途试验及迟到结果。

停止信号应传达到相关优化子任务和执行器；尚未停止的部分显示真实状态，不因点击关闭就宣称全部完成。正在进行的发布或迁移按原发布机制核对已完成、未完成和未知步骤，达到可安全停止或恢复的状态，不粗暴终止后假装未发生。真实回执、必要清理和核对不因停用而丢弃。

已采用的有效方法由基础系统继续使用。停止一个试验、暂停某企业优化、关闭所有自进化以及回退某个方法是不同操作；发生退化时按已有授权和恢复机制处理，不能把一切都混成“关闭 AI”。具体在途和并发状态下一轮再明确。

恢复自进化前核对有效授权、对象当前版本、相关依赖和已发生的动作；旧候选基于的条件可能已改变，不能自动补发停用期间的全部变更。它不能自行解除人为设置的停用、提高自己的权限或保证永远保持运行。

## 7. 需要哪些管理交互

先记录用户需要理解或操作的对象，待三端专题统一归属及菜单，不新增第四端：

| 管理需要 | 应能查看或操作什么 | 范围边界 |
| --- | --- | --- |
| 优化范围与状态 | 当前关注哪些方法/场景，来源依据、启停范围、资源限制及实际运行状态 | 平台通用范围和企业/个人范围分别授权，不能只有一个含义不明的总开关 |
| 问题与改进提案 | 事实与假设、候选差异、影响、依赖、预期收益及尚缺证据 | 提案展示不扩展客户内容权限，提出候选不等于已经生效 |
| 试验及比较 | 进度、资源、采用的标准/样例版本、改善/退化/取舍及无法判断项 | 与共用评测复用记录和页面；详细证据只向有内容权限者显示 |
| 发布与采用 | 哪个版本可用、在哪些范围实际生效，是否符合已有采用策略 | 平台发布与企业采用分开，评测通过不自行扩大权限 |
| 停止与恢复 | 停止什么、哪些已停止、哪些仍需核对，当前有效版本和可行恢复方案 | 停用优化不自动撤销业务动作；恢复和方法回退分别处理 |

具体角色、预授权类别、并行试验的可见性、操作路径及保留期继续细化。沿 DEC-087，配置管理权、内容读取权和业务决定权分别核对；既有授权覆盖的动作不重复索取确认，也不能因管理端身份自动取得所有权限。

| 基础系统统一开发阶段 | 正常任务、必要证据、质量检查、实际方法版本与范围、人工更新/发布/恢复、资源及权限 | 已有原件/任务/尝试、运行概览及部分升级回退基础；细粒度方法组合、完整质量比较和其他新增设计仍待开发，不因已有文档而完成 |
| 基础交付版本完成后 | 接入获准观察和候选任务、组织试验、按授权采用、持续观察及独立停止/恢复 | 尚未实施或验证；届时先选择有限且有可比基准的对象验证完整改进流程，再按证据扩展 |

基础系统“完成”按全局汇总确定的可交付版本和验收判断，不需要等所有远期功能实现；同时不能用已有本地演示或接口联调冒充该版本已经完成。自进化的具体能力和自动范围待测试后决定，不承诺在每家企业、每类任务上持续单调提升。

后接入任务优先复用引擎/任务执行、可信平台、评估和正常发布设施；需要新增的是优化任务的观察依据、候选组织、试验/采用协调、权限资源关联及停止恢复能力。引擎可独立替换、当前有成功经验或运行统计，均不证明自进化闭环已经实现。

## 9. 后续验收场景与待讨论事项

以下为未来验收建议，本轮未执行：

1. 未部署或完全停用自进化时，代表性输入、会话处理、输出、资料/经验正常维护、质量检查和人工方法更新仍能完成。
2. 候选生成或试验失败、积压或资源耗尽时，不改变有效方法，不让基础任务等待候选，也不挤占已承诺资源；允许有依据地保持现状。
3. 方法采用后关闭自进化，方法及其必要依赖仍由基础系统提供；候选临时产物不能被正式工作误用，发布未知状态有独立核对路径。
4. 改进可包含删除冗余流程、替换算法和架构候选；实际采用具有相应比较、兼容/迁移和授权依据，不靠修改权限或评价分数制造提升。
5. 企业专属优化只读取和作用获准范围，总台无客户内容入口；平台版本发布不冒充所有企业已采用，脱敏不自动授权通用复用。
6. 停用时在途试验、发布及迟到结果分别处理，旧任务不会继续采用；已采用方法和真实业务动作不被一并抹去，重新启动前核对新条件。

首轮提出继续讨论**观察与触发怎样形成候选，以及试验和采用的授权边界**，已在第 10 节展开：哪些信号值得调查、怎样避免重复空转、优化任务的最少记录和状态、哪些动作可预授权、候选如何交给共用评估及正常发布。随后收口并发、停止恢复、首个后接入范围与管理需求，再进入三端管理。

本轮未确认自动修改对象清单、触发频率、数值阈值、资金预算、模型选型或首个实验场景，不把“继续讨论”当成启动自动优化的授权。

## 10. 第二轮讨论：触发、候选及试验采用授权

用户要求继续后，本轮细化改进任务如何开始、推进和取得生效依据；用户随后回复“没问题，继续下一步”，认可触发、候选、区分试验与采用、预授权和累计影响的大方向，见 DEC-091。具体字段、权限、数值及交互仍为设计建议，复用[处理调度](处理板块-开发任务书-V0.1.md#67-本轮讨论调度的模型与程序分工)、[版本与发布](处理板块-开发任务书-V0.1.md#68-本轮讨论规则维护发布评估与回退)及[评价标准与样例](评估与运行观测-开发任务书-V0.1.md#11-第二轮讨论评价标准样例和判断权)，不创建真实定时器或优化任务，也不新增实际采用权限。

### 10.1 怎样触发观察

建议组合事件、定期检查和明确请求，分别记录运行范围及依据；不要求自进化模型一直在线，不固定为每天全量扫描所有企业。

| 触发来源 | 适合关注的信号 | 如何控制无效触发 |
| --- | --- | --- |
| 运行与质量事件 | 重要失败/遗漏、反复纠正、资源或耗时变化、方法退化 | 区分正常拒绝/取消和真实问题；先由基础机制处理紧急恢复，再按证据研究方法，不等待优化完成才恢复业务 |
| 定期范围检查 | 授权范围内的方法表现、长期等待的验证、少量正常样本及薄弱处 | 按适用策略限定范围和资源；无新证据可安静结束，不能把未检查标为无问题 |
| 目标、环境或能力变化 | 有效业务要求变化、来源结构变化、模型/工具升级或依赖停用 | 核对信息来源及实际适用性；发布消息本身不等于已经可用、兼容或获准采用 |
| 人工优化请求 | 对某类任务、体验或方法的明确改进要求 | 区分希望获得方案、允许试验及允许真实采用，使用已有授权推进，不从一句“优化一下”推定所有动作都获准 |
| 获准探索 | 没有显著故障时，尝试发现冗余步骤或更有效方法 | 有对象、范围、预算和结束条件，不以必须产出改动作为完成要求 |

触发先进入平台能确定的核对：范围是否启用、授权是否有效、事件是否重复、关联工作是否已经推进、是否具备资源及必要依据。需要语义判断或不能排除有价值的新线索时再调用模型，不要求程序先证明改进一定有效。

程序负责可靠唤醒和资源执行，AI 可在已授权范围内选择观察重点、调查方法和后续时机；新的后续安排必须实际保存才能宣称已安排。持续关注的频率、合并窗口、轮询和探索预算属于可调整策略，具体数值待场景与资源条件明确后确定。

### 10.2 怎样避免重复空转，又不漏掉新变化

围绕相同范围、对象版本和问题依据合并重复信号，不跨企业权限边界合并内容。已有任务运行时，新证据可以加入尚可处理的部分，或登记为下一次待核对依据，不能因“已有任务”永久丢弃。

优化引起的发布、索引更新、记录和评测结果应带必要的关联，使系统识别同一改动造成的后续事件。避免“产出优化记录 → 把新记录再次当改进机会 → 无限启动”的循环，同时保留采用后的效果验证和合法的新线索；不能简单屏蔽全部 AI 产生的事件。

未通过、已否决或无收益的候选保留原因及当时条件。相同证据下可以合并、冷却或结束；新版本、新反例或新业务范围出现时允许重新判断，不永久忽略同一主题。冷却不能屏蔽真实退化，必要的基础故障处置也不受优化排期阻塞。

资源或证据不足时，区分等待和结束：有具体补充来源、下一业务周期或已约定验证时点，就保存条件及期限，届时再唤醒；没有合理后续依据时，可记录“证据不足并结束本次调查”。已经采用方法的待验证责任不能因暂时无结果而消失，也不能以持续模型循环维持等待。

### 10.3 观察、候选、试验和采用分别记录什么

只区分记录用途和真实状态，不要求每次都建五套完整流程或独立物理表。一次观察可以没有候选，多个观察可以支持同一候选，一次比较也可以针对一组明确记录的组合改动。

| 对象 | 最少需要解释的内容 |
| --- | --- |
| 优化任务及触发依据 | 为什么启动、针对什么目标/对象、所属范围和运行身份、已读证据/版本、资源与期限、调查进展和未解决项 |
| 候选方法版本 | 从哪个有效版本出发，具体差异/产物、改进假设及替代解释、适用前提、依赖、预期收益、可能退化和影响范围 |
| 试验或评估记录 | 使用哪个候选与基准、标准和样例版本、执行方式及资源、实际结果/缺失、退化/取舍和证据限制 |
| 采用依据 | 哪项有效授权覆盖哪个动作和范围，需要满足哪些条件，采用前复核结果及未覆盖事项 |
| 发布与实际生效记录 | 哪个版本已可用、何时在哪些范围实际启用、相应回执、在途处理、后续观察及停止/恢复依据 |

优化任务“完成调查”不等于候选通过评估；“评测通过”不等于已发布；平台发布也不等于所有企业已采用。可以用清晰状态呈现调查中、待证据、候选待验证、待决定、范围内已采用、未采用/已替代等含义，精确枚举和页面后续落定，不用一个“优化成功”覆盖全部过程。

候选应能审阅具体差异，如方法说明、规则/配置差异、脚本或代码变更及相应评估，不以“以后注意”或“我已经学会了”代替可验证产物。并非每个候选都必须生成 Skill；产物按真正改变的对象选择。

### 10.4 试验方式按真实影响选择

| 方式 | 实际影响及需要的授权 | 怎样取得结论 |
| --- | --- | --- |
| 获权观察与提出候选 | 读取许可范围内的证据并使用相应资源；不修改正式方法 | 可形成假设、调查结论或可审阅候选，不能据此认定已有改善 |
| 离线或隔离试验 | 使用获准且允许此用途的样例、工具和隔离资源 | 比较相关客观/语义质量及依赖，真实业务动作不重放；只测合成样例时明确适用范围 |
| 影子比较 | 获准读取选定实时输入，使用额外资源和必要记录；候选结果不交付用户、不执行真实业务写入/发布 | 取得接近当前工作条件的差异证据，仍非正式采用；候选产物不泄入正式检索和推荐 |
| 在线限定试用 | 已经真实影响指定用户、任务或流程，因此需要相应采用、数据、工具和资源授权 | 限定范围/期限/累计量及退出条件，观察真实效果；明确每个业务动作只有哪个有效方案执行 |
| 正式或扩大采用 | 在指定范围使用版本、发布与采用机制，覆盖实际影响和后续责任 | 以真实生效回执为准，保留持续观察；扩大范围重新核对是否仍在授权及验证适用范围内 |

这些方式不是固定必经五步。低影响且已有充分依据的兼容更新，可以按已有策略直接采用；复杂变更按真实影响补验证。不因叫“影子”或“小流量”就忽略资料用途、费用及副作用；在线试用也不能冒充对正式系统完全无影响。

一个有效策略可以同时覆盖多种方式，无需每过一阶段再审批。相反，只授权离线试验不能默认为允许在线试用；允许线上读取某企业资料，也不能直接推定可以让该企业用户参与真实方法试验。用户级逐次确认并非必需，已有有权策略可以覆盖明确范围。

### 10.5 预授权应描述允许的工作范围与条件

建议用可理解的对象和动作表达预授权，再由平台校验实际请求。自然语言可以用于提出和解释策略，实际有效授权来自可信配置及相应权限机制，不能仅靠主模型规则文档中的一句“允许自动优化”。

| 授权要素 | 需要明确什么 |
| --- | --- |
| 对象和作用范围 | 可改的方法类别、企业/空间/个人、任务类型及不包含的对象；不能仅按改动字数判断影响 |
| 允许动作与数据用途 | 可观察、运行哪些试验、在线试用、发布、采用或恢复，以及对应数据、工具和环境许可 |
| 资源与累计影响 | 单次及关联优化的预算、并发、试用曝光/任务范围和累计边界；不得拆任务绕过 |
| 质量与兼容要求 | 需要保持的要求、使用何种评价依据、允许的取舍、依赖兼容及不可采用条件 |
| 生效与退出 | 谁可制定/撤回策略、从何时到何时允许哪些动作、停止与恢复办法、实际采用和后续观察范围 |

用户不必手填每个技术字段。后续三端可以围绕“只观察并提出方案”“允许隔离/影子试验”“满足条件后可在指定范围采用”等容易理解的选择组织交互，由系统/AI 协助形成详细策略；这只是交互建议，不预定三个全平台权限等级或一个自动获得所有能力的开关。真实线上试用属于第三类动作范围。

以下情形原则上沿已有授权自主推进：允许范围内的调查、复测、候选调整，满足既有质量/兼容及恢复条件的指定方法采用，或企业有效采用策略已覆盖的通用兼容更新。普通偏好和索引日常维护继续使用基础机制，不为每次维护新增自进化审批。

原策略未覆盖的新增数据/受众/企业范围、不同用途或跨企业复用、新工具/真实动作、业务口径/承诺改变、预算突破及重要迁移等，须补充相应决定。是否需要决定看实际影响及原授权覆盖，而非一律按文件类型或“改了代码”判断。评测合格本身不能扩大授权；不能通过降低评价要求把原本不满足的候选变成可自动采用。

只有部分动作超出范围时，保留具体待决定事项，继续其他仍获准的调查或试验，不冻结所有优化。确需人决定时，应提供可审阅差异、实际证据、作用范围、影响/费用及恢复选项；不能先让人笼统批准未知方案，也不以未回复视为同意。

平台发布和企业采用分别记录，企业已有策略覆盖时可以自动采用，无需逐企业重复确认。总台通用发布权、企业业务决定权和内容读取权不合并；企业内评估使用对应身份，总台只获得获准技术状态和汇总，不能借审批要求上送完整私人样例。

### 10.6 采用前复核与累计变化

每次即将真实采用时，核对候选及评估版本、当前有效方法和依赖、实际作用范围、最新权限/停用状态、剩余资源和恢复条件。候选研究期间发生人工修复或其他升级时，不能凭旧版本的良好评分覆盖新状态。

只有变化影响原判断时才补充相应比较、调整候选或停止采用；不因无关时间戳变化机械重跑全量评测。具体并发发布、部分采用及恢复冲突在下一轮继续设计，沿共用版本/发布机制实现，不能由模型一句“应该兼容”跳过实际校验。

累计影响应关联优化目标、对象、依赖和资源记录。多次小改既看相邻版本差异，也按策略检查相对最近一次充分验证基准的累计变化，防止逐次看来合格但整体偏离。多个候选互相影响时，作为组合评价或分开作用条件；不能给每个候选分配新编号就绕过共享预算或验证边界。

到期和撤销要说明针对哪项许可：试验/发布授权到期会限制后续对应动作，已采用正式版本是否继续使用由其有效状态及采用条款决定，不一概回退全部版本。限定试用到期按预先约定结束或延续，但不能自动转为永久正式采用；退出时核对当前版本，不能让旧试验恢复动作覆盖后来合法发布的修复。权限撤回和必须停止的缺陷仍按当前有效控制立即处理受影响动作。

### 10.7 一个范围明确的检索优化示例

以下仅为说明，不选定为首个实际实验，也未授予权限：某企业用户多次发现已有获准资料却未检索到，系统可将相关反馈、检索条件和实际版本关联到一次调查。

先核对是来源缺失、未索引、正常权限过滤，还是方法确有遗漏。如果发现原资料没有接入，可交回基础输入维护，不必为了优化检索而调整提示词；若发现检索方法不适用，形成新旧方法的具体差异和适用条件。

已有策略允许本企业相关资料的隔离试验时，AI 可自主比较候选，不反复请求批准。验证同时检查相关性、遗漏、延迟/资源和权限，候选索引不替换正式索引；使用独立检查样例时遵守其用途边界。

若策略只允许试验，形成证据和采用建议后停止，不因效果较好就上线。若策略已允许满足条件后对指定空间的新任务试用，则复核当前版本后采用，观察真实效果，并按约定条件退出或保留；推广到未覆盖空间或其他企业，继续核对相应授权和适用证据。整个过程不要求总台读取企业资料正文。

### 10.8 待执行任务、交互与验收补充

后接入阶段拟补：作用范围内的触发计划/事件关联和去重、优化任务与候选版本的关系、试验对共用评估的调用、预授权条件核对、发布/采用回执及后续观察。复用基础调度、权限、资源和方法版本，不另造候选专用的业务事实库。

管理交互需要补充：触发依据和已覆盖范围、未调查/等待/结束的原因、候选差异与比较结果、当前允许哪些动作及期限、待补决定、试验实际影响、平台发布和企业采用状态、累计资源与变化。此处只登记需要，页面和角色在三端专题统一确认，提醒沿首版站内范围。

未来验收建议（本轮未执行）：

1. 重复事件被合并但新版本/新反例仍可进入观察；优化生成的记录不造成无限自触发，必要的采用后验证不会被去重掉。
2. 无新线索可正常结束；有明确后续业务周期或验证承诺时保存等待条件，不持续空耗模型，也不提前宣告提升。
3. 同一候选可以关联多项证据和试验，调查完成、比较通过、发布和范围内生效分别可核对，不靠模型自述修改状态。
4. 已有授权覆盖时可连续完成获准阶段；仅允许离线/影子试验时不会真实采用，在线试用不会新旧双重执行业务动作。
5. 范围/权限/预算或有效基准改变时按影响复核；旧候选、连续小改和新任务编号不能覆盖合法新版本或绕过累计约束。
6. 限定试用到期与正式版本有效性分别处理；总台无内容权仍无法通过候选、样例、审批和对比报告读取企业私人资料。

本节提出接续讨论的**并发候选、停止与恢复，以及首个后接入范围**，现已在第 11—12 节展开：处理同时修改同一方法、部分企业采用、在途试验/发布、回退依赖变化及停用后的恢复；汇总基础版本需预留和自进化阶段实际交付的内容，随后进入三端管理。数值策略、具体角色及自动类别仍待后续确认，当前不运行任何优化任务。

## 11. 第三轮讨论：并发候选、停止与恢复

本节为本轮新增设计建议。沿第 10 节及共用版本/发布机制处理真实状态，不另造一套可以绕过平台权限的自进化发布工具。

### 11.1 可以并行研究，采用时按对象、范围和依赖协调

候选记录其基于的有效版本、拟修改对象、作用范围及影响结论的依赖。彼此独立的观察、候选和试验可以并行，不将所有企业或所有方法全局串行；同一对象、重叠范围或共同依赖上的变化则需协调采用。

| 并发情形 | 建议处理 |
| --- | --- |
| 不同企业的独立配置、无共同变更依赖 | 在各自授权和总资源范围内并行，分别记录试验及实际采用 |
| 两个候选基于同一旧版修改同一方法 | 可以分别比较；一个采用后，另一个核对新基准，按影响调整、补验或放弃，不以较晚返回者覆盖前者 |
| 分别修改检索与输出但共用索引、模型或数据结构 | 核对共同依赖和组合影响，选择隔离作用条件或评价组合，不仅按文件名判断互不影响 |
| 调查过程中出现人工修复或其他合法升级 | 保留新修复；旧候选根据变化补充必要验证，不能恢复旧快照抹去人工变更 |
| 同一批任务同时受到多个试验影响 | 记录真实方法组合，隔离比较范围或明确评价组合效果，不分别将收益全归各候选 |

采用前的权限、停用状态、基准版本及条件复核与最终生效决定，需要由可信平台在一致的控制边界内完成，避免“先核对通过，稍后无条件覆盖”。具体事务、版本校验或发布协调方式留给实现选择，不只依赖模型记忆或两个候选互相口头约定。

长时间研究和评测不持续锁住正式方法或阻塞基础任务；采用时再核对条件和协调冲突，失败后按影响重新处理。不能为了避免版本冲突而让全部业务等待优化结束。

同一采用操作应有可核对的身份、目标版本、范围和执行记录；重复请求、断连重试及迟到回执不能造成重复采用或重复业务动作。结果未知时先查询原操作事实，不直接重新启动整个发布。只对影响判断的变化补验证，不机械重测全系统。

正式任务沿处理板块的版本原则：普通方法更新优先作用于后续新任务；在途任务保留可追溯的组合，等待恢复时根据兼容性继续或明确迁移。权限撤回、工具停用或必要缺陷阻断仍及时生效，不能因为固定旧版本而继续使用失效权限。

### 11.2 分范围采用与共享变更分别处理

平台版本可用、企业符合采用条件和企业实际启用是不同事实。采用过程需要能说明各目标范围已采用、尚未采用、失败或结果待核对，不能用一条“发布成功”覆盖所有企业；企业有效策略已覆盖时可自动采用，不增加逐家审批。

局部失败时先停止扩大受影响范围，核对原因及恢复条件。已经成功采用的范围可以按实际影响和既定策略继续或停用；不能一概全平台回退，也不能因局部成功将失败范围标为正常。当前作用版本及未处理事项保持可见。

只有实际支持并行版本的配置或组件才能按范围分批试用、独立恢复。共享数据库迁移、不可并行的公共依赖及其他共同结构，应按真实共享影响制定升级/恢复方案，不能在界面上承诺每个企业都能单独回退。候选选择、评估及采用范围必须反映这些限制。

### 11.3 停止操作要说清对象与生效状态

| 停止对象 | 生效后阻止什么 | 仍要处理什么 |
| --- | --- | --- |
| 一次观察或候选调查 | 该任务的后续调查动作及新增子任务 | 真实用量/结果记录和必要清理；不自动取消无关试验或原业务任务 |
| 一次隔离/影子试验 | 相应候选继续运行和发起新的试验动作 | 在途执行停止确认、未知结果及受控清理，不将未完成评测算通过 |
| 一次在线限定试用 | 按约定停止给新的相关任务使用试用方案，处理试用退出 | 在途真实任务、当前版本与恢复条件；不能仅关试验进程而让试用无限期继续 |
| 暂停某范围的后续采用 | 在该范围发起新的采用或扩大试用 | 已采用版本按有效状态管理；已提交的发布核对真实结果，不自动撤销全部正式版本 |
| 整体停用该范围自进化 | 新观察、试验、采用及其后续自动启动；关联队列和优化子任务受控停止 | 可信业务记录、权限核验、必要故障监测及发布收尾仍由基础系统完成 |

具体菜单可合并常用动作，但必须让用户理解作用对象和实际结果。“已收到停止请求”“后续动作已阻止”“仍有执行待核对”“已停止”需要可区分，不用点击成功代替真实停止。

停止与采用并发时，以平台持久生效的顺序及操作事实判断：停止生效后的相关新采用应被拒绝；此前已提交的动作查询真实结果并按约定处置。实现须避免校验后绕过最新停止状态提交，不依赖客户端按钮状态；不得让旧队列、定时触发或迟到评测自动解除停用。

正在进行的迁移或发布不一定能立刻终止。按原发布机制完成必要核对、达到可安全停止或恢复的状态，呈现剩余影响，不能强杀后宣称无副作用。停止只阻断对应范围；其他获准基础工作不因关闭自进化而消失。

### 11.4 恢复和回退以当前状态为依据

恢复自进化时核对当前授权、资源、方法版本和依赖、候选适用条件、已执行或未知动作，以及尚未兑现的观察责任。未过期且仍适用的工作可以续接；条件变化的工作调整或结束。停用期间的事件先按当前需要合并和核对，不重放全部历史触发，也不遗漏有效的必要检查。

方法回退前确认旧组合仍获准、可运行且与当前数据兼容。若后续人工修复、索引变化、模型下线或共享迁移使原路回退不成立，可以采用保留新修复的兼容变更、已验证替代或暂停受影响能力；没有可行恢复时如实显示，不能为了“可回退”删除新业务数据或覆盖后来合法版本。

恢复动作同样核对预期的当前版本，防止旧试验到期或迟到回退请求撤掉新修复。恢复方法和修复业务后果分别完成：相关成果、待执行计划和真实动作按各自权限核对、更正或补偿，既不自动重放，也不因方法已回退就标记所有影响已消除。

基础平台的必要监测、记录及正常维护在自进化停用时继续工作，已采用方法的运行依赖不挂在自进化进程上。重新启用优化不等于重新启用已停用的坏方法，也不能恢复此前已经撤回的数据权限。

### 11.5 后接入验证至少覆盖的状态交错

以下均为未来验收建议，本轮未运行：

1. 两个候选基于同一版本并行评估，一个采用后另一个不能直接覆盖；无关对象仍可并行。
2. 采用与停止交错，按实际生效顺序阻止后续动作；重复请求、旧触发及迟到回执不会再次采用。
3. 多范围分批采用出现部分失败或未知回执，各范围状态真实；共享结构不假称可独立回退。
4. 在线试用期间发生人工修复，试用结束或旧回退请求保留修复，并核对真实运行任务。
5. 原版本的模型/索引/数据结构已不可恢复时，使用获准可行替代或明确受阻，不抹去业务事实。
6. 完全停用自进化后，基础任务、既有有效方法、质量检查、权限及必要运维仍能运行；没有充分效果证据的试验不标为成功。

## 12. 自进化板块阶段汇总与三端管理衔接

第 10 节方向获认可（DEC-091）；本节汇总及第 11 节新增设计用于后续分工，不代表具体首个对象、自动类别、角色、阈值和全部并发/恢复交互已获确认。当前继续先讨论任务书、最后统一执行，不以阶段汇总启动自进化开发或实验。

### 12.1 基础阶段与自进化接入阶段分别交付

| 顺序 | 需要具备或交付什么 | 不能由此认定什么 |
| --- | --- | --- |
| 基础交付版本完成 | 代表业务闭环、当前有效方法及依赖、可信任务/版本/回执、必要评估、人工更新和正常发布/恢复、权限及资源 | 不等于自进化已实现；也不要求先实现所有远期业务功能 |
| 准备获准后接入范围 | 明确一类或少量方法对象、场景/空间、证据及数据用途、已有基准、允许动作/预算/期限和可行退出方案 | 不等于把所有企业纳入试验；本文没有产生实际授权 |
| 验证有限对象的完整改进过程 | 观察/候选、调用共用评估、按授权采用、真实范围生效、后续观察及停止恢复，同时覆盖无效候选和不采用 | 只提出方案或只跑离线比较，不等于采用链路与独立性已经验证 |
| 按效果扩展 | 在证据、兼容、权限和资源允许时增加方法类别或作用范围 | 一个场景有效不证明所有企业/行业有效，不承诺持续单调提升 |

首个对象建议优先选择已有明确问题、可靠基准、可比较且易于限定影响的一类方法；资料/经验检索或上下文选取可作为候选。允许改变方法和流程，不局限于调参数；实际对象待基础版本和真实证据具备后选定，前文检索示例没有因此变成已确认实验。

首次接入不以全自动代码升级、共享结构重构、训练微调、所有优化对象或复杂多实验分流为交付前提。上述方向保留，但分别取得工程、效果和权限依据后扩展。首个范围必须能验证完整过程和退出，不能为了容易展示只做“AI 生成建议”的页面。

### 12.2 拟新增能力与复用关系

| 拟新增能力 | 复用的基础能力 | 交付证据 |
| --- | --- | --- |
| 有范围的观察与触发 | 基础调度、事件、任务、权限、运行证据 | 触发依据与范围明确，重复合并不漏新证据，等待不空转，停用不重新启动 |
| 可核对的候选组织 | 方法版本、资料/经验和依赖关联 | 有具体差异、假设/依据、基准、适用范围和失败/未采用原因 |
| 试验与评价协调 | 共用评估、样例用途、隔离执行、资源控制 | 基准/候选/标准版本可比，结果限制真实，无重复业务副作用 |
| 预授权与采用协调 | 可信授权、研发/方法发布、企业采用策略 | 条件满足自动推进，越界部分待决定，平台发布与范围实际生效分开 |
| 并发、停止和恢复 | 原任务控制、版本核对、正常运维及恢复机制 | 旧候选不覆盖新修复，部分采用和未知结果可解释，停用后基础系统独立运行 |
| 后续效果与管理呈现 | 运行观测、反馈、站内输出及三端页面 | 说明实际改善/退化/取舍、资源和未验证范围，不以改动数量证明进步 |

机制可靠性与优化收益分别验收：流程可以正确拒绝一个无效候选，说明控制机制有效，但不能据此宣称已证明自进化能提高业务效果。效果验证要有实际场景的质量、遗漏、用户负担、耗时和资源证据，并考虑观察、试验、迁移及维护投入；证据不足时保留对应未完成结论。

### 12.3 交给三端管理的对象和动作

沿已有三端方向汇总需要，不预先冻结菜单、全部角色或权限矩阵：

| 需要管理的对象 | 需要承接的操作或说明 | 后续三端设计依据 |
| --- | --- | --- |
| 优化范围和策略 | 明确对象/动作/资源/期限，启停、撤回及变更依据 | 平台通用、企业、空间及个人范围分别处理，维护授权不等于内容读取权 |
| 候选及证据 | 查看差异、适用范围、评估结果和缺口，提出或处理必要决定 | 总台仅有获准通用证据/技术汇总，私人及企业内容继续按原权限 |
| 试验及采用 | 查看阶段、实际影响、累计资源、可用版本与各范围实际状态 | 复用评估与发布记录，不为每个板块或端各建实验平台 |
| 停止与恢复 | 明确停止对象、生效点、仍在执行/未知的部分，查看恢复条件和真实结果 | 管理者只能处理有权范围，旧操作不能覆盖当前合法状态 |
| 采用后的影响 | 本人或获权空间的实际变化、必要解释及纠正反馈，企业范围内的维护状态 | 客户端承接工作及内容互动，企业端承接本企业配置，总台承接通用能力与技术运行 |

普通用户不必看到候选编排、内部并发或所有技术参数，只需理解与自己有关的变化及可做动作。需要人工决定时展示可审阅的方案、证据和影响；已授权流程在范围内自主推进，不增加统一逐次审批层。

管理专题进一步建议：共用优化能力按企业授权执行，企业管理端提供范围/托管策略、效果和停止入口，总台负责通用能力与技术运行；两端查看同一任务和变更的获准信息。企业不必自行调算法，总台人员也不因集中执行取得客户内容权。具体业务评价与维护由获权者按轻量操作或集中维护进入相应界面，见[管理任务书第 11 节](三端管理与共用平台-开发任务书-V0.1.md#11-工作与维护入口及企业自进化分工)；这些细化建议不产生实际优化授权。

### 12.4 依赖与未决事项

基础需按输入/处理/输出/评估任务书落实相应事实、版本、样例、方法发布和资源控制。现有统计、尝试账本与回退演练只能作为部分基础，不能证明细粒度方法组合、完整评估或自主实验已完成。物理服务、队列、模型及存储仍按实际依赖选择，不先建设空自进化服务。

| 尚需确定 | 后续归属及边界 |
| --- | --- |
| 基础交付版本、代表业务及首个优化对象 | 全局汇总选择基础范围，接入前根据获准真实证据最终确认对象与基准；不等所有远期功能 |
| 各范围维护者、可自动动作与策略交互 | 三端专题明确对象/动作/角色，沿 DEC-087、DEC-091；未覆盖权限不能由实现自行补授 |
| 频率、样本量、资源、累计影响及停止阈值 | 按具体场景和真实测量形成可执行策略；触发方向认可不等于任意数值已确认 |
| 版本支持、共享迁移、部分采用与恢复细节 | 全局技术收口及对应发布切片，按真实可恢复能力验收，不承诺任意版本原路回退 |
| 证据保留、删除、导出与审计查看 | 三端和全局与评估/输入一并确定，避免候选/评测副本成为权限旁路 |
| 真实模型、真实任务效果及部署运行 | 在既有接入与费用授权内分别验收，当前文档及本地模拟不代替这些证据 |

以上未决项继续跟踪，不阻止进入三端讨论。相关实施按依赖分批推进，缺少某项业务决定只阻止依赖它的动作；当前仍不执行任何优化任务。

### 12.5 下一专题：三端管理及共用平台

输入、处理、输出、评估与自进化均已形成阶段任务书，现按 DEC-090 进入管理专题，并形成[三端管理与共用平台首轮任务书](三端管理与共用平台-开发任务书-V0.1.md)。下一轮细化组织角色及授权生命周期。先从“管理什么对象、谁能做哪些动作、作用于哪里、能看什么证据”确定分工，再安排入口、页面和交互；不按五个板块机械复制五套后台。

随后进行全局范围、接口、兼容迁移、依赖顺序与整体验收汇总，才进入统一执行。三端仍是既有三个端，自进化仍在基础系统完整开发后接入并测试，首版业务触达仍限定系统内。
