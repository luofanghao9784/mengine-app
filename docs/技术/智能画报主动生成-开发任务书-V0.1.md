# 智能画报主动生成开发任务书 V0.1

更新：2026-10-01。用户已在依赖任务完成后授权开始开发。实现及自动检查已完成；实际启用、真实模型与用户验收分别见[实施记录](../交接/智能画报主动生成实施记录-2026-10-01.md)。

本任务将智能画报建设为系统自带的内容生成能力：首次自动准备画报，按卡片类型响应数据事件或定时运行，用户也可以在瀑布流底部点击“生成更多”。有效新分析追加独立卡片，保留旧卡当时的内容、依据与交互状态。

执行依据为 [DEC-120](开发决策记录.md#dec-120智能画报按类型主动生成首次自动出卡与生成更多追加内容) 和[客户端统一实施任务书第 9 节](客户端统一实施任务书-V0.1.md#9-智能画报的系统主动生成与增量交付dec-120)。沿用 CUI-05、AI-11—AI-13、DASH-01—DASH-04；涉及来源、偏好和计划时分别衔接 CUI-03/04、CUI-08、CUI-07。本文 BG 与 BG-AT 编号用于开发和验收跟踪，不替代原需求编号。

## 1 目标与范围

### 1.1 已确认的产品规则

1. 系统按内容类型选择触发策略。资讯倾向定时，数据、洞察及经营分析倾向数据更新；同一类型可以接受多种触发。
2. 基本画报生成不依赖用户创建个人计划、先发起会话或保持网页打开。个人计划继续承担额外定制。
3. 首次初始化自动准备首批画报；资料尚未就绪时等待依赖，不伪造经营内容。
4. 瀑布流底部“生成更多”发起新的分析批次，直接在画报页呈现进度和新增结果。
5. 新的有效分析追加卡片，不批量刷新或静默覆盖旧卡。相同内容的重试和重复事件去重。
6. 页面刷新只同步现有卡片和状态；分页只读取已生成内容，两者均不等同于“生成更多”。

首版采用既定五类：资讯 INFO、数据 DATA、洞察 INSIGHT、建议 SUGGESTION、成果 RESULT。“分析”是跨类型处理能力，暂不增加第六类。会话继续作为触发入口，隐藏的会话类型不因本任务恢复。

### 1.2 本轮实施边界

交付系统策略、统一生成批次、五类内容交付、首次触发、资料事件、资讯定时、生成更多、增量卡片及必要的运行记录。权限、额度、来源准备和取消复用既有平台能力。

本任务不引入系统外推送、新的个人任务中心、跨企业读取或独立自进化。9POP 目前是导入快照；资料导入/更新是可验的事件来源，实时交易同步属于另外的接入任务。不得把旧快照的再次分析描述为当天实时经营变化。

资讯来源、频率、批次数量和相关阈值尚未全部确认。第 8 节提供开发与联调的可逆取值方式，不将其登记为用户已确认的经营规则或新增费用承诺。

## 3 默认触发与内容准入

下表是实施建议。资讯主定时、经营内容主事件承接已确认方向，具体触发条件需在实现记录中落到可验证规则。

| 类型 | 主要触发 | 交付依据 | 不应出卡的情况 |
| --- | --- | --- | --- |
| INFO 资讯 | 系统周期；首次或生成更多也可选取新内容 | 获准来源、原始链接或快照、原发布时间、采集时间及工作关联 | 无可用来源；旧文换标题；无法核实发布时间却声称最新 |
| DATA 数据 | 相关数据就绪/版本变化；统计周期核查 | 确切资料版本、指标口径、单位、期间及可核验计算 | 资料未完成必要解析；无新依据且重复同一指标结论 |
| INSIGHT 洞察 | 数据变化、异常信号；周期综合分析 | 支持新判断的来源，区分事实、推断与待验证原因 | 只换措辞；将相关性直接写成经营原因 |
| SUGGESTION 建议 | 新洞察、目标或业务状态变化 | 建议与证据、目标之间的关系，适用范围及下一步 | 无根据指派人员、编造收益或自动执行业务操作 |
| RESULT 成果 | 真实工作完成且有可复用交付 | 已成功的任务、成果版本及可访问内容 | 普通问候、状态回执、空文件；仅凭模型自述成功 |

程序先检查权限、就绪状态、版本变化、触发去重和额度；通过后才提交主模型判断主题、提炼内容。不要让模型决定访问权限，也不要每条上传事件都先调用一次模型。模型调用使用当前产品已配置的运行时主模型，沿用工具和实际回执，开发助手不代写验收卡片冒充产品生成。

一次分析围绕完整主题交付。只有独立阅读价值充分时才拆卡，不按类型机械凑齐五张。已完成成果可以复用原任务分析和产物；确需新增归纳才追加模型处理。

## 4 统一生成流程与状态

### 4.1 生成批次

首次初始化、数据事件、系统周期、生成更多和会话请求统一进入可追踪的生成流程：触发记录 → 权限与依赖检查 → 去重及额度检查 → 固定资料版本 → 主模型任务 → 内容校验 → 追加交付 → 页面同步。

建议新增生成批次对象，或用等价的既有对象扩展实现。至少保留企业、用户/接收对象、空间范围、触发来源、系统策略版本或个人计划引用、请求幂等键、来源版本集合、事件消费位置、调度时间、任务关联、运行状态、失败/等待原因和已交付卡片 ID。运行身份由服务端确定，不接受客户端指定其他用户为执行者。

触发来源建议明确区分 `INITIALIZATION`、`DATA_READY`、`SCHEDULE`、`GENERATE_MORE`、`CONVERSATION` 和 `PERSONAL_PLAN`。名称可随契约统一，但来源含义不能混淆。内部任务可以复用会话基础设施；系统生成记录不冒充用户发送的消息，也不强制打开会话页面。

### 4.2 建议状态及恢复语义

以下为新增批次的建议语义，实施时可映射现有状态，不要求重写任务引擎。

| 状态 | 含义与页面表现 | 下一步 |
| --- | --- | --- |
| 等待资料 | 必要来源未就绪，说明缺口 | 来源就绪或补查后继续，不持续消耗模型调用 |
| 等待资源 | 当前额度或执行资源不足 | 到允许重试时间重新检查，用户可知等待原因 |
| 排队 / 分析中 / 校验交付中 | 使用真实任务阶段，进度不编造百分比 | 完成、部分完成、无新内容或失败 |
| 已完成 | 预定处理已结束且至少有一张新卡成功交付 | 返回新增卡片和来源范围 |
| 部分完成 | 部分子任务交付，另有失败或未完成项 | 保留已交付卡片，仅重试未完成项 |
| 无新内容 | 已完成检查，但没有足够的新内容 | 正常结束，不以模型回复或旧卡数量冒充新增 |
| 失败 / 已取消 / 权限失效 | 如实给出可行动原因 | 明确重试规则；旧尝试失去写回资格 |

批次、任务尝试与卡片交付分开记账。`PREPARED` 只是准备完成，必须取得实际任务成功和交付回执才对读者可见；批次成功也不意味着每个模型尝试成功。部分成功不能因为整个批次重试而再次发出已交付卡片。

采用持久记录、原子领取和租约/等价并发控制。服务重启恢复已有批次；失去租约、取消或撤权的旧任务不得迟到写回。自动重试必须有次数与退避上限；确定性数据/权限错误不无限重试。

### 4.3 首次生成与后续触发

首次条件建议按“企业已可用 + 当前用户已进入有效使用范围 + 系统策略可执行 + 相应来源就绪”判断，由服务端维护初始化记录。用户无需额外创建计划。现存用户升级时采用同样的幂等检查，不能把每次升级当作新的首次初始化。

首批各类型按实际可得来源独立准备：已有经营资料时不等待资讯服务，有资讯而无经营数据时不伪造经营卡。未就绪类型保留等待原因，首批中某类型成功不永久吞掉其他类型后来的就绪事件。首次总体完成条件及策略升级是否补充新类型必须显式记录。

首次幂等键绑定企业、接收对象和初始化代次；重复登录、标签页、刷新及重启使用同一记录。授权范围扩展或后来加入新空间按正常来源事件处理，不重新生成全部首次内容。

数据事件应在资料版本提交后可靠记录，并等待本次分析需要的全部来源就绪。允许部分资料分析时必须显式记录缺失范围，不能悄悄只计算已解析的半批经营数据。批量上传先合并，在有界等待后给出等待/部分范围说明。

周期执行由后端调度，保存时区、应执行时间、实际开始时间和漏过的时段。停机恢复后可合并补查最新一期，不逐个补跑造成突发调用，也不声称停机期间已按时生成。资讯没有配置可用来源时进入等待来源，不用静态 Demo 或旧文替代新资讯。

### 4.4 幂等与追加规则

必须同时处理三层重复：同一请求的重试、同一批来源事件/时间窗的重复触发、不同触发得到的同一内容。仅按触发类型去重不够，定时与数据事件撞期仍可能重复。

- 触发层：请求键唯一，作用域包括企业和接收对象；相同请求键但不同参数返回冲突。同一对象相同筛选已有执行批次时，连续点击应返回已有批次，不能仅依赖按钮禁用。
- 来源层：固定资料版本和本次消费上界。运行期间新事件进入后续候选；成功后只推进到已处理上界，失败不永久跳过该批资料。没有新版本时仍允许独立角度的生成更多，但不免除内容去重。
- 内容层：比较主题、统计期间、证据版本、主要结论及分析角度。标题哈希不能作为唯一判断；同一证据的新独立洞察也不能一律拦截。首版可用确定性规则配合必要的模型判断，保留去重原因及关联卡片。
- 交付层：持久唯一约束保证并发重试不重复保存同一交付。对已有卡片新增关联或状态记录，不覆盖当时正文、数字、证据和阅读快照。

生成内容保存为资料、任务完成等内部动作需带因果来源，避免“生成画报 → 新资料事件 → 再生成同一画报”的循环。明确业务更新仍可生成新的卡片，不能为防循环屏蔽所有后续数据。

## 5 卡片身份与页面约定

内容卡使用稳定且独立的 `cardId`，与 `conversationId`、`taskId`、产物 ID 和主题 ID 分开。可复用唯一内容产物作为身份来源，但列表、详情、反馈、关注、隐藏、布局、已读以及会话引用必须一致使用该卡片身份。同一会话的第二次分析不能替换第一张卡。

实施时补齐旧会话投影与新内容卡的兼容映射：保留已有深链接、历史会话引用和用户偏好；旧偏好只迁移到其对应的旧卡，不扩散给所有后来生成的卡片。新卡关联“后续分析/数据更新”时仍保留自身来源和时间。权限撤回或明确更正按既有生命周期处理，不因保留旧卡继续泄露内容或展示已知错误而不标记。

“生成更多”位于主内容瀑布流底部，空状态也有对应入口，但不是首次自动生成的必经按钮。默认继承当前获准的空间和类型范围；关注、隐藏、历史日期等展示条件不自动成为后台资料授权。若新卡不符合当前日期或关注视图，提示已生成和查看入口，不暗改历史筛选或自动关注新卡。

建议交互：点击后本地展示正在生成并订阅/轮询真实批次；返回页面可恢复状态；新批次接在本次阅读流后方，保留滚动位置和旧卡尺寸、关注、已读及布局。后台新卡先提示“有新内容”，避免突然打断阅读。具体提示文案与位置可沿现有设计调整。

加载更多既有卡片与生成更多使用不同请求和状态。新增卡片期间采用稳定游标/等价快照分页，保证同一次阅读不漏卡或重复；不能只沿用会随新增记录漂移的 offset 而不处理边界。

## 7 实施顺序与阶段退出条件

| 阶段 | 任务顺序 | 可交付的最小闭环 |

| G1 统一执行与主动请求 | BG-03 → BG-04 → BG-08；BG-09 接入基础观测 | 用户生成更多可真实产出新卡，重试幂等，旧卡不变，失败可解释 |
| G2 首次与经营事件 | BG-05 → BG-06 | 首次无需手动配置；9POP 获准快照的新版本能触发增量分析 |

前述顺序是降低集成风险的实施选择，不改变首次自动生成的最终产品要求。待定资讯来源不阻塞卡片身份、生成更多或经营资料事件开发；来源未具备时 INFO 的真实周期验收保留未通过状态，不能缩减为只验数据卡后宣称整项完成。

## 8 默认参数与权限资源边界

### 8.1 参数收口方式

| 参数 | 开发与联调处理 | 实际启用时的要求 |
| --- | --- | --- |
| 资讯来源与主题 | 使用可追溯合成来源测流程，另用获准真实来源验模型 | 明确可访问来源及主题规则；采集不得携带未经允许的私人经营信息 |
| 资讯周期与时区 | 注入时钟测试，不靠等待真实一天；可用每日一次作为联调策略 | 采用配置化系统默认值，记录企业/用户时区和生效版本；具体时间仍待收口 |
| 首次与手动批量 | 联调上限可暂设为最多 3 张，允许少于上限或零张 | 数量由可用证据和既有额度共同限制，不保证每次凑满 |
| 数据事件合并 | 合成测试可设 60 秒合并窗，时钟推进验证 | 按解析批次和实际数据量调整；最大等待时间有界并可观察 |
| 并发与重试 | 同一接收对象、相同有效范围先按单个活跃批次验证；同批次有限退避 | 同时约束企业总并发/额度，避免多个空间分别达到上限后总量失控 |
| 首次完成条件 | 分类型记录等待、完成和无内容原因 | 核对初始化代次、存量用户和后到数据；不能以曾打开页面作为已完成 |
| 内容增量阈值 | 用重复、微小变化、重大变化、新角度对照样例验证 | 记录规则版本及拒绝原因；业务阈值不由模型自行长期固化 |
| 展示位置 | 手动结果追加底部，后台结果提示有新内容作为初始实现选择 | 保留滚动、筛选和关注布局；结合实际验收调整 |

以上数值仅为可逆联调选择，不是生产 SLA、固定内容量或用户确认的费用上限。系统应随功能提供可用默认策略，不把这些高级参数转嫁给每个用户手动填写。真实启用沿现有获准模型额度执行；不因本任务新增供应商订阅或提高付费上限。

### 8.2 必须从首批实现的约束

默认接收范围沿用当前用户的私人画报，不自动发布给企业全员。后台使用范围必须由服务端结合企业、用户、空间及 AI 使用许可得出，不要求每个用户建计划，也不能以“可阅读”推导可长期分析所有私人会话或未入库附件。

提交、领取、工具读取、交付和后续阅读均复查当前权限。触发后撤权、用户停用或空间变化需要阻止迟到交付；缓存、日志、标题及批次计数同样隔离。合法共享发布副本沿原发布规则处理，不用本任务改写其生命周期。

每批预留/检查资源，记录实际消耗，结算幂等；无新卡也可能发生了模型调用，不能把费用记为零。无数据和明显重复尽量在模型调用前结束。停止未来自动生成、取消当前批次与关闭提醒分别表达，关闭提醒不自动停止工作。

### 9.1 真实模型与 9POP 验收步骤

1. 准备获准的 9POP 资料版本与一个可追溯的资讯来源，记录资料统计期间、范围和权限。新增或修改的验收样例要明确标记，不篡改实际经营原始数据。
2. 在隔离验收对象中验证首次自动出卡；对已有用户不清空历史卡来假装首次。保存触发记录、实际主模型/引擎版本、任务及成功回执。
3. 导入一份有明确业务差异的获准新版本，观察解析就绪后的事件批次，复核指标、单位、期间与图表值；新旧两张卡分别可读。
4. 在画报页点击生成更多，再执行重复点击/网络重试；核对真实任务、去重和追加结果。旧快照无新价值时允许无新卡，不为了演示强行凑数。
5. 验证真实资讯周期的模型处理与来源；调度时钟边界和停机场景用自动化控制测试。二者分别记录，人工调用调度器不能单独证明自然定时运行成功。
6. 在真实接口浏览器流程中验证筛选、阅读、继续会话、关注、已读及刷新恢复；对越权、失败和取消以自动化断言为主要依据。

每条证据关联“触发 → 批次 → 任务尝试 → 工具/计算/来源 → 交付 → 卡片”。保留统计范围、限制和错误码；凭据与用户原始资料不进入仓库或公共日志。真实模型调用成功、代码合入、实例部署与用户验收分别记录。

## 10 交付与回退

交付物包括实现与契约、数据库迁移、系统默认策略说明、必要测试、真实模型证据、用户验收步骤和运行版本记录。更新客户端统一任务书的 B4/B6 状态时链接本任务验证记录，不能直接把“任务书完成”改成“功能完成”。

建议分阶段启用：先验证独立卡片兼容和生成更多，再启用首次/经营事件，最后启用具有真实来源的资讯周期。发布记录固定提交、平台/引擎产物、协议与迁移版本、策略配置和当前数据目录，沿现有验收实例的正式切换流程执行。

回退优先停用相应系统触发策略并终止未交付批次，保留已生成卡片、实际消耗和审计记录。停用不应影响原有会话分析或用户个人计划。涉及新卡身份时先做兼容迁移，旧版本不能读取新结构时不得盲目回滚程序；需事先验证兼容版本或恢复方案。

本任务完成的定义是：五类内容在各自适用触发下可真实交付，首次和后台执行不依赖用户手动建计划，生成更多确实追加新卡，重复请求不重复交付，旧卡及权限规则保留，并提供可供用户验收的明确版本。

用户补充确认：资讯内容应由当前企业上下文、项目和资料库分析其相关性，不采用固定的全局行业主题。首版可信来源适配、限制和默认值见实施记录。
