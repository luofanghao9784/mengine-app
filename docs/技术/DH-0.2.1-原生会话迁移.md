本文件记录实现决定与验收边界；未完成项不因文档存在而生效。任务见 [#120](https://github.com/dimmm1125-coder/dreamcore-workspace/issues/120)。

## 已确认范围

以官方完整运行时和会话前端为能力基准，梦擎提供企业身份、获权资料、成果保存与发布。先保留能力，再按产品范围收敛界面。正式 App 后期交付。本期不承诺恢复旧任务不存在的原生事件或执行现场。

已发布基线固定 `0.2.1-rc.2`：npm 的正式 `0.2.1` 不存在；不跟随浮动 latest，也不依据 master 的 rc.3 臆造 rc.2 接口。它是 DH 依赖版本，不冒充梦擎已经发布完成的产品版本。

## 现状与迁移结构

旧链路同时受引擎 55 秒、平台同步等待约 60 秒、90 秒租约、8 次模型调用及数据库次数约束影响。只改前端或增加单个 timeout 无法释放完整能力。

目标链路：企业鉴权 → 持久任务与会话映射 → 隔离的官方 profile → 原生模型/工具事件；业务工具通过平台回执确认结果。浏览器断线不结束任务；取消、预算暂停、进程丢失与业务完成分别持久化。旧 `ModelPort` 继续服务现有工作流；其文本投影不能作为原生会话的主协议。

官方完整 `web` / `sdk` profile 由发布包组合；企业 overlay 只关闭上游会话日志上传、遥测、插件清单上传、账号登录和宿主插件热修改。保留原生文件、命令、工具、上下文整理、子代理与持久化。overlay 不是企业鉴权或 OS 隔离实现。

`dsh-sdk-client@0.2.1-rc.2` 支持真正的 `resumeSession`，但尚无中途取消协议或服务端发起的交互请求；不能用放弃 Promise 假装取消。完整交互入口以 Web 为目标；SDK 用于可复现基准和生命周期验收。

## 企业边界

官方 owner token 只认证该 DH 实例，不表示梦擎的企业、员工或空间权限。默认 `fs-sandbox` 限制写入，**不限制读取范围**。因此独立目录、前端隐藏按钮、`workspace-write` 均不能证明企业隔离。

正式接入必须满足：

1. 服务端从登录身份绑定 tenant、user、workspace、conversation、root task；模型输入不能改绑定。
2. 工具运行在独立文件和进程边界内，不能看到其他任务、宿主凭据、Docker socket 或预算数据库；网络仅经受控网关。子代理继承同一个根任务授权和预算。
3. 模型凭据及预算账本放在工具边界之外；所有请求，包括重试、标题、压缩和子代理，都经过派发前预留。不能允许原生设置页增加绕过计量的模型路由。
4. 企业资料仅通过每次检查权限的工具获取。保存私人成果与发布共享成果分开授权，保留真实、幂等业务回执。
5. 官方 Web 的 HTTP、WebSocket、附件、导出和恢复入口统一经过企业授权。运行时 owner token 不作为员工可转发的企业通行证。
6. 未通过隔离及授权验收前，不把官方 Web 直接接到正式会话入口。

## 长任务预算

| 范围 | 默认值 | 行为 |
| --- | --- | --- |
| 软阈值 | 15 分钟或 ¥2 | 提示并记录进度，可在硬上限内继续 |
| 根任务硬上限 | 30 分钟或 ¥5 | 停止新派发、取消活动执行、保留可恢复进度 |
| 每员工每企业每日 | ¥20 | Asia/Shanghai，跨任务合并 |

金额使用整数微元；这是资源保护，不是客户价格。单次派发按已核实模型输入上界与输出上限预留，缓存取最保守费率；已知 usage 按 DH 的不重叠输入、缓存读、缓存写和输出口径结算，reasoning 若含在 output 内不重复收费。价格/计量口径未确认则拒绝收费派发。

账本通过 SQLite `BEGIN IMMEDIATE` 跨进程串行预留；未知用量不释放额度，重启不清零，重复回执幂等且冲突拒绝。未结算的昨日请求继续占用今日可用额度，已结算费用归属原派发日。任务 key 由规范化身份三元组生成，不能用 JSON 属性顺序或 attempt 字段重置。

当前 `native/budget*` 是预算原语与 adapter 装饰器，已接真实 DH 调度的合成 provider；**尚未接平台收费调用**。它不替代容器硬超时和业务续做授权。人工追加预算需要独立、幂等的用户动作，不能由模型自行申请重置计量。

## 容器外模型网关基线

`native/model-gateway.ts` 提供 Request/Response 处理原语，尚未作为网络服务或正式路由运行。授权 resolver 必须逐次查询有效权限、返回服务端绑定的根任务及稳定取消信号；原生请求中的 metadata 不参与身份绑定。仅允许固定模型、输入上界、输出上界和服务端 HTTPS endpoint；调用前预留，原始 JSON 和 SSE 字节保持不变，usage 仅作旁路计量。取消、上游失败、截断和缺失 usage 均保留未知用量。

目前只验证 Messages/OpenAI 流式推理；不能把它描述为完整模型 API。官方 `/files` 上传及 opaque file ID 需要按根任务保存授权映射，当前拒绝此入口和直接 file_id。正式接入前必须补齐，不能靠前端隐藏上传功能掩盖能力损失。企业 Web、容器监督器、内网网关部署与模型真实价格仍为待完成项。

## 历史保留与恢复

旧会话及已完成成果保留原读权限和原事实。旧会话接续时生成明确标记的历史上下文，来源仍需逐次授权；它是新的原生任务，不伪造旧 tool/result 或 native seq。原生会话恢复使用持久日志及附件，不创建同名空会话顶替。外部进程不能因恢复日志就视为恢复成功。

## 验收分层

- 原生合成基准：完整 profile、超过旧次数上限的工具循环、进程退出与恢复、预算连续计量。
- 隔离基准：不同任务/企业文件不可见、宿主环境无继承、外网和执行器 socket 不可访问、取消回收、持久卷不丢失。
- 企业链路：登录/撤权/空间切换、资料读取、私人成果、发布回执、旧会话接续、HTTP/WebSocket 及下载授权。
- 效果基准：相同模型、资料、任务，记录完成率、质量、延迟、人工介入与费用。合成 provider 不证明模型能力或费用改善。

目前基础构建和合成基准通过，企业正式入口及效果验收仍待完成。App 不列入此次验收。实际记录见[本地变更记录](../变更记录/2026-10-26-DH021原生运行与预算基线.md)。

## 2026-10-26 前端整合：可复用接口核实（Claude 接手）

交接要求先核实官方 Web 的可复用接口和授权方案，结论如下（依据 `engine/node_modules/@deepseek-ai/*` 0.2.1-rc.2 各包说明）：

- **官方 Web 前端**（`dsh --profile web`）由 Cordis 插件拼装：`dsh-client-connection` 负责带认证的 RPC 与连接代次，`dsh-api-gateway` 在一条 WebSocket 上复用多路 Typert RPC，`dsh-client-ui-conversation` 等包按注册表组装界面。这套协议是生成的内部契约，前端只能整体运行官方客户端运行时才能复用。把它嵌进梦擎页面（同源 iframe 或复制组件）等于让上游代码在梦擎来源下运行、可借用员工会话，不作为发布方案；跨来源 iframe 又会碰到第三方 Cookie 与 `SameSite=Strict` 的授权 Cookie。
- **SDK 协议**（`dsh-sdk-protocol`，MIT）是公开、稳定的线协议：stdio 上的 JSON-RPC，7 个请求（`initialize`、`session/prompt`、`session/resume`、`session/wait`、工作目录读写、`shutdown`）与 4 个通知（`session.event`、`session.status`、`subagent.started/finished`），携带 `dsh-session` 的完整事件词汇。`dsh-sdk-client` 只能在服务端以子进程方式使用，浏览器不能直接用。
- **结论**：梦擎自己的会话界面若要完整展示工具过程、长任务状态与恢复，应以 SDK 事件流为契约，由平台转发给前端（服务端改造），而不是复用官方 Web 内部协议或把事件压回旧的短任务文本。在此之前，官方会话仍在独立窗口中运行。

据此分三步推进：

1. **本轮（已完成，仅用现有接口）**：原生会话并入梦擎会话页与抽屉的会话列表（部署开启时才显示）、新建 / 接续旧会话、打开官方窗口、停止 / 继续、私人成果与员工确认发布，全部状态取自服务端回执；保留 `/native-conversations` 独立入口，旧会话体验不变。
2. **下一步**：任务状态与预算的契约与服务端证据（预算台账在桥接容器内 `budget.sqlite`，需要平台可读的汇报通道），前端再据此显示真实的运行 / 空闲、已用预算和软硬阈值，不用模型自述或计时器。
3. **目标形态**：平台以 SDK 方式驱动运行时并转发 `session.event` / `session.status`，梦擎会话卡片直接渲染消息、工具过程、子代理与成果，不再依赖独立窗口。需要引擎与平台改造，另行规划与认领。
