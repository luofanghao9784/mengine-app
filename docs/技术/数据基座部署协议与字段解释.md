# 数据基座部署协议与字段解释

2026-10-12 用户确认：数据基座承接梦擎外部输入；连接由部署工具配置，人工建表不需要。字段解释由部署时的外部 AI（例如 Codex）调查并保存，不由产品内置 AI 生成。权限、取数控制和空间边界继续遵守现有规则。对应 AI-02—AI-04、WS-08—WS-11、POS-04—POS-05、MAINT-07—MAINT-10，不新增一套业务权限。

## 分工

部署负责源库只读账号、网络/TLS、受限视图或投影、字段映射、字段解释及目的企业/共享空间；企业端查看来源和获权资产，控制频率、立即更新及自动开关。管理来源不意味着能读来源内容。梦擎仅通过平台工具读获权的固定版本，不接触凭据，不生成或修改部署解释。

采集器仍使用 [CollectionAdapter](../../apps/api/src/main/java/com/dreamcore/workspace/collection/CollectionAdapter.java) 1.0 协议，由现有 `ProcessCollectionAdapter` 执行。通用读取器见 [collector.py](../../scripts/data-foundation/collector.py)。不引入独立定时器、SQLite 应用数据库、角色体系或人工表格编辑器。

## 部署清单

沿用 `CollectionDeployment` 的 manifest，`datasets` 新增可选 `fieldDefinitions`。以下全部 ID 和业务说明为合成示例，实际部署需替换为获准的企业与已有共享空间。

```json
{
  "contractVersion": "1.0",
  "tenantId": "00000000-0000-4000-8000-000000000001",
  "connectionId": "00000000-0000-4000-8000-000000000002",
  "name": "合成销售系统",
  "routeLabel": "只读视图 → 销售数据",
  "accessSummary": "部署限定销售空间及编号、金额两列",
  "status": "READY",
  "timeZone": "Asia/Shanghai",
  "datasets": [{
    "id": "00000000-0000-4000-8000-000000000003",
    "workspaceId": "00000000-0000-4000-8000-000000000004",
    "key": "sales_v1",
    "name": "销售数据",
    "description": "合成销售记录；金额不是到账证明。",
    "columns": ["编号", "金额"],
    "fieldDefinitions": [
      {"column":"编号","type":"text","meaning":"源业务记录标识","unit":"","evidence":"合成源字典 v1：记录主键","status":"SOURCE_DOCUMENTED"},
      {"column":"金额","type":"decimal","meaning":"金额对应应收还是实收尚不明确","unit":"","evidence":"当前只有数值字段，缺少业务定义和币种依据","status":"UNKNOWN"}
    ]
  }]
}
```

说明性质可为 `SOURCE_DOCUMENTED`（有来源依据）、`DEPLOYMENT_INFERRED`（部署时推断）、`UNKNOWN`（尚不明确）。不自动把外部 AI 输出视为事实确认。提供说明时必须与 columns 一一对应、保持顺序；不提供时保存空数组并在页面显示未提供，兼容旧清单。每项 meaning/evidence 上限 300 字符，type/unit 上限 40，整体 JSON 上限 24000 字符；manifest 文件仍最多 128 KiB。

数据集的空间、列和字段解释一经登记不可原地修改。含义变化或给已有来源补说明时创建新数据集 ID；旧 ID 的历史任务不会被新解释覆盖。部署完整清单时遗漏的旧数据集会撤下，必须保留其他不变项，不能只提交新增项。正常采集使用同一 ID 追加快照。清理数据集正文时字段解释也会被清理。

2026-10-18 本地修复：相同有效 manifest 重放不增加连接版本、不打断排队或运行中的采集；数据集排列顺序不影响判断。真实元数据或数据集变化仍使旧执行失效。连接创建后，取数计划及其时区由用户设置维护，重放 manifest 不覆盖它们。验证见[第四阶段实施记录](../协作/企业首次接入/第四阶段核查与实施-2026-10-18.md)。

## 私有采集配置

采集配置和公开的 manifest 分开保存；配置必须是权限 0600 的绝对路径普通文件。`DATA_FOUNDATION_CONFIG` 指向它。通用读取器支持 SQLite、PostgreSQL、MySQL，只接受部署固定的表/视图与输出列，不接受运行请求中的地址、凭据、SQL 或新增列。

```json
{
  "kind": "postgres",
  "host": "db.example.internal",
  "port": 5432,
  "database": "approved_reporting",
  "username": "input_reader",
  "passwordEnv": "INPUT_DB_PASSWORD",
  "caFile": "/private/deployment/ca.pem",
  "tenantId": "00000000-0000-4000-8000-000000000001",
  "connectionId": "00000000-0000-4000-8000-000000000002",
  "datasets": [{
    "id": "00000000-0000-4000-8000-000000000003",
    "key": "sales_v1",
    "schema": "public",
    "table": "authorized_sales",
    "columns": [{"source":"id","name":"编号"},{"source":"amount","name":"金额"}]
  }]
}
```

MySQL 用 `kind: mysql` 及实际端口/库，schema 可省略。SQLite 用 `kind: sqlite`、`file: /绝对路径/获准数据.sqlite`，省略网络凭据字段。远程模式必须验证 CA 和主机身份，不支持关闭 TLS 校验。密码只从部署环境读；不能写进 JSON、Git、源字段说明或运行日志。

多来源可用 `{"sources":[配置1,配置2]}` 注册；以 tenantId+connectionId 精确分发，重复或未登记来源拒绝。不同来源的主机和凭据均由配置固定，不允许客户端选择。已有 9POP 专用投影继续使用其采集器；一个实例只有一个采集执行入口，接入混合适配器时由部署侧明确分发，不能直接覆盖既有入口丢掉其他来源。

安装可用独立 Python 环境：

```sh
python3 -m venv .local/data-foundation-venv
.local/data-foundation-venv/bin/pip install -r scripts/data-foundation/requirements.txt
```

SQLite 仅使用标准库。远程驱动固定为本轮验证的版本；升级重新验证只读事务与 TLS。生产使用私有发布目录中的程序、环境和配置，不应指向临时测试目录或可随开发变化的工作树。

由部署包装程序导出 `DATA_FOUNDATION_CONFIG`、凭据环境变量并执行固定 Python/collector 路径，将其绝对可执行路径接入已有 collection runtime 配置。manifest 通过既有主机命令登记：设置 `COLLECTION_MANIFEST_FILE`，使用目标环境已配置的数据库凭据运行 `java -jar apps/api/target/workspace-api-0.1.0-SNAPSHOT.jar --provision-collection`。此操作是实际部署写入，只在对应环境已获准时执行；本轮开发没有运行此命令到用户实例。

## 采集与消费约束

- 固定投影、只读事务和最终 rollback；行级策略在源视图或专用部署采集器落实，不提供产品内筛选授权编辑器。
- 单表最多 100000 行、100 列，总计最多 1000000 单元格、响应 20 MiB、单元格 8192 UTF-16 单元。超限整批失败，不发布截断快照。
- 保留 NULL、字符串编号和精确 Decimal；不自动做分转元。不支持的二进制/复合值需部署成适用投影，不能随意 stringify 成业务事实。源浮点字段已损失的精度不能由采集器恢复。
- 全量读取，不是 CDC；源新增、修改、删除在下次成功快照反映。缺列失败；新增未获准列不会自动进入输出。字段类型或业务语义变化须部署复核，当前不提供自动类型漂移识别。
- 通用读取器返回 `coverageThrough: null`。数据库读取时刻不是业务覆盖截止；需要确定覆盖期时由专项采集器依据业务证据返回。
- 普通行内容、字段含义和依据均是受控输入参考，不是系统指令。字段说明随已有 `dataset_search`/`dataset_read` 的获权列分页返回；不提供源连接参数。无说明的旧来源继续按原路径工作。
- 数据目录、概览计数、连接可见范围和任务检索同时检查现有空间读取限制。文件独立授权不自动授予数据集读取；不自动启用任何企业的新权限灰度开关。

## 2026-10-15 Codex 首轮治理与知识初始化（用户已授权）

用户确认先用 9POP 订单、收款、退款链本地验证，再部署线上。该能力不在产品中增加人工改表或任意写知识接口。原生 PostgreSQL `fieldDefinitions` 部署链与企业场景的口径链保留边界；场景新增受签名保护的部署成果入口，沿现有企业绑定、读取/治理/口径职责及来源版本执行。

### 首次接入与发布

1. 通过部署签名端点 `POST /api/internal/platform-scene` 的 `/deployment-governance/source`，使用已安装来源创建、扫描和拉取。首次拉取设置 `governanceMode: deployment`，等待部署治理，不抢先调用内置模型。
2. `/deployment-governance/context` 返回指定 1–20 张表的字段、全量数量、隔离数量与内容/权限版本令牌。源数据更新或撤权后旧包拒绝发布。
3. 部署包包含 `contractVersion: 1.0`、企业、唯一部署编号、制作方、各表令牌、完整字段解释、逐字段依据及 `SOURCE_DOCUMENTED/DEPLOYMENT_INFERRED/UNKNOWN` 性质、关联/查询规则和来源关联的业务知识。可追加有条件必填检查；异常生成治理提示，不造假补值或自动批准。
4. `/deployment-governance/preview` 在回滚事务中执行同一校验，返回确定性统计事实、知识发布指纹与真实检查结果，不留下字典、知识、版本或审计写入。Codex 可以引用返回的事实编号编写首轮分析知识；不能提交无依据数字。
5. `/deployment-governance/apply` 原子发布口径、来源规则知识、可选分析知识、检查结果、审计与回执。部署编号相同且内容相同返回原回执；同编号异内容拒绝。回执是历史发布事实，不代表来源此刻仍未变化。

只允许绑定的服务身份通过部署签名入口调用；即使持有有效浏览器客户身份也不能导入。调用工具为 `scripts/data-foundation/deploy-governance.py`：

```sh
python3 scripts/data-foundation/deploy-governance.py preview --config /private/bridge.json --input /private/package.json --output /private/preview.json
python3 scripts/data-foundation/deploy-governance.py apply --config /private/bridge.json --input /private/package.json --output /private/receipt.json
```

`bridge.json` 由部署维护，权限 0600，字段为 `url/key/tenant`；密钥不是浏览器凭据。远端 URL 要求 HTTPS，回环地址可 HTTP。输入包与结果按业务私有资料保存，禁止提交真实数据和密钥。

### 服务端接续规则

- `origin: deployment` 与 `origin: model` 分开记录，页面展示实际制作方。部署口径以结构指纹校验，数据行变化不会触发模型覆盖它。
- 部署规则知识依赖同一结构与当前权限；来源或权限失效时隐藏。分析知识依赖行数据、口径、版本和权限指纹，变化后旧结果不再作为当前知识，服务器模型重新计算生成。
- 结构/字段含义变化后旧部署口径失效，等待部署工具重新治理；不让服务器模型静默重写既有业务定义。普通运行中的分析知识仍由现有模型维护。
- 来源失效、任务失败和撤权沿原有规则处理；不保证所有业务问题自动修复。未知口径与有条件缺失提示继续保留。

### 固定投影来源与持续取数

原生连接新增 `kind: deployed`，只提供已登记的 `provider` 标识，不接受命令、SQL 或凭据。`DATABASE_DEPLOYED_SOURCES` 指向本机 0600 的部署登记文件，按企业和来源编号选择固定命令。命令输出使用 `contractVersion/tables/rows/tenantId`，每个值仅为字符串或 NULL，限制与原生场景相同：每表最多 10000 行、30 列及有界输出；超限整批失败。

9POP 固定投影脚本为 `scripts/ninepop/governance_collector.py`，仅三张表的 46 个指定字段，不含姓名、手机号、凭证正文。部署使用本机 MySQL 专用列级 SELECT 账号；只读一致性事务、原始整数分和 NULL，读取时刻不冒充业务覆盖截止。连接通过现有 `database_sync_jobs` 调度，不另设 cron。

SQLite 初轮验证的 NULL 同时保留在行级 `sourceNullFields`，不会因展示层空字符串丢失原始空值性质。资料处理、关系分析与当前业务规则不因本协议扩大企业访问权限。

### 2026-10-18：首次接入受控求和规则

`analysisPolicy` 可额外携带 `conditionalSums`，仅由部署治理包声明，不由模型提示或指标自由文本决定。示例（合成规则）：

```json
{
  "excludeFields": [],
  "noSumFields": ["amount_cents"],
  "conditionalSums": [{
    "field": "amount_cents",
    "equalsFilters": {"status": "SUCCESS", "currency": "CNY"},
    "conversion": "CENTS_TO_YUAN"
  }]
}
```

最多10条受控规则，每条1—5项精确字符串等值条件，全部AND匹配；字段须存在，不允许受限字段，数值字段仍保留在noSumFields。分转元要求治理字段单位为“分”或“人民币分”。主系统仅放行已发布、获准且条件和换算完全匹配的固定方法；原始模型查询的求和禁令不变。规则参与来源范围版本，变化后重新同步并核对方法版本。NULL/空金额停止计算，不补零。该机制不支持SQL、任意公式、OR条件或自动跨表净额。
