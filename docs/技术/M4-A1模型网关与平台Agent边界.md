# M4-A1 模型网关与平台 Agent 边界

> 本文保留第三切片的实现与验证范围。第四切片已增加可信目录与公开检索，并将 Agent 协议升级至 1.1；当前新增能力、上限与升级顺序见[最新技术边界](M4-A1可信目录与公开检索边界.md)。

日期：2026-09-23。第三个实施切片，对应 AI-01—AI-13、POS-05；继续既定 Spring Boot 平台、可独立替换引擎和 React。实现不等于真实模型验收，未改变总台无客户内容访问权的决定。

## 当前结构

网页通过会话 API 提交 `SOURCE_LOOKUP` 或 `AGENT`。Spring 保存企业、空间、发起人、请求键、状态、版本、尝试及产物；独立引擎只接收本次任务和短期执行凭证，经平台回调取得获准资料片段。引擎不连接业务数据库，前端不导入 Harness SDK，也不接触供应商密钥。

- 平台 `AGENT_TASK_MODE=off` 默认关闭；`verification` 仅用于隔离合成测试；`live` 需显式配置真实模型。任务固化执行类别，切换配置后不能把旧验证任务重试成付费任务。
- 引擎 `AGENT_MODEL_PROVIDER=off` 默认关闭；正式入口仅接受 `off/deepseek`，测试回复不能通过环境开关启用。真实适配器需要 `AGENT_MODEL_NAME`、`AGENT_MODEL_API_KEY`、`AGENT_PLATFORM_URL`，后者为固定可信平台地址；跨主机使用 HTTPS，HTTP 仅允许回环地址。双方共享 `TASK_ENGINE_TOKEN`，不少于 32 字符。
- 引擎 0.3.0 在既有能力契约上增加 `agent-verification/agent-live` 与 `agent-task`；运行信息分别标记 Harness 为 `verification/configured`。configured 只表示已配置，不表示完成云模型验收。未启用仍是原本地检索。
- 当前每项 Agent 任务只投影当次工作要求与本次工具历史，没有把整段历史会话自动送给模型；跨轮上下文、长期记忆和引擎自进化仍按后续切片实现。

## 模型适配

`DeepSeekModel` 是平台自有 `ModelPort` 的 HTTP 实现，不依赖供应商 SDK。依据官方 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)和[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)（2026-09-23 核对）。首次适配显式使用非流式、关闭 thinking；没有实现 reasoning 回放，因此意外返回推理内容时拒绝，不把不可用模式假装支持。

生产地址固定 `https://api.deepseek.com/chat/completions`，拒绝重定向、任意供应商 URL 和请求凭据回显。仅测试构造器允许回环传输夹具。适配用户/助手/工具消息、call ID、结束原因及 token 用量；任一次缺失用量，整项用量标为未知，不能按 0 收费。当前只持久化供应商报告的 token 数，不提供金额账单、扣费或企业额度。

单次模型请求覆盖响应头及正文的 12 秒期限，输入 256 KiB、响应 128 KiB；整体最多 4 次模型、4 次工具、25 秒。达到限制失败，不自动重试供应商调用。引擎内存保留 120 秒尝试去重；跨引擎重启依赖平台持久租约和不自动重发策略，不宣称端到端 exactly-once 调用。此为首轮可逆技术上限，需用真实任务验证后调整。

## 授权、取消和资料

1. 任务租约生成不可预测 UUID `attemptId`，有效 60 秒。该凭证不在公开任务响应、网页或模型提示词中出现；平台与引擎的请求通过服务密钥鉴别。
2. 引擎调用固定 `/internal/v1/agent-access/{task}/check` 与 `/search`，Bearer 为本次 attemptId。此接口不使用浏览器 Cookie/CSRF；服务端要求任务正在运行、凭证及租约有效，并从数据库读取真实企业、用户和空间。前端自报身份、任意回调 URL 不属于契约。
3. 每次模型和工具调用前复核权限，运行期间每 400 毫秒再检查；平台等候引擎时每 300 毫秒检查任务是否仍可执行。所有资料授予记入任务/尝试/片段关联表，最终返回的 sourceIds 必须与实际授予集合完全一致。
4. `search_sources` 限定当前会话的单一空间，即使本人还能访问其他空间也不能越界。每次最多 3 个片段、累计最多 10 个，保留原文件、版本和位置；检索工具明确告知这是已解析片段，不是完整原件。数值计算仅覆盖实际取得的片段，不能据此声称已汇总整份大表。
5. 取消先通过平台事务改变状态，旧凭证立即不能继续取资料或写回；HTTP 断连、授权检查拒绝和预算到期会沿 AbortSignal 传至模型请求及本地工具进程。平台重查权限后才提交成功，迟到结果不能覆盖取消状态。

撤权不可能收回已发送给外部供应商的数据；这些检查限制后续执行和交付，并非对每个网络字节承诺即时撤回。已有资料传输不在数据库事务中长期持锁，避免模型响应阻塞成员撤权。凭证只面向可信引擎服务，生产仍需网络隔离、密钥管理及容量防护。

## 工具产物与隔离

真实模型入口本切片只开放 `search_sources`。`run_javascript` 仅由测试目录中的构造器授予，且 `live` 类别配置沙箱会直接拒绝；生产代码执行要在云端隔离完成后单独启用。

本地验证把获准片段复制为 `<chunk-id>.txt`，沿用 macOS 独立沙箱，默认拒绝网络和其他任务数据；执行回执来自真实文件字节。平台校验每个产物的安全文件名、规范 Base64、SHA-256、来源授权和工具成功回执；单任务最多 8 个、合计 64 KiB。本切片以私有 bytea 保存这些小文件，后续大成果可替换存储适配器。

文本回复、来源关联、工具摘要、用量和产物一次事务写回。下载必须仍是会话本人且有企业/空间/来源权限；总台和同事没有旁路。返回 attachment、no-store 和摘要，网页再次核对字节数和哈希。产物只属于私人任务，没有自动发布到资料库、画报或共享空间。

沙箱仍只证明本机合成验证；总进程内存/总临时磁盘硬限额、Linux/容器运行时、正式联网和工具目录安装尚未完成，不能对客户开放任意代码。

## 协议、升级和接续

- 公共会话 OpenAPI 更新到 1.1.0，新增 Agent 模式、执行类别、回复及产物元信息；原 SOURCE_LOOKUP 保持 200 字/8 关键词限制。新旧网页需与平台一起部署，旧契约不理解新模式时应拒绝。
- 独立 [Agent 结果协议](../../contracts/engine-api/agent-results.schema.json) 保持引擎内部类型不泄漏，包含任务/尝试、结果、来源、回执和用量。回调契约及凭证生命周期见本文；平台数据库和用户权限不交给 Harness。
- V8 新增授权关联、产物及任务 Agent 字段；旧 V1—V7 不改。升级先迁移和平台，再启用匹配引擎模式；降级前关闭 Agent 提交并排空/取消任务，保留 V8 数据，不删除迁移。生产升级/回退演练尚未执行。
- 可独立替换 ModelPort、Harness 适配器、TaskSandbox 或平台产物存储；替换须重验 HTTP 契约、逐步授权、取消、来源集合和真实产物，不能只验证返回一段文字。

下一步仍在 M4-A1：可信 Skill/工具目录、公开搜索/阅读、新能力失败路径与云隔离。真实模型的供应商账号、发送资料范围和预算确定后，再验收理解质量、真实工具调用和用量；WeKnora 实机仍属于 M3-A1。当前未接画报主动分析或自进化算法。
