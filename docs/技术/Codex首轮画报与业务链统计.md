# Codex 首轮画报与业务链统计

2026-10-15，用户授权补齐首轮选题、分析和出卡，本地验证后上线，服务器模型接续维护；沿用既有权限范围。

## 执行路径

9POP 已治理完整投影 → Wiki 当前获权共享导出 → 固定跨表配方 → 平台版本化数据集与采集快照 → Codex 选题及分析 → 平台可信计算和画报校验 → 私人画报 → 同范围服务器模型增量维护。

`NINEPOP_CHAIN_EXPORT_ENABLED=true` 启用八项固定配方：订单/收款、会员/课程/产品、课时/课程、体验开课/转化、审批/动作、转店/结算事件、最新日课债/课程、退款/门店。配方只接受已经通过共享导出权限的来源，不向模型提供 SQL，不改变 54 张受限源表的访问范围。106 张源表接入不代表本轮所有表都参与画报。

跨表计算先将一对多子表归集，再与主表关联；金额按整数分计算，输出元，保留两位小数。孤立关键关联、重复主键、缺失金额等阻止本次导出；缺少或撤权的必需来源不产生对应派生数据。派生版本包含来源版本、权限版本、内容摘要与配方版本。各表读取时点独立，不承诺源库事务一致性。

订单收款只统计财务确认的登记金额，不直接等同净收入、银行到账或可分配资金。课程按会员当前门店看存量，不能用于重写历史销售归属。课债只取最新一日，按快照门店归属，不跨日累加。退款保留历史财务标记缺失，用户确认的旧系统退款不列为异常，也不补造现金和凭据。

## 首轮部署接口

宿主机 CLI：`java -jar api.jar --bootstrap-briefings`，无 HTTP 导入端点。

- `BRIEFING_BOOTSTRAP_FILE`：绝对路径、私有 JSON 清单，最大 256 KiB。
- `BRIEFING_BOOTSTRAP_RECEIPT`：绝对路径、新回执文件，不覆盖已有文件。
- `BRIEFING_BOOTSTRAP_PREVIEW`：默认 true，执行真实计算后回滚；false 才落库。
- 清单包含 `contractVersion: "1.0"`、UUID `requestId/tenantId/ownerId/workspaceId`、`maintain` 布尔值、1–20 个 `cards`。
- 每卡包含 `topic`、现有 `DatasetCalculationService.Request` 格式的 `calculation`，以及现有画报请求格式的 `content`。`content.businessType=DATA`，`calculationArtifactId=null`；服务端绑定本次真实计算产物。预览允许 content=null。

先预览，依据回执撰写选题和分析，再用相同固定源版本应用。服务端核验企业/空间/数据集读取权与当前快照，正常工具产物及画报校验不旁路。整批事务，任一卡失败整体回滚；同请求同内容幂等，变更内容拒绝。最后再次校验来源版本和权限。提交后回执文件写入失败时可按相同 requestId 重试，数据库已有回执不会重复出卡。

任务 `execution_class=external`、尝试 `EXTERNAL_DEPLOYMENT`、模型名 `codex-external`；没有伪造服务器调用次数或 token。客户端显示“Codex 首轮生成”。首轮不消耗服务器自动生成配额，正常服务端授权、历史、工具回执及产物仍保留。

## 服务器接续

`maintain=true` 保存已分析内容基线，启用该所有者/空间的策略，并将其维护范围限制为首轮数据集稳定 key。数据内容或口径变化才重新分析；仅新采集回执不触发重复生成。每批选择一项业务链，走现有模型、配额、可信计算、出卡及失败管理。此策略不自动发起无关资讯抓取。读取权限撤销依然由平台判断，范围记录不会授予内容权限。

仅对首轮卡片生成成功或已有相同内容的项建立基线；模型维护和首轮生成不是同一个任务，也不将外部分析记为服务器真实调用。回退时先暂停对应策略、撤下派生导出开关，再恢复准确备份的发布文件；保留来源、画报历史与新增数据库表，禁止直接回滚业务数据。
