## 1. 首版页面与范围

| 位置 | 最终职责与保留内容 | 合并或移出的内容 |
| --- | --- | --- |
| 主导航 | 会话、智能画报、资料库；普通进入默认画报，具体工作链接与中断位置优先 | 不新增任务中心、经验库或独立成果主入口 |
| 会话 | 提问、添加资料、处理任务、查看结果；资料、画报、成果、计划复用卡片交互 | 去掉重复上下文选择、同意图重复确认和无意义跳转 |
| 智能画报 | 资讯、数据、洞察、建议、成果；推荐、关注、日期、类型及空间筛选；详情反馈和发起会话 | 会话类型和“正在跟进”分组保持隐藏；任务完成不自动等于值得推荐 |
| 画报内待办 | 首期隐藏，后续完善后开放（DEC-121） | 保留底层事实与数据，不挂载待办列表，不占画报空间 |
| 资料库 | 个人与企业资料，上传、查找、阅读、属性、版本；个人文稿并入日常入口 | 后台对象不强行合表；不让用户在资料和文稿两个入口重复找文件 |
| 空间归属与共享 | 资料库中的个人/企业范围及共享空间；会话、画报沿用空间归属或筛选 | 取消独立空间首页与“工作与管理”弹窗；资料动态改为企业资料库/共享空间“资料操作”内按需查看 |
| 头像/个人设置 | 我的档案与偏好、账号信息、密码、接受邀请、退出 | 不重复摆企业选择器，不混入企业档案维护 |
| 顶部当前企业 | 企业名称菜单承接多企业切换及当前企业获权管理入口；平台管理仍限平台身份。单企业且无可用管理入口时仅显示名称 | 不因进入管理端而静默切换企业；不重复放企业选择器 |

工作空间组织部门、持续业务和项目，不成为每次提问的必选前置。个人工作与管理职责可以由同一账号承担，管理操作后能够返回原工作。

首版客户端不展示经验搜索、列表、阅读或经验专属来源/版本卡，不处理候选整理、编辑、核实、发布、停用和使用登记；会话命令、反馈后续动作和旧链接同样不能进入这些维护流程。正常纠正、资料引用、成果保存及评价保留。引擎在既有权限内检索、判断及采用经验的后台能力保留，不删服务和历史数据，不新增自动采集或发布授权。企业端经验维护另行讨论，见[管理任务书](三端管理与共用平台-开发任务书-V0.1.md)。

本轮不增加系统外业务推送、App 持续本地扫描、任意前端代码生成执行或独立自进化实验。Web 授权多文件/目录上传沿已确认资料范围实现；浏览器不能持续扫描时留待 App。自进化后接入的版本、观测及替换边界继续保留，基础使用不依赖它运行。

## 2. 可以复用什么，实际还缺什么

以下为源码与已有记录的能力核对，不代表当前验收实例已切换到这些版本。实现前逐项确认接口与数据状态，不以隐藏按钮、Demo 成功提示或模型自述替代真实能力。

| 能力 | 已有基础与主要定位 | 本次需补齐的差异 |
| --- | --- | --- |
| 登录与应用外壳 | `src/identity/` 已有三端登录、邀请、多企业、主导航；手机号切片有独立本地验证 | 精简重复入口、档案归位、完整返回上下文；手机号前后端及数据库兼容检查，真实短信仍待接入 |
| 会话与卡片 | `src/conversation/`、`src/components/DeckCard.tsx` 已接真实任务和来源阅读 | 跨入口统一层级/关闭/展开/全屏/草稿恢复；属性改为按需关联卡片；不能只对齐外观 |
| 资料与成果 | `src/material/`、`src/documents/` 已有原件、解析、目录、版本、文稿和共享副本 | 会话私有附件生命周期、统一查找和入口；文稿与资料的统一呈现；保存/共享少跳转 |
| 检索与工具 | API 会话、上下文及任务服务已有单空间、版本引用、受控工具和权限机制 | 区分工作归属与获准检索范围；支持当前企业获准资料补查和任务级“只用所选资料”，同步工具、缓存及撤权检查 |
| 画报与图表 | `src/briefing-live/` 已有任务/发布候选、反馈和布局；Demo 有 `BriefingBusinessChart` | 五类业务内容契约、服务端筛选分页、结构化图表与可追溯计算；不能把 Demo 图形视为真实经营数据已接通 |
| 反馈与待办 | `src/feedback/`、`src/attention/`、`src/forwarding/` 有真实服务基础 | 各来源反馈按钮能力对齐，补共享副本等对象的缺口；待办真实状态联动与返回恢复，不混入经验维护 |
| 计划与档案 | `src/plans/` 有每日/资料变化计划；`src/profile/` 有档案，任务服务有有限明确偏好处理 | 自然语言计划的真实保存/修改与统一卡片；长期/临时偏好判定、撤销及个人设置整合；现有有限入口不等于通用能力已完成 |

原件与格式处理按实际解析器、受控工具及 Harness 支持范围交付。已有验证专用能力不能直接假设普通用户已可使用；选择文件后必须说明准备/失败状态，不能把仅接收文件等同于模型已经读到内容。

## 3. 统一改造任务

各项按第 5 节依赖实现，现已统一交接；新增对象复用 B1 的卡片基础。已有能力的复用和本次增量分别记录。每项完成需有前端行为、真实接口回执与相应验收证据。

### CUI-01 入口、身份与返回

依据：DEC-103/106/117，POS-03、WS-02—WS-03。

- 前端：落实第 1 节导航；保留深链和中断位置优先；企业仅一处切换；带当前企业/空间/对象进入获权管理页面并返回原工作。手机和窄屏沿同一信息层级。
- 平台：复用身份与权限，必要时补准确定位所需的查询；返回仅传必要标识，不在 URL 放正文、草稿或凭据。切换企业/账号后重新核验目标，撤权目标给出可用去向，不显示旧缓存正文。
- 交付：入口映射、返回状态与失效处理；保留已有手机号加入和旧账号绑定语义。实际验收环境升级前核对前端、API、契约和迁移，不用合成短信代替真实手机号归属验证。

### CUI-02 共用卡片与跨页面上下文

依据：DEC-104/105/109/110/117，AI-01—AI-03、WS-06—WS-16。

- 前端：统一会话、资料、画报、成果的卡片层级和宽度、收起、全屏、关闭、滚动；资料正文与按需属性卡准确关联。关闭属性不关闭正文，多份资料之间不串属性；设置、来源和历史按需展示。
- 前后端：从画报详情或资料发起会话时携带确切内容/版本及获准依据，保留输入草稿；只打开或选取不提交任务，用户发送才执行。后台运行不锁住整套导航，提交未知时保护原请求并提供核对路径。
- 交付：共用组件及状态契约。浏览器刷新恢复工作位置，页面内刷新只更新数据；画报退出会话回原背景页，不另弹回已关闭的详情。

### CUI-03 会话附件与授权检索

依据：DEC-112，AI-01—AI-03、AI-06—AI-07、WS-06—WS-16。

- 前端：一个“添加资料”入口承接本地上传、已有资料选择与拖入；准备状态、失败重试/移除就地显示；关闭阅读卡不移除待发送引用。既有资料引用准确版本，不重复上传。
- 平台/引擎：本地附件随当前企业、本人私有会话保留，默认不入普通资料库；可从卡片保存，默认个人空间。模型优先当前问题、上下文及明确引用，必要时补查当前企业本人有权读取且允许 AI 使用的个人/共享资料。
- 交付：附件归属及生命周期、任务检索范围、引用、缓存、重试幂等。显式“只用所选资料”落实任务和工具层；其他私人会话、其他会话未入库附件、他人私有数据和其他企业不能进入默认范围。旧计划后台授权和公开联网范围不随此扩大。

### CUI-04 资料库与成果闭环

依据：DEC-107/110，AI-11—AI-13、WS-06—WS-16。

- 前端：个人/企业资料统一日常入口，合并名称和正文查找；默认搜索当前目录及子目录，上层入口可查个人全部或企业内获准范围。成果留在原会话，保存/下载按需出现；个人文稿沿资料库查看，文件属性使用 CUI-02。
- 平台：统一查询范围、排序、去重、分页与资料/文稿标识，不靠前端已加载的一页过滤。保存有准确任务/版本依据；共享指定版本形成独立企业副本，不夹带私人会话或无权来源。
- 交付：上传/批量状态、查找、固定版本阅读、保存、导出、共享及更新全链路。个人内容和企业副本各自显式更新，失败可恢复，同一请求重试不重复保存或发布；查看、读取、维护和共享分别授权。

### CUI-05 五类画报与经营图表

依据：DEC-108/109/119，总任务书 15.2，AI-11—AI-13、DASH-01—DASH-04。主动生成与增量展示按本文第 9 节最新决定执行。

- 前端：沿固定 Demo 恢复五类内容、筛选、详情、推荐及关注布局；围绕完整主题成卡，有独立价值才拆分。图表和文字共用“详情 → 发起会话 → 发送”路径，不新增必经配置。
- 平台/引擎：候选有明确业务类型、内容、来源范围、生成时间、版本及可见性；先服务端权限与类型过滤再分页。图表使用结构化可验证数据，记录指标定义、单位、周期、口径和数据截至时间；缺失不记零，更新失败不假装最新。
- 交付：五类均有真实接口承载的明确合成样例，再用获准资料验证实际内容质量。按 DEC-120，有效新分析新增独立卡片，原卡保留当时内容与依据，同主题用关联关系衔接；沿用现有数字、趋势、对比、构成等组件，合适时用表格/文字。历史无类型内容不凭关键词硬猜，迁移规则在本批记录，不丢原会话结果。

### CUI-06 反馈、关注、转发与待办

依据：DEC-105/108/116/117，AI-11—AI-13、DASH-01—DASH-04。

- 前端：有用、没用及原因、关注、站内转发沿 Demo 的详情按钮和卡片交互，以真实对象能力提供；本人任务与企业发布内容都核对后台缺口，不能仅补图标。推荐自动排布，关注支持已有布局保存/撤销/恢复规则；已读与刷新沿既定规则。
- 平台：反馈记录、当前内容纠正、偏好和持续委托分开处理；关注不自动建计划，转发仍按当前权限，共享副本关注等缺失契约需补齐。保留会话质量反馈，不由好评自动提炼或发布经验。
- 待办：最多两排/展开/收起，异常可就地重试；卡片说明事项、原因、下一步并到原对象。原任务、计划与管理页面共用实际状态，处理后返回保留筛选/位置并更新相关状态；阅读不等于完成，正常等待不形成待办，无经验维护入口。

### CUI-07 会话管理持续计划

依据：DEC-113，AI-01—AI-03、AI-06—AI-07、DASH-01—DASH-04。

- 前端：会话建立/调整，计划卡显示工作内容、状态、下次时间或触发条件、最近结果；配置/历史按需查看，“我的计划”为次级集中入口。
- 平台/引擎：明确条件且已有授权覆盖时直接保存并返回真实回执；缺少关键条件或 AI 主动提议时才补充或确认。版本检查、幂等请求、权限、资料范围、接收者、期限和资源条件须落到实际计划，不能只生成一段“已安排”。
- 交付：创建、调整、暂停/恢复、取消本次执行及关闭提醒含义分明；解释对在途工作的影响。正常等待不占待办，有价值成果进入画报，首版只在系统内查看。先沿现有每日/资料变化能力接入，其他周期按第 6 节处理。

### CUI-08 档案与偏好

依据：DEC-114，MAINT-09、DEC-084/089。

- 前端：个人设置中查看当前企业“我的档案与偏好”；默认有效内容与适用场景，修改/不再使用就地可达，来源/历史用关联卡片。
- 平台/引擎：日常会话明确的低风险长期偏好真实保存、轻提示并可撤销；临时要求只影响本次，重要推断先核实，一次评价不直接变永久偏好。撤销/修改按当前版本处理，来源权限持续有效。
- 交付：语言表达、实际写入、查看、后续任务应用及撤销闭环。企业/空间档案沿原获权入口；个人偏好不变企业默认、权限或计划，管理员身份不授予他人私有档案访问权。

### CUI-09 首版经验界面退出

依据：DEC-116。

- 前端：移除导航、经验专属卡片和搜索/维护界面；旧链接说明未开放并回可用入口；反馈后续动作、会话引导和待办不再提供经验维护。
- 平台/引擎：核对客户端可触发的动作，不能只隐藏导航而留下会话维护旁路。复用既有服务、权限及数据；后台经验检索/适用性判断/采用仍可工作，不因隐藏界面新增来源提炼或发布权限。
- 交付：列明所有受影响入口并验证。企业管理端既有页面不因本任务全盘重做，后续设计与当前能力明确区分。

## 4. 前后端先对齐的约定

这些约定在所属批次落实，不要求开发前一次冻结所有字段，也不暴露成用户填写的技术表单。

| 约定 | 必须保证的行为 | 负责批次 |
| --- | --- | --- |
| 对象与版本 | 会话附件、资料、文稿、共享副本、画报和计划保持可定位身份；界面入口合并不混淆内容所有者、确切版本或更新规则 | B1 定映射，B2/B3/B4 实现各对象 |
| 读取与发布 | 工作归属、AI 读取范围、内容可见性、维护权、发布权分别执行；任务与工具重新核验撤权，引用及缓存不绕过权限 | B2 起逐项验收 |
| 内容与图表 | 类型、来源、指标定义、数据时间与生成时间明确；卡片/会话承接同一内容版本，历史分析不被新数据无声改写 | B3/B4 |

## 9. 智能画报的系统主动生成与增量交付（DEC-120）

2026-10-01。沿 CUI-05、AI-11—AI-13、DASH-01—DASH-04 补充。本节区分用户已经确定的产品方向与待细化的默认策略；最初用于记录需求及验收；后续实现及原实例升级状态以[实施记录](../交接/智能画报主动生成实施记录-2026-10-01.md)为准。已形成[智能画报主动生成开发任务书](智能画报主动生成-开发任务书-V0.1.md)，以 BG-01—BG-10 拆分实施任务，衔接 B4/B6，细化依赖、状态、旧卡兼容和验收证据；当前实现及确定性检查已完成，原实例有一次真实主模型新增洞察卡证据；自动首次成功、真实资讯周期和五类内容质量仍待验收。

### 9.1 已确定方向与现状

用户明确：不同卡片类型应采用适合的触发方式；智能画报生成是系统自带能力，不以用户逐个建立定时任务为前提；系统首次初始化应自动生成；瀑布流底部增加“生成更多”；有效新生成追加卡片，不重跑或替换全部旧卡片。

首次核查时实例为引擎 0.13.1，仅 DATA 有完整真实模型证据。随后客户端六批任务已提交五类契约/生成/筛选基础并完成合成回归，报告原实例升级至引擎 0.14.0、迁移 V46；五类真实内容质量与本节新增主动生成能力仍须分别验收。实施接续其最终主线版本，不重复开发已有基础。既定五类是资讯、数据、洞察、建议、成果；用户所说“分析类”先按跨数据/洞察等内容的分析能力理解，是否新增第六种类型尚无明确决定。

系统主动策略与 DEC-113 的个人持续计划并存：默认画报能力由系统策略驱动；个人计划用于额外定制主题、时间和交付要求。底层可以复用调度和任务记录，但不得把系统自动生成记成用户明确创建的私人委托。后台任务也不要求用户先打开会话或保持网页在线。

### 9.3 首次自动生成、生成更多与刷新

- **首次自动生成（已确定）**：系统在初始化阶段主动准备首批画报，无需用户先提问或创建个人计划。建议启动条件为企业/用户必要初始化完成、后台使用范围有效、相应资料或资讯来源已就绪；缺数据时等待依赖或交付实际可得类型，不伪造经营卡。重复登录、刷新、进程重启不得重复执行同一初始化批次。首次批次按企业、用户及可见范围隔离，具体首次标识/完成条件在实现时收口。
- **生成更多（已确定）**：瀑布流底部发起一批新的分析与内容生成，直接在画报页显示真实进度和完成后的新增卡片，不强制先开会话或配置计划。与分页读取既有卡片分开；仅取出已生成但未展示的内容不能称为新生成。建议结合当前类型/空间筛选、近期已有内容和有效偏好选题，范围仍由服务端执行。重复点击或网络重试合并到同一批次，失败保留原卡。无新内容或必要资料不足时如实结束，不靠重写旧结论凑数。
- **页面刷新（沿用原约定）**：同步已有结果和状态，不重跑全部内容、不删除旧卡、不自动等于一次“生成更多”。
- 系统定时/事件产生的画报与首次批次、“生成更多”共用生成、校验和保存链路，保留实际触发原因、数据版本及生成时间。

### 9.4 追加卡片与去重

本节替代 CUI-05、AT-07 旧有“数据卡用稳定身份更新”的生成交付解释：每次有效的新分析追加独立内容卡，旧卡继续代表当时的结果；同一主题、同一期间的新版本可关联“后续分析/数据更新”，不静默覆盖旧正文与数字。内部主题身份可以稳定，但不能据此覆盖原阅读快照。错误更正、来源失效及权限变化沿原有生命周期处理，保留卡片不代表继续显示失去读取权限的内容。

新增不等于无限重复：同一数据、同一主题、同一结论的重复事件与任务重试应复用既有交付；只有新的依据、期间、重要结论或有独立价值的分析角度才新增。上传批次需合并并等待必要资料就绪；分析期间的新事件不永久丢弃。系统自身的生成动作带因果关联，避免反复触发自身。

展示建议：用户点击“生成更多”后将新批次接在瀑布流后方，保留滚动位置和旧卡状态；后台新增可先提示“有新内容”，由用户在合适时机展开。关注布局和已读记录不因生成新批次被重置。这些位置、提示文案及默认批次大小属于待细化的交互选择。

系统提供可用的默认策略，用户个人计划作为补充，不把完整高级配置作为首次看到画报的前置步骤。默认策略仍须明确来源范围、运行身份、接收范围、调用额度及停用方式，并复用现有企业隔离和权限复核；可读取某空间不自动扩大为长期后台分析任何私人资料。首版站内交付继续生效，不由本次讨论新增系统外发送。

尚待收口：资讯来源与主题获取方式；首次必要资料和完成条件；各类型默认频率/事件合并窗口；每批数量和资源上限；重要变化/重复内容判定；后台新内容的插入位置。定时和生成更多均须按实际数据与真实完成状态反馈，不能用模型成功自述代替交付记录。

- 手动生成和页面打开期间的自动生成都呈现占位；轮询保留已展示内容。刷新得到同一新卡时不重复显示。
- 等待、失败、取消、无新内容、请求结果未知、已生成但读取失败都按真实状态呈现；只有排队/运行显示流光，减少动态效果停用动画。读取重试和刷新不得新增生成请求。
- 首期不展示自动生成开关；新空间默认开启，V48 恢复所有已有暂停策略，保留权限 epoch、来源指纹、历史批次与用量边界。
- 验证依据见 [实施记录](../交接/画报生成入口卡片化-2026-10-02.md)。
