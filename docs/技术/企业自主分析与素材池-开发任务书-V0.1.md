## 1. 目标与已确认边界

让梦核在企业授予的范围内自主发现值得分析的问题，形成有证据、可更新、可复用的素材，再按受众权限与工作职责生成画报。用户主动提出问题时，也能先确定权限，复用有效素材或补充分析后交付。

1. **主题由引擎模型自行提炼。** 企业目标、来源目录、数据变化、未解决问题和反馈提供上下文，不把主题固定为人工预设菜单。模型可以发现、延续、合并、延后或结束主题。
2. **企业统一分析不意味着全企业无限权限。** 平台提供有明确授权范围的执行身份，模型不能自行获取更多空间、私人会话或跨企业数据。
3. **素材按事实、计算结果、分析判断、行动建议分别管理。** 每份素材保留证据版本、业务口径、依赖、时效和访问依据；不是把完整企业报告切成几段缓存。
4. **分析权限、发布权限、表达适配分别判定。** 可以分析不等于可以分发；改写、脱敏、删掉金额或姓名不自动使结论获得更低权限。
5. **主动与按需两条路径共用素材能力。** 一次分析可以服务多个获准受众；用户请求不能借用后台身份绕过自身权限。
6. **输出必须再次检查时效与权限。** 模型选材前、成果提交或交付时、后续读取时均执行相应检查，不能只在素材入库时检查一次。
7. **首期真实验证维持负责人范围。** 9POP 新增财务与经营投影仍仅企业负责人可读，后续分发权限单独授权。开发本身不扩大现有空间成员或发布范围。

不以素材数量、主题数量或每日卡片数量衡量成功。允许分析后没有值得发布的新内容；用户已明确要求的任务仍需反馈结果、缺口或失败。

## 3. 两条运行路径

### 3.1 企业主动分析

获准来源发生相关变化或到达复核时点 → 平台确认企业分析身份和预算 → 模型结合目标、变化与历史主题决定分析价值 → 读取获准证据并执行计算 → 校验并保存版本化素材 → 根据发布依据筛选受众可用素材 → 生成适合岗位的内容 → 提交及交付复核 → 保存实际结果与反馈。

主题发现本身也是受预算约束的模型任务。平台先合并事件、排除无实质变化的重复采集，再让模型判断值得分析什么；不是每个来源、每次采集都调用一次模型。对已承诺的定期任务保留其交付要求。

### 3.2 用户主动生成

请求与当前身份 → 确认目的、期间和可用范围 → 检索当前可用素材 → 检查证据、时效与发布依据 → 足够则复用，不足则在请求授权范围内补算或查询 → 生成适配内容 → 提交及读取复核。

用户可以使用明确发布给自己的结论，即使不能读取该结论的私人原件；但不能访问内部证据链。对其不可见的企业分析，检索结果、数量、标题、推荐原因也不能泄露。没有可用素材时，回到获准原始来源分析，不默认提升身份。

## 4. 主题由模型维护，平台控制执行

主题输入包括企业背景与有效目标、来源能力与覆盖范围、变化摘要、尚未解决的问题、既有素材、用户反馈及明确请求。私人对话和反馈只在有明确使用依据时进入企业分析上下文。

每次提出主题应包含：要回答的问题、发现依据、业务价值、需要的数据与期间、证据缺口、与已有主题的关系、下一步及结束或复核条件。模型排序参考重要性、证据充分度、新颖程度、时效和预计成本，不强制形成固定评分公式。

建议主题状态：候选、跟踪中、等待依据、已解决、已合并、已停止。一次执行的排队、运行、失败等状态沿用任务系统，不能把任务失败直接记为业务问题解决。合并保留旧主题指向与历史；旧问题再次出现可以重开并记录原因。

平台检查实际数据与工具权限、次数/时间/费用限制及运行条件。模型可提出增加来源或扩大范围的需求，不能自行生效。证据不足时保留缺口、降低结论强度或不生成结论，禁止为了凑卡片编造原因。

测试可以设置“收入增加但可用资金下降”等合成案例，但运行代码不写死这些主题。素材主题与画报标题不是同一个对象；一个主题可以生成多份素材、多种输出，也可以暂不发布。

## 5. 素材形式与存储

### 5.1 核心对象

| 对象 | 最少信息与职责 |
| --- | --- |
| 主题 | 企业、问题、目标依据、业务范围、生命周期、关联主题、复核条件 |
| 分析运行 | 主题、触发原因、执行身份与授权版本、任务/尝试、输入版本、资源消耗、真实结果 |
| 素材及不可变版本 | 稳定素材身份、版本号、类型、正文/结构化结果、创建任务、校验结果、适用条件、限制 |
| 依赖关系 | 原件/数据集及版本、上游素材版本、查询范围、筛选口径、计算方法版本、规则/目标版本 |
| 有效性记录 | 数据覆盖截止、业务期间、生成时间、最近复核时间、失效原因、当前适用状态 |
| 发布依据 | 被授权的准确内容版本、范围、受众、责任身份、授权来源、有效期及撤回状态 |
| 输出与交付记录 | 请求/受众、采用的素材及发布版本、表达版本、权限复核依据、交付结果、去重键 |

事实记录原始证据及其含义；计算结果记录输入、单位、过滤条件和确定性计算回执；分析判断区分证据与推断；行动建议还需记录适用职责、目标及行动是否已执行。计算正确不等于因果判断已经证实。

数据库保存版本、状态、权限依据及依赖关系，正文和附件使用现有版本化成果存储。搜索或向量索引仅用于候选检索，不作为权限、最新版本或有效性的最终依据；首期不以引入向量库为前提。

### 5.2 版本与状态

正文、证据和计算口径提交后不可原地覆盖；更正生成新版本。当前版本指针和有效性状态由平台更新，保留变更记录。旧画报始终引用当时的准确版本，不能悄悄换成新数据证明旧结论。

素材可用性区分待校验、可用、需复核、已替代、已撤回；旧版本可被保留用于审计，但保存历史不意味着用户永久拥有读取权。权限状态、业务时效与内容质量分别记录，避免一个“失效”字段掩盖原因。

相同内容的新采集批次可以增加复核观察记录，证明检查到了新的截止时点，不必重写素材正文或重复计算。观察记录关联实际检查的快照、范围与方法，不能仅更新时间冒充完成复核。

## 6. 更新、时效与依赖失效

必须分别保存业务期间、来源覆盖截止、分析生成时间和最近复核时间。页面显示的“今天生成”不能替代数据时效证明。

| 变化 | 处理原则 |
| --- | --- |
| 采集生成新快照但相关内容未变 | 记录复核，复用仍有效的计算与素材，不自动产生新卡片 |
| 相关记录新增、修改、删除或状态改变 | 按依赖范围标记受影响素材，重算必要部分并生成新版本 |
| 历史期间更正 | 重新计算受影响期间及下游，不因期间已结束而永远免检 |
| 口径、规则、企业目标或职责变化 | 重新判断计算、推断及建议哪些仍适用；建议可能先于事实失效 |
| 来源撤回、访问撤销或企业停用 | 及时阻断相应来源绑定内容的读取与在途交付，不等下次定时任务 |
| 明确独立发布副本的原作者或私人来源撤权 | 保留既有独立发布语义；按副本自身授权、撤回和企业状态判断访问 |
| 数据不完整、采集失败或覆盖未知 | 记录缺口，不将缺失当零；按目的决定等待、部分交付或明确无法判断 |

依赖不能只记已读取的行 ID，还需覆盖查询条件、门店/人员范围、期间和聚合口径，才能识别后来新增的相关记录。实现内容指纹时规范排序、字段语义及删除标识；权限变化独立触发检查，不能被“内容哈希相同”跳过。

当前资金、审批和待执行建议优先检查最新可用数据；期间趋势按期间与采集完整性检查；历史结论可以复用但受更正影响。具体有效期按业务来源与用途配置，不能统一套用一个固定天数。

输出处理过期素材时可以刷新、选取有效部分、明确回答历史情况或反馈缺乏可靠依据。只有依赖独立且重新验证的部分才能单独使用；删除不可见段落不能自动使剩余推断成立。

## 7. 权限与发布契约

### 7.1 分析身份

企业分析使用平台授予的企业内作用域和工具范围，不使用拥有所有业务数据库权限的默认超级身份。身份与授权依据写入运行记录。引擎通过受控接口读取，不能绕过平台直连业务数据库。

个人请求沿用个人当前权限；企业管理员或平台管理员身份不自动获得所有私人内容。租户、空间、对象和操作权限在服务端与工具层执行。

### 7.2 两类可用内容

- **来源绑定素材：** 访问者具有当前必要来源及空间权限，才可读取或生成视图。涉及多项必要依赖时不能采用“任一来源可见就全部可见”。
- **明确发布的独立内容：** 准确版本经过有效发布规则授权后，目标受众可按该发布对象权限读取。原件、内部来源名称/ID、工具日志和私密附件不随之开放。

保持输出任务书及 DEC-066 的独立企业副本语义：原作者离职或原私人来源撤权，不自动撤回已合法形成的独立副本；副本自身撤回、读者撤权及企业停用仍生效。内容后来被纠错时保留历史，但不得继续作为当前有效建议推荐。

发布可以由明确且预先授权的规则执行，不要求每一项都人工批准。规则必须限定内容类型与范围、受众、适用条件、责任和有效期；模型建议不能充当授权。首期只实现规则能力和合成数据验证，不创建面向普通员工的真实财务发布规则。

### 7.3 输出检查与缓存

1. 选材前由平台裁剪候选；受众表达模型只接收该受众获准的内容，不能先读完整高权限素材再要求删减。
2. 提交或交付前重新核对当前权限、来源绑定或独立发布依据、素材版本与有效性；变化则拒绝提交或重新选材。
3. 后续列表、搜索、正文、附件、下载与再次发送继续检查当前规则。数量统计和分页前完成权限过滤。

采用版本/授权修订号等服务端并发防护，并在提交事务或等效一致性边界复核，覆盖读取到交付之间的撤权和素材更新。缓存键包含企业、内容版本及实际授权范围；不能只按“店长”等角色名称共享，命中后仍需检查撤销状态。

权限覆盖标题、摘要、图表、建议、来源链接、附件、检索结果、日志和动态。对用户展示其可见的依据，内部审计证据另行受控。

## 8. 调度、成本和失败恢复

复用现有事件与任务调度，补充内容变化合并、检查水位、主题去重、周期复核与漏事件补扫。相同主题/输入/方法的并发运行使用稳定去重依据；重试可以保留新的执行尝试，不能重复入库或重复交付。分析成功但交付失败时重试交付，不无条件重跑分析。

分析费用与画报交付额度分别统计：无新卡片仍可能消耗模型费用；复用素材也可能需要表达调用。新增企业分析预算不能继承“每用户每天卡片数”作为唯一限制。达到预算、失败或缺少来源时记录真实原因，采用有限重试与退避，避免持续空转。

预算、并发、事件合并窗口和时效阈值先采用可配置、保守且默认关闭新自动链路的实现。实期开启前明确生效配置，不在本文擅自确定新的收费或无限持续运行承诺。保留现有生成链路及额度行为；如调整日界线，单独验证旧新周期衔接，避免重复扣额或额外放量。

任务中断后按持久任务与素材记录恢复；不承诺任意模型进程断点续跑。只将已校验并成功提交的版本标为可用，半成品不得因恢复而被检索输出。

## 9. 交互与可观测性

复用现有画报、任务与运行观测入口，先补必要信息：实际数据期间/截止、素材复用或更新状态、可见依据、无法判断的原因，以及负责人可见的主题状态和处理结果。无需让普通用户管理素材库或逐个审核主题。

管理观测记录来源变化次数、主题合并/延后原因、分析与表达调用成本、有效复用次数、重复计算量、失效到停止交付的延迟、生成及交付失败。指标可按授权范围汇总，不暴露其他用户的私人任务正文。

业务分析素材与经验库分别管理：前者有企业业务证据和时效，后者沉淀可复用方法。主题正常更新不属于独立自进化，也不自动将企业经营信息写入通用经验。

## 10. 顺序实施与阶段交付

仅在当前目录 `main` 顺序实施，不新建开发 worktree、不并行改造其他页面。

| 阶段 | 开发范围 | 进入下一阶段的证据 |
| --- | --- | --- |
| A：契约与安全底座 | 核对基线；素材/依赖/观察/授权模型与迁移；执行身份；版本写入与读取接口 | 合成数据证明企业隔离、不可变版本、来源绑定与独立发布边界 |
| B：变化识别与自主主题 | 内容指纹、范围依赖、事件合并、水位；模型主题契约、合并与生命周期 | 无变化不重复计算；新增行可失效；模型能提出未预设主题并正确延后缺证主题 |
| C：分析与素材维护 | 复用现有计算工具、证据校验、四类素材、选择性重算与纠错 | 确定性金额/状态口径可复算；更正形成新版本；旧输出可追溯 |
| D：统一画报选材与输出 | 手动/主动路径接入；受众准入、表达、提交复核、额度分离与交付去重 | 两路径复用同一素材；在途撤权阻断；重试不重复出卡 |
| E：多受众验证与负责人试运行 | 合成负责人/店长/员工差异；必要界面与观测；9POP 负责人真实数据验收 | 合成跨角色无泄露；真实分析注明覆盖与限制；成本和结果有回执 |

每阶段更新对应需求依据、接口、迁移说明和验证记录；架构调整记入开发决策记录。A—D 可以在既有授权内推进开发；新链路真实自动运行的预算和开启范围须在上线记录中明确。真实非负责人财务分发继续等待后续授权，不阻塞本次框架实现。

## 12. 迁移、上线与回退

采用兼容性迁移和独立功能开关。旧画报继续按既有对象规则读取，不自动补成“已校验素材”；如需导入历史成果，另行校验证据及权限并记录导入来源。

先完成合成验证，再按负责人范围进行受控真实验证，最后开启已配置的自动策略。数据采集开关、企业分析开关和画报交付开关分别控制；本任务书不改变已部署采集计划，也不启动付费模型或重新生成今天的画报。

回退时关闭新分析/选材入口，停止未完成新任务或阻止其交付，恢复旧画报路径；保留已发生的成本、任务和版本记录。撤回不应分发的内容使用对象撤回机制，不通过整库恢复覆盖期间新业务记录。

上线证据至少包括准确代码版本、迁移结果、生效范围与预算、真实模型任务及计算回执、权限校验、可用画报和回退办法。实现完成、部署完成、真实模型验证与客户验收分别报告。
