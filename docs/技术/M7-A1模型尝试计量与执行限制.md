# M7-A1 模型尝试计量与执行限制

2026-09-24，M7-A1 第七切片，DEC-078。沿用 POS-03/POS-06 和运行概览权限边界。本批是运行元数据计量，不是计费系统；全部验证使用合成数据与本地模型 HTTP 响应，费用上限仍为 0。

## 记录与口径

V15 新增 `agent_attempt_usage`、`agent_model_requests`。平台认领每次 Agent 尝试时保存独立记录；失败、取消、租约到期中断、成功均保留原尝试。显式重试创建新尝试，不重置旧记录。认领和状态变化与业务任务在同一事务中提交。

模型调用前，引擎先向平台登记请求，再调用供应商。登记成功但响应丢失、网络断开或进程崩溃时，不能确定供应商是否收到请求，因此页面称“登记请求”，不称供应商调用成功。未收到回执保持 PENDING；已收到但供应商未提供有效 Token 时用量为 null。已知 0 与未知严格区分；不根据字符数或模型自述估算。

适配器从有界 JSON 响应提取有效用量，即使回答结构不合法，仍能上报该次已知消耗。HTTP 错误、超时、过大/无效 JSON 等无法可靠取得用量时记未知；不自动重新发送模型请求。不完整累计值保持 null，单次已知用量仍各自保留。

两管理端共用 Operations 1.1.0 新增的 `attemptUsage`。按**尝试开始时间**落入 `[from, checkedAt)` 的记录计算，与现有“任务创建时间”统计分开。显示尝试状态、登记请求数、Token 上报覆盖率、未收到回执及未计量尝试；成功任务旧口径放入折叠区，不与新口径相加。仅统计启用 V15 后新认领的尝试，既往尝试不回填。旧引擎未启用新回调时明确计为未计量，不伪造零消耗。

## 执行及回调边界

引擎 0.11.0 保持 Agent 1.4、来源 1.0、Runtime 1.0；平台回调升级为 1.4，新用量协议为 [Model Usage 1.0](../../contracts/engine-api/model-usage.schema.json)。三个内部 POST 路径位于 `/internal/v1/agent-access/{task}/model-usage/`：

| 操作 | 权限与行为 |
| --- | --- |
| `open` | 当前有效尝试、企业/账号/资料授权检查后开启计量，返回固定策略。重复开启不能重置预算 |
| `start` | 当前有效尝试再次检查授权；串行登记 1—8 号请求，前次 PENDING 时不能继续；重复序号返回冲突，不重新授权调用 |
| `finish` | 只补写该尝试已登记请求的固定结果枚举和 Token，不能读取资料或发起任务；原尝试令牌有效补报窗为认领后 120 秒。取消、重试、撤权不丢弃已产生的消耗。完全相同的重复回执幂等，冲突拒绝，等待行锁后重查有效期 |

令牌仍是平台生成的随机尝试能力，不是员工会话或模型生成内容。补报接口不返回原回执、任务资料或账号信息；旧令牌不能给新尝试记账，也不能新增请求。所有响应 no-store。尝试、企业、空间归属来自业务表，不接受模型指定。平台成功落库时再次核对新回调登记数和 Token 与最终结果，拒绝不一致回执。

技术上限沿用每次尝试最多 8 次模型请求、8 次工具调用、Harness 25 秒；平台和引擎同时限制新回调的请求数，每次最多申请 2,048 个输出 Token。并发登记受数据库事务串行控制；平台原有 Agent 租约仍为 60 秒。超时取消后，用量补报使用独立的 1.5 秒有界请求，不恢复任务。以上是执行限制和请求参数，不保证供应商实际收费上限；不新增企业商业额度、价格、扣费、自动收费重试或付费回退。

## 升级、回退与数据保留

先升级平台到 V15，再切换引擎。新引擎缺少计量握手时在模型调用前失败；旧平台拒绝未知回调版本。新平台同时接受既有 1.3 和新增 1.4 回调声明，因此可以回退引擎；回退后的尝试明确未计量。0.9.0 的过渡接入仍需显式开关，不扩大版本猜测。实际演练结果见[验证记录](../交接/M7-A1模型尝试计量验证-2026-09-24.md)。

V15 为增量表迁移，不删除 V14 内容。切换前应排空任务；已经运行但没有尝试记录的旧任务不能凭空补出账本。新备份工具要求 V15，并将新增表纳入全表指纹及转储；旧 V14 备份沿其原代码版本还原后再升级，不修改已有备份。保留/删除周期没有新增业务决定。

## 隐私和未验事项

总台仍只看授权的汇总元数据，无员工、任务、会话、空间编号、提示词、回复、文件名、模型自定义名称、供应商原始错误或客户内容入口。企业管理员只能看本企业汇总；同一 SQL 快照、3 秒查询上限、授权前后复核及前端切换范围清屏继续有效。

真实百炼用量及供应商对账、生产容量、货币费用封顶、长期历史错误分析、资料保留政策和真机体验继续待验。本次不调用云模型、部署或接入客户资料。
