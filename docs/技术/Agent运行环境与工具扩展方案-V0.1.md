# Agent 运行环境与工具扩展方案 V0.1

依据：[需求基线](../产品/产品需求基线-V0.1.md)、[整体开发框架](整体开发框架与待办-V0.1.md)、[开发决策记录](开发决策记录.md) DEC-040。本文区分用户已确认方向、实施建议与后续细节，未建立运行环境或接入真实模型。

## 1. 本轮已确认

- 默认覆盖 PDF（含扫描件）、Word、Excel/CSV、Markdown/TXT、PNG/JPG 图片文字。这是基础能力及验证范围，不是所有任务的格式上限；具体扩展名、文件复杂度及质量还需样例验证。
- 遇到默认范围以外的文件，Agent 应寻找适用 Skill 或工具，尝试完成任务。用户随后选择两种自主方式组合：可信目录内自动安装使用；公开网络候选自动做隔离试验，通过检查后用于当前任务。具体执行环境与验证机制需工程验证，不等于允许在业务主机任意安装、向任意外部服务上传企业资料或保证处理成功。
- 网页能力首期支持公开搜索与阅读，业务系统通过授权接口接入；登录后网页点击、填表和下载自动化不纳入当前确认范围。
- Excel/CSV 的处理深度按用户目标、模型和工具实际能力决定，不预先固定为只读、计算、修改等档位。计算结果、公式与结构仍须根据任务验证，不能以模型声称完成为准。
- 首期支持网页编辑系统文稿；上传的原 Office 文件采用下载修改后上传新版本的流程。完整 Office 网页编辑器及多人同步编辑尚未确认。Agent 能否处理文件副本与是否内嵌 Office 编辑器是不同问题。
- 继续沿用 Spring Boot 平台、独立梦核引擎、React，以及云端为主、共用服务、企业隔离的决定。

## 2. 能力模型建议

| 层次 | 作用 | 交付口径 |
| --- | --- | --- |
| 默认能力 | 常用文件读取、OCR、检索、计算和成果生成 | 以已验证样例及已知限制说明支持范围，不仅检查扩展名 |
| 按需扩展 | 查找技能、组合工具、必要时编写脚本或转换格式 | 可以尝试；记录来源、版本、过程、失败原因与验证结果 |
| 可复用能力 | 将有效方法、依赖配置及测试样例保存 | 候选保存、个人/企业启用、平台公共发布分开；一次成功不自动发布给所有企业 |

Skill 负责方法、脚本与参考材料的组织；工具负责实际动作；运行环境提供依赖、文件与执行资源；业务平台决定实际权限。技能文本不能自行扩大工具授权或把文档中的指令提升为平台规则。

## 3. 运行环境建议

| 部分 | 责任 |
| --- | --- |
| Spring Boot 业务平台 | 身份、企业/空间权限、原件及版本、任务状态、结果入库、共享、用量 |
| 梦核引擎 | 任务理解、上下文与方法选择、主动判断及反馈；算法保持独立升级 |
| Harness 适配运行层 | 驱动模型与工具循环，动态获得获准能力；不将私有插件结构泄露为公共业务契约 |
| 工具与技能目录 | 保存技能来源、固定版本、依赖、所需权限、适用范围与验证状态；按企业和用户过滤可用项 |
| 独立任务执行环境 | 建议提供 Python、Node.js、文件处理及受限命令执行，按需配置网络/浏览器；与业务服务和数据库执行环境分离 |

运行进程、临时文件与代码按任务隔离；会话记录、方法和正式成果持久保存在平台。按需创建执行环境、结束后回收，并不等于丢弃会话上下文。续做任务根据授权文件版本、过程记录和必要检查点恢复，恢复后重新核验权限。

任务只取得本次获准文件的副本或受限访问句柄，写入产物区；不能把整个企业资料库或服务器目录暴露给脚本。正式资料更新经平台版本接口完成，旧版本、确认版本和引用关系沿用 WS-08、WS-14。

进程隔离、文件系统、网络出口、资源额度由执行基础设施约束。具体选择容器强化隔离、独立虚拟机或其他沙箱后端需原型验证，不把普通容器或 Harness 自带开关等同于已完成多租户隔离。运行凭据由工具网关持有或提供短期、最小范围授权，不将平台主密钥放入任意代码环境。

## 4. 陌生格式的一次执行流程

1. 保存原件并识别文件特征、版本、任务目标；明确区分已保存、待解析、解析成功、部分解析及无法处理。
2. 先检索当前获准的技能与工具，判断已有能力能否转换或读取。
3. 若有缺口，查找公开文档及候选工具，或编写任务脚本；可信目录内自动安装，公开网络候选在隔离环境自动试验，通过检查后用于当前任务。
4. 固定工具及依赖版本，在独立环境中试运行。不得让安装脚本在业务主进程或拥有全量企业数据的环境中执行。
5. 验证结果：例如页数和表格是否缺失、关键数值是否一致、公式引用是否改变、导出文件能否重新打开。失败时在任务额度内调整方法，无法解决就说明缺口或提出替代输入方式。
6. 返回实际产物和对应来源；由平台按任务权限保存。成功方案可以保存为候选能力，后续启用和发布规则单独确定。

正常用户界面展示工作进度、必要问题、产物和实际限制；不要求员工选择 Python 包或查看终端日志。详细工具版本和执行记录留作维护与复核。

## 5. 自主权限与后续细节

用户已选择“可信目录自动使用＋公开网络候选自动隔离试验”组合，并确认首期公开搜索/阅读、业务系统通过授权接口接入。普通员工不需要逐次确认查资料、装已允许的依赖或运行任务内脚本；新增外部服务、费用和越出既有业务授权的动作分别处理。

| 动作 | 推荐起点 | 当前状态 |
| --- | --- | --- |
| 查找已获准技能、组合工具、编写任务脚本 | 在任务范围和额度内自动执行，无需每一步确认 | 自主方向已确认，环境实现待验证 |
| 新依赖安装与技能试用 | 可信目录内自动装入任务环境；公开候选自动隔离试验，检查通过后用于当前任务 | 用户已确认两者组合；共享目录的启用规则另行细化 |
| 公开网页能力 | 首期支持搜索与阅读，业务系统通过授权接口接入 | 用户已确认；登录后网页操作后续再定 |
| 企业文件发往新外部处理服务 | 与公开搜索、下载本地工具分别控制；按企业允许的服务、数据范围及费用处理 | 具体服务接入时确认，不因工具可联网而获得上传权 |
| 能力沉淀 | 保存来源、版本和验证样例；任务使用、企业启用和平台公共发布分开 | 具体自动启用程度后续确认，不重开已暂定的引擎算法讨论 |

公开工具调查可以在无企业原件、无业务凭据的环境中进行；使用合成样例完成适配检查后，实际数据处理仍按企业授权边界。公开搜索的查询也不应无意带出企业文件正文或业务秘密。模型已获准的数据范围、工具安装联网、外部文件转换是不同出口，不相互授予权限。

公开候选的“检查通过”建议至少覆盖来源与版本可追溯、实际依赖和安装行为、所需文件/网络权限、可运行样例、输出完整性及资源消耗。自动检查并不证明代码绝对安全；检查通过后仍保留运行隔离、网络出口限制和任务范围授权。检查未通过则换工具、缩小任务或说明缺口，不通过取消隔离继续执行。具体检查规则在原型中实现与验证。

下载依赖的环境不装载企业原件或业务凭据；真正处理资料时仅开放任务获准输入和必要出口。包安装脚本、Skill 自带脚本、模型编写脚本都服从同一执行边界；普通目录分隔、静态扫描或一次成功结果不能独立充当多租户防护。将候选升级到企业或平台共享目录需单独定义启用和回归规则，当前任务试用成功不自动获得全局发布权限。

具体时间、重试次数、CPU/内存、文件大小与模型费用阈值尚未确定；结构上记录并限制资源消耗，达到限制时保留结果及下一步选择，避免无限尝试或静默追加费用。

## 6. 对现有组件和前端的影响

- WeKnora 继续作为默认解析/检索候选；其不支持的格式可以由独立工具转换为可检索内容或直接处理。衍生内容需保留原件版本、转换工具版本与引用映射，不能把转换后的文字当成无来源原件。
- Harness 承载执行循环及工具扩展；任务环境、技能目录和业务规则经接口接入，避免把自主扩展绑定到单个 Harness 的私有插件机制。新发现的工具优先在任务环境经稳定工具接口调用，不自动热装进承载其他企业任务的共享 Harness 主进程。
- React 继续使用平台任务、事件、产物与确认契约；新增进度、能力缺口及可恢复失败状态，不需要为了每一种文件格式重做页面。后续所有客户端复用该契约。
- 常用能力预置与按需扩展并存；暂时做不成某种格式时，已上传原件、其他资料和会话仍可用，前端明确解析与任务状态。

## 7. 最小验证建议

首个原型分别覆盖：一个默认支持的文件任务、一个需要额外工具的任务，以及一个无法完整完成的任务。文件样例在实现前确定，验证实际读取/计算/导出、缺失提示和失败保留。

另验证任务取消和重试不会重复发布，两个企业的文件与工具上下文不串用，撤权后不能继续获取资料，任务脚本不能访问宿主业务文件和平台凭据，未获准外部上传被出口策略拒绝。工具替换、环境重建后按记录可再次执行代表任务。当前未运行这些检查。
