# 手机号登录与账号加入实施方案 V0.1

日期：2026-10-01。对应 DEC-106，延续 POS-03、WS-02、WS-06—WS-16 及 M2 身份/三端管理范围。

## 1. 已确认规则与本轮范围

用户确认收敛登录、创建账号和加入企业流程，并明确密码至少 6 位、手机号作为登录账号，邮箱不再必填；随后要求继续，并说明尚未准备短信服务，先完成本地验证。

- 日常使用手机号和密码登录；密码 6–128 字符，可用更长密码，不增加字符组合规则。旧密码继续有效。
- 企业开通和员工邀请使用手机号。加入页面识别新账号、已有账号、匹配的登录账号及账号不匹配四种情况。
- 新账号验证受邀手机号，填姓名和一次密码，提交后创建账号、成员关系和个人空间并建立登录会话。已有账号以原密码或当前匹配会话接受，不允许凭邀请覆盖旧密码或姓名。
- 开通时明确指定的初始负责人，可在加入页面主动勾选接受职责；不默认勾选，不因此获得共享内容权限。
- 旧邮箱账号先验证原账号，再验证并绑定手机号；保留账号 ID、密码散列、成员关系和资料归属。绑定后该账号的邮箱登录退出使用，历史邮箱只用于迁移追溯。
- 普通入口进入智能画报；明确的工作链接优先。单企业直接进入，多企业沿用本人有效的上次选择，无记录时选择一次；失权的明确目标不能静默切换企业。
- 找回密码使用短信验证；修改密码验证原密码。两者完成后删除旧会话并递增账号凭据版本，旧请求即使延迟写回会话也不能恢复认证；重新登录。普通登录不要求每次短信验证。

本轮为第一批核心闭环。真实短信供应商/模板、批量邀请时配置初始空间授权，以及更长登录保持策略属于下一批；当前仍为 30 分钟不活动过期，不将这些后续项标为已完成。企业画像、职位和完整资料初始化继续可后补。

## 2. 数据与兼容

V43 在原 accounts/invitations 表增加规范化手机号；账号手机号唯一，关联验证时间；原邮箱变为可空。邀请在同一企业、同一手机号只允许一条有效待接受记录。原邮箱记录不伪造手机号，不删除旧账号或重建资料。原邮箱字段在兼容响应中可为 null，新页面优先显示手机号。备份排除验证码挑战和会话；恢复按账号 ID、手机号和历史邮箱的当前交集重新授权，凭据版本递增并发放新密码，不恢复旧验证证明。

实现选择：大陆号码可输入 11 位号码并规范化为 +86；其他号码须带国家区号，统一以 E.164 形式保存。此默认不是业务承诺的服务国家名单，真实发送地区须在供应商接入时核定。

原邮箱 API 保留历史本地夹具和迁移兼容；正常页面只创建手机号邀请。旧待接受邮箱邀请在新页面提示联系管理员重发手机号邀请；总台可重新生成未接受的初始邀请，普通旧邀请先撤销后重发。历史已接受记录和权限不受影响。无法访问旧账号的恢复不自动认领、合并或由管理员代改手机号。

## 3. 验证码与邀请意图

- 验证码区分 JOIN、BIND、RESET，绑定当前浏览器随机会话意图、手机号及相关账号/邀请；不同用途或浏览器不可互换。
- 工程默认值：验证码 5 分钟、同手机号发送冷却 60 秒、每条最多 5 次错误尝试；复用持久手机号/IP 尝试限流。随机验证码使用现有密码编码器保存散列，不进入正常 API 返回、日志或审计正文。
- 失败次数在独立事务提交，业务失败不能撤销计数；验证成功后的证明与建号/绑定/重置在同一业务事务消费。业务回滚不消耗一个本应仍可重试的验证机会。
- 新邀请将令牌从地址栏移除，只在前端内存短暂使用。服务端会话只保存已核验邀请的散列，使刷新可恢复。切换账号先退出原身份，再保留这一邀请意图，不保留原认证或验证码证明。
- 加入后的重试只返回当前仍有效的成员关系，不重复建号、个人空间或职责。已撤销/过期邀请、停用企业、停用成员不得通过重试恢复。
- 绑定要求原账号密码和新手机号验证双重成立；手机号已占用时拒绝自动合并。手机号锁与唯一索引处理并发归属；账号使用非键更新锁，避免失败审计的账号外键检查与业务锁互相等待。

## 4. 本地验证与真实投递边界

默认 `PHONE_DELIVERY=disabled`，无真实短信适配器；缺少通道时明确失败，不伪装发送成功。只有 local profile 加显式 `PHONE_DELIVERY=local` 才将测试短信写入私有目录。只有再启用 `PHONE_LOCAL_PREVIEW=true` 且请求来自回环地址，才能使用当前浏览器自己的测试验证码预览。邀请链接预览另外校验当前企业管理权或总台初始邀请权限。

页面始终标注“本地测试短信，未发送至手机”。本地验证码预览不能用于证明真实手机持有权，只服务于合成流程验收；不作为上线身份验证能力。

试用器新增 `--phone-local`，只允许非 live 实例；清除继承的 PHONE_* 环境配置，测试短信归属该实例。不要用此模式接管现有真实资料验收实例。完整命令、证据与局限见[本地验证记录](../交接/手机号登录本地验证-2026-10-01.md)。

## 5. 交付与回退

前端、公开身份契约 1.4.0、平台 API 和 V43 需作为同一切片发布。迁移只增加字段并放宽旧邮箱非空约束，不改写既有账号；未在用户现有数据库执行。数据库一旦产生手机号账号，旧版要求邮箱必填的客户端/API 不再兼容，不能只退应用包；需前向修复或在完整备份基础上协调回退。真实部署和用户资料迁移另行验收。

下一批再接入真实短信、重新发送状态与投递回执、批量邀请及初始空间授权。保持登录时间、敏感操作重新验证和新设备策略共同确定，不只延长现有 Cookie。
