# M7-A1 引擎升级与回退边界

2026-09-24，DEC-070，对应 M7-A1、POS-06、AI-04 与独立引擎升级要求。本批交付任务协议检查、只读运维预检和真实版本的本地升级/回退演练。引擎 0.9.1，平台数据库仍为 V14；前端和业务 API 不变。

## 发布版本与协议分开

引擎发布版本编译在 `engine/src/release.ts`，能力信息、检索结果、Agent 结果共用该值；运行环境不能任意覆写。协议使用独立版本：来源任务 1.0、Agent 1.4、平台资料回调 1.3。算法改进、工具内部优化与发布版本变化，不必同步改变任务协议。

新增服务间 `GET /internal/v1/runtime`：要求现有任务 Bearer 密钥，返回 Runtime 1.0、发布版本、执行模式和各任务协议，没有租户、任务或资料内容。旧 `/internal/v1/capabilities` 和公开 system-info 投影结构保持不变；这些元信息不能替代按任务类型的协议检查。

平台每次发任务前读取该声明，不缓存成功结果。来源任务只要求 sourceLookup 1.0；Agent 必须同时为 agentTask 1.4、platformCallbacks 1.3，且 `agent-verification`/`agent-live` 与平台配置一致。格式/版本不兼容在发送 prompt/source IDs 前拒绝，任务记录 `TASK_RUNTIME_INCOMPATIBLE`；网络/身份失败明确失败，无模拟内容或自动降级到另一模型。

预检和执行之间存在进程切换窗口，因此平台带 `X-Dreamcore-Engine-Version`；0.9.1 引擎在解析任务及调用模型/工具前拒绝不匹配版本。平台还核对返回结果的版本、taskId、attemptId。旧平台不传该头时，0.9.1 保留原接口行为；本批实际切换演练使用本批平台，没有声称对每个历史平台二进制完成兼容测试。

HTTP 检查有 16 KiB 响应上限、连接/请求及完成期限，不跟随重定向，日志不输出凭据或引擎返回正文。Agent 在检查前后仍检查尝试/权限有效性；资料范围和成果读取始终由平台验证。

## 0.9.0 回退过渡

0.9.0 没有 Runtime 端点，但已实现上述任务协议。平台默认 **不启用旧版本推定**。在明确保留本批验证过的 0.9.0 回退产物时，才配置 `ENGINE_LEGACY_090_ENABLED=true`：仅 Runtime 返回 404，且旧能力响应精确为 0.9.0/已知能力与模式时，采用这一固定兼容映射。其他版本、500/鉴权错误、畸形响应或新版声明不兼容均不触发回退。

该过渡开关不是“任意旧版兼容”，完成过渡后应关闭。0.9.0 不实现版本头保护，回退时必须停止新任务进入并等待现有任务结束；不能仅凭探测成功承诺并发切换无费用或无损。引擎是受信任的服务端产物，协议声明也不是代码签名；操作者仍需使用对应构建与依赖锁。

## 预检与升级顺序

在已通过私有环境注入 `TASK_ENGINE_TOKEN` 的运维终端运行：

```bash
npm --prefix engine ci
npm run build:engine
npm run engine:check -- --url http://127.0.0.1:18182 --expected-version 0.9.1 --mode source-lookup
```

检查配置好的 Agent 节点时，将 mode 换为 `agent-verification` 或 `agent-live`，不能用未配置模型的来源检索节点冒充 Agent 就绪。预检只检查配置和协议，不发任务、不会调用模型，也不证明供应商密钥/余额/模型质量可用。CLI 只允许回环 HTTP 或 HTTPS，凭据不写命令参数；失败退出码为 1。

有明确回退产物时可预检：

```bash
npm run engine:check -- --url http://127.0.0.1:18182 --expected-version 0.9.0 --mode source-lookup --allow-legacy-090
```

1. 保存原引擎构建、依赖锁、目录资源及配置引用，记录源码 SHA/产物摘要。先在旁路端口启动候选引擎，不给用户任务流量；预检目标版本和实际使用模式。
2. 首次安装本批平台检查需要更新平台。若此时仍使用 0.9.0，先明确配置上述过渡开关；或者先装兼容原接口的 0.9.1，再装新平台。之后协议兼容的引擎更新可独立进行。
3. 通过部署系统/维护窗口停止新任务进入，等待进行中任务完成或明确取消，再切换稳定引擎地址的服务目标。平台和数据库不需要因此重启；业务网页不用重编译。本批没有交付生产流量控制、准入暂停或自动发布系统。
4. 检查新任务结果记录的新版本，以及旧引用/原件/产物、画报和文稿仍可读取；保留明确回退路径。
5. 候选不满足协议时保持原引擎；异常切换或进程中断会明确失败，不自动重做可能计费的工作。用户显式重试建立新的尝试身份，重复同请求不会重复执行。回退沿同样的预检、停止新任务、等待结束和复核步骤。

`trial:start` 仍是三端捆绑监督启动器，不提供在线替换子引擎的命令；手动结束其子进程会触发既有“所属服务异常则停止试用”的规则。普通本地试用更新采用停止 → 构建 → 重启。本批独立切换通过专门的一次性演练启动独立进程、固定平台和测试路由完成，不操作用户现有试用环境。

## 实际验证与限制

`npm run test:engine-upgrade` 从固定提交 `65443b35719be33b1a4e3d19214d0768a6b0daa5` 导出并重建真正的 0.9.0，不通过改版本号冒充旧版；和当前 0.9.1 使用各自 dist/catalog/锁文件。比较并记录两套构建摘要，平台 PID 与数据库始终相同。稳定服务地址由测试专用转发器维持，不作为产品发布组件。

新旧两版均执行真实 Harness、平台授权检索与 macOS 本地工具。模型仅为本地合成 HTTP 传输：本批升级演练 10 次请求，零云模型调用。读取旧会话/固定引用、附件/PDF 字节、原件版本、画报卡片与文稿；中断正在读取的合成模型响应，验证失败、显式重试和幂等；平台角色/跨企业/企业停用边界继续生效。详见[验证记录](../交接/M7-A1引擎升级与回退验证-2026-09-24.md)。

本批没有新数据库迁移；此结论不扩展为任意协议、数据库、模型或执行器版本可回退。云节点、负载均衡、滚动排空、在途跨版本任务迁移、模型费用、客户真机与生产部署另验；也未将本地 macOS 工具隔离等同于生产隔离承诺。
