# 企业管理端功能盘点与待确认事项

日期：2026-10-02。状态：现状盘点与讨论稿，尚未确认新的菜单、交互和业务规则。

本文响应“先把每个功能点和业务板块梳理出来，再一起确认交互流程和逻辑”。依据用户提供的管理页截图、当日日常开发目录的实际源码（含未提交修改）、相关服务端权限代码和活动需求文档。源码存在入口或接口，不代表真实业务已验收；本轮没有逐项操作真实企业数据，也没有修改页面、账号权限或保留政策。

## 1. 当前结论与已确认边界

管理端已经包含多套业务能力，但页面主要按开发模块排列，尚未形成管理员的工作顺序。需要先分清管理对象、操作者和动作后果，再决定页面归属。

此前已确认的边界继续有效：

- 客户端和企业管理端共用账号及登录，可相互切换，也可另开标签页并行使用。页面选择和未提交工作各自保留，身份、实际权限和业务数据仍然共用。
- 客户端只为当前企业有管理资格的账号提供切换入口；企业管理操作集中在管理端。
- 员工会话、画报、资料上传及日常整理仍属于客户端；管理员身份不自动赋予共享正文或他人私人内容访问权。
- 首期优先保证主流程。客户端经验界面已后置；企业端经验维护的范围和操作需在本次专题重新确认。

有关来源见[产品需求基线](产品需求基线-V0.1.md)及[开发决策记录](../技术/开发决策记录.md)中的 DEC-116、DEC-123 后续补充及双端并行决定。早期文档中的五类工作区属于建议，不能直接当成已确认菜单。

## 3. 全部功能清单

下列编号只用于本次讨论，不替代原需求编号。“当前能力”描述实现现状；每组的“待确认”才是后续需要共同决定的内容。

### A. 企业、成员与职责

| 编号 / 功能 | 当前能力 | 重要边界与待确认 |
| --- | --- | --- |
| A1 企业基本信息 | 查看企业名称、标识、启用成员数、共享空间数；修改企业名称 | 当前“企业设置”主要只有名称，不是完整企业资料或工商档案。与供 AI 使用的企业背景分开 |
| A2 企业成员 | 按姓名/手机号搜索、状态筛选、分页；查看身份及企业成员状态、全局账号停用提示；普通停用、恢复 | 普通停用只影响本企业，保留资料及原授权。不是正式离职，也不删除全局账号 |
| A3 成员邀请 | 输入手机号生成邀请；查看邀请状态、有效期及本地链接；撤销邀请；接受邀请后加入企业 | 当前管理页明确标注本地投递，未发送真实邀请短信。真实投递方式及失败后的处理要另行收口 |
| A4 企业授权负责人 | 已指定人员明确接受初始职责；现任负责人发起交接；接任者接受后生效；查看待交接状态 | 不能自动把任何管理员推定为负责人。交接完成后原负责人仍保留配置管理身份，需另行调整 |
| A5 管理员任命 | 负责人选择有效成员，任命为配置管理员或调整回普通成员 | 任命不附带内容访问权；负责人撤销自身配置管理职责前需先交接。业务名称、任命范围和呈现方式仍需确认 |
| A6 专项职责授权 | 查看本人职责；负责人给成员授予或撤销档案、经验、评估、永久清理、批量导出、方法采用、持续计划配置、正式离职、企业退出等能力 | 区分企业范围与空间范围；空间职责不代替空间访问。离职、退出限企业范围。持续计划入口已隐藏，但授权列表仍出现该能力 |
| A7 紧急安全停用 | 成员存在安全风险时立即切断本企业资格；可处理负责人或最后管理员，并生成待核验记录 | 与普通停用的保护条件不同。当前负责人恢复申请只登记待核验，不提供完整核验与恢复闭环；不应作为日常成员操作的同等主按钮 |

当前没有在这套成员页面看到部门树、岗位管理或组织汇报关系。工作空间可以用于部门协作，但不能因此认定已实现组织架构管理。

待确认：首期是否采用“企业负责人、企业管理员、按空间授权的维护者”这三类易懂称谓；普通管理员能给哪些人授权；本人授权及安全停用后的恢复由谁处理。

依据：[企业配置](../../src/tenant/TenantAdminHome.tsx)、[职责与授权](../../src/governance/GovernancePanel.tsx)、[服务端职责规则](../../apps/api/src/main/java/com/dreamcore/workspace/governance/GovernanceAccess.java)、[成员管理规则](../../apps/api/src/main/java/com/dreamcore/workspace/identity/TenantAdminService.java)。

### B. 工作空间与内容授权

| 编号 / 功能 | 当前能力 | 重要边界与待确认 |
| --- | --- | --- |
| B1 共享空间管理 | 搜索、创建、查看空间；修改名称；查看已授权成员数 | 创建空间不自动让创建者获得内容访问权；没有在此页面看到空间归档、合并、删除的完整操作 |
| B2 空间成员 | 搜索并添加有效成员；查看已有授权；撤销授权 | 新授权默认只读；停用期间授权保留；撤销后重新授权从只读开始 |
| B3 资料维护权限 | 对已有空间成员授予维护或改回只读 | 资料查看、资料维护、经验维护和其他专项能力不是同一个权限；目前分别在空间详情与职责页面设置 |

待确认：以“空间详情—成员与权限”还是“成员详情—可访问空间”为主要授权路径；建议先保证空间视角完整，成员视角用于核对。不要让管理员在两个无关联页面反复设置同一个人的权限。

存在具体实现差异：后端允许企业授权负责人明确自授权，普通配置管理员不能给自己或其他管理身份新增内容权限；前端“添加成员”和“允许维护”仍无差别禁用本人。此项需对齐业务规则后修正，不能仅调整文案。

### E. 评价、问题与方法采用

| 编号 / 功能 | 当前能力 | 重要边界与待确认 |
| --- | --- | --- |
| E1 标准与样例 | 建立、修订、撤回标准和样例；设定回归/调优用途；记录检查项、事实/内容/用户作用/运行等维度、要求强度、场景、预期、未知项及确切依据版本 | 可使用合成样例或本人任务/反馈、获权资料；管理身份不扩大原证据权限 |

| E3 问题处理 | 登记问题、分类、影响、下一步；本人接手或转交给有权处理者；更新处理中、等待、待复核、结束；记录结束原因、证据和处理历史；已结束可重新打开 | 是评价证据关联的问题记录，不等于通用客服工单、全部失败任务收件箱或自动重试入口 |
| E4 方法采用与回退 | 查看平台已发布方法版本；选择企业默认或获权空间范围；明确采用、停止、回退历史版本；查看当前生效来源、参数及采用历史 | 当前方法实际为推荐排序权重。企业端不提供通用方法开发与发布；停止空间采用会回到企业或内建默认 |

待确认：普通企业管理员是否需要直接管理评价标准和排序方法；建议将专业维护放在次级入口。尚不能把 E1—E4 宣称为已完成的“企业 AI 自进化闭环”。

另一个范围问题：当前评价、方法和内容生命周期页面使用可访问空间列表，没有统一排除本人的个人空间。这里不意味着能读取他人私人内容，但与“企业集中管理”的页面定位仍需对齐。

### G. 保存、回收与清理

| 编号 / 功能 | 当前能力 | 重要边界与待确认 |
| --- | --- | --- |
| G1 对象回收与清理 | 按范围、对象类型、状态筛选；查看对象修订、原始时间、固定截止、依赖限制、失败及完成状态、操作历史；按服务端允许动作停用、启用、回收、恢复、永久清理或重试；评估详情可标记临时试验 | 对象包括本人任务、文稿、工具产物、经验/反馈/评估/档案/方法版本及导出缓存，实际可见与动作按对象授权限制。此页不同于客户端资料文件回收站 |
| G2 保存政策 | 查看各类数据保留规则、执行范围和历史；获权人员为可配置项修改后续期限并填写原因；查看相关清理执行状态 | 修改只作用于后续相应事件，不延长旧对象固定截止；恢复不自动重新启用或重跑旧任务；在线正文清理不证明所有备份已删除 |

当前政策涵盖下列 13 类。这是现有开发配置盘点，不将天数或可配置项升级为生产承诺：

| 类别 | 当前默认 | 配置状态 |
| --- | --- | --- |
| 正式资料、保存的会话和成果 | 按有效用途保留 | 无自动闲置删除天数 |
| 已生效经验及必要版本 | 按有效用途保留 | 无自动闲置删除天数 |
| 档案、偏好、方法与正式评测案例 | 按有效用途保留 | 无统一自动到期天数 |
| 未发布经验候选 | 90 天 | 可配置 |
| 每个版本的原始反馈 | 180 天 | 可配置 |
| 临时评测与试验详情 | 90 天 | 可配置 |
| 平台本地技术日志 | 30 天及容量上限 | 企业不能修改平台上限 |
| 闭合任务通知及重复操作记录 | 180 天 | 可配置；必要业务与授权事实另行保留 |
| 普通回收期 | 30 天 | 可配置 |
| 临时导出包最长保留 | 7 天 | 可配置上限，包按支持的期限选择 |
| 解析、索引及受限派生缓存 | 随来源和用途 | 无统一天数 |
| 离职私人内容隔离 | 30 天 | 可配置，正式办理时固定 |
| 企业退出受限导出期 | 30 天 | 可配置，正式办理时固定 |

待确认：首期向企业暴露多少政策设置，是否主要提供默认值说明和必要例外；普通回收、永久清理、备份处理的入口与结果必须明确区分。

## 4. 谁能做什么：现状和需要收口的地方

| 身份或资格 | 当前作用 | 不自动包含 |
| --- | --- | --- |
| 企业授权负责人 | 接受企业责任；任命管理员；授予专项能力；明确内容授权；发起负责人交接 | 他人私人内容；全部空间正文；全部离职、退出、导出、清理能力 |
| 配置管理员 | 企业名称、成员、邀请、共享空间管理，企业运行信息与保存政策；企业级背景维护 | 任命其他管理员；任意内容自授权；全部空间维护与专项执行能力 |
| 空间只读成员 | 读取已获权共享范围 | 上传/修改资料、经验发布、评价维护等动作 |
| 空间资料维护者 | 维护已授权空间资料和人工来源；其职责也可能使管理入口可见 | 任意企业配置、其他空间内容或其他专项维护能力 |
| 专项维护者 | 在具体授权范围内维护背景、经验、评价、方法等 | 一种维护权不等于所有维护权，企业范围能力也不能笼统解释成所有空间权利 |
| 离职/退出办理者与迁出人员 | 前者执行明确授权的办理；后者按指定范围迁出 | 办理资格不自动提供全量导出或私人空间接管 |
| 平台维护者 | 平台开通、通用能力与平台运行工作 | 首期不因平台身份进入客户内容 |

这些不是要新增七种固定角色，而是把现有混在一起的身份、权限和工作分工分开说明。最终产品可用更少角色表达常用组合，仍由服务端逐动作校验。

当前管理端入口按能否进入管理工作区判断，不是简单检查“企业管理员”。部分页面对所有已进入者展示，但进入后可能没有可维护范围；菜单可见不等于能执行操作。

## 6. 建议的业务归属与首期层级（待确认）

以下分组用于讨论，不表示将表中每行做成一级菜单，也不意味着所有已实现能力都进入首期。

| 建议归属 | 包含功能 | 首期建议 |
| --- | --- | --- |
| 企业与成员 | 企业信息、成员、邀请、负责人及管理员职责；从成员详情进入离职 | 主线，先把加入、可用、变更、离开连通 |
| 工作空间与权限 | 创建和管理共享空间；成员查看/资料维护权限；相关专项职责 | 主线，让管理员明确知道谁能在哪个空间做什么 |
| 资料与工作背景 | 人工来源、补交覆盖、企业/空间背景 | 按实际需要提供次级管理；员工上传与整理仍在客户端 |
| AI 使用与改进 | 可用能力说明、经验维护、评价、问题、方法采用 | 能力说明简洁呈现；经验范围单独确认；专业评价和排序方法建议放高级维护或后置 |
| 使用情况与记录 | 一处运行概览、关键管理变更及对象历史关联 | 保留简明运行信息，暂不扩成绩效或财务平台 |
| 企业设置中的数据管理 | 保存政策、回收清理、企业退出与迁出记录 | 低频下钻；不把永久清理和退出设为默认首页主要动作 |

首页建议只承担“当前企业是否能正常开始工作、有哪些必须由我处理的事项”的概览。先复用已有事实，是否新增统一待办、初始化向导和快捷操作，需要在流程确认后决定。

最小主线建议先验证：**企业负责人明确 → 邀请成员加入 → 建共享空间 → 授予读取/维护 → 成员回客户端工作**。日常变化从成员或空间详情接续，避免管理员为完成一次授权跨多个无关联模块。
