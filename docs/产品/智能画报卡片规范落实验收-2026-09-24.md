# 智能画报卡片规范落实验收（2026-09-24）

范围：AI-11、DASH-01—DASH-04。依据用户最新批注和[卡片规范](智能画报卡片规范讨论稿-V0.1.md)顶部的当前规则；旧设计记录不作为恢复历史交互的要求。当前为本地实现与自动验证，待用户体验验收。

## 已落实

- 标题完整换行，移除单行、两行及固定字符截断。浏览器测量标题、关键数字、统计周期、必要说明与来源所需空间，容量不足即扩大显示规格，自动补洞不能将卡片压回不足的尺寸。极长人工标题在最大规格仍放不下时增加整行，网格仍对齐；关注的保存偏好不被响应式扩容覆盖。
- 同一卡片保留同一身份，数据卡跟随当前可读来源更新，不按天复制或追加历史。内容更新不会断开原会话、关注、隐藏与布局偏好。
- 资讯、成果、建议保留产生时的内容与依据，日期入口只匹配产生当天。来源退出当前候选列表后仍可找到已产生内容，但每次显示和操作都检查当前来源权限。洞察暂采用相同规则，属于可调整的实施选择。
- 数据卡不进入过去日期。卡面标注数据更新时间，真实新闻来源与原文日期、图表统计周期和单位保留；移除“模拟底表 v1 · 某日情境”尾标。
- 关注、有用反馈或来源的高重要性标记可使数据卡再次推荐。新数据可推荐，已读且数据未变时采用 24 小时间隔；隐藏和没用抑制该路径。再次推荐保留已读与反馈，独立记录推荐时间，不改内容日期或数据更新时间。既有活跃业务会话／待处理申请例外独立保留。
- 有用／没用、关注和已有会话以右下角图标表达，互斥或并存规则与详情一致，刷新后仍可识别。

## 兼容与边界

- 旧浏览器的卡片历史数组仅保留，不再追加或在画报查询。资料版本、原始业务数据、会话消息、任务和引用依据仍按原规则保留；没有清空浏览器存储或执行数据库迁移。
- 旧按日卡片若曾被旧版更新，迁移保留当前内容，并使用它的实际留存时间，避免把后来内容标成更早日期已产生。新内容按独立身份生成，不能靠复制旧卡实现每日推荐。
- 当前空谷页面仍采用合成数据及预编写内容，没有新增真实模型生成、外部业务实时数据连接、自动重要性识别或数据源故障恢复服务。已验证的是当前数据来源更新后的卡片行为，不是实时数据 SLA 或推荐效果。
- 真实 API 仍提供私人会话结果卡：先取同一会话最近成功结果，再按日期、当前权限、空间和偏好筛选；日期不复活旧回复卡片。历史任务接口继续可用。契约说明升至 1.1.0，返回字段不变；没有重启或部署 API，也没有把 Demo 的五类内容生成与推荐冒充真实服务能力。

## 内容密度补充（同日页面批注）

- 用户要求卡片避免大片空白和大片文字，按实际内容及重要性选择尺寸，大尺寸主要用于较大的图表或有价值的媒体。自动布局现从当前实际图文选择规格：短结论优先 1×1；重点文字、简短图表优先 2×1；多点趋势、矩阵和分面图优先 2×2。容量不足先加宽，仍保留完整标题及关注页的手动偏好。
- `konggu:C35` 不再沿用旧 2×2 纯文字配置，展示收款与履约收入的两组构成图。数字直接取既有合成底表：10,500＝8,100＋2,400；11,400＝8,100＋3,300。共同尺度用于比较，两组不相加；订金不计履约收入。宽屏横卡并排，窄屏一格上下排列，保留统计期、模拟限定和单位。来源内容改变时不继续套用该旧数据图。
- 简短洞察等纯文字卡缩为小卡，短卡摘要可展示最多三行；图表卡优先展示图形。大趋势图、矩阵和分面图随实际可用高度绘制，减少固定图高造成的空白。不增加卡片版本，不修改原事实、内容时间或已保存的用户配置。
- 验证：`npm run build` 和 138 条单元检查通过；本轮 17 条 Chromium 与 8 条 WebKit 检查通过，覆盖 1440／977／768／390／320 的内容密度、完整标题、图形与来源不重叠，以及多断点布局、关注拖动、反馈与生命周期。WebKit 自动化不代表用户 Safari 自然设备验收。
- 原拖动用例改为向下移动，避免新尺寸让首张小卡处于首行时向上拖动只触及边界；布局单测按卡片身份查找保存坐标，不再假定自动补位后数组顺序不变。拼版回归检查所有可容纳后续卡片的空位；完整标题要求两列时，不强制把两列卡压入剩余的一列空位。完整标题与必要信息优先于补洞。
- 视觉截图和日志保留在开发 worktree 的 `.local/card-density/`。本轮只调整前端呈现与规范，没有新增后台生成或实时业务数据服务。

## 手动四种尺寸修复（同日页面批注）

- 用户反馈关注卡片只能调整出两三种规格。定位到旧自动扩容缓存会把宽度限制带入另一种形状，以及最右列直接禁止加宽；过渡动画中的临时宽高也可能造成错误的后续容量限制。
- 拖动预览和提交不套用目标卡片的旧容量缓存，保存手动尺寸后重新测量。测量跳过拖动和未完成的过渡，动画完成后再次核对；不因中间帧把卡片锁大。手动 1×1 优先完整标题并将次要摘要收为一行，自动排版仍按前述内容密度规则。
- 右边缘加宽时只向左移动所需列，保持所在行；把手在窗口内剩余距离即可触发加宽，不需要移到窗口外。键盘左右、上下分别切换宽高；窄屏单列仍保留宽屏选择。取消、撤销、刷新保留、尺寸仅归属关注页等规则不变。
- 验收用批注原卡 `konggu:C29` 在正常动画下连续拖过四种规格并反向缩小，核对显示尺寸、保存值、完整标题及刷新保留；另测自动加宽后改为竖卡、两列时选择小卡、最右列键盘和指针加宽。较长标题在修复前的竖卡用例确实得到 2×2 而非 1×2，原版本右边缘加宽同样失败；不修改事实、卡片历史和会话。
- 验证日志和四种规格截图位于开发 worktree 的 `.local/resize-four/`；构建及 138 条单元检查通过。Chromium 的 5 条四规格场景及 4 条关注回归通过，原完整标题、密度及拼版的 8 条回归也通过；WebKit 的四规格与完整标题规范共 9 条通过。本轮仍为本地前端修复，WebKit 自动化不代表用户 Safari 的自然设备验收。
