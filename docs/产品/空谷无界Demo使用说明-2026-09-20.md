# 空谷无界 Demo 使用说明

用户已确认按[调研资料](../调研/空谷无界/调研结论与演示设计.md)替换默认演示。当前为纯前端、预编写分析示例，突出资料整合、依据核对和成果沉淀；没有接入真实模型或门店系统。

首页最新位置展示独立会话的最新回复；此前内容分组包含贵阳咖啡博览会预告、过去7天零售、研发准备和贵州风味新闻。画报使用3张已核验的真实原站配图，资料阅读可显示其他已选配图。第三方图片加载失败时保留文字和原文入口；没有把新闻照片下载进代码或转发包。原站能访问不等于取得再分发授权。

## 建议现场演示顺序

1. 从智能画报点击“过去7天零售48,178元”，核对订单、客单、上期及活动金额；点击引用资料打开底表。综合销售59,578元包含履约活动11,400元，活动到账10,500元中的2,400元是未来订金。
2. 打开“贵州风味，正在进入咖啡杯”，查看原文。进入“从贵州风味资讯到下一轮试饮”会话，输入“整理下一轮新品试饮计划”，观察外部资讯、顾客反馈、试饮与成本依据共同进入个人草稿。
3. 打开“30人读书会：把需求变成筹备方案”，输入“整理30人读书会方案”。核对人数、布置与撤场、模拟6,000元报价及待确认事项，再编辑资料或明确共享到活动空间。
4. 从会话入口新建一段会话并发送，返回画报查看“活跃会话”卡片；点击继续原会话，回复后仍只更新同一张卡。原内容卡展开的会话不再重复生成卡片，归档会话退出画报。
5. 展示资料版本、关联资料、卡片关注／隐藏／标题与尺寸优化；刷新页面确认修改保留。

入口：`/#/briefing`、`/#/chat/kg-review`、`/#/chat/kg-development`、`/#/chat/kg-event-plan`、`/#/apps/events/kg-followup`。

## 资料与运行边界

- 默认身份“空谷主理人”，六个空间均可维护，员工仅为模拟角色，没有生成真实个人信息或联系渠道。
- 空谷浏览器存储键 `enterprise-ai-demo-konggu-v1`，旧通用场景 `enterprise-ai-demo-v1` 不读取、不覆盖。个人设置重置只清除空谷修改。
- 画报为初始底表v1的固定演示结果，不自动重算用户修改的销售表或活动应用。原画报打开引用时绑定v1；来源不可读时隐藏相关卡片，资料已有新版本时预设分析提示重新核对。
- 任意新资料、未知版本或超出预设的问题不会交给真实模型。生成草稿是本地操作，不发消息、不报名、不下单、不确认真实档期。
- 真实业务隔离、实时数据同步、系统主动工作与模型分析能力仍需后续接入和验收。

- `npm run build`：TypeScript与生产构建。
- `npm test`：50项状态检查，包括6项空谷场景与原有44项规则回归。
- `npm run test:e2e:konggu`：6项空谷浏览器流程；真实配图加载、原文链接、表格、新版本、草稿、偏好持久化、1440／768／390像素布局、配图失败降级。
- 人工查看桌面画报、手机画报、销售资料与研发会话截图，存于 `.local/konggu/`。修正折线坐标留白、空要点产生的“0”，以及大样本格子图按人数截断造成的比例失真。
- 原有客户A等通用场景E2E脚本保留历史用途，本次未以全量旧场景E2E作为空谷验收；当前专用入口为上述命令。
- 从研究源更新前端：`python3 scripts/sync-konggu-research.py` 生成 `src/kongguResearch.ts`，随后构建检查。卡片编辑在 `src/kongguBriefing.ts`，种子在 `src/kongguSeed.ts`，预设回复在 `src/kongguReply.ts`。旧用户修改不会在加载时强制覆盖。
