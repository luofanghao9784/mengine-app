## 2. 当前基础与本次差异

调整前，Demo 默认进入独立的“开始一项新工作”页面，智能画报是侧栏入口。代码已有卡片关联会话、内容快照、建议提示词、专门的卡片优化会话和部分事项状态联动。

调整前，业务会话的画报背景主要表现为文字摘要和上下文说明，尚未完整复用用户点击的原卡片视觉。卡片优化会话已有卡片预览，不等同于本次确认的业务会话展示。

本次主要新增工作为：首页与新建入口的关系、悬浮输入的展开与收起、原卡片在业务会话中的呈现，以及从画报到会话再返回的接续。既有卡片身份、快照和会话关联可作为基础继续完善。

现有能力仍是前端模拟；本稿没有确认真实模型、后台主动执行、服务端权限或部署范围。

## 3. 本轮打通的使用路径

### 3.1 用户已有明确需求

打开智能画报首页 → 直接在悬浮输入框表达需求 → 发送后进入完整会话 → 继续讨论并产生结果。

建议点击输入框时仅编辑草稿，发送后才创建持久会话，避免产生大量空会话。首页可以直接发起未归入空间的工作，不强制先选择项目。

### 3.2 用户从画报发现要处理的工作

阅读画报 → 点击卡片 → 进入完整会话并看到该卡片 → 选择建议或自由输入 → 推进工作、查看结果 → 返回画报。

首次打开可建立带背景的会话，但打开动作本身不直接执行业务处理。原卡片应保留标题、关键事实、图表或图片、依据及时间，按会话宽度适配。

### 3.3 用户回来继续已有工作

通过原卡片或侧栏打开已有会话 → 找回当前背景和此前进度 → 继续工作。

同一事项、同一快照不重复插入相同内容。建议再次进入时兼顾“刚才点击的卡片可见”和“快速回到最近进度”，具体展示方式见第 6 节。

## 4. 本轮采用的交互细节

以下交互已在本轮采用，尺寸和动效等可逆细节可继续根据实际体验调整。

| 情境 | 建议行为 |
| --- | --- |
| 首次打开首页 | 底部显示轻量单行输入框 |
| 向下阅读 | 输入框平滑收起为底部圆形加号，不显示文字；保留稳定的新建入口，并预留内容底部空间 |
| 恢复输入 | 点击小入口、明显向上滚动或回到顶部时恢复；避免轻微滚动反复触发 |
| 已输入或正在编辑 | 不因页面滚动自动收起，保留草稿和已选资料 |
| 从空间发起 | 明示并预选当前工作空间，允许调整；浏览画报筛选不隐式改变新会话归属 |
| 从卡片进入 | 展示原卡片，建议提示词紧接其后；避免再用长段文字重复卡片内容 |
| 卡片下方建议 | 用户可选择，也可自由输入；重要授权和执行规则沿用现有业务要求 |
| 返回画报 | 恢复离开时的分类、筛选及阅读位置；来源卡隐藏或不可见时合理回到附近位置 |
| 历史卡片 | 保留当时版本和时间；若来源已有更新，明确标示，后续执行核对当前资料与权限 |
| 当前画报与会话历史 | 画报反映当前事项状态；历史卡片不被后来的结果覆盖，当前结果通过后续记录或状态体现 |
| 重复进入 | 不重复创建同一事项会话或相同版本的卡片；若用户点击了新的快照，明确区分新背景与旧讨论 |

建议将原卡片作为可辨认的“画报引用”呈现，不伪装成用户输入或 AI 刚刚生成的新回答。展示无需机械保留画报网格尺寸，但要保留信息与视觉辨识度。

## 6. 本轮已确认的三项细节

用户随后明确“按照建议进行调整”，已选择下表 C1、C2、C3 的推荐方案并授权对应前端实施。其他方案保留用于解释取舍。

| 编号 | 确认内容 | 已采用的推荐方案 | 另一方案及影响 |
| --- | --- | --- | --- |
| C1 | 下一轮调整范围 | 先做画报首页、悬浮输入、完整会话中的原卡片、返回接续及必要的导航适配 | 同轮加入完整侧栏、空间概览和会话状态重构，需要一起确定更多页面关系 |
| C2 | 侧栏“新建会话”打开什么 | 直接打开完整的空白会话编辑页，发送后才创建会话；当前画报阅读位置保留 | 返回画报并聚焦悬浮输入，入口更集中，但从其他工作页新建需先回首页 |
| C3 | 原卡片在长会话中的位置 | 原卡片放入会话内容，首次进入完整展示；继续讨论时随内容滚动，保留紧凑的来源入口用于展开或定位 | 原卡片始终完整固定在顶部，背景始终可见，但占用持续讨论和成果查看空间 |

对于 C3，建议再次从画报进入已有会话时，先展示这次点击的卡片，并允许一键继续最近进度；不重复写入同一快照。具体定位与折叠方式可在原型中验证。

默认首页已采用用户提出的智能画报方案。是否进一步开放个人默认入口设置，可以根据使用反馈决定，不需要作为这一轮布局调整的前置条件。

## 7. 本轮验收依据

1. 用户从首页可直接提出需求，无需先阅读卡片或选择空间；草稿不会因收起和恢复而丢失。
2. 点击画报卡片后进入完整会话，并能辨认刚才点击的卡片；图表、图片、依据和时间按实际内容保留。
3. 点击和返回不直接触发业务执行；同一事项接续原会话，相同快照不重复插入。
4. 已有会话和更新后的卡片能同时解释历史依据与当前状态；新业务周期仍按既有规则处理。
5. 返回画报恢复原分类、筛选及阅读位置；最后一张卡片不会被悬浮入口遮挡。
6. 个人草稿、共享成果及空间归属沿用既有边界；旧浏览器中的会话、资料与卡片关联保留。

本轮已完成对应前端调整。草稿和阅读位置在当前页面会话内保留，刷新或关闭网页后不承诺恢复未发送草稿；已发送会话与卡片快照沿用浏览器持久化。实际检查记录见 [Demo 使用与验收](前端Demo使用与验收-V0.1.md)。真实模型与后台执行未接入，用户体验验收待反馈。

## 8. 本轮实现补充

- 根路径与品牌入口进入智能画报；沿用当前四个圆形导航与按需展开的会话列表，列表中的“新建会话”打开完整编辑页。
- 新建草稿在首页和完整编辑页共用，可先选资料与空间；发送才建立会话。滚动收起不丢草稿，资料仅引用原条目。
- 卡片作为可辨认的画报引用进入消息流，保留内容和显示配置快照；顶部紧凑入口可定位原卡片、继续最近进度或返回原画报。
- 按卡片身份和快照版本去重；历史消息保留，旧版文字背景可增量补齐原卡片呈现。
- 同一浏览会话内按画报路径保留分类、类型、空间、日期、关闭列表状态和滚动位置；返回时按当前布局恢复并自然限制在可滚动范围内。
- 浮动输入区域根据自身高度预留画报底部空间，兼容窄屏底部导航。


## 9. 最新确认：会话浮层与横向卡片带

用户逐项确认后要求“按照建议确认”，本节为当前执行口径，替代前文与之冲突的页面形态。对应 AI-01、AI-11—AI-13；不扩大模型、数据权限或业务执行范围。

- 桌面依次展示独立的会话列表、当前对话、画报来源、文件卡片。普通会话没有画报来源时不制造来源卡片，没有文件则不显示文件卡片。原画报内容继续作为消息流中的初始引用随消息滚动，右侧另有独立来源卡片，保持打开时的内容与时间。
- 点击画报卡片时，由原卡片缩放为中间会话卡片，其余卡片淡入；关闭时反向收回。页面保留在背景并模糊，导航图标保持在前台。没有当前可见来源的直达会话、导航入口和已切换会话使用轻微缩放与淡出，不伪造返回目标。
- 最新浏览批注替代“列表缩回导航图标”：会话列表折叠在会话框后方；会话卡片向左移动后停住，宽度保持不变。来源和文件随横向浏览依次覆盖前卡，前卡折叠留在后方。实现保留可点击展开的窄边缘，支持触控板、横向滚动条及左右按钮。
- 同批六处简化：列表标题改为“会话列表”；移除输入框底部 Enter 提示、旧的原卡片／继续最近进度／返回画报操作条，以及会话标题下重复的空间入口。保留会话标题、输入区空间操作和实际 Enter／Shift+Enter 行为，发送按钮改为圆形。
- 所有桌面卡片可拖动右侧边缘调整宽度，也支持聚焦边缘后按左右键；双击边缘恢复默认。具体上下限与窄屏约束属于可逆实现选择。宽度在当前打开网页期间保留。
- 已有成果文件自动加入，引用文件点击后横向追加，同一资料身份只开一张查看卡并显示当前版本；文件可单独关闭和重新打开。文件读取沿用演示可见范围，不改变源资料位置或权限。
- 点击导航的智能画报、资料库、应用，收起会话浮层并切换页面，保留未发送草稿。最新批注确认：取消会话图标悬浮展示或展开列表，悬浮仅显示名称。点击直接进入会话列表与带启动建议的新会话框的浮层；已有会话从列表进入，发送前不创建记录。窄屏默认展示新会话卡，通过顶部切换列表。会话浮层存在期间图标保持激活，列表宽度、分组、阅读位置和未发送草稿继续保留。
- 右上角关闭、Escape、点击模糊背景均可关闭。内层资料或审批弹窗优先处理 Escape。关闭不归档会话、不丢失当前网页内的输入，恢复原背景页面的阅读位置；刷新后已存会话可直接打开，未发送草稿和宽度不承诺跨刷新恢复。
- 窄屏优先显示对话，通过顶部切换列表、画报来源和文件，底部导航保持可用。系统设置减少动态效果时取消长动画。

最新实装入口为 `ConversationOverlay.tsx`；本地验证结果见 [Demo 使用与验收](前端Demo使用与验收-V0.1.md)。实现完成不等于用户体验验收。


## 10. 圆形新建入口与输入过渡（2026-09-19）

- 用户最新批注明确：收起的新建会话入口改为圆形加号，不显示文字；输入框与图标之间加入过渡动画。
- 收起状态为 48px 圆形加号，保留“新建会话”可访问名称；点击后展开并聚焦输入。原有向下收起、明显向上或回到顶部恢复，以及编辑中／有草稿／有引用时保持展开的规则不变。
- 输入框与加号共享同一外框，采用约 280ms 的宽高与圆角变化，配合内容和图标淡入淡出。快速反向滚动从当前状态继续过渡；输入节点保留，收起时不可聚焦或误操作，避免闪换。
- 支持窄屏、键盘；系统启用减少动态效果时直接切换。尺寸和时长属于可逆实现选择，发送后才创建会话的语义不变。

## 12. 自适应宽度与标题拖动排序（2026-09-22）

对应 AI-01、AI-11—AI-13。用户明确要求：有空间时会话卡片更宽且居中，有其他卡片时再让位；鼠标或触屏拖动标题栏调整卡片位置与顺序；会话列表固定排序首位；用户随后补充新会话中列表应紧贴会话框、不要单独留在画布最左边，拖动需像画报一样实时让位。本节覆盖第 9 节固定对话宽度和固定工作卡片顺序的旧口径，其余文件版本、来源快照与阅读规则继续保留。

本次可逆实现选择：

- 独立会话默认取扣除列表后的可用宽度约 68%，限制为 560—880px，不铺满大屏。新会话中以会话框居中为主，列表贴在其左侧并保持 8px 间距，两者一起调整位置；空间不足时整体向左收紧。已有会话将列表与工作卡片作为整组居中，留白放在整组外侧，不插入列表与会话之间。出现画报来源或文件后，先使用留白，再将默认对话宽度收至最低 480px；仍不足时使用既有横向浏览与层叠边缘。关闭文件后重新计算，独立会话恢复居中。
- 来源默认 360px（可调 300—580px），文件默认 400px（可调 320—680px）；对话手动可调 420—1040px。窗口不足时限制实际显示宽度，但保留手动设置，恢复大屏后复原。双击对话右边缘清除手动值，回到按当前窗口与卡片数量计算的自适应宽度；来源和文件双击恢复各自默认值。
- 列表固定首位，不提供标题拖动或排序；既有列表边缘调宽（默认 240px，208—340px）、分组与滚动位置保留。横向浏览时仍可折在前方工作卡片后，通过边缘展开。
- 对话、来源、文件均可拖动标题栏；超过约 6px 才开始移动，显示随手指／鼠标移动的卡片和插入线，跨过邻卡后立即重排，其他卡片实时让位；松手只保存当下顺序，不再等松手才移动邻卡。取消恢复拖动开始时的顺序。保持卡片统一高度，不引入自由纵向错位。靠近视窗左右边缘时自动横向滚动，支持拖到当前屏幕以外的卡片旁。
- 用户进一步要求邻卡让位也像画报一样有动画：沿用画报的 240ms 与 `cubic-bezier(.22,.68,0,1)` 缓动，卡片滑到新位置；连续跨越、反向拖动或取消时，从当前可见位置继续移动。命中判断与折叠计算使用最终布局，避免动画中的位置反复触发换位。减少动态效果开启时直接换位，运行中切换该设置也立即结束过渡。
- 用户随后要求横向滑动到尽头仍继续滑动时给出弹性反馈：左滑压缩到底后继续滑动，间隙与露出的叠边略微收紧；右滑完全展开后继续滑动，间隙略微拉开。列表作为固定端，卡片宽度和顺序不变，松开后衰减回弹。当前可逆参数为每处间隙最多压缩 6px／拉开 8px，总位移不超过 32px，折叠边缘至少保留 8px；越界距离越大，新增位移越小。触控板优先通过原生惯性标记开始回弹；不支持时以连续衰减的像素滚动量推断尾流，无后续事件时约 48ms 开始回弹，避免等整个惯性尾流结束。触屏松手或取消时回弹，回弹约 500ms 结束；反向滑动立即恢复正常浏览。只有视觉位置参与弹性，实际滚动范围与折叠／展开状态不变。卡片全部放得下时也能提示边界；窄屏单卡、减少动态效果、弹窗与卡片拖动期间不触发，正文竖滑和内部横向阅读保持原行为。
- 松手响应修正：原生标记采用 [Pointer Events 的 WheelEvent.momentum](https://www.w3.org/TR/pointerevents4/#dom-wheelevent-momentum)，有标记时以其为准，不把主动减速误当松手；兼容路径在连续至少 3 次下降且幅度降至峰值 60% 后锁定尾流。锁定持续到下一次手势，视觉归零不清除，避免残余事件再次拉开卡片；间隔超过 140ms、反向或明显重新加力可重新接手。惯性仍参与正常横向滚动，只停止对边界弹性的累加与回弹计时重置。兼容识别属于可逆启发式，不能精确测量实体触控板的抬指时刻；真实设备体验仍需验收。
- 最新点击反馈：列表、会话、来源、文件只要未完整显示，点击其任意露出区域都平滑移动到完整可见的位置，包括部分遮挡的正文、折叠边缘的顶部／底部和视窗边缘露出的局部。以最小必要横向位移同时避开裁切与后卡遮挡，不改变顺序或宽度。未完整显示时第一次点击只展开，防止误触半露出的按钮；完整后控件正常执行原操作。标题点击与拖动区分，移动超过 6px、正文滚动或触摸取消不算点击展开。原展开按钮也支持键盘，减少动态效果时直接定位；文件阅读、版本面板与未发送草稿保留。
- 最新间距与层次反馈：普通间隙全部统一为 8px，比此前列表与会话之间的间隙更紧凑；去掉工作卡片前额外的居中留白，并修正贴边时重复计算滚动内边距的问题。列表及其他卡片折叠后的露边统一缩为 12px，覆盖区域更紧凑；所有卡片使用统一的左侧接触阴影与下方柔和阴影。布局、默认宽度分配、点击展现、拖动插入线和弹性效果共用相同间距数值。数值与阴影强度属于本次可逆实现选择。
- 阴影与叠放识别补充：用户反馈阴影被左侧、顶部截断且偏重。本次将滚动容器横向及顶部的阴影留白调为 16px，顶部向工具栏空白区延伸以保留卡片原有起点；左右留白同步参与宽度、层叠与点击定位计算，8px 卡片间隙不变。阴影较上一版减轻、收短。按最新反馈，悬停完全折叠或部分遮挡卡片的露出区域时，整张卡片圆角表面统一使用浅蓝色高亮，当前采用主题色 12% 透明度轻染；取消深蓝实色、内描边和展开按钮独立的长条高光。不提升卡片层级或改变叠放顺序。在目标卡片外部上方显示实际标题，当前与卡片相隔 8px，沿用导航文字的柔和模糊背景；标题独立于滚动裁切及卡片层级，长文本最多两行，超长部分省略，辅助技术仍可读取完整标题。键盘聚焦展开按钮时同样提示；移开、滚动、点击展开、拖动、关闭与窄屏切换时清理提示，正文与点击展现继续使用原交互。
- 标题内的选项、关闭、版本等按钮保持原功能；正文可正常阅读、滚动和选字。Escape、触摸取消、失焦或调整窗口可取消当前移动，Escape 在拖动期间不会顺带关闭会话。拖动使用鼠标、触笔与触屏共用的 Pointer Events。
- 键盘聚焦标题后可用 Alt＋左右方向键前后移动，Alt＋Home／End 移到工作卡片首尾；列表不在这个排序范围。DOM 与视觉顺序一致，资料查看器保持身份，重排不重建文件版本视图或清空未发送草稿。
- 1000px 及以下保留单卡阅读，顶部切换按钮按同一顺序排列。标题横向拖动超过约 48px 即预览向左／右移动一个位置，松手保存；正文手势继续用于阅读。窄屏卡片使用可用全宽，边缘调宽隐藏。
- 顺序按会话记录在当前打开网页内，关闭重开或切换后恢复；新出现的卡片默认追加。宽度沿用当前网页内偏好，不额外写业务存储，也不承诺刷新后保留布局偏好。
