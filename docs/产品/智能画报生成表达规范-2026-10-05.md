# 智能画报生成表达规范

对应 AI-11、DASH-01—DASH-04。2026-10-05 用户指出真实卡片充满系统数据术语、易读性差，要求调整。本文记录当前表达规范与生效位置；内容质量仍需真实生成与用户阅读验收。沿用[卡片规范](智能画报卡片规范讨论稿-V0.1.md)与[内容展示规范](智能画报内容与媒体展示规范-讨论稿-V0.2.md)，不改变卡片生命周期、权限、来源或真实计算规则。

## 规则在哪里生效

| 层次 | 当前位置 | 作用 |
| --- | --- | --- |
| 引擎通用规则 | `engine/src/runtime/task-rules.ts` | 所有任务的事实、授权、工具与成功证据要求。不是专门的画报文风文件。 |
| 画报专用表达规则 | `engine/src/runtime/briefing-writing-rules.ts`，版本 1.0.0 | 当前可执行的选题、文风与内部术语边界，集中维护。 |
| 画报阶段提示 | `engine/src/runtime/agent-task.ts` | 系统生成的每个阶段注入上述表达规则，同时约束检索、计算和交付。 |
| 画报交付工具 | `engine/src/runtime/briefing-delivery.ts` | 复用同一表达规则，覆盖系统主动生成和会话中调用交付工具的画报。 |
| 平台任务提示 | `apps/api/src/main/java/com/dreamcore/workspace/briefing/BriefingGenerationService.java` | 触发原因、固定来源、历史去重、类型和任务目标。内部工具术语可保留，但不是正文模板。 |
| 平台校验 | `BriefingContentService`、`AgentTaskService` | 校验格式、来源授权、计算产物、回执、重复内容和发布状态，不代替编辑质量判断。 |
| 产品文档 | 本文及历史画报规范 | 给开发与验收人员查阅；模型不会自动读取仓库里所有 Markdown 文件。 |

在开发协作中提出的产品级调整，需要更新运行代码、构建并安装后，才作用于新生成。客户端的某次会话或单卡优化不会自动改写全局规则，也不是训练模型权重。规则更新可全局约束画报；个人偏好与企业事实继续使用各自有权限的上下文。现阶段不新增在线规范编辑器。

## 内容要求

- 写给企业员工与负责人：发现了什么、为什么与工作有关、依据是什么、必要时下一步做什么。
- 标题直接表达业务发现或行动；摘要先给结论；正文以2–4个简短自然段说明关键依据、影响、条件或建议。
- 不把字段清单、资料行数、采集时间、数据结构概览、工具执行报告当作洞察。只有用户明确要求结构介绍或技术诊断时，才以它们为主题。
- 正文不出现工具名、API、JSON、UUID、快照编号、内部类型代码和计算配置。来源区域继续保留可追溯依据，不能以简化语言为由删除证据。
- 确切状态翻译成业务中文，但不改含义：`finance_confirmed` 为“财务已确认”，不是到账证明；`canceled` 为“已取消”，不等于已退款；`deposit` 为“定金”。未知状态说明待核实。
- 数值、单位、业务期间、样本范围和不确定性必须真实。样本观察不能推算全部记录，金额的分与元不能混淆，未验证的原因不能写成事实。
- 没有新业务发现时可以不生成卡片。系统画报任务通过已有“暂无新内容”交付协议取得真实跳过回执，不能为了达到生成目标输出空洞结构介绍。

## 表达示例

以下仅示范表达方式，不代表新的真实分析结论。

| 原表达 | 更适合业务阅读的表达 |
| --- | --- |
| 收款明细数据集结构概览与时间覆盖说明 | 若样本确有取消记录：核对已取消收款的后续处理 |
| 样本包含 canceled 状态，compare_dataset 缺少期间字段 | 本次查看的部分收款记录已取消，建议核对后续处理是否完整。此观察不代表全部收款。 |
| 无法生成 DATA，建议生成 INSIGHT | 没有有用业务发现时不发布这段话；说明还缺哪项业务依据。 |

不能仅凭结构或时间跨度把现有卡片改成经营结论。已有洞察保持生成时内容；本次规范对后续生成生效，旧卡重做需要明确操作，不能静默改写。
