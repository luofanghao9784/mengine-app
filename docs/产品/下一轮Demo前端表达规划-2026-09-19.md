**一、Demo 需要让人体验到什么**

1. 进入系统时，AI 已经准备好与自己工作有关的信息和建议。
2. 从一张画报卡片即可开始讨论或处理工作，不必重新说明背景。
3. 用户通过少量关键选择推进工作，始终能补充自己的表达。
4. 重复需求能够保存为可复用操作、画报组件或应用。
5. 用户调整偏好后，后续页面和卡片确实发生相应变化。
6. 老板、管理者和执行者能使用同一套能力，各自看到不同重点。

以上均使用合成数据和可预期的前端模拟。Demo 中的状态联动需要成立，但不表示已实现主动推理、后台运行、真实审批或任意功能生成。

**二、页面与入口安排建议**

沿用现有 AI 会话、工作台、资料库、同事智能体、应用和工作空间入口。重点改造工作台与会话；梦境、自适应、组件搭建和方法复用分布在对应场景中。

| 页面 | 本轮承载的表达 | 当前基础 |
| --- | --- | --- |
| 工作台 | 智能画报、需要处理的事项、AI 主动准备结果、使用侧重点 | 已有待处理卡片、共同进展及合并后的仪表盘 |
| 新建会话与会话页 | 需求引导、操作卡片、画报上下文接续、成果、优化与复用建议 | 已有输入、资料引用、成果预览及专用场景卡片 |

**四、重点交互的表达要求**

智能画报先用少量代表性卡片体现差异。例如一张业务指标卡、一张交付问题卡、一张团队进展卡、一张相关资讯卡。各卡根据内容展示摘要、数字、趋势或列表；首屏控制密度，完整依据按需展开。

画报动作应明确区分“继续讨论”和“开始处理”。进入会话时展示简洁的事项摘要及来源引用，不要求用户阅读内部提示词。处理完成后，原卡片显示最新状态；再次点击进入同一事项或后续会话，不重复制造待办。

三种侧重点建议通过工作台的“调整首页”与个人设置配置；为方便演示，可提供轻量的预设切换。经营关注优先展示画报，团队管理优先展示待处理和进展，工作执行优先展示继续工作和会话入口。使用侧重点只改变呈现；模拟负责人身份在演示控件中明确区分，不由选择“管理”自动授予权限。

操作卡片按实际任务出现，不把所有种类同时摆在会话里。澄清卡片保留自由表达，处理卡片允许修改方案，执行中的卡片显示当前状态，完成卡片给出结果位置。明确的一次选择可以推动后续模拟步骤，不要求每步再输入文字。

主动工作在工作台用简短摘要表达，例如“已整理资料并准备项目提醒”，详情再展示具体任务。已完成维护进入动态，需判断内容进入待处理。资料库展示相应分类、简介或关联变化。资讯来源和推演依据使用明确标记的样例，推测不能显示为已确认事实。

搭建画报组件与搭建应用共用会话中的需求引导和预览体验。画报样例可用“临近交付且未完成的事项”；应用样例优先扩展现有客户跟进或项目交付。配置中的频率只保存为演示选项，不意味着已启用后台调度。任意自由输入超出演示范围时，说明可体验的样例并保留用户输入。

Skill 和脚本可在用户界面以“可复用操作”表达，详情说明输入、处理步骤、产物与适用范围。演示至少包含一次保存和第二次使用，证明这个能力在体验上真正被留下；不只弹出“已生成 Skill”的提示。具体是否与应用共用列表、如何命名分组，在页面设计时确定。

自适应需要有可观察结果，例如用户选择“只看异常”后画报过滤内容，或保存常用范围后下一次卡片预填。涉及 AI 自发发现重复需求时，用预设场景触发并标明模拟。运行调优仅在次级详情中展示“发现问题—建议改进—待验证／演示结果”，不创建虚假的实际成功率、成本节省或真实评测记录。

管理者体验至少串联一项需要决策的工作，例如应用共享、资料入库或权限申请；并展示一个任务分配或流程调整的样例。通过方案摘要和操作卡片说明对象、范围、负责人及结果，不在本轮建设完整流程设计器或权限后台。

**五、个人设置与控制项**

用于表达个性化的配置建议包含：主要职责与关注主题、默认进入工作台或会话、首页侧重点、画报板块顺序及信息密度、常用工作范围、输出偏好和个人记忆。

用于表达主动服务的配置建议包含：关注主题、更新频率、只在重要变化时提醒、个人资料或指定空间的使用范围、自动整理偏好。选项在本地演示中能保存，并改变相应样例的显示或预填；不以纯装饰开关暗示后台已经运行。

首次体验直接提供完整样例，配置保持可跳过，不把填写档案变成开始工作的前置步骤。

**六、三条建议演示路线**

| 路线 | 演示步骤 | 主要表达 |
| --- | --- | --- |
| 经营关注 | 打开画报 → 看客户 A 的交付问题 → 查看依据 → 进入会话讨论 → 选择下一步 → 保存处理成果 → 返回查看状态 | 主动发现、智能画报、上下文接续、行动与结果 |
| 团队管理 | 打开需要我处理 → 查看共享或权限申请 → 讨论或调整方案 → 模拟负责人处理 → 查看空间与申请人侧结果 | 管理者重点、操作卡片、跨页面状态一致 |
| 工作执行 | 表达重复工作需求 → 选择关键条件 → 预览组件或应用 → 保存 → 再次调用 → 调整并保存偏好 | 需求表达、搭建能力、方法复用、自适应 |

梦境维护及资料变化嵌入上述路线；每条路线都有明确起点和可查看的结果。预设示例只用于表达产品体验，不证明真实模型能够完成相同工作。

**七、模拟状态与验证清单**

未来实施时，前端应能表达以下状态：准备中、待补充、待决定、处理中、已完成，以及无新变化、资料不足或处理失败。按各场景使用必要状态，不要求每条路线经过全部状态。

- 全局沿用演示模式标识；资料、生成内容和模拟执行在必要位置明确标记。
- 画报、会话、待处理、应用和资料引用相同事项与产物；状态更新能相互反映。
- 保存的偏好、组件、应用和复用操作在刷新后可继续体验；不重置已有浏览器资料。
- 多次点击同一动作不重复生成同一演示结果；旧方案与最新方案能辨认。
- 切换使用侧重点保留工作进度；模拟身份与页面偏好分开表达。
- 预览、保存、共享申请和模拟批准各有明确结果，失败或缺资料时有可恢复的说明。
- 提供受控演示入口或样例恢复方式，避免依赖真正的时间调度；恢复样例不得无提示清空个人已有演示数据。

本轮为文档规划，尚未实施或验证上述新交互。

**八、建议实施顺序**

1. 先改工作台智能画报与使用侧重点，建立整体体验。
2. 打通画报、会话卡片、成果和事项状态，完成一条工作路线。
3. 将梦境维护和主动准备结果接入相同路线，补齐资料与空间表现。
4. 增加组件／应用搭建、可复用操作及自适应示例，完成第二次使用。
5. 补齐个人设置、管理样例及异常状态，检查三条演示路线。

顺序用于拆分前端改版，仍需在用户授权实施后执行。本轮输出仅为规划文档。
