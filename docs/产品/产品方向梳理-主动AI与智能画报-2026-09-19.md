**产品方向梳理：主动 AI、自适应工作方式与智能画报**

本文整理用户在 2026-09-19 提出的近期思考，供确认后安排下一轮产品调整。文中的“用户提出”记录原始意图；“整理理解”是对这些意图的归纳；“建议”是本次补充的方案；“待验证”表示尚无实际使用证据。本文尚未成为需求基线或开发任务单。

当前依据为 [产品需求基线 V0.1](产品需求基线-V0.1.md)、[用户流程与页面梳理](用户流程与页面梳理-V0.1.md)、[开发启动说明](../交接/开发启动说明.md) 及当前前端代码。已有产品为前端交互 Demo，真实模型、后台主动运行、真实企业权限与生成式应用能力尚未接入。

**一、总体判断与产品定位**

建议支持这一方向，并先验证一条完整工作路径。最值得投入的变化，是让 AI 在用户提出下一条指令之前，就能基于持续积累的工作信息准备有用的内容，并逐步减少同类工作的表达与操作成本。

建议将定位表述为：

> 一个理解企业工作背景、在授权范围内主动准备和推进工作，并能随使用积累适合个人与团队的工作方法的 AI 工作空间。用户通过智能画报发现重点，通过会话与操作卡片完成工作，将有效成果和方法沉淀为可复用的资料、组件与应用。

这是对本次思考的归纳，仍待用户确认。所谓“把 AI 当作可独立思考的个体”，在产品中可以落实为：具有持续目标、可用资料、工作记忆、执行工具、启动条件和责任边界的工作参与者；不将模型具有人类式意志或持续自我意识作为实现前提。

现阶段的事实、推断与假设需要分开：

| 性质 | 内容 |
| --- | --- |
| 已知事实 | 现有基线已经包含会话、资料维护、梦境、提问卡片、仪表盘和自然语言搭建方向；本次重点是重新组织它们的关系，并扩展主动性和适应能力 |
| 已知事实 | 竞品已经覆盖部分主动执行、自动化、Skills 与自然语言搭建能力，详见下文官方来源 |
| 整理理解 | 将这些能力贯通，可能减少普通用户寻找入口、重复解释和手动配置的负担 |
| 待验证假设 | 系统在用户开口前产生的内容，足够准确、相关，值得用户主动回来查看 |
| 待验证假设 | 自适应卡片和可复用能力能减少总耗时，且维护成本不会抵消节省的时间 |

最强的支持理由：工作背景、有效成果和操作偏好能够连续积累，下一次工作就有机会直接从已有基础继续。最强的反对理由：同时建设主动维护、个性化首页、生成应用和运行优化，可能把复杂性转移到后台，最终增加用户核查、确认和维护负担。

**二、四个方向之间的关系**

这四个方向可以作为一套产品机制的不同侧面理解，不必各自新增一个菜单。

| 用户提出的方向 | 核心问题 | 主要产品表现 |
| --- | --- | --- |
| AI 的主动能力 | 用户没有当次提问时，AI 能为工作提前做什么 | 梦境维护、相关资源收集、问题发现、画报准备与更新 |
| AI 的自进化和自适应 | 同样的工作，下一次能否更贴合、更省事 | 偏好适应、卡片优化、重复需求识别、Skill 或脚本复用、运行优化 |
| AI 的垂直触达能力 | 用户的具体需求如何表达并变成稳定可用的能力 | 需求引导、选择卡片、画报组件生成、业务应用搭建 |
| 页面极简与人群差异 | 用户进入系统后，如何最快找到自己要看的信息和要做的事 | 按职责与偏好安排首页重点，统一会话与事项入口 |

这里“垂直触达”按用户原意理解为深入具体岗位、任务和个人需求，不自动等同于已经选定某个垂直行业。

贯穿它们的工作路径是：

**获准资料、业务记录、个人档案与会话 → AI 主动准备 → 智能画报呈现重点 → 会话和卡片推进工作 → 产生真实成果 → 积累可复用方法 → 改善下一次工作。**

这条路径允许用户从任意会话直接开始工作；不要求先读画报，也不要求每一次临时需求都沉淀成应用。

**三、主动能力：有持续工作目标的 AI**

用户提出的范围包含三个层次：

- 信息维护：自发整理资料库、维护分类与索引、识别重复和过时内容、补充关联。
- 信息准备：围绕用户职责和关注主题收集资源，结合已有资料进行知识推演，发现值得关注的问题或机会。
- 结果呈现：依据资料、个人档案与获准会话生成并更新智能画报，优化内容组织和展现形式。

建议将“梦境”作为后台持续维护的产品概念，不限于夜间固定运行。具体机制可以由资料变化、任务完成、已设置的目标或周期触发，AI 在每次运行中判断值得处理什么。启动机制、工作内容选择、最终执行权限是三个不同问题。

整理结果也应有不同去向：可在既定授权内自动完成的维护直接生效并留记录；需要用户注意的发现进入画报；需要用户决定的事项进入操作卡片。避免每次整理都新增一条待办。

建议约定四项可配置内容：关注什么、可以使用什么资料和工具、可以自行完成什么、最多消耗多少资源及注意力。外部资源收集需要明确来源范围与时效，知识推演保留依据与不确定性。

个人档案、私人会话和企业资料保持各自使用范围。个人画报可以使用本人获准的工作背景；团队画报只使用可向相应受众展示的信息。已有资料维护授权不自动变成发布成果、修改业务事实或对外执行的授权。

主动性的效果应以省下的整理与判断时间衡量。无需为了每天展示“AI 在工作”而制造新内容；没有重要变化时，可以保持原有结论并说明检查时间。

**四、自进化与自适应：把改善对象说清楚**

用户提出：AI 识别会话中的重复需求和低效操作，自行生成及优化操作卡片、Skill、脚本和可复用组件，发现运行问题，调整参数，提升整体体验、能力与效率。

建议将这一方向拆成三个不同层次，分别验证：

| 层次 | 可以改善什么 | 如何证明改善 |
| --- | --- | --- |
| 个人适应 | 称呼、输出格式、常用资料、选择项默认值、信息密度、关注主题 | 用户更少纠正，任务结果仍符合要求；偏好可查看和修改 |
| 工作方法积累 | 将反复出现的任务变成可重复执行的方法、脚本、卡片或组件 | 同类任务在资料变化后仍正确，人工步骤与总耗时减少 |
| 系统运行优化 | 上下文选择、检索策略、工具调用顺序、重试策略，以及获准的运行参数 | 在代表性任务上比较质量、成功率、耗时与成本，有退回旧版本的办法 |

这里的“自进化”优先表达系统工作方式的改善，不预设需要训练或修改模型权重。模型参数训练、运行参数调优、记忆更新和业务工具生成应分别讨论。

建议采用“识别问题 → 提出改法 → 用样例验证 → 在获准范围采用 → 观察实际效果”的过程。个人低影响偏好可以按既有记忆规则自动适应；共享工作方法和影响多个用户的系统变更需要与其影响相称的验证。AI 可以自发诊断平台问题并准备修复方案，平台代码发布、权限规则及全局策略不与个人偏好更新使用同一套自动生效机制。

操作卡片是用户与能力交互的界面，Skill 是可复用的任务方法，脚本是适合确定性步骤的执行实现。三者可以组合，也可以独立使用。一次任务是否值得沉淀，应看复用价值和维护成本，不能仅凭出现过一次或点击率较高就生成永久工具。

**五、垂直触达：帮助表达需求，再把需求变成可用能力**

这一方向解决两个连续的问题：首先帮助用户发现和说清楚需求，再将需求实现为适合日常工作的功能。

建议的交互顺序为：

1. 用户说出目标或困扰，例如“我希望每天知道哪些交付可能延期”。
2. AI 结合获准背景补齐已有信息，只询问会改变结果的关键问题。
3. 通过选择卡片确认范围、判定口径、更新频率和预期动作，同时保留自由输入、修改选项及表达“不确定”的能力。
4. 展示可操作预览，让用户检查具体结果，并用自然语言调整。
5. 根据需求的持续性，保存为个人画报组件、可复用操作，或带业务记录的应用。

用户少输入的前提是系统承担了信息整理工作，不能把未问清的业务规则直接猜成确定事实。必要输入量以能正确完成工作为准。

功能形态可按需求自然增长：临时任务使用会话；重复执行的方法形成 Skill 或脚本；持续观察的信息形成画报组件；需要保存记录、多人流转和管理状态时形成应用。用户无需先理解这些技术分类才能提出需求。

“系统给出标准和限制”建议具体化为：可用数据与权限、输入输出、可执行动作、界面规范、错误处理、版本与维护归属。优先复用现有能力，缺口才生成新实现。生成的应用要能持续读取正确数据、保存真实结果、处理失败和后续变化，不能只交付一个外观正确的界面。

**六、智能画报：从重点信息进入具体工作**

用户提出的“智能画报”可归纳为：

> AI 围绕用户职责、关注事项和当前工作，持续组织事实、分析、建议与行动入口的可交互工作简报。

它保留仪表盘的数据呈现能力，并增加信息筛选、业务解释、建议和下一步入口。名称暂沿用“智能画报”；“画报”描述组织和阅读体验，不限制为一张静态图片，也不要求每天采用固定日报版式。

用户希望纳入的内容包括系统数据、经营情况、相关资讯、员工工作与流程进展，以及 AI 对这些内容的分析和建议。板块可由用户表达需求、AI 辅助搭建，并随使用优化。

建议用下列共同结构保持卡片可读、可追溯、可行动，具体字段按内容精简：

| 内容 | 用户需要知道什么 |
| --- | --- |
| 重点与事实 | 发生了什么，涉及哪个时间和范围 |
| 依据与时效 | 来源是什么，资料或数据更新到什么时候 |
| 分析与建议 | 为什么值得关注，有哪些可能解释和下一步；推断与事实分别表达 |
| 工作入口 | 查看明细、继续讨论、生成成果或执行获准操作 |

例如，合成演示卡片可以写“客户 A 方案仍引用旧版报价，建议先核对后更新”。依据为方案的引用版本与报价文件，动作可为“查看差异”“起草修订”“继续讨论”。这类事实只能证明存在版本差异，不能直接推断已经造成损失。

卡片进入会话时，系统准备相关资料及版本、事项状态、当前问题和候选任务，用户可以直接推进。候选提示词可转化成“分析原因”“起草方案”等易懂操作，不要求用户阅读提示词配置。打开讨论与执行具体动作应表达清楚；执行时重新核对当前资料和权限，避免旧画报触发过时操作。

同一事项在画报、会话和应用中应引用相同的工作状态；处理后各处同步，重复点击不重复创建工作。

形式可以是摘要、图表、时间线、进度列表或成果预览。建议允许内容与适宜的呈现方式变化，同时保持核心导航、用户固定板块和重要操作位置稳定。自动调整不能以牺牲用户的熟悉程度为代价。

**七、三个使用侧重点，共用一套产品能力**

用户的分类适合作为使用视角，而非互斥身份。同一个人可同时承担经营、管理和执行工作。

| 使用者 | 进入系统时的主要目标 | 建议优先呈现 | 随后如何工作 |
| --- | --- | --- | --- |
| 老板 | 了解经营现状，发现问题，作出决策 | 经营结果、变化与异常、项目和团队进展、建议 | 从画报进入分析，制定行动或交给相应负责人 |
| 管理者 | 组织工作、处理阻塞、维持流程与权限 | 审批与授权待处理、任务进展、例外情况、团队画报 | 在卡片中处理明确事项，在会话中讨论复杂问题，在应用中管理流程 |
| 执行者 | 完成当前工作，生成并交付成果 | 当前任务、最近会话、资料及成果、常用操作 | 在会话中生成与修改，使用卡片和工具，提高重复工作的效率 |

具体谁能设置企业权限、审批或派发任务，仍由实际职责与系统授权决定，不能因为选择了“管理者视角”就获得这些权限。老板也不因此自动可见员工私人会话。

建议由用户选择主要侧重点，允许混合和调整；AI 可提出偏好建议。角色决定默认排序，当前任务影响内容重点，明确的用户设置优先于推测。

**八、对当前页面的调整建议**

当前侧栏包含新建会话、工作台、资料库、同事智能体、应用，以及空间和会话列表；仪表盘已经合并在工作台中。因此，本次主要需要讨论首页内容组织与工作衔接，无须先假定再增加一个“智能画报”一级入口。

建议保留两个稳定的主要工作入口：AI 会话承接提出需求和完成工作；工作台承接主动发现、需要处理的事项和智能画报。两者保持同级可达，用户可以选择默认进入哪一个。

页面简化可以先采用以下原则：

- 首屏优先当前用户最需要的结果与动作；详细资料、依据和配置按需展开。
- 同一事项以同一张工作卡片连接画报、待处理、会话与应用，减少重复描述和重复创建。
- 资料库承接找资料与管理资料；工作空间继续组织业务背景、成员和成果；应用承接可重复使用的业务工具；同事智能体承接找人和协作。
- 简化菜单的判断依据是用户能否更快完成典型任务，不以菜单数量本身作为目标。
- 画报的信息密度、板块顺序和默认入口可以配置，整体导航和关键交互保持稳定。

以上是布局原则建议，尚未冻结新的导航或视觉设计。具体是否折叠低频入口、怎样呈现三种侧重点，需要在下一轮页面原型中验证。

| 现有需求依据 | 本次思考的变化 | 后续处理建议 |
| --- | --- | --- |
| AI-01、AI-08—AI-13 | 会话和卡片进一步成为画报、维护建议、审批与生成能力的共同交互方式 | 延续原编号，补充卡片来源、上下文接续与事项状态 |

| DASH-01—DASH-04 | 仪表盘升级为含事实、分析、建议和行动入口的智能画报 | 保留数据口径要求，确认新定义及呈现方式后补充需求 |
| BUILD-01—BUILD-04 | 自然语言搭建进一步连接需求发掘、操作卡片、个人工具和可复用方法 | 补充需求引导、预览、验证、保存与维护流程 |
| POS-01、WS 系列、ACT 系列 | 延续员工使用 AI、空间内积累成果、团队共同维护 | 主动能力继续以真实资料、工作状态和权限为依据 |

| 尚无完整对应规则 | AI 自发诊断系统问题、参数调优、评价改善效果与采用新版本 | 作为新增讨论项，单独确定验证与生效范围 |

这轮思考提升了原本后续能力在整体体验中的重要性，可能影响实施优先级。确认产品方向、确认下一轮 Demo 范围、确认真实服务开发范围是三个不同决定，后续应分别记录。原有后续阶段不因本文自动提前。

**十、先验证一条最小完整路径**

最危险的假设是：**AI 在用户开口之前准备的内容，能稳定减少人的工作量，而不会把时间转移成审阅、纠错和确认成本。**

建议先用现有“客户 A 交付项目”合成资料演示一条路径：资料出现变化 → AI 准备一条有依据的发现 → 工作台画报呈现 → 点击卡片进入已有上下文的会话 → 用少量选择确定处理方式 → 生成并保存成果 → 更新事项状态 → 将确有复用价值的处理方式保存为可再次调用的操作。

该演示用来检验页面、表达方式和衔接是否易懂；预设卡片和脚本不能证明 AI 能自行发现问题或稳定生成工具。

真实验证建议在获准材料范围内，选择一家试点的一个反复发生的场景，覆盖三种工作视角，观察约一周或至少数次重复任务。同一人可以兼任多种视角。先比较现有做法与新路径，记录：

- 准备、表达、操作、审阅、纠错的总耗时是否降低。
- 主动发现是否有依据、是否有用；漏掉的重要事项是否可接受。
- 用户是否在无人提醒时回来查看，是否关闭或忽略大量卡片。
- 复用操作能否在新的资料上继续正确完成任务。
- 生成与维护的成本是否适合该类工作的价值。

具体阈值在取得基准后再确定。以使用结果评估价值，不以画报数量、任务运行时长或生成工具数量证明成效。

如果主动推送价值不足，先收窄成用户明确订阅的主题和事件；如果自生成工具不稳定，先复用经过验证的模板与配置；如果复杂画报妨碍完成工作，保留简短重点卡片并提高会话入口优先级。这些回退路径都能保留已积累的资料与成果。

**十一、供本轮确认的三项主张**

1. 产品主线采用“主动准备 → 智能画报发现重点 → 会话和卡片推进 → 成果与方法复用”，其中 AI 会话仍是核心工作入口。
2. 老板、管理者、执行者作为可混合、可调整的使用侧重点，共用一套能力，页面默认重点与访问权限分别管理。
3. 下一轮优先验证智能画报、会话、操作卡片和成果状态之间的一条完整路径；自适应、主动维护和生成能力按该场景逐项加入，具体 Demo 与真实接入范围另行明确。

前三项是本次归纳与建议，等待用户确认。梦境可自动处理的范围、画报默认频率、首批生成组件类型及系统运行优化的自动生效程度，留到相应切片中细化。
