# 画报状态角标与来源标签调整

2026-09-24。沿用 AI-11、DASH-01—DASH-04；用户通过浏览器批注要求卡面显示有用、没用、关注状态，并移除“模拟底表 v1 · 某日情境”标签。对应[卡片规范](智能画报卡片规范讨论稿-V0.1.md)与[详情反馈验收](画报详情与反馈前端验收-2026-09-24.md)。

## 本次实现

- 在卡片右下角并排显示反馈、关注及已有会话图标，复用详情中的赞、踩、星形及原会话图标。有用与没用互斥，关注和已有会话可同时存在；角标表示状态，操作仍由详情承接。
- 卡面读取与详情相同的当前反馈和关注状态；撤销反馈、取消关注后同步移除相应角标。取消选择没用原因不会显示已标记没用。角标具备文字说明和辅助技术标签。
- 根据角标数量预留底部来源与图片署名空间；图片卡采用浅色角标，保留文字和图标的可读性，窄屏不与正文或署名重叠。
- 仅从卡面移除旧演示来源行“模拟底表 v1 · 某日情境”，同时移除该行悬浮提示。真实资讯来源、原文发布日期、数据统计周期、图片署名和页面演示标识保留。使用展示层格式化兼容已有浏览器数据，不清空本地存储。
- 本次是上述两项前端批注的实现。卡片唯一状态、按日内容和数据卡重新推荐的整体机制仍以最新需求记录为准，尚未因移除标签而完成；原会话、引用依据及详情内容不迁移。

## 验收依据

1. 从详情标记有用及关注，关闭后两个角标同时显示；刷新后保留。
2. 选择没用原因后，没用角标替换有用角标；取消原因选择保留原反馈。撤销反馈及取消关注分别移除对应角标。
3. 图片卡可以同时显示反馈、关注和已有会话三个角标；在 1440、977、390、320 像素窗口中不重叠或越过卡片边界。
4. 演示卡不显示旧情境来源行，真实资讯仍显示来源与发布日期。

实现检查命令：`npm run build`、`node --experimental-strip-types --test tests/briefing-feedback.test.ts tests/briefing-magazine.test.ts`、`CI=true PLAYWRIGHT_PORT=5197 npx playwright test tests/e2e/briefing-status-marks.spec.ts tests/e2e/briefing-magazine.spec.ts tests/e2e/briefing-feedback.spec.ts`。

实际结果：构建通过，12 项相关单元检查通过；20 项既有 Chromium 反馈与排版检查通过，2 项新增状态角标检查随后通过。新增用例首轮误用了调整会话的返回按钮名称，按实际普通会话的“关闭会话”入口修正后通过，没有修改产品逻辑或放宽断言。用本地临时配置另在 WebKit 执行相同的 2 项新增检查并通过。已查看桌面 Chromium、窄屏 Chromium 和 WebKit 的图片卡截图，三个角标与署名没有重叠；差异及新增文档链接检查通过。上述为本地验证，不代替安装版 Safari 或用户体验验收；未提交、部署或修改实际业务数据。
