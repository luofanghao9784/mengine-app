# 9POP 订单收款退款业务知识样稿

本知识用于解释一笔课程业务从订单、分次收款到退课退款的关系，帮助员工和 AI 判断“这笔钱是什么、现在到哪一步、应该怎样核对”。订单金额、登记收款、银行到账、课程履约、退款出款和财务处理，是彼此相关但不能相互替代的事实。

**版本：V0.1，2026年10月16日，待审阅。** 仅为本地样稿，未发布到线上知识库。

阅读标记：**【已核实】**表示已对照 9POP `7c1d1788` 源码或当日线上知识与字段解释，不等同于用户重新确认制度或所有线上版本一致；**【待补证】**表示还需要继续查规则、执行记录或资料，不需要用户替系统猜答案；**【待你确认】**表示需要明确业务表达或管理口径。本稿示例全部是假设，不对应真实会员或订单。

## 一笔业务怎样串起来

**【已核实】**完整订单记录课程交易及付款安排；收款记录描述这张订单的一次付款分段，一张订单可以对应多笔收款。退课退款记录通过会员课程关联业务，再核对相关订单与收款。退款申请、退款暂挂、实际出款和财务影响分别留痕。[依据 1、2、3]

| 业务对象 | 回答的问题 | 不能单独证明什么 |
| --- | --- | --- |
| 完整订单 | 约定多少钱、采用什么付款方案、订单处于什么阶段 | 钱已经全部到账、课程已经上完 |
| 收款分段 | 哪次付款、登记多少、凭证和财务处理到哪一步 | 银行已经完成结算、全部金额已实现为收入 |
| 会员课程 | 这笔交易对应哪项课程权益 | 仅凭课程存在就推定付款或退款成功 |
| 退款申请与退款记录 | 为什么进入退款流程、采用什么计算结果、是否生效 | 仅凭审批或生效状态补造付款凭据 |
| 退款暂挂 | 退款处理期间的课程保护状态是否仍有效 | 把暂挂状态当作付款状态 |
| 退款财务影响 | 哪部分冲减收入、哪部分计为费用、对应哪些分录 | 把所有财务影响再当作现金支出扣一次 |

退款与订单按课程关联时，应检查关联是否唯一。单次数据核验没有重复，不等于今后可以省略检查；遇到多笔、缺失或历史记录，应先说明，不能按会员姓名强行合并。

## 订单和收款怎样理解

### 金额的含义

**【已核实】**订单总金额是交易约定口径；订单累计已付是汇总口径；收款表保存分次登记。核对时应先按订单汇总符合所选口径的收款，再与订单比对，不把两个层级相加。[依据 1、2]

> **示例**：一张订单约定 10,000 元，订单累计已付 10,000 元，关联两笔财务确认收款 2,000 元和 8,000 元。该口径的登记收款为 10,000 元，不是 20,000 元。银行到账和收入确认仍需各自依据。

### 收款状态说明什么

**【已核实】**当前收款状态及主要处理条件如下。财务处理要求记录处于已上传凭证状态；被财务退回后可重新上传凭证。[依据 2]

| 状态 | 业务解释 |
| --- | --- |
| `pending_confirmation` | 待确认收款 |
| `confirmed_pending_voucher` | 已确认，待补凭证 |
| `voucher_uploaded` | 已上传凭证，待财务审核 |
| `finance_rejected` | 财务退回，需要重新处理 |
| `finance_confirmed` | 已通过财务处理；部分界面标签为“已对账”，仍不能单独证明银行到账 |
| `canceled` | 已取消，不能混入有效收款汇总 |

“客户已经付款”“系统登记收款”“财务确认”“渠道对账”“银行到账”可能需要不同证据。AI 应沿提问口径判断，不因一个状态名称包含“确认”或“对账”就跳过后续核验。

### 订单完成不等于服务完成

**【已核实】**普通全款与定金尾款方案在财务确认后有不同订单状态：全款路径可进入订单完成及无后续应收阶段；定金路径进入待尾款及尾款应收阶段。[依据 2]

`completed` 表示订单流程状态，`receivable_stage=none` 表示当前应收阶段标记。两者都不能单独证明课程履约完成、银行资金结算结束，也不能抹去后续退款或历史例外。

**【待补证】**分期表已经接入，但分期与普通定金尾款的差异、逾期处理及课程可用权益规则，还没有在本稿逐项核实。不能把所有分期统一解释为“定金加尾款”。

## 退款流程怎样理解

### 申请与暂挂

**【已核实】**退款提交流程会建立活动暂挂，退款撤回或驳回会走释放流程，退款生效会结束暂挂。暂挂有自己的状态，不能直接套用退款记录或审批单的状态解释。[依据 3、4]

| 暂挂状态 | 对应含义 |
| --- | --- |
| `active` | 暂挂仍有效，相关受保护的课程变更需要检查此状态 |
| `applied` | 退款生效流程已将暂挂结束，记录结束时间；不是“刚提交申请” |
| `released_rejected` | 退款驳回后释放暂挂 |
| `released_withdrawn` | 退款撤回后释放暂挂 |

**【待补证】**上课、签到、补录、付款及课程变更的具体入口，需要逐个核对暂挂检查及日期边界。本稿不据“课程暂不可变更”的提示，直接推定所有操作都被禁止或允许。

### 撤回和驳回以后

**【已核实】**释放暂挂会先结束暂挂，再处理此前延后的请假、停卡等生命周期事项，并按条件计算补偿延期天数。补偿与计算版本、暂挂前课程状态、生效日期及课程结束日期等有关，不能承诺“撤回后统一延长若干天”。[依据 4]

**【待补证】**各课程状态和版本的延期计算明细、实际案例，以及操作责任人的说明，需形成后续专题。

### 审批 付款 生效的关系

**【已核实】**当前退款生效服务会在相应终结路径中处理课程结算、发布课程退款事件、结束暂挂并更新退款事实。存在人工付款、线上原路退款确认和符合条件的零现金结算等分支。[依据 3]

因此，AI 应区分“审批结论”“实际退款出款”“课程及业务生效”。历史退款的 `applied` 状态不能补足缺失的付款事实；零现金分支也不能被误判为“没有付款所以失败”。

**【待补证】**消费券核定调整、零现金资格、线上原路退款失败与重试、各节点责任人，还没有在本稿完整展开。遇到这些情况，应转查对应记录和专门规则，不套用普通退款示例。

## 退款金额怎样计算

### 普通课程的两条计算路径

**【已核实】**普通双路径退款使用课程保存的价格档位快照，分别计算按天数和按课次的保留价值，再得到退款本金。[依据 5、6]

| 路径 | 计算依据 | 不能怎样简化 |
| --- | --- | --- |
| A `PATH_A_ONLY` | 使用天数与课程价格档位，分段计算保留价值 | 不能默认用现售价乘一个统一剩余比例 |
| B `PATH_B_ONLY` | 有效已使用课次与档位保底课次，分段计算保留价值 | 不能把所有登记课时都当作有效课次，也不能随意套统一单价 |

普通路径下，保留价值不超过已付金额，退款本金为已付金额减去对应保留价值，最低为零。金额应由既有计算器按原始单位及精度规则计算；AI 负责解释输入与结果，不能另写一个近似算法替代。

**【已核实】**普通课程预览未指定路径时，默认选择退款金额较高的一条；两条相同时选 A。已明确指定 A 或 B 时，预览使用指定路径。这个默认行为不等于 AI 有权替操作人提交或批准选择。[依据 6]

> **示例**：假设系统基于同一组有效事实算出 A 退款 6,000 元、B 退款 6,500 元，未指定路径的普通课程预览默认选 B。历史上 A 使用得更多，不是这一笔改选 A 的依据。

### 日期与例外

**【已核实】**V2 退款计算将申请计算日和退款生效日分开：剩余天数按退款生效日计算，有效课次统计到生效日当天零点之前；退款资格窗口仍按申请计算日判断。[依据 5]

计算器另有正式 7 天卡、历史赠送课、退款资格窗口、请假停卡和价格快照缺失等专门处理，不应一概套用普通双路径公式。缺少价格档位快照时不能让 AI 猜价格。

**【待补证】**特殊产品的完整适用边界、历史版本差异、允许人工选择不同路径的岗位和业务理由，应分别补证；未核实前不承诺具体退款额或办理资格。

### 计算退款不等于最终出款

**【已核实】**系统退款本金、保留收入、其他费用、实际退款出款与门店费用影响是不同指标。普通及特殊退款分支可能有其他费用或核定调整，不能把计算本金直接改称实际付款额。[依据 7]

解释一笔实际退款时，应读取该笔锁定事实、最终出款与相关财务记录，不根据本文示例反推真实金额。

## 退款怎样影响财务

**【已核实】**退款本金的财务影响按相关收款分段处理，而不是整张退款单凭名称统一归类。当前终结服务沿收款确认时间、编号排列收款分段，核对已付金额及本金分配，并检查原收入与相关期间条件。[依据 7]

| 收款分段条件 | 本金财务处理 |
| --- | --- |
| 非历史关闭，且原核算期未锁定 | 冲减原核算期收入 `income_reduction` |
| 已锁期或属于历史关闭收款 | 列入退款付款月份费用 `refund_expense` |
| 同一退款包含两类本金影响 | 汇总显示 `mixed` |

这张表解释分类原则，不替代终结时的锁定检查、原收入核验、金额一致性及权限校验。其他费用单独处理；它本身不是判断本金 `mixed` 的充分条件。

> **示例**：假设一笔退款的本金影响中，2,000 元符合原期收入冲减，1,000 元符合退款月费用，分类为 mixed。这是对同一退款的财务分解，不能再把两项与实际出款重复相加作为现金流出。

### 历史空字段怎样处理

**【已核实】**现有部署知识已记录：V68 于 2026 年 7 月 18 日引入财务终结字段，明确不回填历史记录。旧退款缺少财务处理类型，不自动等于异常、未付款或应当重新退款。[依据 1]

历史付款时间、结算时间或分类缺失时，保留未知，并核对原付款或账务凭据。不得用创建时间替代付款时间，不得用旧门店费用影响反推新财务分类，也不得把缺失金额补成零。

## 怎样回答本月净收款及订单差异

**【待你确认】**“本月净收款”尚不应作为一个无需解释的统一指标。以下是供选择的命名方案，不是已生效口径。

| 建议区分的指标 | 要表达什么 | 需要先确定什么 |
| --- | --- | --- |
| 本月财务确认登记收款 | 系统中符合财务确认条件的收款登记 | 按收款确认日还是财务审核日归月 |
| 本月实际收付净额 | 同一范围实际流入减实际退款流出 | 到账证据、渠道结算和手续费处理、退款付款日期 |
| 本月订单金额 | 本月形成的课程交易约定金额 | 订单归属日期、取消退款及软删除规则 |

不能默认把上述任意两项相减就称为“欠款”。本月收款可能来自过去订单，本月订单也可能以后收款；跨期、未审核、退款及口径差异需要分别说明。

口径明确以后，AI 应执行以下核对：

1. 固定期间、门店范围、数据截止时间和所采用的指标定义。
2. 按指定状态与日期筛选收款，以收款分段为粒度计算；确认单位，排除不属于该口径的记录。
3. 按订单先汇总收款再关联，避免一对多展开后重复累计订单金额。
4. 按实际选定的退款口径核对退款事实；涉及现金净额时不能再重复扣收入冲减与费用影响。
5. 将差异拆为跨期、付款阶段、审核阶段、退款、取消或删除、缺失依据和未匹配关联，逐类解释，不强行配平。
6. 同时报告已核实金额和待补证范围。待补证记录不能被静默删除，也不能被当作零。

**【待补证】**上述是核对顺序，尚不是可直接执行的正式查询配方。需要把已确认口径落实到字段、状态和异常分类，并用真实案例核对；原订单收款配方及退款分组只能支持其中部分步骤。[依据 8]

## 需要补齐和确认的事项

### 先由系统继续核查

| 缺口 | 需要补齐的证据 | 未补齐时 AI 的回答边界 |
| --- | --- | --- |
| 分期与定金尾款的区别 | 付款计划、收款关联、权益规则及案例 | 不解释具体分期资格或逾期后果 |
| 暂挂对上课和各类操作的影响 | 各入口服务端检查、日期边界、撤回案例 | 不直接承诺能否上课或延期几天 |
| 特殊退款 | 消费券、零现金、历史赠送、线上原路退款及失败流程 | 不套普通双路径规则计算或建议操作 |
| 责任分工 | 当前岗位权限、审批模板及已执行案例 | 不凭惯例指定店长、教练或财务谁能办理 |
| 来源变化后的适用性 | 当前线上版本与规则来源的对应关系 | 不把旧版本说明默认用于新流程 |
| 报表完整配方 | 指标定义、字段和状态映射、案例核对 | 不把“有数据”说成“已算出可靠结论” |

### 请你审阅时重点确认三件事

1. **默认报什么。** 当你只说“本月收款”，希望默认看到“财务确认登记收款”还是“实际到账口径”？建议两项分开命名，不以一个“收款”掩盖差异。
2. **登记收款归哪月。** 财务确认登记口径采用收款确认日还是财务审核日？已有报表若有正式约定，应优先沿用并补上依据，不另创一套。
3. **待补证怎样展示。** 建议主结果只纳入满足所选口径的事实，另外列出待审核、待凭证及历史缺失的数量、可确定金额和原因；无法确定的金额显示未知。是否采用这种展示方式？

以上问题仅供本次样稿审阅，不需要先回答才能继续阅读。未回答前保留“待确认”，不写成正式知识或系统默认值。

## 这版知识应当怎样帮助 AI 回答

| 员工提问 | 样稿支持的回答要点 |
| --- | --- |
| 一笔订单和两笔收款会不会重复算钱 | 先汇总收款再核对订单，不跨层相加 |
| 订单完成是不是代表课上完了 | 订单流程和课程履约分别判断 |
| 为什么退款有时减收入 有时记费用 | 看收款分段对应的原期间及历史关闭情况，两类并存可为 mixed |
| A 和 B 是什么 为什么这笔默认选 B | 普通双路径分别按天数和课次；未指定时预览选退款额较高者，相同选 A |
| 暂挂 applied 是刚申请退款吗 | 不是；它是退款生效流程结束暂挂时的状态 |
| 为什么还不能直接报本月净收款 | 指标、月份和退款范围未明确，先说明缺口，不能凭统计文章补定业务规则 |
