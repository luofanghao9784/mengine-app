# 契约分片提纲（草稿 · DQ 拍板再改 · 不改 API 实现）

日期：2026-10-30 · 作者：梦擎·前端架构  
状态：已定稿进仓（纯文档）· 不改 `apps/api` / 业务代码  
依据：DQ 定稿用词 1–10 + 本轮拍板（去 governance 分片名前缀 / data-version-readonly / isStale / inputVersionId / admissionTestVerdict）

## 分片一览

| 分片 | 建议路径 | 表面（乙） | 目的 |
| --- | --- | --- | --- |
| 能力登记与准入 | `contracts/public-api/capability-registry.openapi.json` | **platform** | 目录、版本、准入测试、candidate→admitted |
| 检查调试执行 | `contracts/public-api/quality-check-run.openapi.json` | **tenant** | **CheckDebugRun** 单模块试跑（禁自动发布） |
| 检查流程配置 | `contracts/public-api/check-flow-config.openapi.json` | **tenant** | 固定步骤绑定模块；publish / 回退（**原 governance-config，已改名**） |
| 检查运行记录 | `contracts/public-api/check-run-log.openapi.json` | **tenant** | 真检查任务 + attempt；三态分列（**原 governance-run-log，已改名**） |
| 数据版本只读 | `contracts/public-api/data-version-readonly.openapi.json` | **workspace** | 员工 B6/B7 只读投影（**新增**；老板已锁员工端首版） |

共享错误继续 `$ref` 现有 `error.schema.json`。引擎 `contracts/engine-api` **独立**。

**feature 命名**：tenant 侧统一 **`quality-ops`**（debug / config / runs）；platform 仍 **`capability-admission`**；workspace 侧 B6/B7 挂 **`data-version`**（或现有 material 扩展须新路由模块，禁止旧 governance 页 id）。

### 命名对照（必读）

| 定稿 | 说明 |
| --- | --- |
| 分片名 | **不得含 `governance`**：`check-flow-config` / `check-run-log`；禁止再写 governance-config / governance-run-log |
| feature | **`quality-ops`**（不用 governance-ops） |
| `executionMode` | `simulated` \| `real` |
| 准入 `admissionStatus` | `candidate` \| `admitted` \| `deprecated` |
| 准入测试结论 | **`admissionTestVerdict`**: `passed` \| `failed` \| `pending`（**独立字段**，勿复用 `QualityVerdict`） |
| 运行态字段 | **`runStatus`**: queued \| running \| awaiting_human \| succeeded \| failed \| cancelled |
| `qualityVerdict` | `pass` \| `fail` \| **`pending`**（定稿；不用 pending_confirm） |
| `publishStatus` | **`unpublished` \| `published` \| `superseded`**（首版无 withdrawn） |
| 过期 | **独立布尔 `isStale`**（不算进三态枚举） |
| 输入版本 | **统一 `inputVersionId`**（不用 inputDataVersionId） |
| 配置 `status` | `draft` \| `published` \| `retired`；回退用 `supersedes` / 事件，无 `rolled_back` |
| 空间 | **`spaceId`**；旧 `workspaceId` 仅对照 |
| IssueKind | unit_mix \| date_ambiguous \| missing_business_key \| conflict_duplicate \| other（无 normal） |

## 1. capability-registry（platform）

**Capability**
```text
capabilityId: "quality-check"
name, kind?: "quality_check"
```

**CapabilityModuleVersion**
```text
capabilityId, moduleVersionId, moduleVersion?, interfaceVersion
supportedFormats, ioSchemaRef?, permissionsRequired[], timeoutMs?, costClass?
admissionStatus: candidate | admitted | deprecated
lastTestRecordId?, createdAt
```

假数据：**同一** `capabilityId=quality-check`，两个 `moduleVersionId`（如 `qc-rules-a@1.0.0` / `qc-rules-b@1.0.0`）。

**AdmissionTestRecord**
```text
testRecordId, moduleVersionId
runStatus
admissionTestVerdict: passed | failed | pending   // 定稿名；≠ QualityVerdict
sampleSetId, summary, finishedAt?
```

端点示意：`GET/POST .../platform-admin/v1/capabilities`、`.../modules`、`.../admission-tests`、`PATCH .../admission`。

非目标：Agent 市场、拖拽编排、读客户正文。

## 2. quality-check-run（tenant）· CheckDebugRun

独立资源，与 `CheckTask`（check-run-log）**分 id 空间**。

```text
CheckDebugRun {
  debugRunId
  tenantId, spaceId?
  inputVersionId          // 统一命名
  capabilityId?
  moduleVersionId
  configVersionId?
  executionMode: simulated | real
  runStatus
  qualityVerdict?         // 跑完才有
  issues: QualityIssue[]
  warnings?, usage?, error?, evidenceComplete?
  // 无 publishStatus；或文档写明不可发布
}
```

端点：`POST/GET .../tenant-admin/v1/quality-ops/check-debug-runs`、`.../cancel`。

## 3. check-flow-config（tenant）

**原名 governance-config，已废止。**

```text
CheckFlowConfigVersion {
  configVersionId, tenantId, spaceId?
  status: draft | published | retired
  supersedes?: configVersionId      // 定稿；不用 basedOn
  stepBindings: [{ stepId, moduleVersionId?, toolPolicy?, budget? }]
  // 首版步骤：ingest → parse → quality-check → review → publish
  requiredChecks?: string[]
  publishedAt?
}
```

回退：`POST .../rollback` → 新 published + `supersedes`；旧版 `retired`。

端点：`.../tenant-admin/v1/quality-ops/config-versions`、diff / publish / rollback。

## 4. check-run-log（tenant）

**原名 governance-run-log，已废止。** 类型建议前缀 `Check*`，避免类型名再带 governance。

```text
CheckTask {
  taskId, tenantId, spaceId?
  inputVersionId, configVersionId, lockedConfigVersionId
  moduleVersionId?
  runStatus, qualityVerdict, publishStatus
  executionMode
  stage: ingest | parse | quality-check | review | publish
  openIssueCount, failedStep?, usage?
  isStale?: boolean           // 可选：任务级过期提示；版本级过期见 data-version-readonly
  createdAt, updatedAt
}

CheckAttempt { attemptId, taskId, lockedConfigVersionId, steps[], retryOf? }
```

三态必须分列；`runStatus=succeeded` 且 `qualityVerdict=fail` → `publishStatus=unpublished`。

**QualityIssue**
```text
issueId, kind: IssueKind
qualityVerdict, summary
evidence: { inputVersionId, row?, column? }  // 定稿 column（非 field）
rawValue?, proposedValue?, rationale?
```

## 5. data-version-readonly（workspace）· **新增**

供员工端 **B6 数据版本 / B7 问题只读**。老板已锁员工端首版；**不作后置**。

```text
DataVersionSummary {
  assetName
  inputVersionId            // 统一
  sourceLabel, stageLabel | stage
  runStatus?, qualityVerdict, publishStatus
  openIssueCount
  publishedVersionId?
  isStale: boolean          // 定稿：独立字段，不进三态枚举
  executionMode?
}

IssueReadonlyView {
  inputVersionId
  issues: QualityIssue[]
}
```

端点示意（只读）：  
`GET /api/workspace/v1/data-versions`、`.../{inputVersionId}`、`.../{inputVersionId}/issues`  
（具体前缀待后端确认；前端不得写。）

权限：员工只读本空间；不得发起 publish / debug。
