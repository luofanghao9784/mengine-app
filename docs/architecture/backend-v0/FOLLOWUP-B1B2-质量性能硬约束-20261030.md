## §1 ADR-B2：首版硬限（有界队列 · 信号量 · 超限失败 · 超时叠加 · job 清理）

### 决策条文（建议原文级写入 B2）

**CapabilityExecutionPort 经 `LocalProcessAdapter`（及首版 in-process 以外、会占 OS 进程/临时目录的适配器）必须满足下列首版硬限；禁止无界排队。**

1. **有界队列**  
   - 端口（或适配器）维护**有界**等待队列；队列容量为显式配置常量（种子默认值由实现 ADR/配置定稿，**本文不编造具体数字**，但合入 PR 必须写出默认值与配置键）。  
   - **禁止**无界 `BlockingQueue` / 无界线程池 / 无限 `CompletableFuture` 堆积作为默认。  
   - 入队前已满：立即失败，**不得**阻塞调用方直到资源出现（除非契约显式约定同步背压且有超时；首版默认「满则失败」）。

2. **信号量 / 并发上限**  
   - 同时处于「进程已拉起、尚未回收」的 `local-process` 执行数 ≤ 配置上限（信号量或等价物）。  
   - in-process 规则执行可另设更高上限，但仍须有界；不得与 local-process 共用无界池。  
   - 超限与队列满使用**稳定失败码**（见下），不得静默丢弃、不得改写为成功/PARTIAL 伪绿。

3. **超限失败码（稳定、可断言）**  
   - 建议语义码（契约定稿可改名，**不得删语义**）：  
     - `EXECUTION_QUEUE_FULL` — 等待队列已满  
     - `EXECUTION_CONCURRENCY_LIMIT` — 并发信号量耗尽  
     - `EXECUTION_TIMEOUT` — 步骤/适配器超时（与现有解析 85s、table-compare 10s 对齐，首迁数值不变）  
     - `EXECUTION_OUTPUT_LIMIT` — 输出超限（与现有限额对齐）  
     - `EXECUTION_JOB_CLEANUP_FAILED` — 临时 job 目录清理失败（可降为 warning + 指标，但不得掩盖主结果失败态）  
   - 失败时 `ExecutionResult.status` 映射为失败态；**禁止**用空 warnings 或成功态掩盖。

4. **超时叠加策略**  
   - 单步 `limits.timeout`（或 ModuleVersion 默认）为**硬上限**；端口不得在适配器外再无限等待。  
   - 队列等待时间计入总时限或单独配置 `queueWaitTimeout`；二者任一触达即失败并返回 `EXECUTION_TIMEOUT`（或拆分 `EXECUTION_QUEUE_WAIT_TIMEOUT`，契约定一即可）。  
   - **禁止**「队列等待无超时 + 进程超时」叠加导致调用方挂死。  
   - 首迁：解析 85s、table-compare 10s 的**进程内**超时数值不变（对齐 B2 既有约束）；本条约束的是端口调度层，不得借机改 sandbox 数值。

5. **job 目录清理**  
   - 每次 local-process 执行使用独立临时目录（或既有 job 目录约定）；**成功与失败路径均须**尝试清理。  
   - 清理失败不得把主结果从失败改成成功；须可观测（日志/指标）。  
   - 禁止依赖「进程退出后 OS 偶然回收」作为唯一清理手段。

6. **验收（实现 PR 必勾）**  
   - [ ] 存在配置化的队列容量与并发上限；默认值写在 PR 说明与配置样例中。  
   - [ ] 单测/集成：填满队列或打满并发时返回稳定失败码，且无成功伪绿。  
   - [ ] 超时用例：队列等待或执行超时均失败且码稳定。  
   - [ ] 成功与失败路径均覆盖 job 目录清理断言（目录不存在或为空）。  
   - [ ] 无 `continue-on-error`；无「跳过资源限制」的测试后门进入默认 CI。

### 明确不做（本补丁）

- 不在本条文锁定具体队列容量/并发数字（留给实现 PR + 配置评审）。  
- 不启用 model-agent / engine-http 的限流细则（预留适配器启用时另开）。  
- 不改 sandbox.py 行为与现有超时/限额数值。

## §2 ADR-B1：qualityops 首个代码 PR 前的可执行自动断言

### 决策条文

**手工 PR 审查清单不能单独充当门禁。** 在合并**任一** `com.dreamcore.workspace.qualityops`（或等价包根）业务/适配器代码进主干之前，必须已合入**至少一条**在默认 CI 中执行的自动断言，满足下列之一（可并存）：

| 方案 | 最低要求 |
| --- | --- |
| **A. 包依赖测试** | ArchUnit（或等价）规则：`qualityops` **不得**依赖 `material` / `knowledge` 的内部实现包；只允许经 `MaterialKnowledgeReadFacade`（或契约定稿之只读端口包）。 |
| **B. CI grep / 结构检查** | 在 Contracts·Engine 或 API 门禁 job 中增加失败即红的检查脚本：禁止 `qualityops` 源码出现对 `material.` / `knowledge.` 内部类的 import；禁止业务包（非执行适配器包）出现指向 parser 的 `ProcessBuilder`。 |

补充：

- ArchUnit「可 backlog」**仅适用于文档期**；**首个 qualityops 代码 PR 的前置条件**是 A 或 B 已绿。  
- 适配器包白名单路径须在检查配置中写死；扩大白名单须过质量性能 + 测试审查，并报总监。  
- 本条与 B1 既有「PR 审查清单必勾」**同时生效**：清单仍勾，自动化为硬门禁。

### 验收

- [ ] 主干上已有对应测试或 CI 步骤，在故意引入违规 import 的分支上**必红**。  
- [ ] 文档/纯契约 PR 不要求本条（无 qualityops 代码即可）。

## §3 验收：`simulated` 不得呈现生产可用质量/发布态（可勾选用例名）

### 决策条文

与 B1 调试默认、三态 ADR 一致，下列断言必须进入契约测试或 API 集成测试，并在纵切「契约 / quality-check-run / debug」相关片中可勾选：

| 用例 ID（建议名，可改名不可删语义） | 断言要点 |
| --- | --- |
| `debug_run_simulated_rejects_production_publish_surface` | `executionMode=simulated` 时，对外契约/API **不得**将 `publishStatus` 表示为可生产发布（如 `published` / 等价生产可用态）；若返回，须为明确非生产态或 4xx 业务拒绝。 |
| `debug_run_simulated_quality_not_production_ready` | `executionMode=simulated` 时，`qualityVerdict` **不得**单独被 UI/报告解释为「已通过可上线」而不展示 simulated；响应中须能区分模拟与真实（字段或并列 `executionMode`）。 |
| `debug_run_real_requires_explicit_mode_and_authz` | 选择 `executionMode=real` 必须显式传参；缺省为 `simulated`；无相应权限时拒绝（权限码由身份/契约 ADR 定稿，本文不编造码名）。 |
| `three_state_columns_not_merged` | 存储与契约中 `runStatus` / `qualityVerdict` / `publishStatus` 分列；合并单一 `status` 或同义混用——测试失败。 |
| `execution_mode_enum_closed` | `executionMode` 仅 `simulated` \| `real`；其它值契约校验失败。 |

### 合入规则

- 字段「存在」类弱断言**不算**满足本条；必须覆盖 **simulated → 非生产可用表面**。  
- 合入审查遇模糊标注（文案/枚举把模拟当生产）——**一律否决**（对齐测试审查第 4 条）。

## §4 首个 qualityops / admission workflow：禁 continue-on-error；admission 默认禁 live/model

### 决策条文

1. **YAML 硬约束**  
   - 首个（及后续）`qualityops`、platform `admission` / `admissionTestVerdict` 相关 GitHub Actions workflow **正文禁止** `continue-on-error: true`（job 级与 step 级均禁）。  
   - 禁止用 `|| true`、吞掉非零退出码、或把失败步骤标为 success 的包装脚本进入默认 PR 门禁。  
   - 审查：质量性能或测试审查对门禁 PR 必须打开 diff 核对上述模式。

2. **admission 默认禁 live/model**  
   - 默认 PR / 默认 branch 门禁**不得**设置真实模型密钥，不得跑 live/model smoke。  
   - `admissionTestVerdict` 相关用例必须在 **simulated / 夹具** 下可绿；依赖 live 的用例须环境变量门闩，且默认 CI **不设置**这些变量（对齐现有 API 门禁：不跑 `model:smoke` / `test:model-smoke` / live 类测试）。  
   - 需要 live 的验证只允许手工/受控 workflow，且不得作为合入主干的唯一绿灯。

3. **与纵切关系**  
   - 仍遵守 B1：契约 → V190 → 端口 → `pii-regex/v1` → data-version **逐片绿**；任一片红不得宣称整链通过。

### 验收

- [ ] workflow 文件无 `continue-on-error`。  
- [ ] 默认 job 环境无线上模型密钥；live 测试类未被调度。  
- [ ] 故意失败的探针步骤能使整 job 变红（防伪绿抽检，可选但推荐）。
