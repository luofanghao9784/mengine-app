## 数据基座专题：已确认重点与待确认交付范围

2026-10-10 用户明确：数据基座搭建是引擎工作的基础，也是实际服务的重点。主册已将其提升为独立章节，并贯穿产品定位、引擎介绍、实施流程、试点评价和收费说明。该定位已确认，不再列为待决定事项。

新增章节依据既有业务数据获取方案和服务边界展开。下列具体交付物及服务深度仍需确认，不能因写入手册自动成为所有客户的标准套餐承诺。

| 编号 | 待确认内容 | 需要明确的范围 |
| --- | --- | --- |
| D01 | 首次盘点与整理 | 资料来源数量、文件体量、历史跨度；去重、分类、字段映射和缺失检查各做到什么程度 |
| D02 | 交付物 | 来源清单、口径说明、权限与责任约定、更新安排、样例验证记录是否作为标准交付，哪些按场景提供 |
| D03 | 接入方式与责任 | 当前标准支持哪些方式，哪些需另行开发；第三方授权、供应商协调、接口费用与变更维护由谁承担 |
| D04 | 业务事实与质量核对 | 客户由谁确认口径；采用哪些基准或样本，如何处理冲突、缺失和无法追溯记录，不承诺修复全部历史数据 |
| D05 | 持续维护 | 检查频率、异常发现与处理方式、人工补交责任、支持工时及新增范围的认定 |
| D06 | 验收标准 | 按任务定义覆盖期间、更新时效、完整性、解析或计算核对、权限检查与异常处理；阈值须按客户确定 |
| D07 | 定价与服务拆分 | 首次搭建、持续接入维护、资料治理和新增实施如何报价；是否包含差旅或供应商费用 |
| D08 | 经销商参与方式 | 经销商可承担哪些盘点、协调、培训或维护工作；资质培训、客户数据访问与交付责任如何约定 |

章节中的不同获取渠道属于按场景评估的服务方案，不是已经全部上线的通用连接器；资料整理、质量核对和业务确认包含人工服务，不能改写为全部由引擎自动完成。数据基座建设从单项工作开始，不要求先完成全企业治理，也不默认包含 ERP、CRM 或完整业务系统重建。

| 编号 | 能力 | 项目中已有的依据 | 本版处理与后续核实 |

| P06 | 独立自进化 | 官网介绍了巡检、调整、验证的方向；不据此证明独立自主实验与上线闭环可交付 | 未列为成熟卖点；确认实际启用范围、人工控制和验证证据后再增补 |

| P10 | 历史版本与恢复 | 历史版本查看有依据；个人文稿原位编辑记录明确首版未新增版本还原 | 正文写“查看历史版本”，未沿用官网“退得回去”的宽泛描述；还原能力另核实 |

| P13 | 公开联网资讯 | 有主题联网查询与快捷入口实现记录 | 确认当前搜索服务、来源阅读、时效和实际交付质量；不将内部资料发送到搜索作为默认行为 |
| P14 | 手机与电脑 | 有浏览器适配及部分手机登录页验证记录 | 不代表所有系统版本、浏览器或完整手机旅程已验收；原生 App 不列现有能力 |

| P17 | 主动计划、审批与跨部门协作 | 部分历史功能与远期设计保留，首期入口有收敛和隐藏 | 不自动纳入现有销售包；确认开放入口和完整业务验收再介绍 |
| P18 | 私有部署与模型选择 | 当前方向为云端服务，私有部署另阶段考虑；开发所用模型不代表产品模型 | 正文不承诺私有部署、任意模型切换或 GPT-6 产品接入；以交付配置与合同为准 |

## 四、渠道政策另行确认

以下属于商业决定，不能通过产品文案推定：

1. 合作方式：代理、经销、推荐佣金或联合实施。
2. 商机报备、客户保护期、区域或行业保护。
3. 经销价格、佣金比例、结算依据与付款时间。
4. 合同签署、收款、开票、退款与争议处理主体。
5. 续费归属、客户转交、终止合作后的服务安排。
6. 售前演示、试点配置、培训和售后由谁承担。
7. 经销商能否接触客户资料、所需授权和退出后的权限处理。
8. 对外报价及功能承诺的审核机制。

本版未生成任何既定渠道政策，后续可以在这些决定确认后编制独立经销商合作附件。
