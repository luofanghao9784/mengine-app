## 本地启动

使用 Node.js 24+ 和 pnpm 11.25.0，在本目录执行：

```sh
pnpm install --frozen-lockfile
cp .env.example .env
# 按本机环境填写 .env，模型凭据只写本地文件
pnpm dev
```

API 默认监听 `127.0.0.1:4400`。前端在仓库根目录运行 `npm run dev`，访问 `/tenant-admin/prototype/`。`MENGINE_API_URL` 可在前端运行环境指定 API 地址。场景允许来源默认配置为 `http://127.0.0.1:5173`。

新环境可设置 `DEMO_MODE=true` 创建合成演示账号及资料；不会包含本机已有宠物门店数据或既有连接。接入已有环境时使用其数据库和文件存储配置，先备份并停止其他写入同一数据库的 API 实例，勿同时运行两份后台同步服务。生产环境禁止演示模式，账号、存储及反向代理需另行配置。本次仅交付源码和本地验证，不代表生产部署。

```sh
pnpm typecheck
pnpm test
pnpm build
```

## 本次功能与边界

- 数据基座对接真实资产、字段解释、治理问题、人工校验通过、复检与审计；指定前端不提供数据导入、新建连接、记录修改/删除、AI 查询口径及暂停提供给 AI 的入口。
- 知识库对接资料知识，并分析治理后的结构化业务数据生成有证据的业务知识；标题正文使用业务语言，校验失败候选不发布。沿用原有星图动画，来源或权限变化后旧知识及关系失效。
- 当前业务知识逐批分析由知识库页面激活时驱动；尚未改为独立后台持续生成任务。
- 数据一致性增强（跨表统一读取点、整批发布、定期对账、独立后台知识更新、CDC）仅为讨论方案，尚未实施。现有机制为定时单表全量同步，单表上限 1 万条，失败保留旧数据。
- 其他原型板块仍有演示内容。详细验证、交接及限制见 ../../docs/交接/数据基座接入Mengine-2026-10-13.md。
